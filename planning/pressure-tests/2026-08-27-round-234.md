# ISS-006 proportionality replan — round 234

## Disposition

`REPLAN_TO_DESCOPE_HOSTED_ISOLATION`.

This round is an external proportionality review of the whole ISS-006 delivery
to date, not a landing review of one module. It finds the harness sound in its
schema, census, receipt, and provider-record machinery, and disproportionate in
its same-host OS isolation machinery, its review cadence, and its integration
posture. The replan below amends the ISS-006 draft, the trusted-harness ledger
in `docs/architecture/contract-decisions.md`, and the work model in the same
reviewed change.

## Findings

1. **Inverted effort.** The branch `codex/iss-006-trusted-harness` holds 330
   commits and roughly 122,000 inserted lines. Planning records account for
   about 47,000 of those lines; `packages/conformance` and `packages/contracts`
   for nearly all implementation; seventeen of nineteen packages remain stubs.
   The kernel the platform exists to deliver has no code. Verification
   machinery is being hardened for a product that does not yet exist.
2. **Disproportionate isolation authority.** ISS-006's threat model already
   restricts candidates to independently reviewed revisions of this repository
   admitted through protected-main dispatch, and each hosted job runs on a
   provider-fresh virtual machine that is discarded afterward. Against that
   admission boundary, the same-host OS-principal stack — a 7,902-line C
   Windows broker with a committed compiled executable, a privileged macOS
   helper in C, and Linux account/DAC/pidfd custody modules — defends against
   a threat the architecture excludes. Under the work model's own rule, that
   is a finding, not a safeguard. The machinery this stack answers becomes
   in-scope only when unreviewed candidate bytes must execute, which is owned
   by the self-host promotion path and is not earlier than `ISS-019`.
3. **Committed binary.** `windows-isolation-broker-x64.exe` is checked into
   `packages/conformance/src/` and loaded at runtime. A provenance-centered
   repository must not execute unreviewable committed bytes; everything
   executed must build from reviewed source.
4. **Review cadence exceeds delivery.** 235 pressure rounds in twelve days,
   averaging roughly 200 lines each, against one partially delivered issue.
   The review ritual has become the dominant output. The work model already
   forbids repeat-until-clean removal rituals; this round extends that rule
   with an explicit per-slice cap and a length proportionality test.
5. **No integration.** `main` has received no code since the bootstrap merges
   of 2026-08-16. A 122,000-line unmerged branch cannot receive the
   independent review the trust architecture requires. Integration cadence is
   now a work-model rule.
6. **The authorized deliverable does not exist.** After all of the above,
   `.github/workflows/conformance.yml` — the hosted three-OS evidence ISS-006
   names as its footprint — has not been created.

## Proportionality

| Mechanism | In-scope threat | Deletion test | Result |
| --- | --- | --- | --- |
| Protected-main dispatch, reviewed candidate revision, provider record | unreviewed or substituted candidate bytes gain hosted evidence | workflow-structure and provider-record mutants (already built) | retain |
| Materialization consume/delete custody and stable-parent timing | candidate reads stable paths or self-reports results | landed Round-232/233 mutants | retain (already landed, cheap to keep) |
| Per-job fresh hosted runner VM as execution boundary | cross-candidate or cross-job contamination | provider VM lifecycle, not repository machinery | adopt as the boundary |
| Same-host OS-principal isolation (C broker + exe, macOS helper, Linux custody) | hostile candidate escaping a same-host principal | threat excluded by admission boundary until self-host promotion | **delete from ISS-006; park with unpark condition at `ISS-019`** |
| Unbounded pressure rounds per slice | none identified | 235 rounds produced one partial issue | **cap: one round per slice, plus one after repair** |

## Planning impact

criteria, footprint), the trusted-harness ledger topology and local-mode
sections in `docs/architecture/contract-decisions.md`, and
`docs/planning/work-model.md` (delivery cadence, review cap, no committed

reviewed change that lands this replan. No roadmap edge changes: ISS-006 keeps
`blocked_by: [ISS-002]` and continues to block `ISS-003` and `ISS-022`.

The deleted isolation modules remain reachable in branch history; no parked
issue is registered for them because their unpark condition is named in the
ISS-006 draft and owned by the `ISS-019` review, matching the parked
concurrency precedent in `EPIC-KERNEL`.

This disposition authorizes the descoped ISS-006 completion: land the existing
contracts/conformance work on `main` in reviewable slices, delete the isolation
stack and committed binary, and implement `.github/workflows/conformance.yml`
against the descoped ledger.
