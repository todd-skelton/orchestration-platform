# ISS-006 explicit-stable-root review — round 239

`BLOCK_REPLAN`.

The explicit root correctly selects stable contracts, but it also launches the child script directly from `stableRoot`.
Node exposes that entrypoint as `process.argv[1]` to the child that imports candidate code, so the candidate receives a stable-checkout path, violating the ledger's opacity boundary.
Executing the child from the checkout also defeats the required external execution-root boundary; the passing tests and three-walk reproduction do not attack either relation.
Minimal repair: authority-check and copy the stable child into `executionRoot`, include it in the exact artifact census, and launch only that copy; never pass a stable path to the child.
Retain the caller's already-realpathed, authority-checked `stableRoot` solely for stable input reads and the copy source; no new root authority is needed.
Proportionality: one verified copy reuses the external-root design and is smaller than weakening opacity or adding isolation; no binary or checkout-write issue was found.
