## Design consequences and declared readings

These are the layout readings this packet makes where the subsection leaves a
choice. Each is stated so review can attack it directly.

1. **The archive root is also the immutable output directory.** The subsection
   fixes the archive root as the preparation root and requires the second census
   to be taken "before the report is serialized". Sealing therefore writes
   exactly one further member, `report.json`, into the archive root after the
   census and re-reads it, and the root's direct children go from exactly
   `build`, `controls`, `preparation` to exactly those plus `report.json`. The
   member's name is this packet's choice; the subsection names no name. There is
   no separate output tree, so no retained byte is copied twice.
2. **No manifest file is written into the archive.** The subsection states that
   "the only archive member outside those four prefixes is the report itself",
   so the archive manifest — the report row plus every retained row — is
   returned to the caller instead of stored. That costs stage four nothing: the
   ledger already requires the verifier to reread and revalidate the bytes
   "rather than trusting their hashes".
3. **`case-diagnostics.json` presence is derived from the report's custody.**
   "Whenever the case phase ran" is read as `custody.initialIdentity !== null`,
   because `case-context.mjs:setup()` is the only writer of that member and
   `finalize()` — the only writer of `case-diagnostics.json` — exists only after
   it. This is the reading the 3.4 receipt's observation 4 asked 3.5 to make: a
   context whose case-phase entry was refused still finalized, still wrote the
   file, and still has an initial identity, so the file is required, and the row
   results stay `UNKNOWN`. The presence rule is weighed against what is actually
   on disk before the census difference, so a file present when the case phase
   never ran is refused as the presence violation it is.
4. **A retained case's actual child actors come from its own events.** For
   `HOLDER` and `CONTENDER` the landed `runCases` records the capture at launch,
   so appearing in the row's events is exactly retention. For `DEFAULT_CHILD`
   the landed `actors.DEFAULT_CHILD` is assigned only by `childClosed`, which
   returns immediately after emitting that actor's `CLOSE` event, so the derived
   rule is: `DEFAULT_CHILD` retains transcripts only when a `DEFAULT_CHILD`
   `CLOSE` event exists. A child addressed but never closed therefore retains no
   transcript row, which matches the landed context's own cleanup-failure path
   rather than turning it into an archive refusal.
5. **No observer is registered, and that is the fence.** The landed per-OS
   report producer is `probes/portable-primitives/experiment/report.mjs`, a
   JavaScript module with no declaration file; importing it from a `.mts` needs
   either a declaration file or an `allowJs` change, both outside this slice's
   exact six-file footprint. `boundary.observe` therefore has no default, and
   the check sits before any filesystem work, so
   `runHostedNativeLockObservationEntry` validates every provider fact and then
   refuses with `observer-not-registered` having resolved no root, loaded no
   candidate and allocated nothing. That is the strongest available form of
   "still unreachable from any trigger"; registering an observer belongs to the
   stage-four activation slice.
6. **The sealed census is never caller-shaped.** The 3.5 collector binds to
   `hostedNativeLockSealedCensus(prepared.preparation)`, which reads the
   builder's own `PENDING_CANDIDATE_CONSUME` return and refuses a status,
   prefix, shape, hygiene or duplicate substitution. The observer supplies only
   the report.
7. **The 3.3 receipt's observation 4 and the 3.4 receipt's observation 7 are
   honoured downstream, not here.** `substitutions` lives in
   `controls/<id>/observation.json`, which this collector retains and hashes but
   never parses; `controls/<id>/observation.json` is required for every one of
   the twelve rows and `controls/<id>/input.json` exactly for the executed ones.
   No provider, revision or result fact is read out of any control input file —
   a test writes a hostile payload into all nine and the derived census is
   unchanged.
8. **`censusHostedNativeLockArchive` is not the archive census.** Its
   `build`-and-`preparation` child rule is a preparation-time fact. Its
   docstring now says so; its code is untouched.

## The archive census derivation and the post-case binding rule, as implemented

Derivation, in `deriveHostedNativeLockArchiveCensus`, from three sources and
nothing else:

1. the builder's own sealed rows, each required to begin `build/` or
   `preparation/`, to carry a canonical decimal `byteLength` and a lowercase
   `sha256`, and never to begin `build/transcripts/`;
2. the report's twelve control rows: `controls/<id>/observation.json` for every
   row, and `controls/<id>/input.json` exactly when that row's arm is executed
   (`refused !== null`);
3. the report's four case rows: `transcripts/<caseId>/<actor>.stdout` and
   `.stderr` for each retained child actor, plus `build/case-diagnostics.json`
   exactly when the case phase ran.

Every derived path passes the hygiene gate — non-empty, no NUL, no backslash,
not absolute, no empty, `.` or `..` component, one of the four archive prefixes,
never named `native-lock`, and a round trip through both mapping functions —
and the duplicates gate. The mapping is two mutually inverse functions:
`build/transcripts/X` maps to `transcripts/X`, `transcripts/X` maps back, and
everything else is the identity. Nothing else moves a path between prefixes.

Binding, in `sealHostedNativeLockArchive`, in this order: canonical archive root;
structural report parse; archive name; custody root external to the archive
root; derivation; physical walk of the archive root, whose direct children must
be exactly `build`, `controls`, `preparation`, refusing any symlink, junction or
non-regular entry and taking no path through one; the `case-diagnostics.json`
presence and custody-agreement rule against what is actually on disk; the exact
census difference in both directions; then a hash of every expected file through
`readConformanceBundleFileRow`, which re-reads the bytes under `O_NOFOLLOW` with
a directory-chain identity check; then the bound; then the sealed-to-observed
binding on `byteLength` and `sha256`; then serialization of the report into the
archive root under `flag: "wx"`, a re-census of the root's children and a byte
re-read of what was written.

The bound applied is the subsection's: at most 8192 retained entries under
`build/inputs/headers/`, at most 512 further retained entries, and at most
512 MiB of retained bytes summed over the second census, refused together. The
walk additionally stops at 32768 entries or depth 24 so that an unbounded tree
cannot be enumerated; that hard stop is deliberately far above the bound so the
bound gate, not the walk, is what refuses an over-large archive.
