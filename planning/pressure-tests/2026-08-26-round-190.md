# ISS-006 Windows partial-execution cleanup replan — round 190

## Disposition

`PASS_TO_REWRITE`.

Round 189 contains one constructibility contradiction. Its execution ATTEMPTED
record correctly carries zero root and target bindings because no root need
exist yet. It then requires DELETE_ATTEMPTED to be durable before every cleanup
mutation, but also says CREATED and every later record must carry complete
nonzero root and three-target bindings. After a crash following directory
creation or a partial first-file write, those complete bindings do not exist and
cannot be truthfully reconstructed. The broker would be forbidden both to
publish DELETE_ATTEMPTED and to delete the partial mutation.

The smallest repair is a closed predecessor-selected union for
DELETE_ATTEMPTED and ABSENCE_PROVED. A deletion record whose predecessor is
ATTEMPTED preserves zero root/target bindings and authorizes only Round 189's
stable-only fixed-subset cleanup. A deletion record whose predecessor is
CREATED preserves all exact created bindings. ABSENCE_PROVED must preserve the
selected arm exactly. No explicit caller-controlled arm or new phase is added.

This repair makes the copy-only lifecycle constructible without weakening the
pre-mutation intent rule or complete-root custody. All other Round-189 scope,
non-goals, protocol, source/parent custody, package denial, cleanup ordering,
and authority limits remain unchanged.

## Corrected OPWX phase grammar

The uniform OPWX field layout from Round 189 remains unchanged:

```text
magic:"OPWX" | version:u8=1 | kind:u8=1..4 | reserved:u16=0 |
totalLength:u32le | token:32 | priorDigest:32 | Dstate:32 |
profileCreatedDigest:32 |
executionParentPathUnits:u16le | executionParentPathUtf16LE |
parentBinding:32 | executionRootPathUnits:u16le | executionRootPathUtf16LE |
sourceBindings:3*32 | rootBinding:32 | targetBindings:3*32
```

Replace only Round 189's statement that “CREATED and later kinds contain all
exact bindings” with this closed grammar:

| Kind | Exact predecessor | Binding arm |
| --- | --- | --- |
| ATTEMPTED `1` | none; `priorDigest` is all zero | `PARTIAL`: exact nonzero parent and three source bindings; root and all three target bindings are all zero |
| CREATED `2` | exact ATTEMPTED digest | `COMPLETE`: parent/source fields equal ATTEMPTED; root and all three target bindings are exact and nonzero |
| DELETE_ATTEMPTED `3` | exact ATTEMPTED digest | `PARTIAL`: every field except kind/prior digest equals ATTEMPTED; root and target bindings remain all zero |
| DELETE_ATTEMPTED `3` | exact CREATED digest | `COMPLETE`: every field except kind/prior digest equals CREATED; all exact root/target bindings remain nonzero |
| ABSENCE_PROVED `4` | exact DELETE_ATTEMPTED digest | Preserve the predecessor's arm and every parent/path/source/root/target binding byte exactly |

The predecessor digest and the fully preflighted group select the arm. No arm
byte appears in the request, record, response, or in-memory public surface. A
DELETE_ATTEMPTED record with any other predecessor is malformed. A PARTIAL arm
with any nonzero root/target byte, a COMPLETE arm with any zero or changed
binding, and an ABSENCE_PROVED record that changes arms or binding bytes all
refuse before mutation.

The profile-created digest, token, Dstate, parent/root paths, parent binding,
and three source bindings remain exact and nonzero in both arms. PARTIAL does
not mean unauthenticated path cleanup; it means that the durable pre-creation
intent, rather than nonexistent post-creation identities, owns the fixed
mutation namespace.

## Correct partial and complete cleanup authority

After ATTEMPTED is durable, any failure before CREATED becomes durable must
first publish and read back the PARTIAL DELETE_ATTEMPTED record. Only then may
cleanup inspect or delete the intended root. This includes failures after:

- `CreateDirectoryW` may have succeeded but its response was lost;
- any fixed child create may have succeeded;
- any child write, flush, close, or readback may be partial or ambiguous; or
- CREATED pending/final publication did not become durably authoritative.

PARTIAL recovery never adopts or completes construction. It admits only exact
root absence or one non-reparse, one-link, stable/SYSTEM-only root under the
exact retained parent, containing a subset of the three fixed stable/SYSTEM-
only child names. Child contents and identities are not evidence. At every
deletion boundary it retains the opened object, reopens the current pathname
no-follow, compares the two identities and exact stable-only security, rejects
unknown entries, aliases, hard links, streams, movement, or profile drift, and
deletes only that fixed retained object. The package SID has never been granted
access in this slice.

If exact root absence is already proved, the PARTIAL delete record still closes
the attempted mutation before ABSENCE_PROVED; no filesystem delete is needed.
If cleanup itself becomes partial, retry uses the same durable PARTIAL arm and
admits the remaining fixed subset. It never invents bindings for deleted or
never-created objects.

Once CREATED is durable, PARTIAL cleanup is permanently forbidden. The broker
must publish COMPLETE DELETE_ATTEMPTED and require the exact persisted root and
three target bindings before and throughout cleanup. It cannot downgrade a
substituted or missing CREATED object to the more permissive partial subset
rule. Retry after one or more complete-object deletions remains on the COMPLETE
arm and uses the retained durable identities plus exact absence/remaining-
object relations fixed by Round 189.

Both arms require exact child-before-root deletion, execution-parent flush and
readback, root-path absence, and durable matching ABSENCE_PROVED before the
existing PROFILE_DELETE_ATTEMPTED transition. Profile cleanup cannot infer the
arm, skip execution absence, or treat an API return as proof.

## Alternatives removed

| Alternative | Removal result |
| --- | --- |
| Delete the partial root before publishing DELETE_ATTEMPTED | Rejected: it recreates the exact unjournaled cleanup mutation prohibited by Round 175 and Round 189. |
| Reconstruct three complete bindings from the crash residue | Rejected: missing files and partial bytes make the statement false; accepting observed residue as “created” launders an incomplete copy. |
| Add a variable-length observed-subset binding vector | Rejected: it records attacker-shaped partial state, adds combinatorial parser arms, and adds no deletion authority beyond the earlier stable-only fixed-name intent. |
| Add separate PARTIAL_DELETE and PARTIAL_ABSENCE kinds/files | Rejected: predecessor kind already supplies the discriminator; extra phases duplicate the same state and expand publication faults. |
| Make ATTEMPTED itself authorize deletion without a deletion phase | Rejected: it loses the required durable barrier immediately before destructive cleanup and cannot distinguish construction intent from cleanup intent. |
| Require construction to become complete before cleanup | Rejected: completing from unknown partial bytes after a crash is adoption, not recovery, and widens mutation after failure. |

The predecessor-selected union is the smallest representation that preserves
both pre-mkdir construction intent and pre-delete cleanup intent.

## Required deletion evidence

Round 189's evidence remains required, with these additional exact mutants:

- actual production control flow must fail immediately after mkdir and during a
  partial first-file write, publish/read back PARTIAL DELETE_ATTEMPTED before the
  first disposition/delete call, clean the fixed subset, and append matching
  PARTIAL ABSENCE_PROVED;
- every pending/write/flush/close/rename/readback fault while publishing the
  PARTIAL delete record must cause zero delete calls and retain ATTEMPTED;
- PARTIAL records with one nonzero root or target-binding byte, COMPLETE records
  with one zero or changed binding byte, DELETE with the wrong predecessor, and
  ABSENCE with a changed arm/field must refuse before mutation;
- a durable CREATED group offered a PARTIAL delete record must refuse rather
  than downgrade; an ATTEMPTED group offered a COMPLETE delete record must
  refuse rather than promote partial residue;
- retry after partial child deletion must retain the PARTIAL arm and remove only
  the remaining admitted subset; retry after complete child deletion must
  retain the COMPLETE arm and exact persisted identities;
- profile delete must be observed only after matching execution
  ABSENCE_PROVED for either arm; deleting the profile after ATTEMPTED or either
  DELETE_ATTEMPTED arm is a surviving mutant; and
- the opt-in Windows diagnostic must include one real pause after mkdir, then
  RECOVER through the PARTIAL arm to exact empty parent and profile absence.
  The existing post-CREATED diagnostic continues to exercise the COMPLETE arm.

Structural source checks alone are insufficient. The fixture must invoke the
real journal serializer/parser, construction failure reducer, cleanup reducer,
and recovery ordering with only OS observations substituted.

## Proportionality and authority status

The union adds no new file, field, public contract, mode, opcode, mutation, or
candidate authority. It makes two already-required recovery authorities
disjoint:

- PARTIAL is justified only by a durable pre-mkdir intent in an exact stable-
  exclusive namespace that never received a package grant; and
- COMPLETE is justified only by the durable independently verified CREATED
  bindings.

Merging those authorities was the Round-189 defect. Keeping them predecessor-
selected prevents partial residue from claiming complete custody and prevents
complete custody loss from falling back to a weaker deletion rule.

No ISS-006 draft, ledger, roadmap, or board change is warranted. This remains
an implementation detail of Round 175's existing execution-root construction
and recovery obligation. The slice remains private, unwired, copy-only, and
non-authoritative; LAUNCH stays NOT_IMPLEMENTED, no package ACE or process/token
exists, and macOS remains required before ISS-006 completion.

`PASS_TO_REWRITE` supersedes only Round 189's contradictory CREATED-and-later
binding sentence and the resulting undifferentiated delete wording. It does not
authorize implementation landing without a fresh exact-tree review, nor any
hosted receipt, candidate certification, promotion, workflow change, consumer
mutation, or Chase Sets access.
