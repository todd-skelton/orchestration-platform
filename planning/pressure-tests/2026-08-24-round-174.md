## macOS facts that constrain the design

- GitHub-hosted macOS VMs provide passwordless `sudo`, but candidate code must
  never receive that caller identity, its environment, or an invocable stable
  helper path.
- macOS stores local users and groups in Directory Services, not editable
  passwd/group files. Local record absence and system resolver/cache absence
  are distinct required facts.
- Root `setgroups(0, NULL)`, then `setgid(gid)`, then `setuid(uid)` clears the
  group access list and sets real, effective, and saved group/user IDs. The
  order is required; no Linux capability set or `no_new_privs` exists here.
- macOS BSD modes coexist with inherited filesystem ACLs and BSD flags. Mode
  bits alone therefore do not prove the claimed access relation.
- macOS has no Linux pidfd analogue. Apple `kill(2)` defines `pid == -1` for a
  non-root sender as signalling every process with the same UID except the
  sender. The sender can first irreversibly drop to the fresh candidate UID,
  avoiding numeric-PID use and PID-reuse risk.
- `sysctl(3)` returns a consistent process-table snapshot and exposes real and
  effective UID process data. One `KERN_PROC_ALL` snapshot can inspect both
  fields atomically; separate sequential UID queries are not substituted for
  that complete absence proof.

## Authorized reduced macOS design

The rewrite may implement only the following bounded design.

1. **Hard platform and source boundary.** The production factory captures the
   native platform at module initialization and refuses before option parsing,
   helper lookup, state access, or mutation unless it is exactly `darwin`.
   Private test fixtures may exercise the core with injected results, but no
   injection can turn the production factory into authority off macOS. The
   macOS adapter and helper remain private package files and do not enter the
   root export or any portable record.

2. **Stable helper identity.** Resolve and capture exact absolute identities
   for `/usr/bin/sudo`, `/usr/bin/dscl`, `/usr/bin/dscacheutil`, the selected
   Xcode `clang` resolved through exact `/usr/bin/xcrun`, the stable Node 24
   runtime, and the tracked macOS helper source. Every admitted executable is a
   regular non-link file with captured real path, device, inode, UID, GID, mode,
   size, and ctime; system helpers are root-owned and group/world-nonwritable,
   stable runtime/source are stable-owned and candidate-inaccessible. Recheck
   every identity around its authority use. Missing, aliased, moved, writable,
   architecture-mismatched, or substituted input refuses.

   Before any principal exists, exact stable source and exact compiler argv
   produce one job-private Mach-O helper in an owner-only external root. The
   output is opened, byte-hashed, architecture-checked, made `root:wheel 0500`,
   and rechecked before and after use. The helper has only three closed modes:
   `EXEC`, `KILL_UID`, and `CENSUS_UID`. It has no path-discovery, shell,
   arbitrary-command, file-mutation, daemon, or RPC mode. A compiler/helper
   unavailability is refusal, never a script or same-principal fallback.

3. **Burned identity allocation and cleanup intents.** A stable-only external
   state root records a create-exclusive, file-and-parent-synced allocation
   intent before any mutation. Select one unused value from the closed inclusive
   range `60000..64999` as both UID and private primary GID, plus distinct
   lowercase ASCII user/group names of at most 31 bytes derived from a
   cryptographic per-job nonce. Every attempted name, UID, and GID remains
   burned for the lifetime of the hosted job even after successful deletion;
   recovery never reallocates it. Exhaustion refuses.

   Register and sync a cleanup intent before each privileged group/user create
   or attribute write, ACL removal, ownership/mode change, execution-root
   creation, candidate launch, signal pass, root cleanup, user deletion, group
   deletion, and cache flush. Timeout, throw, signal, lost response, or partial
   completion always triggers an independent probe and bounded reversal. A
   forward command reporting failure never cancels its prior cleanup intent.

4. **Exact name and numeric absence.** Before creation and after teardown,
   require successful bounded, terminal, detached results from an exhaustive
   `/Local/Default` user-name/`UniqueID` and group-name/`PrimaryGroupID`
   enumeration plus system `dscacheutil` queries by user name, UID, group name,
   and GID. The local enumerations must parse completely with no duplicate,
   malformed, truncated, extra-diagnostic, or over-bound row. Each scoped cache
   query admits only its hosted-probed exact not-found shape: exit zero, no
   signal/timeout, empty stdout, and empty stderr. Unknown exits, a not-found
   diagnostic treated as success, cache/helper refusal, or a record in either
   namespace is not absence. Post-deletion performs one successful privileged
   cache flush and repeats all probes to exact absence; retry exhaustion
   refuses while retaining cleanup state.

5. **Minimal non-login account and private group.** Create the private group
   first in `/Local/Default/Groups/<groupName>` with the selected
   `PrimaryGroupID`, disabled password marker, empty explicit member lists, and
   no authority-bearing attributes. Then create exactly one
   `/Local/Default/Users/<userName>` record with selected `UniqueID`, that
   `PrimaryGroupID`, `/var/empty` home, `/usr/bin/false` shell, disabled
   password marker, no `AuthenticationAuthority`, no shadow hash, and no admin,
   wheel, sudo, remote-login, or other explicit membership. No other local user
   may name the GID as primary, and the private group may name no explicit
   member. Re-enumerate the system resolver to prove exact name/number binding,
   stable-runner inequality, and no second record. Any auto-added or unknown
   attribute that can authenticate or widen group authority refuses.

6. **ACL-free exact DAC and custody.** The stable execution parent, stable
   state/helper roots, stable/provider/materialization roots, and every complete
   ancestor are identity-checked regular directories owned by the expected
   stable/root identity, other-inaccessible, free of extended ACL entries, and
   free of immutable/append flags. The fresh execution root and exact runtime,
   candidate artifact, and RPC runner become `root:<privateGid>` with directory
   mode `0510` and file mode `0550`; the fresh scratch root becomes
   `<uid>:<gid> 0700`. Other bits, set-id/sticky bits, ACL entries, inherited
   ACEs, aliases, symlinks, mounts, and unlisted grant paths are forbidden.

   Stable code retains opened parent/root handles and verifies complete ancestor
   plus leaf device, inode, type, UID, GID, mode, flags, ACL absence, and exact
   byte identity before and after every transition. Before candidate import, a
   credential-dropped stable probe proves exact runtime/artifact/RPC read/
   execute, their write denial, scratch write, and stable-root read denial
   without passing denied stable paths to candidate code. ACL removal is only
   the deletion of entries on fresh harness-owned objects; named ACL creation or
   restoration machinery is not authorized.

7. **Irreversible credential drop and candidate self-check.** Stable launches
   only `/usr/bin/sudo -n -- <native-helper> EXEC ...` with exact argv, empty
   candidate environment, exact retained stdio pipes, scratch cwd, and no shell.
   The root helper hard-checks Darwin and exact numeric arguments, calls
   `setgroups(0,NULL)`, `setgid(gid)`, then `setuid(uid)`, and requires exact
   real/effective UID and GID plus an empty supplementary list. It additionally
   proves attempts to regain UID/GID zero fail before `execve` of the exact
   execution-root Node runtime and stable RPC runner. Any credential syscall,
   self-check, cwd, environment, or `execve` ambiguity refuses before candidate
   import.

   The RPC runner independently binds pristine `getuid`, `geteuid`, `getgid`,
   `getegid`, and `getgroups` functions before candidate import and accepts only
   the expected UID/GID with no supplementary identity other than Node's
   documented effective-GID reflection. It verifies the closed principal argv,
   Darwin guard, exact challenge, and stable expected-value response before
   importing candidate bytes. Candidate code never receives a sudo/helper,
   Directory Services, compiler, state, stable-root, or cleanup path.

8. **Stable timing, pipes, and root terminality.** The existing isolated-walk
   coordinator continues to own the canonical challenge, expected values,
   hostile response parse, captured monotonic launch-to-terminal-response
   interval, normalization, three fresh principals, and teardown-before-result
   order. A launch is terminal only after the tracked `sudo` child has produced
   an OS wait status and every stdin/stdout/stderr pipe is closed. PID text,
   candidate EOF, a kill request, or child self-report is never terminal proof.
   On timeout the stable parent starts the UID-scoped kill pass and then waits
   for this exact root/pipe terminal observation before evidence.

9. **Complete process quiescence without PID signalling.** `CENSUS_UID` runs as
   root, obtains one complete `KERN_PROC_ALL` consistent snapshot, and returns a
   detached, bounded, sorted census of every process whose real or effective UID
   equals the burned UID. PIDs are diagnostics only and are never passed to
   `kill`. Truncation/`ENOMEM`, malformed structure/size, duplicate or invalid
   entry, unreadable snapshot, helper ambiguity, or over-bound output refuses.

   When the census is nonempty—or immediately on launch timeout—stable invokes
   `KILL_UID`. That helper clears groups, sets GID then UID exactly as above,
   proves it cannot regain root, calls `kill(-1,SIGKILL)`, and exits; Apple
   defines the non-root broadcast as all same-UID processes except the sender.
   Stable waits for the kill helper and launch root/pipes to become terminal,
   then takes another complete snapshot. It repeats within a fixed bounded
   attempt/deadline until one snapshot is empty. A forking, reparented,
   `setsid`/process-group-escaped, inherited-pipe, set-user-ID transition,
   residual process, or nonquiescent race refuses. Because absence is proved
   while the UID remains allocated and burned, an empty atomic snapshot leaves
   no candidate-UID process able to create a successor. No numeric-PID signal,
   process-group-only kill, parent-tree census, `ps` text, Linux `/proc`, pidfd,
   cgroup, or container substitutes.

10. **Revocation, root cleanup, deletion, and final absence.** Only after root
    terminality and empty process census, remove all group access from the exact
    execution files/root, restore them to root-only ownership/modes with no ACL
    or flags, and prove a fresh dropped-UID access probe is denied. Then remove
    candidate-created scratch contents with a helper-owned fd-relative,
    no-follow, same-device walk; unlink only observed non-mount entries; remove
    the identity-checked scratch/execution roots; and prove every root absent
    while the stable parent/state/helper roots retain identity. Recursive path
    deletion through text, moved ancestors, symlink following, mount crossing,
    or best-effort cleanup is forbidden.

    Delete the user record before the group record, with separate pre-mutation
    intents and post-mutation local probes. Group-first deletion, one deletion
    standing in for the other, or account deletion while a process/grant/root
    remains refuses. Flush the resolver cache and prove user name, UID, group
    name, and GID absent from both `/Local/Default` and system resolution. Keep
    the allocation burned until authority close; do not interpret deletion as
    permission to reuse it.

11. **Crash recovery order.** On factory open and before any new allocation:
    authenticate helpers/state, load every synced intent hostile-safe, finish
    any pending `KILL_UID`/root terminal reconciliation, repeat the atomic UID
    census to absence, revoke DAC/ACL access, perform fd-relative root cleanup,
    delete user, delete group, flush cache, and prove dual name/numeric absence.
    Recovery uses the burned numeric UID even when a Directory Services record
    is partial or already absent. Unknown state, missing helper, moved root,
    failed mutation, or unresolved residue keeps authority closed and can only
    produce refusal/`UNSUPPORTED`, never a fresh identity or hosted PASS.

The macOS adapter supplies opaque principal lifecycle authority only. It does
not select the challenge, expected result, timing, receipt, aggregate, provider
record, capability, certification, or promotion outcome. No macOS term enters
the nine portable records.

## Trust and removal sweep

- Stable protected-main bytes alone select the tracked helper source/compiler
  invocation, account identities, execution bytes, RPC runner, challenge,
  parser, timing, and cleanup. Candidate output and scratch are hostile data.
- Directory Services is used only to reserve/delete one disabled local identity;
  execution itself uses exact numeric credentials and does not depend on PATH,
  login, home, password, shell, or candidate-controlled lookup.
- ACL absence plus root/private-group BSD DAC expresses exactly one
  stable-to-candidate read/execute relation. Named ACLs, sandbox profiles,
  containers, VMs, and generalized grant registries are larger and deleted.
- Irreversible `setgroups`/`setgid`/`setuid` plus failed root-regain and RPC
  self-check is the macOS credential proof. Linux capability fields,
  `setpriv`, `no_new_privs`, `/proc`, and pidfds are neither required nor
  imported.
- UID-scoped `kill(-1)` is race-safe for signalling because it names the burned
  credential set, not a reusable PID. The consistent all-process real/effective
  snapshot, root wait, repeated kill loop, access revocation, root removal,
  user/group deletion, cache flush, and final dual absence form one fail-closed
  teardown chain.
- The authority interface, three-cycle coordinator, stable timing, hostile pipe
  response, private package boundary, and no-candidate-writer rules remain
  unchanged. Linux composition is not refactored into a speculative generic OS
  abstraction.
