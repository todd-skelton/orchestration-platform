### What the builder accepts and produces

`buildBootstrapVerifierAnchor(facts)` is total over `unknown`. Its accepted
fact census is exactly `assets`, `createdAt`, `operatorConfirmation`,
`repositoryId`, `signerWorkflow`; asset and signer rows reuse the ledger's own
field lists (`verifierAnchorSchemaFields.asset`, `.signer`) by reference, and
the confirmation census is `actorId`, `confirmedAt` only. The builder supplies
the five ledger literals (`cliVersion`, `expectedOidcIssuer`, `releaseTag`,
`schemaVersion`, `trustBootstrap`) and the `claim` literal, orders the three
asset rows ascending `LINUX|MACOS|WINDOWS`, delegates every value grammar to
`parseBootstrapVerifierAnchor`, and returns the canonical bytes plus `Danchor`
from `computeBootstrapVerifierAnchorDigest`. It computes no instant, no
identity, and no digest claim of its own; `confirmedAt` is the operator's or
the build refuses.

### What the store helper does

`canonicalBootstrapVerifierAnchorPath(stateRoot)` constructs exactly
`<state-root>/bootstrap/verifier-anchor.json` (`contract-decisions.md:7063`)
and throws `TypeError` on a state root that is not absolute and normalized.
`writeBootstrapVerifierAnchorFile` parses the record before touching the
filesystem, binds the caller-supplied path to that one spelling, and creates
the anchor exclusively (`flag: "wx"`). `readBootstrapVerifierAnchorFile`
requires the caller's expected `Danchor` and refuses a mismatch.

2. **`Danchor` from the written bytes.** The same test re-parses the bytes read
   back through `parseCanonicalContractBytes` and asserts
   `computeBootstrapVerifierAnchorDigest` over that record equals
   `70be486e417574fa4e1211828b7e3028c7b1b8583f42d440772d514b669e2bd5`, the
   digest the landed ISS-054 corpus independently pins for the same record
   (`test/contracts/verifier-anchor.test.ts`).
3. **Every refusal vector with the exact issue code.** All seven named vectors
   are covered with exact, sorted, deduplicated issue arrays and a paired
   accepted control:
   - absent OS row -> `facts.assets:os-census-required`;
   - duplicate OS row -> `facts.assets.<OS>:duplicated`;
   - substituted OS row -> `facts.assets.<OS>:duplicated` plus
     `facts.assets.<OTHER>:missing`;
   - mutable selector -> `facts.cliVersion:unknown-field` (and the same for
     each of the other four literals, `latest`, `selector`, `downloadUrl`);
   - custom root -> `facts.customTrustRoot:unknown-field` at the fact
     boundary, and `anchorPath:canonical-path-required` /
     `anchorDirectory:custom-root-refused` / `anchorFile:custom-root-refused`
     at the path boundary;
   - executable-path substitution ->
     `facts.assets.0.executablePath:unknown-field`;
   - combined anchor-plus-verifier substitution -> a structurally valid but
     differently identified anchor, refused on read as
     `anchor:digest-mismatch`.
   Deletion-mutant evidence is recorded under "Verification" below.
4. **ISS-054 closed corpus.** The same-realm mutable, sealed, frozen and
   null-prototype corpus is accepted with an unchanged `Danchor`; the
   proxy, cross-realm, subclass, hole, symbol, extra, non-enumerable,
   accessor, custom-iterator, exotic-prototype and cycle corpus refuses at the
   fact boundary with exact `facts.`-prefixed codes, with a `vi.fn` trap
   asserted never to have been invoked.

**Local structural evidence versus external provenance.** Everything above is
local structural evidence over supplied values. The fixture's three repeated
digit SHA-256 values and its numeric identities are synthetic and say so in the
fixture's own `note` field. Real acquisition of the official assets and the
independent checksum comparison behind `operatorConfirmation` are `ISS-036`

parser itself "cannot prove who supplied it or that the comparison occurred"

## Review attack surface

Attack, in order of expected yield:

- The exclusive-create decision. `writeBootstrapVerifierAnchorFile` refuses
  `anchorFile:already-exists` even for a byte-identical rewrite. The draft says
  "writes/reads", not "writes once". The reasoning is that the anchor is the
  chronology anchor for `ISS-036` O7/O8 and a silent overwrite is precisely the
  "set or move the anchor after the producer run" control; removing the anchor
  is left as an explicit operator action. If review judges this out of the
  draft's scope, the smaller shape is a plain write and the
  `anchorFile:already-exists` vector is deleted with it.
- The required `expectedDigest` argument on the read helper. A reader with
  nothing to compare against cannot distinguish the operator's anchor from a
  consistently substituted one, so the helper refuses rather than reporting an
  unbound value. Attack whether `ISS-062`'s offline verifier can always supply
  it (it reads `VERIFIER_ANCHOR_SHA256`, so it can).
- The state-root namespace split: the supplied path is compared in the
  caller's namespace, the bytes land in the real namespace. Attack a case where
  those two disagree in a way that lets an anchor land outside the state root.
- The `facts.` prefix convention. Fact-boundary codes are namespaced and the
  landed parser's grammar codes are passed through verbatim; a reviewer should
  check that no parser code is silently rewritten and that no fact-boundary
  code collides with one.
- The second `parseBootstrapVerifierAnchor` call in the read path. It exists
  only to narrow the registry's `ContractRecord` to the family type without a
  whole-tree cast. Attack it as redundant machinery; the alternative shapes are
  a cast (which Decision #282's review seed warns against leaning on) or a
  hand-rolled re-implementation of the landed encoding grammar.
- The golden fixture doubling as the vector source: both test files read their
  operator facts from the same committed file. Attack whether that makes any
  assertion self-fulfilling (the digest and byte length are also asserted
  against literals restated in the test, and against the landed ISS-054
  corpus's independently pinned values).
- Any claim anywhere in this change that reads as external provenance.

## Proportionality

For each retained mechanism: the concrete in-scope threat, the deletion test,
the smallest credible alternative, and why the retained shape is smaller or
better evidenced.

| Mechanism | In-scope threat | Deletion test | Smallest alternative | Why retained |
|---|---|---|---|---|
| Closed fact census | An operator (or a caller upstream of one) supplies `latest`, a download URL, an executable path, or a custom trust root | `B-facts-closed` killed | Accept extra fields and let the parser refuse | The parser refuses them too, but only after the builder has assembled a record from them; refusing at the boundary is the same size and reports the exact offending field |
| Ascending OS ordering | A supplied row order silently changes `Danchor` | `B-order` killed | Require the caller to order rows | Ordering here is three lines and removes an entire class of caller error the ledger already fixes |
| Per-OS duplicate/missing census | A substituted OS row | `B-duplicate`, `B-missing` killed | Rely on the parser's `assets:os-census-required` | The parser cannot name which OS was substituted; the operator needs that |
| Exclusive create | A silent anchor replacement after the chronology is fixed | `S-exclusive` killed | Plain write | See "Review attack surface"; flagged for review |
| Real-path check on `bootstrap` | A directory-typed reparse point redirects the anchor to a custom root | `S-directory-redirect` **survives**, declared | `lstat` directory check alone | Retained with a named non-codifiable reason: no credential-free, non-native vector creates one on a hosted runner |
| Required `expectedDigest` | A consistently substituted anchor read as the operator's | `S-digest-binding`, `S-expected-grammar` killed | Optional argument | An optional binding is a trust-me path in a fail-closed custody helper |

Two mechanisms were **deleted** during this attempt on mutation evidence: the
`isSymbolicLink()` clause on the state-root check and the same clause on the
`bootstrap` directory check. Both survived their mutants because `lstat`
reports a symlink as a link and never as a directory, so the adjacent
`isDirectory()` check already covered them. One coverage hole found the same
way was closed instead of deleted: a `bootstrap` entry that exists as an
ordinary file now has its own vector and its own killed mutant
(`S-directory-kind`).
