## Removed findings

### `OP-R97-001` — lifetime global identity is now derived

`validateBootstrapGenesisCoreBinding` now accepts the closed global-identity
record, parses it with `parseStateMutationGlobalIdentity`, and computes its
digest with `computeStateMutationGlobalIdentityDigest`. The parser admits only
the exact `state-mutation-global-identity/v1` schema. The composition then
equal-binds:

- installation, project, state-root, and custody instance to the anchor;
- the canonical authority path to `stateMutationAuthorityPath`;
- authority path instance to the already-derived E0 `Dp`; and
- derived `G` to `Dbg`, proposed-genesis input, the GENESIS history record,
  successor core, and selected authority value.

The independent in-memory attack changed the global identity's custody member,
recomputed `G`, `Dsc`, use intent, `Dgb`, GENESIS `Dh`, selected E0 `Dv`, and
`Dbg`, and changed every corresponding sibling. The public E0 validator refused
with `globalIdentity.custodyInstanceDigest:mismatch`. Agreement among rehashed
siblings can therefore no longer replace derivation from anchor/`Dp` identity.

### Genesis ACTIVE provenance in `OP-R97-003` — existing mutation validators are composed

E0 calls `validateBootstrapAnchorMutationBinding` with an exact all-null prior
triple, the selected anchor proposal/value, the recomputed anchor digest, and
the anchor's bootstrap grant. On the genesis owner arm it also calls
`validateDestinationOwnerMutationBinding` with an exact all-null prior triple,
current `Dobs`, anchor/destination/installation identity, and the bootstrap
grant. These existing validators enforce ordinal zero, ACTIVE shape, null
predecessors, transition/source, mutation ID, selected value, observation, and
transition evidence.

Two coordinated attacks rebuilt all selected anchor/owner proposal, value, and
tip digests plus use intent, `Dgb`, `Dh`, E0 `Dv`, and `Dbg`:

- changing both ACTIVE ordinals to `"7"` refused with the anchor activation
  shape and owner ordinal/genesis-shape findings; and
- changing anchor transition evidence plus owner transition evidence and
  observation refused through both mutation validators and the pre-existing
  intent provenance checks.

The composition remains deliberately branch-specific. It does not pretend that
null predecessor inputs are valid for a successor activation.

### `OP-R97-004` — one shared effective time now admits `Dobs`

The E0 composition closes `intentExpectedInput` against the exported use-intent
expectation census. It supplies that exact record to use-intent validation and
passes the same `effectiveAt` member to
`validatePhysicalObservationBinding`. The existing absence-time validation is

### Successor readback hardening — correct in the owning validators

Focused contract and compatibility suites remained green, and no schema

## Remaining blocking findings

### `OP-R97-002` — selected active release remains disconnected

The authority value's active-release `Dp/Dt/Dv/Dr` is still checked only
against four SHA-256 values in `coreExpectationFields`. The reviewed bootstrap
operation and `Dsc` continue to describe release manifest, installed bytes,
release subject, independent review, and installer, but no selected
active-release value/proposal/tip graph is consumed to connect that reviewed
release to the tuple installed in authority E0.

The independent reconstruction replaced all four active-release members in
both authority value and the expectation, recomputed E0 `Dv` and `Dbg`, and
received `[]`. This is the exact round-97 deletion test and remains a semantic
blocker.

Smallest repair: consume the existing selected active-release graph and
reviewed installed-release context, recompute its pointer identities, and bind
its immutable release identity to the exact reviewed `BOOTSTRAP_INSTALL`
operation/`Dsc`. Remove digest-only expectations as an authority substitute;
add no E0-specific record or digest domain.

### Successor portion of `OP-R97-003` — E0 still omits full successor composition

The successor helper is hardened, but E0 does not call it. Its successor-arm
fixture still supplies an opaque `Dsrc` and selected successor anchor/owner
records without the actual successor review core, prior selected RETIRED
tip/value/proposal, teardown archive, or independent-review record. Therefore
E0 cannot prove that the successor owner ordinal follows the actual prior
RETIRED ordinal or that `Dsrc` is the externally reviewed core for that prior
lineage.

The same omission matters for `Dsrp`: use-intent correctly derives the whole
receipt readback, but it does not own or repeat the successor validator's three
selected-record readback derivations. A bounded E0 reconstruction replaced all
three internal readbacks, recomputed `Dsrp`, and supplied the canonical
whole-receipt readback. E0 returned `[]`. In contrast, supplying those same
coordinated substitutions to the actual successor post-selection validator
returned the three derived-readback failures. The defect is composition, not
the hardened helper.

Smallest repair: make the E0 successor arm consume and compose the existing
prior-RETIRED review core validator and successor post-selection validator,
including teardown archive, independent review, selected successor graph, and
their exact trusted expectations/readbacks. Keep the genesis arm null-prior
and keep `Dsrp` downstream; do not duplicate the lifecycle machine or add an
upstream `Dsrp` field.
