# Pressure round 431 — ISS-048 hosted acquisition boundary

Status: bounded replan plus stage-two acquisition implementation. No candidate
materialization, native build/load/run, workflow trigger, artifact upload,
provider record, selection, or operator authority is activated.

## Measured blocker and disposition

The planned single-OS owner combines two independently failing external-input
surfaces with process chronology and archive ownership. Exact Node distribution
acquisition is network and byte bounded. Hosted compiler/SDK capture depends on
OS-specific, already-installed paths and fixed child commands. Candidate
consume/delete, preparation, controls, cases, and final archive sealing then
operate on those retained outputs under a separate custody transaction.

Landing all of them together would make removal review cross network origin,
ambient environment scrubbing, candidate custody, native loading, death timing,
and archive completeness. Disposition: land one private acquisition owner first,
with no live caller. The next slice consumes its result only after this byte and
toolchain boundary is independently reviewed on all three OS runners.

## Scope and acceptance evidence

The acquisition owner requests only the official exact-version URLs under
`https://nodejs.org/dist/${process.version}/`: `SHASUMS256.txt`, the matching
headers archive, and the matching Windows `node.lib` path when applicable.
Downloads have a fixed byte ceiling, reject redirects/non-200/malformed length,
and are retained with length and SHA-256 references. A 404 is `UNSUPPORTED`;
transport or malformed response is `UNKNOWN`.

Toolchain capture resolves only `cc`, `clang`/`xcrun`, or `cl.exe` from the
closed hosted `PATH`. It runs fixed argv with `shell:false` through a mockable
boundary, scrubs inherited loader/candidate variables, and retains stdout and
stderr. Windows consumes the already-established `INCLUDE`, `LIB`, and
`SystemRoot`; it never invokes `vcvars`, chooses a latest install, or installs a
tool. The canonical capture uses only `AVAILABLE|UNAVAILABLE|UNKNOWN` and feeds
the already-landed preparation parser unchanged.

Acceptance evidence includes mocked exact-URL, OS recipe, environment scrub,
missing distribution, ambiguous toolchain, reused root, malformed `PATH`, and
census-order tests; typecheck; focused format; planning and live-board parity;
diff check; independent exact-head review; and Linux, macOS, and Windows hosted
bootstrap verification.

### Follow-up after independent review

The exact-head review found four evidence gaps inside the acquisition boundary:
unbounded or identity-ambiguous responses, executable lookup errors collapsed
to absence, semantic version strings that could exceed the preparation parser,
and references computed before write readback without an exact final tree
census. The single follow-up replaces whole-body reads with bounded streaming,
requires exact final URL/no redirect and declared/actual length equality,
preserves `FOUND|UNAVAILABLE|UNKNOWN` lookup outcomes, derives bounded actual
version fields while retaining full streams, feeds an `AVAILABLE` capture
unchanged through `prepareNativeLockBuild`, and rehashes a sealed exact tree.
Redirect, status, length, oversize, permission, I/O, moved executable,
overlong-version, and extra-file mutants provide removal evidence. Scope and
authority boundaries are unchanged. The superseded hosted run also showed that
the macOS test fixture supplied the `/var` alias of `/private/var`; the same
follow-up canonicalizes only that synthetic root and leaves the production
canonical-path refusal intact.

The sealed-tree check retains and revalidates the nanosecond identity stamp of
every visited directory after the complete readback. A late-mutation mutant
adds a file to the already-visited distribution directory while the later
toolchain directory is enumerated and must be refused by that global recheck;
millisecond timestamp aliasing cannot satisfy the seal.
