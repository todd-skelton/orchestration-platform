## OP-R150-1 removal verification

The repaired focused test creates three frozen alternate records:

```text
movedTransaction = selected + otherTransactionId
movedSource      = selected + cleanup-gate-pre-fence
movedPredecessor = selected + different predecessorReceiptDigest
```

Each path expectation is exact rather than a weak inequality. Its key suffix
is computed by calling
`computeRecoveryAttemptReservationPredecessorKey` on the same alternate record,
independently from `recoveryAttemptReservationPath`. The expected parent
transaction and source are written explicitly from the relevant trusted
fixture values.

That structure keeps the three properties independent:

- For `movedTransaction`, expected and actual key computation both see the
  alternate transaction. A mutant that fixes only the path parent transaction
  therefore preserves the same key suffix and source, but fails solely because
  the parent UUID remains the original fixture UUID.
- For `movedSource`, expected and actual key computation both see
  `cleanup-gate-pre-fence`. A mutant that fixes only the path parent source
  preserves the same transaction and key suffix, but fails solely because the
  parent source remains `recovery-fence`.
- For `movedPredecessor`, transaction and source are unchanged. The expected
  key is recomputed from the changed receipt digest. A mutant that fixes only
  the path key to the selected fixture golden therefore fails solely at the
  final key segment.

The fixed-key mutant also fails on the earlier moved-transaction assertion,
because transaction is itself an authorized key input. That is legitimate
independent discrimination: the mutant preserves the correct parent but
substitutes only the key suffix, and the expected suffix is recomputed by the
unmutated key function. The dedicated moved-predecessor assertion additionally
proves predecessor-only key sensitivity with parent context held constant.
