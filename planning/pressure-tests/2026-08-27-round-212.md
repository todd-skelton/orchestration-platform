## Remaining production blocker: failed worker close loses the pipe

`terminal_worker_main` at
`packages/conformance/src/windows-isolation-broker.c:6024-6025` executes:

```c
if (!CloseHandle(worker->pipe)) worker->failed = 1U;
worker->pipe = NULL;
```

The pointer is cleared whether `CloseHandle` succeeds or fails. A failed close
therefore loses the exact pipe owner even though the thread is now terminal.
`terminal_close_workers` sees null and cannot retry or propagate resource
ambiguity. `run_active_terminal` observes only `worker.failed`, returns ordinary
refusal, and can subsequently complete TEARDOWN/kind 7/OPWX/OPWJ successfully
while the pipe end remained unclosed and untracked until process exit.

This is the same ownership invariant Round 211 required for allocation
failure. Moving initial ownership fixed only the pre-thread prefix; every
fallible ownership release must retain the handle on failure.

Smallest required repair:

1. the worker sets `pipe = NULL` only after a successful `CloseHandle`;
2. after trusted worker join, the stable main thread retries any retained pipe
   through the normal exact close helper;
3. a successful retry may still produce a refused candidate observation, but
   a persistent close ambiguity must never produce successful TEARDOWN/kind 7;
   it must retain ownership until fixed hard-abort/process exit and phase-5
   recovery; and
4. no other worker/thread/runtime handle may be nulled after a failed close.

The fix requires no new worker, protocol field, journal kind, or cleanup
mechanism.

## Remaining deletion-evidence blockers

### Terminal close and simultaneous-resource faults

The fixture's terminal `CloseHandle` path delegates real pipe/thread closes.
The terminal fault matrix never enables the existing resource-close fault
seam. It therefore cannot detect the production lost-pipe defect and does not
prove any pipe/thread close failure or simultaneous close/free ambiguity.

Add direct production-function cases for:

- each worker-owned stdin/stdout/stderr pipe close failing once then succeeding
  on joined-main retry;
- each retry persistently failing and selecting hard-abort/no reversal;
- each of three worker thread-handle closes;
- both output-buffer frees independently; and
- simultaneous pipe, thread, and buffer failures while every safe remaining
  cleanup attempt occurs and no success/absence phase is emitted.

Assertions must census exact handle ownership, not only return codes or free
counts. No fixture cleanup may erase the production observation before it is
asserted.

### Defined read/bound seams are not actually discriminating

`fixture_admission_ReadFile` defines fault modes for one-byte partial reads
(1), true zero reads (2), over-bound output (4), and exact-bound output (5).
The matrix meaningfully drives only error mode 3 and over-bound mode 4. Its one
combined fault-1 case closes both child output writers without writing data, so
the “partial read” seam never has bytes to partition. Modes 2 and 5 are not
called through an output success path.

Add stdout and stderr cases independently for 0, 1, exact 4 MiB, and 4 MiB+1,
with one-byte and mixed chunk partitions, true-zero EOF, broken-pipe EOF, and
non-EOF error. Exact-bound data must serialize successfully without overflow;
over-bound data must latch overflow, continue drain, and never serialize a
truncated success.

### TIMEOUT field mutants are coupled

The serializer matrix's first TIMEOUT invalid has nonzero exit, stdout, and
stderr simultaneously; its second clears exit and stdout but leaves stderr.
Deleting the TIMEOUT exit-code check or stdout-length check still leaves another
invalid field to make both tests fail. Add isolated mutants for:

- nonzero TIMEOUT exit with both streams exactly empty;
- nonzero TIMEOUT stdout only with exit/stderr zero and a nonnull buffer; and
- nonzero TIMEOUT stderr only with exit/stdout zero and a nonnull buffer.

Retain the canonical empty TIMEOUT and exact EXITED stream/order/reserved-byte
checks.

### Deadline boundaries

The backward-clock seam and generic wait failures now execute, but the fixture
still does not independently pin before, exactly-at, and after 5,000 ms. A wait
returning timeout drives the kill path without demonstrating the
`terminal_remaining` arithmetic at the inclusive boundary. Add fixed tick
sequences proving no early TIMEOUT, exact inclusive timeout, post-bound timeout,
and no terminal response until post-kill root/workers/complete Job zero.
