## Blocking finding and smallest repair

### OP-R137-1 — the archive's `Drrp` member is never equal-bound to actual `Drrp`

The proposed archive contains:

```text
revokePostSelectionReceiptDigest:sha256
```

The surrounding prose requires later composition to parse the actual revoke
post-selection receipt, recompute `Drrp`, bind that receipt to the selected
REVOKED state, and require the generic tombstone's
`terminalProofDigest = Drrp`. It also requires recomputation of `Draa` from the
actual archive. None of those statements requires:

```text
archive.revokePostSelectionReceiptDigest = actual Drrp
```

Recomputing `Draa` proves only that the tombstone names the exact archive bytes;
it does not prove that a digest member inside those bytes names the actual
receipt. Independently checking the tombstone's terminal proof proves only the
tombstone field. A coordinated archive/tombstone object can therefore use
`archive.revokePostSelectionReceiptDigest = X`, compute `Draa(X)`, set
`tombstone.archiveDigest = Draa(X)`, and set
`tombstone.terminalProofDigest = actual Drrp`. Every currently stated archive
and tombstone equality holds while the archive falsely claims to have archived
`X`.

This is not a parser concern and must not be implemented as a caller-supplied
expected digest. ISS-004 must derive and authenticate the actual graph:

1. derive the archive/state/receipt paths from authenticated transaction and
   installation context;
2. parse the actual selected REVOKED value/proposal/tip and recompute
   `Dp/Dv/Dr/Dt`;
3. use that state's `removalOperationId` to parse the actual revoke receipt,
   recompute `Drrp`, and bind its transaction, operation, selected `Dt`, and
   time;
4. require
   `archive.revokePostSelectionReceiptDigest = recomputed actual Drrp`;
5. recompute `Draa` from that exact archive; and
6. require tombstone `archiveDigest = Draa` and
   `terminalProofDigest = archive.revokePostSelectionReceiptDigest = actual
   Drrp`, plus the stated prior triple, `Dp`, time, proposal, epoch, selection,
   and read-back rules.

The ISS-002 acceptance matrix should include independent archive-member and
coordinated archive/tombstone mutants. Deleting the equality must make a
committed mutant with `X != actual Drrp` survive and fail the suite. Structural
archive tests remain correctly unable to authenticate this relation.

Retaining the member is smaller than replacing the design. It is the archive's
one direct identity of the exact receipt observation that precedes archive
creation. The downstream generic tombstone repeats it as a required
cross-record link, not as an independent source. Removing the archive member
would change the stated archive outcome into a transaction/time marker; adding
selected `Dp/Dv/Dr/Dt`, operation, lifecycle, or native fields would recreate a
larger proof bag. The one missing equality is the bounded repair.

## Exact archive census, order, and proportionality

The proposed record has exactly four unique required members in ascending
canonical JSON member order:

```text
archivedAt:timestamp
revokePostSelectionReceiptDigest:sha256
schemaVersion:recovery-authorization-archive/v1
transactionId:uuid-v7
```

The scalar closure is complete. `archivedAt` is the new durable archive event,
not receipt, state, proposal, or caller time. The schema literal closes the
record and selects the archive digest/serializer route. `transactionId` is the
archive's own canonical path input and later transaction/path equality.
`revokePostSelectionReceiptDigest` is the minimum direct identity of the exact
upstream revoke observation, provided OP-R137-1 binds it to the actual receipt.

`Dp`, `Dv`, `Dr`, `Dt`, `Dac`, operation, core, mode, lifecycle, gate, native
receipts, generation, and disposition remain correctly absent. Actual `Drrp`
commits the exact revoke receipt's transaction, operation, durable time, and
selected `Dt`; actual `Dt` commits `Dp/Dv/Dr`; and later composition parses the
actual selected graph. Copying those members into the archive would add no
source, locator, or replay discriminator.

`transactionId` is not removed merely because actual `Drrp` also commits it.
The archive digest does not otherwise frame the archive's filesystem path. The
record-local transaction supplies the one self-contained archive-own path
equality and lets moved archive bytes refuse before treating the path as this
record's canonical location. This is the same bounded path-input role retained
for transaction and operation in the already-cleared post-selection receipt
ledger.

## TOMBSTONE position and generic pointer composition

The authorization-state TOMBSTONE position is exactly:

```json
{ "mode": "TOMBSTONE", "parts": {} }
```

It is the smallest position evidence. Archive and terminal-proof digests are
already carried by `pointer-tombstone-value/v1`; the pointer mutation ID also
commits the successor tombstone `Dv`, position digest, prior triple, pointer

independent binding.

The position hashes only in the derived
`authorization-state-position-tombstone/v1` domain. The same empty JSON shape
may be structurally meaningful for another tombstone-capable pointer only under
that other pointer kind's distinct domain; it must not produce the
authorization position identity. VALUE remains the distinct empty-parts
`authorization-state-position/v1` domain. Specialized parsing must accept only
TOMBSTONE/empty parts, while common dispatch must choose the domain from the
authenticated pointer kind. Nonempty parts, wrong mode, malformed closure,
untagged hashing, or substituting another family's resulting digest refuses.

The generic tombstone supplies all required terminal links without widening
this literal slice: exact `RECOVERY_AUTHORIZATION_STATE` kind, prior selected
REVOKED `Dt/Dv/Dr`, `archiveDigest = Draa`, and `terminalProofDigest = Drrp`.
The common proposal and mutation formulas then bind the same transaction-
scoped `Dp`, TOMBSTONE position, successor tombstone `Dv`, prior triple,
`TOMBSTONE_PROPOSED/REMOVE`, stable external epoch, and selected read-back.
Parsing a position or tombstone alone grants no proposal, CAS, mutation, or
selection authority.

## Chronology, acyclicity, and FULL_REQUIRED behavior

The complete intended order is acyclic:

```text
selected REVOKED Dt
  -> revoke post-selection receipt Drrp
  -> archive Draa
  -> tombstone Dv/Dr/Dt selection
```

The REVOKED graph contains no `Drrp`, `Draa`, or tombstone digest. The revoke
receipt contains selected REVOKED `Dt` but no downstream archive or tombstone.
The archive contains only upstream `Drrp`. The tombstone contains upstream
`Drrp`, `Draa`, and the prior REVOKED triple, and does not enter any of their
preimages. OP-R137-1 completes a missing equality but adds no edge and creates
no digest cycle.

The inclusive chronology is sufficient at millisecond precision:

```text
selected REVOKED state recordedAt
  <= revoke receipt recordedAt
  <= archive archivedAt
  <= tombstone tombstonedAt
```

ISS-032 owns exact selected/revoke read-back, create-once archive write,
byte-identical retry/read-back, and durable time production. ISS-004 owns
authenticated selected graph, path, operation, transaction, digest, chronology,

archive, tombstone, and all pointer history remain FULL_REQUIRED. Missing,
conflicting, noncanonical, truncated, unreadable, or bare-absent evidence is
