## Exact contract choices

All derived digest recipes now name their domain, exact ordered runtime
`FramePart` tags, and exact canonical projection. Canonical JSON record keys are
sorted, so insertion-order changes retain identical bytes. Reordering parts or
changing a part tag changes the framed bytes. Arrays retain the contract's
already fixed row order.

`github-api-request-identity/v1` uses `text(purpose)` then the complete request
record as one canonical part. `github-api-page-request/v1` uses raw request
identity then nullable pagination cursor. Both first-page branches use null;
every GraphQL page recomputes from its supplied nullable request cursor.
Subsequent REST request bytes are absent, so their request digests remain
supplied opaque leaves but must equal both the immediately prior
`nextRequestDigest` and its sole NEXT target. Request query/document/variables
leaf digests exclude pagination position, which the page chain represents.

REST relation names, rather than whole relation/target tuples, are unique and
UTF-8 sorted by relation. Every page request digest is globally unique. Any
present FIRST, PREV, NEXT, or LAST target resolves respectively to the exact
first, previous, next, or final admitted page request. FIRST/PREV are forbidden
on the first page; NEXT/LAST are forbidden on the final page; a one-page result
has no relations or Link digest. NEXT alone is mandatory on every nonterminal
page. FIRST/PREV/LAST remain optional wherever permitted so the parser does not
invent provider links. NEXT targets are globally unique and cannot repeat the
current or an earlier request, closing the reviewed cyclic-chain gap.

Response-body and non-null raw-Link-header hashes are supplied leaves because
their preimages are not receipt members. The pure parser checks SHA-256 grammar,
nullability and exact chain joins. ISS-036/038 authenticated composition must
bind the retained preimages, Link origin and actual followed request. Neither
an opaque digest nor an internally linked page count proves pagination
completeness. REST Link rows sort by the exact UTF-8 relation/target tuple.

`github-api-complete-reduction/v1` commits the raw request identity, an ordered
canonical array of ordinal/response-digest pairs, then the raw reduced-value
digest. `github-api-terminal-pagination/v1` commits request identity, API kind,
and an ordered branch-specific canonical page projection containing every Link
or cursor handoff and the final terminal cell. Neither formula includes its own
output.

`github-api-reduced-value/v1` uses text purpose plus one canonical projection.
Exact projections now exist for the six fresh-shared purposes and historical
WORKFLOW_RUN. WORKFLOW_RUN contains the complete triggering BUILD row.
PULL_REQUEST and PULL_REQUEST_REVIEWS retain opaque reduced-value claims because
the compact receipt has no reducer preimages; ISS-036 must bind their exact
closed preimages in its authenticated archive, and ISS-038 never joins them as
fresh semantics.

Ruleset semantics uses one canonical part containing its exact existing
five-member projection. Each family identity uses one canonical value part.
Fresh terminal evidence uses one canonical, non-circular projection containing
the ordered six purpose/request/terminal rows, exact start/end, the complete
five-member fresh environment binding, and the identical ruleset-semantic
projection.

The fresh environment update now satisfies anchor creation less than or equal
to fresh update, fresh update strictly less than historical REVIEW producer
start, and fresh update less than or equal to fresh observation start. Fresh
and historical ETags and update times may differ only within their respective
chronology windows. A post-producer same-value rewrite or retarget-then-restore
therefore refuses even when the final anchor digest is restored.

The pure binder result is a deeply frozen six-member record containing exactly
`anchor`, `anchorDigest`, `observedProtection`, `protectionDigest`, `receipt`,
and `terminalEvidenceDigest`. It contains no boolean or claim of authority,
freshness, authentication, verification, completeness, operator action or
grant.

identity; REST first page; GraphQL null and non-null cursor pages; complete

reduction; ruleset semantics; both family identities; fresh terminal evidence;
and the binder result census. Canonical record-key insertion-order variants
must preserve bytes. Frame-tag, frame-order, array-order and projection-member

reordering, duplicate REST relation names, every wrong-index or

NEXT/target/next-row disagreement, early or missing terminal cells, GraphQL
cursor mismatch/repetition, and terminal claims formed from a caller count.
Positive boundary vectors omit optional FIRST/PREV/LAST and require no invented
link on one-page, first-page, or final-page boundaries. Deleting relation-name
uniqueness, any target/index rule, request/NEXT global uniqueness, or any
boundary rule must make its matching committed mutant survive and fail the
suite. Each opaque leaf mutates independently and moves every enclosing derived
digest while remaining only a structural claim. No pure positive may claim its
absent preimage, API origin or completeness was verified.

Binder vectors delete or alter every repository, signer, anchor/environment,
request-identity, semantic, chronology, expiry, freshness and terminal-evidence
join. They pin detached deeply frozen inputs and the exact return names, with no
authority-like result member. Fresh update vectors refuse before-anchor,
producer-start equality, post-producer, after-observation-start, same-value

comparison must make its matching mutant fail the suite. Exact-head independent
review and hosted three-OS execution remain required before source can count as
