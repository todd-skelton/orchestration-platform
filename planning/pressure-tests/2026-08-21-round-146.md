## Mutation-ID formula and no-migration proof

The Round 144 formula repair remains exact. The mutation-ID preimage is ordered:

```text
pointer kind text
canonical path text
Dp raw32
transaction ID nullable text
source token text
position digest raw32
prior Dt nullable raw32
prior Dv nullable raw32
prior Dr nullable raw32
successor Dv raw32

```

There is exactly one final outcome part. Intent is not a second part because it
is derived from trusted position mode and the closed pair invariant. The
formula matches the existing public `computeMutationId` helper's closed input
and framing order; valid mutation IDs, paths, proposals, conflict evidence,
run-current targets, commit evidence, and goldens do not change.

The locator must build the helper input from its already-closed trusted identity,
the parsed proposal's exact prior `Dt/Dv/Dr`, recomputed successor `Dv`, and the
admitted proposal outcome. It requires the result equal
`proposal.mutationId` before returning the selected tuple. The Round 144
coordinated attack—substitute an arbitrary SHA-256 mutation ID and recompute
`Dr` plus tip `Dr/Dt`—therefore refuses without adding a caller expected digest
or fifth input.

Omitting intent is the proportional choice. Once the common two-row pair and
trusted-mode equality hold, intent carries the same VALUE-versus-TOMBSTONE
choice already established by position mode and outcome. Hashing it again
would change every valid identity without removing another attack.

## Trust, self-certification, and scope attack

Parser success, a deterministic mutation ID, coherent aliases, or a locator
success result is evidence, not mutation authority. The locator does not read
the canonical current tip, decide currentness, perform CAS, issue a handle,
authenticate the producer epoch, review a candidate, or promote a release.
Only stable external authority may select the canonical pointer through the
later ISS-004 mutation path.

The mutation-ID equality prevents a candidate/caller from selecting its own
mutation name, but it does not make the derived name a capability. Candidate-
written aliases remain non-authoritative until a stable current-tip CAS names
their exact graph. A losing candidate may leave coherent orphan content; the
content does not certify or activate that candidate.

Producer kind/digest, selected authority-epoch tuple, proposal time, family
value semantics, root/archive records, terminal proofs, canonical persisted
bytes, iterative history, conflict resolution, and currentness remain later
composition/runtime obligations. No Git, GitHub, repository, consumer,
provider, OS-secret, endpoint, or adapter vocabulary enters the engine
contract.
