## Blocking findings

1. **The helper binding does not cover the executions it claims.**
   `captureIss022Executable()` opens and hashes the resolved `process.execPath`,
   compares its handle/path identities, and then closes the handle. The suite
   calls it once before all eight handler groups. Every later child spawn again
   resolves `process.execPath`, but there is no retained handle or post-capture
   equality check spanning those launches. A path/executable substitution after
   capture can therefore make `Dhelper` describe the old bytes while vector
   facts come from different Node bytes. The current movement mutants alter a
   finished report; they do not attack this lifecycle gap. Refuse unless one
   suite-scoped executable custody observation proves the same regular-file
   handle, path, realpath, size, and exact bytes across every child-launch
   boundary, and bind the spawned executable to that observation.

2. **An ADMITTED locator survives non-PASS physical evidence.**
   `deriveIss022PhysicalProfile()` requires PASS only for rows 1–3
   (`PHYSICAL_ABSENT_LEAF`, case alias, Unicode alias). Rows 0, 4, and 5 are
   ignored, after which `constructIss022ProfileArtifacts()` unconditionally
   emits `disposition: "ADMITTED"`. For example, changing
   `PHYSICAL_EXISTING.rootStable` to false and its recomputed result to UNKNOWN
   leaves the absent-leaf derivation intact and the closed parser accepts the
   report. The same class applies to unsupported/unknown symlink or parent-swap
   evidence. Require all six exact physical executions to be PASS before
   emitting the non-null OS/custody/locator profile; otherwise use the existing
   null non-admitted arm. Add mutants for each ignored row.

stack is justified.
