## Archive parser, path, identity, and registry

`recovery-authorization-archive/v1` is implemented with exactly four unique
required members in ascending canonical JSON order:

```text
archivedAt
revokePostSelectionReceiptDigest
schemaVersion
transactionId
```

The parser snapshots input before semantic reads, requires the exact schema
literal, validates `archivedAt` as a canonical timestamp,
`revokePostSelectionReceiptDigest` as SHA-256, and `transactionId` as UUIDv7,
and rejects missing, extra, renamed, null, or cross-type members. The archive
does not copy state `Dp/Dv/Dr/Dt`, core identity, operation, gate, lifecycle,
mode, native receipts, generation, disposition, proposal, or tip fields.

The implementation reuses the already-registered constructor exactly:

```text
installation/recovery-authorizations/<transactionId>/archive.json
```

It validates the transaction input before constructing the path and changes
the path when a different valid transaction is supplied. No enumeration,
latest-record selection, digest lookup, caller path, alternate archive root,
or operation search was added.

The only archive digest is:

```text
Draa = SHA256(frame("recovery-authorization-archive/v1", canonical archive bytes))
```

The implementation supplies exactly one canonical-record frame part. The
public serializer has an explicit schema-specific route and returns the
existing exact success shape `{ ok: true, bytes, digest }` with canonical bytes
and `Draa`, rather than the generic untagged canonical digest. Parser dispatch,
canonical-byte parsing, schema vocabulary registration, `schemaVersions`, and
the compatibility matrix all include the exact v1 literal; cross-version and
unknown schema behavior remains fail closed through the existing registry
rules.

Focused evidence pins the exact canonical bytes and `Draa` golden, proves
`Draa != canonicalDigest(archive)`, rejects reordered detached bytes, removes,
nulls, cross-types, and renames every member, and exercises deleted copied
proof fields against record closure. Hostile reflective archive input returns
a parse failure without throwing. Deleting the closure, schema literal,
transaction path validation, domain tag, serializer branch, or registry entry
leaves a direct committed mutant killed by the focused or compatibility suite.

## Authorization TOMBSTONE position and common dispatch

The specialized parser admits exactly:

```json
{ "mode": "TOMBSTONE", "parts": {} }
```

It snapshots the outer record and nested `parts`, rejects outer extras,
missing members, nonempty or malformed parts, and any mode other than
`TOMBSTONE`. The pre-existing VALUE parser and digest semantics are retained:
VALUE still admits only its distinct empty-parts shape and still produces the
pinned `authorization-state-position/v1` identity.

Common `computePointerPositionDigest` now dispatches
`RECOVERY_AUTHORIZATION_STATE` by authenticated mode to the corresponding
specialized parser before hashing. TOMBSTONE therefore uses exactly the
registry-derived `authorization-state-position-tombstone/v1` domain; VALUE
uses `authorization-state-position/v1`. The two pinned digests differ.
Nonempty cleanup-gate-style parts cannot bypass the authorization parser, and
the common cleanup-gate route refuses the authorization tombstone. A different
tombstone-capable pointer kind selects its own registry-derived domain, so the
same structurally meaningful empty shape cannot become the authorization
position identity through cross-family dispatch. The non-tombstone-capable
authority-rotation row remains refused by the existing common check.

No broader malformed-position bypass was introduced. The new branch is
limited to one pointer kind and tightens that kind's previous VALUE-only
specialization by adding an equally closed TOMBSTONE arm. Other pointer-kind
validation branches and all existing VALUE goldens remain unchanged and green.
The specialized parser and digest exports also make mode deletion observable:
removing either specialized distinction makes the cross-mode tests fail rather
than silently routing both modes through a caller-selected domain.
