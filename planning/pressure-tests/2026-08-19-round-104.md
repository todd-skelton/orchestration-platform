## `OP-R104-001` — the selected graph does not authenticate the named use intent

The authority order is explicit:

```text
owner/anchor ACTIVE -> use intent -> Dgb -> GENESIS Dh -> E0 Dv/Dbg
  -> Dr/Dt -> Dgp -> anchor CONSUMED -> owner CONSUMED
  -> final consumption receipt
```

`Dgb` is the required bridge. Its closed
`authority-history-genesis-bootstrap-input/v1` record carries the exact
`useIntentDigest`, owner ACTIVE triple, anchor ACTIVE triple, `Dba`,
destination, global bootstrap identity, transaction, grant, and `Dsc`.
`state-mutation-bootstrap-genesis-core/v1.genesisBootstrapInputDigest` then
binds that `Dgb` into `Dbg`, whose digest is the selected bootstrap proposal's
producer and is repeated by `Dgp` and anchor `CONSUMED`.

The new validator parses the supplied intent, recomputes its digest, and
compares that digest only to the final receipt. It directly compares the
intent's anchor ACTIVE triple and four basic destination/transaction/custody
fields, and independently compares the core's owner ACTIVE triple. It never
accepts the actual `Dgb`, recomputes `Dgb`, compares it to
`core.genesisBootstrapInputDigest`, or compares `Dgb.useIntentDigest` to the
supplied intent. The two sides can therefore move independently.

An approved read-only in-memory bundle of the exact checked-out source and
committed fixture performed three independent attacks. In each case it changed
only the named intent member, recomputed
`receipt.useIntentDigest = computeBootstrapAnchorUseIntentDigest(intent)`, and
left the selected E0, `Dgp`, anchor/owner transitions, and all other receipt
members unchanged:

| Moved intent fact | Public validator result |
| --- | --- |
| `destinationOwnerActiveTipDigest` | `[]` |
| nested `reviewedInstaller.reviewReceiptDigest` | `[]` |
| nested `proposedGenesisInput.globalIdentityDigest` | `[]` |

The proposed-genesis mutant was also executed against both committed valid
origins. Genesis-origin returned `[]`; successor-origin returned `[]`. This is
not a caller-expectation-only theoretical gap: it is an accepted
cross-authentication substitution at the final public composition boundary.

The committed test named “binds every receipt digest, selected graph,
readback, custody, and time” changes each receipt digest independently and
rehashes one downstream anchor/owner `Dgp` substitution. Those are useful
controls, but they never change the intent and receipt digest together. No
test can exercise the required `Dgb` edge because the public validator does
not take `Dgb` as an input.

### Smallest repair

Add the actual closed `authority-history-genesis-bootstrap-input/v1` record to
the consumption composition, then:

1. parse it with the existing total parser and recompute `Dgb`;
2. require that digest to equal
   `state-mutation-bootstrap-genesis-core/v1.genesisBootstrapInputDigest` from
   the exact core already selected by the E0 proposal/`Dgp` graph;
3. require its `useIntentDigest` to equal the recomputed supplied intent and
   retain direct equalities for its owner/anchor ACTIVE triples, `Dba`,
   destination, transaction, grant, global bootstrap identity, and `Dsc`
   against the already parsed siblings; and
4. add genesis- and successor-origin coordinated mutants for each independent
   intent branch, plus null/hostile `Dgb` totality controls.

This adds no schema, persisted receipt, digest domain, path, lifecycle state,
coordinator, capability, or later semantic surface. Calling the complete E0
validator again, inventing a second receipt, or accepting another digest-only
expectation would be larger and is unnecessary. The actual selected `Dbg`
already provides the downstream anchor; the missing work is only to expose and
validate its existing `Dgb` preimage.
