## `OP-R108-001` — the prior selected graphs are digest-only, not composed

The new function accepts 21 inputs. It parses the current anchor, its current
selected tip/value/proposal, the current selected owner tip/value/proposal, the
teardown records, and the two new RETIRED graphs. It then composes:

- `validateBootstrapAnchorTeardownBinding` over the current selected graph and
  teardown pair;
- `validateBootstrapAnchorMutationBinding` for the current anchor selection to
  anchor RETIRED; and
- `validateDestinationOwnerMutationBinding` for the current owner selection to
  owner RETIRED.

That proves the two new RETIRED edges relative to the supplied current graphs,
but it never proves how those current graphs themselves were selected.

### CONSUMED is accepted without its ACTIVE predecessor or consumption graph

For every CONSUMED fixture, `anchorSelection` writes literal placeholder prior
digests `d("7")/d("8")/d("9")` into the anchor CONSUME proposal. The owner
CONSUME proposal similarly writes placeholder prior digests
`d("e")/d("f")/d("1")`. There are no actual ACTIVE predecessor
tip/value/proposal inputs to `validateBootstrapRetirementBinding`, so neither
triple can be recomputed or shown to select a real record. The function also has
no inputs for the actual use intent, E0 core/value/proposal/tip/post receipt,
anchor consumption receipt, consumed readbacks, or full genesis-selection
composition.

Nevertheless, both committed CONSUMED fixtures return `[]`:

```text
consumed-genesis   -> []
consumed-successor -> []
```

The nested teardown validator checks only that the placeholder predecessor
triples are all non-null, that the current proposal mutation IDs recompute from
those caller bytes, and that the current CONSUMED anchor/owner graphs agree
locally. Rehashing agreement among siblings cannot establish that a predecessor
record exists or is selected. This contradicts the ledger's exact selected
prior-triple requirement and the compatibility claim that composed validators
bind every value/proposal/tip readback.

### Successor ACTIVE is accepted without prior RETIRED, `Dsrc`, or `Dsrp`

The successor-origin fixture supplies only `d("8")` as the anchor's
`successorReviewCoreDigest`. Its owner `ACTIVATE_SUCCESSOR` proposal again uses
the arbitrary non-null placeholder predecessor triple
`d("f")/d("1")/d("e")`. The new function has no inputs for the actual prior
RETIRED owner tip/value/proposal, its teardown archive, the closed successor
review core and expected preimage, or the successor post-selection receipt and
its readbacks/custody expectation.

Nevertheless, both committed successor arms return `[]`:

```text
unused-successor   -> []
consumed-successor -> []
```

This is the same digest-only trust failure removed from the E0 and Dgse
compositions in the prior rounds: equality to a caller-supplied `Dsrc` string
does not authenticate the actual review core, exact prior RETIRED archive, or
downstream `Dsrp`. The successor test is therefore not a valid positive control;
it codifies the missing provenance as accepted input.

### Bounded remedy and regression proof

Replan the public composition around a closed branch-specific input shape and
reuse the existing pure validators rather than adding another schema or
receipt:

- ACTIVE genesis must retain exact null-predecessor anchor/owner activation;
- ACTIVE successor must consume the actual prior RETIRED owner triple,
  teardown archive, successor review core/expectation, successor
  post-selection receipt/expectation, and exact selected successor graph;
- CONSUMED must consume the actual ACTIVE anchor/owner triples and the complete
  existing E0/consumption relation needed to prove both CONSUME proposals'
  predecessors; and
- successor-origin CONSUMED must preserve the full successor provenance through
  that actual ACTIVE predecessor rather than recovering it from the anchor's
  retained digest alone.

Regression tests must use complete genesis- and successor-origin fixtures and
then independently and coordinately replace the immediate predecessor triples,
prior RETIRED archive, `Dsrc`, `Dsrp`, E0/consumption siblings, and all matching
digest copies. Each rebuilt attack must refuse through the public retirement
composition. Missing/null/hostile branch-only inputs must remain total.

## `OP-R108-002` — recorded chronology does not enforce retirement order

The normative order is:

```text
Dabs -> lifecycle archive -> teardown receipt -> anchor RETIRED
     -> owner teardown archive -> owner RETIRED
```

Digest dependencies preserve acyclicity and exclude future value/proposal/tip
digests, but the public evidence also carries canonical recorded timestamps.
The existing teardown validator correctly rejects a lifecycle archive whose
`archivedAt` precedes `Dabs.observedAt`. The new retirement composition adds no
corresponding order checks for either new selection proposal.

An approved read-only in-memory probe rebuilt every affected downstream digest,
mutation ID, value, proposal, tip, teardown receipt, and owner archive from the
exact checked-out fixture. Both invalid cases returned `[]`:

```text
anchorRetiredProposal.proposedAt = 2026-08-19T12:01:30.000Z
lifecycleArchive.archivedAt      = 2026-08-19T12:02:00.000Z
result                           = []

ownerRetiredProposal.proposedAt  = 2026-08-19T12:02:30.000Z
anchorRetiredProposal.proposedAt = 2026-08-19T12:03:00.000Z
result                           = []
```

These are not stale-digest mutants. The anchor proposal/receipt/tip was
recomputed, then the owner archive, owner RETIRED value/proposal/tip, and every
dependent digest were rebuilt in order. The second attack likewise recomputed
the owner proposal receipt and selected tip. The validator therefore accepts
canonical records that state the reverse of the lifecycle order they claim to
attest.

The bounded repair is to compare canonical timestamp text after parsing:

- anchor RETIRED `proposedAt` must not precede lifecycle `archivedAt`; and
- owner RETIRED `proposedAt` must not precede anchor RETIRED `proposedAt`.

The existing `archive.archivedAt >= Dabs.observedAt` check remains. Focused
tests must fully rehash both reverse-time tails and require the exact new named
findings; changing only one timestamp without rebuilding its digest descendants
is not discriminating.
