## Accepted observation repairs

### Observation happens before mutation

When destructive observation is armed and the operation is
`FileDispositionInfo`, the wrapper first obtains the live handle's normalized
DOS final path. Zero, over-bound, or otherwise unclassifiable results latch
`fixture_execution_unidentified_delete`. It then forwards the real operation,
so the fixture observes the same live object offered to Windows rather than a
cached handle value after close.

This removes the Round-194 local-handle omission. `delete_partial_target` may
hold its child in a function-local `RETAINED_OBJECT`, but its live path ends in
the fixed target filename and is now recorded as role 1. Case 3 therefore
requires exactly target 0 followed by root (`{1,4}`).

Recognized COMPLETE cases continue to require `{1,2,3,4}` and the durable
one-target-absent retry requires `{2,3,4}`. Unknown/path-resolution failures are
consulted in the failure, retry, census, and normal cleanup assertions.

### Independent source survival

The TypeScript driver stores detached original buffers for runtime, RPC, and
candidate sources. After each compiled execution process returns successfully
and before teardown removes its temporary directories, it rereads the three
source paths and requires exact byte equality. A direct deletion or mutation
of any source used by the current 41 cases is therefore visible independently
of the C observation seam.

This kills the Round-194 source-deletion mutant for the fixture's current
noncolliding names.

## Remaining finding: suffix classes are not exact object classes

`fixture_execution_path_phase` recognizes an OPWX phase by checking only
whether the path ends with one of:

```text
-00-attempted.opwx.pending
-01-created.opwx.pending
-02-delete-attempted.opwx.pending
-03-absence-proved.opwx.pending
```

The disposition wrapper excludes any such path as “journal rollback.” It does
not compare the path with `execution_journal_path(root, token, phase, 1, ...)`,
the retained state-root path, or even require equality with the currently live
`fixture_execution_pending_handle`.

Likewise `fixture_execution_object_role` maps roles 1–3 from only these suffixes:

```text
\node.exe
\rpc-runner.mjs
\candidate.mjs
```

Only the root role uses full path equality. The role mapper does not construct
and compare the three exact child paths beneath `fixture_execution_root_path`.

The execution protocol permits arbitrary canonical source paths outside the
state and execution roots; it does not reserve these basenames or OPWX-like
suffixes globally. Therefore these concrete mutants remain:

- a product mutant disposes a retained source named
  `source-00-attempted.opwx.pending`; the C seam excludes it as journal
  rollback; and
- a product mutant disposes a retained source whose basename is `node.exe`,
  `rpc-runner.mjs`, or `candidate.mjs`; the seam records it as an expected
  execution child.

The independent reread would catch those deletions only if a test actually
used colliding source names. The current driver uses `node-source.exe`,
`rpc-source.mjs`, and `candidate-source.mjs`, so both classifier branches and
their source-survival backstop remain unexercised.

This is also a direct mismatch with Round 194's repair authorization, which
required excluding the known journal-pending disposition only and resolving
exact target/root paths.

### Smallest repair

Keep production, PE, protocol, and case count unchanged if desired. In the C
fixture:

1. Exclude a disposition only when its handle is the current
   `fixture_execution_pending_handle`, its full final path equals the exact
   canonical pending path constructed from the retained state root and token,
   and its phase equals the active publication phase.
2. Construct target 0–2 full paths from the captured exact execution root and
   compare the complete final path. Do not classify by suffix.
3. Treat every other path—including an OPWX-like path outside the state root or
   a target basename outside the execution root—as unidentified.
4. Add executable collision cases or parameterize existing cases so one source
   has an OPWX-pending-like basename and another has a fixed target basename.
   Attempting to dispose either must latch unidentified state, while normal
   cleanup still recognizes exact execution children and the driver proves all
   source bytes survive.

No production code or tracked PE rebuild is justified for this fixture-only
closure.
