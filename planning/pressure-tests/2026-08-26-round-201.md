## Round-200 blocker verification

### 1. Per-object original-or-grant recovery: production repaired, deletion evidence incomplete

`admission_recovery_descriptor_state` now captures each of the execution root
and three target descriptors and independently admits only exact equality to
the retained original or Dgrant's package descriptor for every active/revoke
phase 1–6. A third descriptor refuses. Recovery then durably enters kind 6,
terminates/proves the named Job absent, restores root first and targets after,
reproves exact original custody and fixed census, proves the scratch probe
absent, and only then records kind 7. This removes the Round-200 production
deadlock after best-effort reversal and lost kind-6 publication.

The executable matrix does not exercise this reducer. The real crash cases
cover uniform boundary states: original at GRANT_ATTEMPTED and grant at the
later admission pauses. The OPWL publication fixture persists synthetic
records and retries publication; it never opens the four execution objects or
calls `recover_admission`. There is no compiled case for each original/grant
combination, each individual third descriptor, partial `SetKernelObjectSecurity`
progress, or lost kind 6 after every predecessor followed by clean
reconstruction and OPWX/OPWJ cleanup.

### 2. Exact-source compiled admission/OPWL matrix: still blocked

`OP_WINDOWS_ADMISSION_FIXTURE` directly calls several real static helpers, but
its scope is only:

- `valid_admission_transition` and whether `admission_record` serializes;
- `valid_admission_final_set` over 128 presence masks;
- a few detached-SID and token-group length/duplicate examples;
- empty/one/duplicate Job PID-list examples; and
- equality of the six-member denied-right array.

It does not macro-substitute any admission OS operation. The TypeScript test
still explicitly requires the fixture source to contain no `CreateProcess`
token. Separately, the outer lifecycle fixture still maps
`OP_BROKER_RUN_ADMISSION` to `fixture_run_admission`, a three-argument stub that
prints `fixture:admission` and returns success.

The `fault-admission-publication` scenario does use the real OPWL publisher and
scanner for all legal predecessor/target edges and 13 publication faults. That
is useful durability evidence, but after scanning it manually clears pending
state and retries only `persist_admission_phase`. It does not drive
`run_admission_lifecycle`, `recover_admission`, grant restoration, Job cleanup,
or outer OPWL-before-OPWX/OPWJ composition. Its mask test also calls the pure
set reducer rather than constructing hostile whole journal sets through the
scanner.

Therefore removal of `apply_admission_grant`, any startup attribute,
`CreateProcessW`, actual token proof, an access/open arm, Job termination, or
descriptor restoration still survives the compiled fixture family. The real
host happy/crash run cannot replace deterministic fault injection at these
authority boundaries.

### 3. Hostile token and Job validation: production repaired, matrix incomplete

The production parsers now fail closed on the relevant shapes:

- scalar token queries require exact returned sizes and values;
- variable token queries require an exact second returned length;
- SID pointers must be aligned and point to a complete exact in-buffer SID;
- SID-bearing token structures require the SID to begin exactly after the
  fixed structure and consume the whole detached result;
- token groups bound the count, prove the row array and every contiguous SID
  extent, reject unknown/conflicting attributes and duplicate SIDs, and reject
  enabled stable/SYSTEM/Administrators groups;
- zero capabilities require the exact canonical zero-row buffer; and
- Job PID lists bind returned bytes to count, cap count at 64, reject zero,
  over-`DWORD`, duplicate, wrong-child, count mismatch, and truncation, then
  reconcile the list with exact accounting and Job membership.

The compiled hostile-buffer test covers only a small subset: one SID
offset/truncation, zero/one-group truncation, duplicate groups, zero/one PID
list truncation or wrong PID, and duplicate PIDs. It does not exercise the
actual token query wrapper, scalar returned sizes, application/package/
integrity/capability members, hostile pointers, count bounds, attributes,
forbidden groups, most Job count/returned-length/accounting relations, or
resource-return ambiguities. Thus the production repair is accepted, but its
required deletion evidence remains part of the compiled fake-OS repair.

The real diagnostic necessarily executes these loops on its one host, and the
new compiled helper fixes the exact six-member array. It does not execute or
observe either loop. Deleting one API loop, skipping one object class, mapping
a right to the wrong object, accepting an unrelated error, or bypassing
impersonation can still leave the compiled suite green. Round 200's one
right/object/API deletion evidence is therefore not closed.

## Preserved trust boundary

- stable N constructs Dgrant and Dlaunch from retained profile/execution
  custody; candidate bytes supply neither expected values nor authority;
- grant order is children before root and restore order is root before
  children;
- the exact package SID receives only protected read/execute access while
  stable and SYSTEM retain full control;

- production contains no `ResumeThread`; the primary thread cannot execute
  candidate code in this slice;
- token, Job, access, and scratch observations are stable-owned; child output
  is required empty and cannot certify or promote anything;
- runtime/Job termination and OPWL absence precede execution/profile cleanup;
  and
- LAUNCH remains private refusal-only NOT_IMPLEMENTED after complete reversal.

The broker/PE remains private and absent from both package-root export lists.
There is no receipt, aggregate, provider result, certification, installation,
promotion, or public authority surface.

Extend the existing include-based C fixture; do not add another broker, helper,
mode, opcode, journal kind, or TypeScript authority. In a dedicated admission
mode, macro-substitute the Windows observations before including the exact
production source and invoke the real static admission and recovery paths.

The minimum landing matrix is:

1. all four execution objects as original/grant through recovery phases 1–6,
   each third profile, partial grant/restore progress, all kind-6 publication
   faults after predecessors 1–5, durable retry, root-first restore, and final
   OPWL-before-OPWX/OPWJ cleanup;
2. real parser/scanner construction of every admitted Round-198 branch and
   hostile gap/fork/prior/cross-record set, plus every OPWL publication prefix;
3. actual production job/create/token/access/runtime functions under fake OS
   observations, covering each startup attribute and identity/size/value,
   process/job result, token/member/buffer boundary, cleanup/resource
   ambiguity, and no-resume invariant; and
4. observable AccessCheck and impersonated-open calls for every dangerous
   right on targets and root, with one deletion mutant per right, object class,
   and API path.

This is proportional because every requested fake observation corresponds to
an already retained authority-bearing operation. A service, TS privilege
fallback, same-principal launch, candidate probe/verdict, wider ACL, public
schema, or candidate-visible source path remains forbidden.
