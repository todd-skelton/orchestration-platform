## OP-R148-1 removal verification

### One exact internal `Dp` dispatch

The repaired authority now says that `RECOVERY_ATTEMPT_RESERVATION` alone uses
the existing `computePointerInstanceDigestFromCanonicalPath` behavior inside
the public common identity dispatcher. That route:

1. parses the exact registered reservation path template;
2. requires the path transaction UUID equal the closed identity transaction;
3. requires the path source equal the closed identity source;
4. requires the predecessor-key segment be lowercase SHA-256;
5. reconstructs the exact canonical path; and
6. applies the unchanged `pointer-instance/v1` formula to the ordinary identity
   scalars.

The same internal family dispatch is mandatory for:

- public `computePointerInstanceDigest`;
- `computeMutationId`, which consumes the ordinary pointer identity; and
- `validateLocatedSelectedPointerEvidence`, which recomputes `Dp` and mutation
  identity before accepting the selected graph.

Thus one constructed reservation identity with empty position produces one
identical `Dp` through identity, mutation, and selected-location flows. There
is no public flag, overload, alternate input, new digest, or second identity
type from which a caller could choose a weaker route.

The canonical-path helper was already public and used by common commit
validation. The repair adds only an internal dispatch to it; it does not
migrate stored identities or change any non-reservation family. Removing that
dispatch makes empty-position reservation identity/mutation/locator positives
refuse and is explicitly a required deletion mutant.

### Exact path grammar and malformed identities

The canonical path remains exactly:

```text
installation/activation-recovery-launches/<transactionId>/<sourceToken>/reservations/<Kreservation>.json
```

`transactionId` is canonical UUIDv7, `sourceToken` is exactly
`cleanup-gate-pre-fence|recovery-fence`, and `Kreservation` is lowercase
SHA-256. Static segments, separators, and `.json` are fixed by the registry
template. Missing, extra, empty, uppercase, non-digest, traversal, wrong
transaction, wrong source, or alternative spelling refuses structurally.

The key constructor still accepts only the exact closed five-input predecessor
record and the path constructor still consumes that same parsed input. It does
not accept a caller-supplied key. Cross-transaction or cross-source input
recomputes both a different key and a different path; changing a predecessor
branch/digest recomputes the key path segment.

### Wrong well-formed key and family ownership

The generic canonical-path route intentionally accepts any path whose key is
well-formed lowercase SHA-256 and whose transaction/source equal the trusted
identity. That proves a structurally valid pointer identity only. It cannot
prove the key came from a selected terminal attempt-log predecessor because
the generic locator has no predecessor input and must not gain one.

The repaired authority explicitly requires later reservation family
composition to:

1. parse actual tagged genesis or selected terminal predecessor evidence;
2. recompute `Kreservation` from its exact transaction/source/branch/`Dt/Dv/Dr`;
3. reconstruct the whole reservation path; and
4. require equality to the independently trusted selected identity before
   generic locator success is used.

That later equality is sufficient. It rejects a well-formed wrong key without
duplicating the key in position or widening the generic locator. The future
reservation value ledger must assign focused key/path substitutions and
deletion mutants to that family composition; this identity slice does not
prematurely invent value fields.

## Key, branch, and position reattack

The predecessor input remains exact:

```text
predecessorReceiptDigest: nullable SHA-256
predecessorTipDigest: nullable SHA-256
predecessorValueDigest: nullable SHA-256
sourceToken: cleanup-gate-pre-fence | recovery-fence
transactionId: UUIDv7
```

The predecessor triple is either wholly null genesis or wholly non-null
selected predecessor. Partial and swapped triples refuse or produce different
keys. Framing remains stable:

```text
recovery-attempt-reservation-predecessor/v1
transactionId text
sourceToken text
00 genesis | 01 selected-predecessor
selected only: Dt raw32, Dv raw32, Dr raw32
```

The one-byte tag is fixed raw data, not enum text or caller numeric data. UUID
time and digest lexical order provide no attempt ordering. No attempt ID,
ordinal, lifecycle, descriptor, log record, or archive fact enters the key.
The key depends only on an already terminal upstream attempt-log selection, so
there is no self-reference or digest cycle.

VALUE position remains exactly:

```json
{ "mode": "VALUE", "parts": {} }
```

The specialized and common position routes must require that exact closure and
the existing `attempt-reservation-position/v1` domain. Nonempty parts, nested
extras, missing/extra fields, TOMBSTONE, cross-family evidence, or generic
bypass refuses. `Kreservation` is already in canonical path/`Dp`; future
attempt identity is in value/`Dv`. Copying either into position would be
redundant. Tombstone position correctly remains deferred to the archive ledger.

## Proportionality and interoperability

| Mechanism | Concrete threat | Deletion result | Smallest disposition |
| --- | --- | --- | --- |
| Reservation-only canonical-path dispatch | Empty position cannot supply the registered key placeholder to common identity/mutation/locator flows. | Deleting dispatch makes constructibility positives fail. | Retain one internal branch to an existing helper; no new public API or digest. |
| Closed five-input key | Malformed or moved predecessor context selects a bucket. | Removing any field admits a scalar/branch mutant. | Retain; no attempt ID or ordinal. |
| Transaction/source key parts | Detached opaque keys compare equal across valid contexts. | Changing context no longer changes key. | Retain; fields are already required by path and add no input. |
| Fixed branch and `Dt/Dv/Dr` order | Genesis/selected or selected digest roles collapse. | Tag/part deletion or reorder breaks goldens. | Retain exact framing. |
| Empty VALUE position | Key/attempt facts are hashed redundantly. | Adding any part must fail closure evidence. | Retain empty; derive reservation `Dp` from path. |
| Structural generic locator | Caller presents malformed or graph-inconsistent selected identity. | Path/`Dp`/mutation/graph deletion mutants survive. | Retain structural scope only. |
| Later family key/path equality | A well-formed wrong key is mistaken for authorized predecessor lineage. | Deleting family equality admits a coordinated selected-value/path mutant. | Assign to future value/family composition; do not widen generic locator. |

The chosen dispatch is smaller than copying key into position, adding the five
predecessor inputs to every common identity, creating a reservation-only
identity API, or changing `pointer-instance/v1`. It is also better evidenced
than permitting callers to choose between position-derived and canonical-path-
derived formulas.

Transaction/source inclusion remains proportionate. Although the parent path
also carries them, the public opaque key itself changes when detached from one
valid context and moved to another. This costs no additional input and grants
no standalone authority, index, cache, lookup, or enumeration behavior.

selected terminal predecessor, live handle, review receipt, release verdict,

future reservation. Candidate output cannot certify or promote itself.

be authored before this identity implementation passes review.
