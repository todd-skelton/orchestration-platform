## Round-183 implementation repairs confirmed

### Active lifecycle and response ownership

- `write_all`, `read_frame`, and `send_response` now return closed results rather
  than exiting from an active profile state.
- `serve` owns `EMPTY`, `PREPARED`, and `TERMINAL`; EOF, partial or malformed
  second frames, over-bound bodies, wrong-order requests, broken PREPARE output,
  and broken LAUNCH output all route through `finish_prepared`.
- `finish_prepared` attempts profile cleanup, then root/resource release, and
  distinguishes exact refusal `65` from recovery-required `70`.
- TEARDOWN closes profile and root custody before emitting OK. A post-cleanup
  response failure cannot resurrect or certify the deleted profile.
- The compiled lifecycle fixture includes the exact production parser and state
  reducer and behaviorally proves the principal input/output loss arms,
  successful teardown, cleanup failure, and root-close failure.

### Recovery and census reduction

- `complete_profile_census`, `recover_groups`, and `preflight_and_recover` now
  preserve the three required meanings: clean, pre-mutation refusal, and
  recovery required.
- A recognized durable group, malformed/noncanonical state-root entry, owned
  `orch6` residue, mixed group ambiguity, cleanup error, or returning-resource
  ambiguity cannot reduce to ordinary refusal.
- The whole sorted journal/census set is preflighted before recovery mutation.
- Round 180's raw-row rule remains intact: exact unrelated duplicate name/SID
  identities are permitted, conflicts refuse, and target rows are never
  canonicalized together.
- A target row must contain one valid `userSid` equal to the retained stable
  process user. Null, malformed, and wrong-user target rows are behaviorally
  rejected while unrelated rows remain outside target authority.

### Resource and folder custody

- `release_root` accumulates process-token, root-handle, SID, security, heap, and
  prior resource ambiguity and returns a result used by every terminal status.
- `bind_folder` is all-or-null: a partially opened candidate is closed on every
  failure and cannot overwrite an existing retained handle.
- The successful create path checks the resource-ambiguity latch before PREPARE
  can emit OK and attempts cleanup if it is set.
- Cleanup handles CREATED and DELETE_ATTEMPTED retry states without treating a
  delete return value as absence. It still requires target census absence,
  folder-path absence, pending cleanup, and durable ABSENCE_PROVED.
- Folder owner, DACL, low-label SACL, path, type, link count, file identity, and
  complete security bytes remain bound under the retained stable root relation.

### ACE safety repair

Both stable record/root ACL parsing and profile-folder DACL/SACL parsing now
require `AceSize >= 16` before passing the SID at offset eight to `IsValidSid`.
They then require valid SID length within the declared ACE before `EqualSid`.
This removes the short-ACE out-of-bounds arm identified in Round 183 without
changing the accepted Windows-created ACL formula.

### Real diagnostic evidence

- The tracked PE performs one real PREPARE, refusal-only LAUNCH, TEARDOWN cycle.
- Fixed source-identical diagnostic builds pause immediately after durable
  ATTEMPTED and immediately after the real create call but before folder capture
  and CREATED. The test kills each process and uses the tracked RECOVER PE.
- A separate native verifier independently enumerates raw profiles by exact
  moniker or SID and probes the captured folder path for absence after normal
  teardown and both recovery cycles.
- The permanent five-record chains and absence tombstones remain; pending files
  do not.

The author-reported exact-tree opt-in diagnostic passed all three cycles and
left no temporary `orchestration-windows-*` root or profile residue. That result
is useful implementation evidence only. It is not a receipt, provider record,
hosted Windows PASS, authority grant, certification, or promotion input.

## Remaining bounded evidence gap

The fake fixture still separates its coverage into:

1. raw census and journal-record helpers;
2. a source-identical active lifecycle reducer whose root, preflight, create,
   cleanup, and release operations are replaced as whole functions; and
3. one happy `durable-publication` path that uses real root custody,
   `persist_phase` for all five records, and `scan_journals` to parse the final
   chain, but performs no AppContainer mutation and injects a synthetic folder
   and binding.

That is materially better than Round 183's fixture, but it does not satisfy the
immutable deletion requirements in Rounds 179–183. A successful chain cannot
kill a removed flush, identity check, failure mapping, cleanup branch, or ACL
arm.

Before landing, compiled source-inclusion fixtures must behaviorally cover the
following bounded matrix:

### Durable publication and recovery

- For each USED, ATTEMPTED, CREATED, DELETE_ATTEMPTED, and ABSENCE_PROVED phase,
  fail independently at pending create, canonical write/length, file flush,
  retained-handle byte/security/file-ID readback, rename, pending absence,
  root-directory flush, close, final share-zero reopen, and prior-digest parse.
- Prove every ambiguous prefix leaves recoverable durable state, returns `70`
  once mutation ownership exists, and a clean retry reaches exactly one
  canonical chain without token reuse.
- Execute `preflight_and_recover` over malformed, forked, unknown, unreadable,
  pending-only, substituted, and mixed sorted groups. A later bad group must
  prevent mutation of every earlier valid group. Only an exact empty root and
  pre-mutation API failure may return `65`.
- Delete or replace the retained root/path and share-zero pending/final leaf at
  each publication boundary. Path/file-ID/security disagreement must refuse
  without publishing or deleting an unrelated object.

### Profile, folder, and absence control flow

- Execute the production ATTEMPTED create-or-reconcile path with create success,
  already-exists, other failure, null/invalid/wrong returned SID, target census
  disagreement, folder lookup failure, and CREATED persistence failure.
- Substitute folder wrong path, reparse/type/link/file-ID change, wrong owner,
  missing/duplicate package ACE, short/invalid/out-of-ACE SID, deny ACE,
  dangerous unknown ACE, wrong inheritance, missing/wrong/duplicate low label,
  and security drift after binding.
- Exercise delete success and failure independently from target-row and folder
  presence. No delete status may replace both absence facts, and cleanup must
  remain retryable after every partial result.

### Returning resources

- Fail actual folder, record, find, root, and process-token close arms and the
  returning SID/security/heap/BCrypt release arms. Include bind failure after a
  successful open, folder close before delete, root close after
  ABSENCE_PROVED, and multiple simultaneous failures.
- Prove all remaining releases and safe reversals are attempted even after the
  first failure, no OK is emitted, and the final reducer returns `70`.

The existing real crash diagnostics remain required; they do not replace these
deterministic failure/deletion tests. Text searches and direct calls to
`journal_record` are not substitutes for production control flow.

## Proportionality and removal result

No new Windows mechanism is warranted. Keep one private broker, SERVE/RECOVER,
PREPARE/LAUNCH/TEARDOWN, zero capabilities, five phase files, one permanent used
tombstone, shared retained root, share-zero leaves, raw target census, and the
documented AppContainer APIs. Do not add TypeScript authority, a service,
registry scan, alternate rename, guessed folder, general command, receipt, or
public schema.

The smallest next change is compiled fault injection around the existing native
OS/dependency boundary and deletion tests for the matrix above. Production
semantics need no redesign unless a deletion mutant exposes a new defect.
