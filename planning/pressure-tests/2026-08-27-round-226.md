## Remaining blocker: the two drain facts short-circuit and share one oracle

At `windows-isolation-authority.ts:739-742`, hard abort uses:

```text
Promise.all([
  bounded(reader.requireEnd(), ...),
  bounded(stderr.requireEnd(), ...),
])
```

Both promises start, but `Promise.all` rejects as soon as the first drain
refuses. `hardAbort` returns without awaiting or aggregating the other resource
outcome. TEARDOWN can begin a second abort/RECOVER while the first invocation's
other drain watchdog is still live. The second rejection is internally handled
by `Promise.all`, so this does not necessarily become an unhandled rejection;
the defect is that stable cleanup never records the complete two-resource
result it claims to own.

The fake's `omitEnd` flag suppresses both stdout and stderr end events together.
Its expectation accepts either
`broker-output-end-timeout` or `broker-diagnostic-end-timeout`. Therefore:

- deleting the stdout drain leaves stderr to satisfy the test;
- deleting the stderr drain leaves stdout to satisfy the test;
- swapping which drain fails first is not observed; and
- one failure plus a distinct second failure is never aggregated.

This is the exact simultaneous-resource mutant Round 223–225 required. It is
small, but a latest removal round cannot issue a landing disposition while one
owned control pipe can disappear from cleanup evidence.

### Smallest repair

Run both individually bounded drains through `Promise.allSettled`, wait for both
settlements, and throw one closed AggregateError containing each rejection in
fixed stdout/stderr order. Do not discard the results as the Round-224 version
did. Add separate fakes for:

1. stdout missing end with canonical stderr end;
2. stderr missing end with canonical stdout end;
3. simultaneous missing ends;
4. stdout error plus stderr timeout and the inverse; and
5. both canonical ends.

Each case must assert both drain observers were reached, the exact ordered error
census, root close before drains, and RECOVER attempted after terminal close
despite the aggregate refusal. A deletion of either drain must fail its own
case. No production protocol or authority redesign is required.
