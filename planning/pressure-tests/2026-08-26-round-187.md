## Corrected folder relation

`derive_folder` converts only the independently derived package SID to the
canonical string passed to `GetAppContainerFolderPath`. It admits only the
absolute canonical path returned by that API. `bind_folder` then opens that
exact path with read-attributes/read-control authority, `FILE_SHARE_READ`,
`OPEN_EXISTING`, `FILE_FLAG_BACKUP_SEMANTICS`, and
`FILE_FLAG_OPEN_REPARSE_POINT`. It requires a non-reparse directory, one link,
retained volume/file identity, exact security, and a digest binding those facts.
Recovery rederives the API path and requires exact path and binding equality.

The corrected real observation is the API-returned
`...\\Packages\\orch6-...\\AC` directory. Its direct package ACE is
`OICICR;FA`, where `CR` is `CRITICAL_ACE_FLAG`; its sole mandatory label is
low-integrity `OICI;NW`. The manually inspected top-level package parent is not
an input to production and cannot invalidate this relation.

Production now requires exactly one direct package allow ACE with flags
`OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE | CRITICAL_ACE_FLAG` and
`FILE_ALL_ACCESS`. It requires exactly one low mandatory-label ACE with flags
`OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE` and
`SYSTEM_MANDATORY_LABEL_NO_WRITE_UP`. `INHERIT_ONLY`, `NO_PROPAGATE`, inherited
package/label, deny, duplicate, malformed, high-label, null DACL/SACL, dangerous
unrelated inherited write, generic-write, and generic-all variants refuse.

This directory is retained OS-created profile custody and the future hostile
candidate scratch root; its contents are never evidence. This slice does not
grant execution bytes, launch a candidate, or interpret scratch contents.
