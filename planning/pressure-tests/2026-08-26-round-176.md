## Exact reduced design

1. `executionParent` is one dedicated, initially empty directory directly
   beneath already-searchable trusted system ancestry, such as a fresh child of
   `/tmp`. It is disjoint and nonnested with account, DAC, and execution state,
   helper, checkout, materialization, provider, evidence, and stable authority
   roots. A shared stable-only ancestor is not widened.
2. Its resting profile is exact `stableUid:stableGid 0700`. Before mutation,
   retain and durably bind its complete ancestor/device/inode/type/UID/GID/mode
   identity and the exact one-current-execution-root census.
3. `PREPARE` installs child grants first and the parent grant last:
   `executionParent = stableUid:<privateGid> 0710`, execution root
   `root:<privateGid> 0510`, copied Node/RPC/candidate files
   `root:<privateGid> 0550`, and scratch `<uid>:<privateGid> 0700`. Other bits
   remain zero. The parent grant permits search only: no read, listing, write,
   create, rename, delete, sibling, state, helper, checkout, provider, or stable
   authority access.
4. Stable launches only the copied runtime using the existing closed
   `sudo -n -D <scratch> setpriv ... env -i` chain and relative in-root runtime,
   RPC, and candidate names. Node's absolute canonical reopen is admitted only
   through the dedicated parent's private-group search bit.
5. After exact root/pipe terminality and UID pidfd quiescence, restore the
   execution parent first to `stableUid:stableGid 0700`. Then restore the
   root/files/scratch, remove scratch and the execution root by retained
   identity, and prove the parent empty and unchanged.
6. Every partial parent grant/restore and crash prefix remains bound by the
   existing durable DAC intent. Ambiguous mutation retains the intent and
   retries idempotently before any new principal or evidence.

The direct private-GID parent transition is smaller than a root launcher and
more complete than inherited fd/procfd paths, because Node reopens canonical
module paths. It grants one search bit on a dedicated empty parent for one
burned private group, then revokes it before cleanup. It does not expose any
stable bytes and does not change an engine-facing contract.

## Proportionality and trust sweep

- World execute on the parent is deleted because the one burned private group
  is the exact candidate set.
- A shared parent is deleted because a candidate could search sibling names.
- A new root launch helper is deleted because `sudo -D` already performs the
  bounded privileged chdir and a helper would not remove Node's canonical
  reopen requirement.
- Inherited directory descriptors and `/proc/self/fd` are deleted because Node
  still canonicalizes/reopens modules and they add handle inheritance.
- Stable runtime execution is deleted; only the copied, identity-checked runtime
  receives the private-group execute relation.
- Candidate output remains hostile semantic data. Stable owns timing,
  normalization, teardown, receipts, and every later authority decision.
