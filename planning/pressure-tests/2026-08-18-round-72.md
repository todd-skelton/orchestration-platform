## Independent attack result

### One prior record is sufficient and non-recursive

`priorCheckpointEvidence` is one closed
`pointer-mutation-run-checkpoint-evidence/v1` composition. It already contains
the prior segment and core, the selected generic
`POINTER_MUTATION_RUN_CURRENT` value/proposal/tip graph, its exact readbacks and
downstream `Dpost`, and the nullable ordinary terminal resolution required by
that checkpoint state. The existing composition equal-binds segment and core
identity, binds the selected run-current value to the recomputed `Dcore`, and
binds `Dpost` to that core plus the recomputed selector `Dp/Dt/Dv/Dr` and
readbacks.

For a positive current run ordinal, the amendment additionally requires:

- prior core run ordinal plus one equals the current run ordinal;
- prior and current target kind/path/`Dp`/mutation and complete
  installation/project/state/transaction/source identity are equal;
- prior and current `G` and selected old-authority epoch are equal;
- the recomputed prior selector `Dp/Dt/Dv/Dr` and `Dpost` are exactly
  checkpoint zero's predecessor fields; and
- the current run ID uses the recomputed prior `Dcore` as its sole nullable
  prior-checkpoint input.

Those equalities make the one record the exact immediate CAS predecessor, not
a digest-only assertion. A different record at the same ordinal changes its
core, selector, observation, current run ID, checkpoint-zero predecessor, and
`Dcommit`; copying the forged values through sibling fields cannot preserve the
selected graph and recomputed identities. Earlier checkpoint records do not
need to be recursively embedded in this non-persisted envelope: the generic
run-current predecessor chain and FULL_REQUIRED run audit remain the existing
durable lineage, while this member proves exactly the immediate hop needed by
the current run.

No digest cycle is introduced. The prior checkpoint evidence contains no
`Dcommit` and no `priorCheckpointEvidence` member. Its `Dcore` excludes its
selector and `Dpost`; the selector graph selects that core; `Dpost` is
downstream; and only the current checkpoint-zero core consumes that downstream
observation. The resulting order remains:

```text
prior segment/core -> prior selector Dv/Dr/Dt -> prior Dpost
  -> current run ID and checkpoint-zero core -> current selector graph
```

### Zero, positive, and branch semantics are closed

Every ORDINARY and every AUTHORITY_ROTATION outcome receives the same common
nullable member. Run ordinal zero requires exactly null. Every positive safe
decimal ordinal requires exactly one non-null closed prior checkpoint record
whose core ordinal is exactly one less. Omission, null at a positive ordinal,
non-null at zero, skip, reuse, reorder, partial selector tuple, stale `Dpost`,
different target, different `G`, or different old authority therefore has one
unambiguous refusal result.

The member does not widen any outcome arm. ORDINARY still has exactly nine
same-epoch checkpoints and its selected/lost/unknown resolution. Rotation still
has only selected old checkpoint 5 and its RESUMABLE/SELECTED/UNKNOWN derived
evidence; checkpoints 6–8, ordinary resolution, later selector artifacts, and
successor-epoch writes remain forbidden. Rotation UNKNOWN still has null packet
authority, null outer authority/history, an empty authority slot, and no live
capability. The nested prior evidence is structural old-run evidence already
bounded by the common old epoch; it cannot manufacture current authority or a
restart handle.

The repair does not independently authorize a restart from any selected
checkpoint. Actual continuation remains gated by the existing selected
run-current state, target reconciliation, current selected authority, kernel

including a terminal prior checkpoint, cannot issue that capability. Thus the
new member records lineage for a run admitted by the existing lifecycle; it

### Target `Dp` is derived from existing evidence

member and coordinated changes to every copied `Dp` therefore fail against the
recomputed value. No new identity member, caller-selected run ID, epoch key,
