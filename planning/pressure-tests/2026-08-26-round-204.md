## Finding 1: canonical Dlaunch fields lack an independent oracle

`fixture_admission_canonical_plan_matrix` does call the real
`admission_plan_digest` with modeled stable/integrity/package identities,
original descriptors, profile folder, execution parent/root, and fixed target
names. It independently requires nonzero Dgrant/Dlaunch digests and the exact
four creation flags, then passes the plan to real suspended creation and
cleanup.

It does not independently assert the plan's application, command line, cwd, or
environment. Fake `CreateProcessW` compares those arguments back to
`fixture_admission_launch_plan`, which is the same plan produced by the function
under test. A production mutation changes both sides of that comparison.

Concrete green mutants include:

- omit or substitute the RPC runner argument;
- use the RPC path instead of the candidate file URL;
- substitute execution root/parent for the profile scratch cwd;
- omit `TEMP`, `TMP`, `LOCALAPPDATA`, `SystemRoot`, or `WINDIR`; or
- reorder/substitute environment values while retaining canonical double-NUL
  termination.

The real native diagnostic cannot independently certify these stable expected
values; its child remains suspended and the same mutated plan creates it.

### Smallest repair

Before launch, construct an independent expected projection from the modeled
fixture inputs and fixed Windows directory: exact target-0 application, exact
three quoted arguments including the candidate file URL, exact profile cwd,
exact ordered five-key environment with double NUL, and exact flags. Compare
every plan field and `environment_units` to that projection. Then retain the
current distinct command-pointer and real create/cleanup checks.

Do not compute expected values by calling production quoting, file-URL, or
environment helpers; that would repeat the same self-comparison.

## Finding 2: outer clean-refusal result is untested

The lifecycle admission seam now returns `1` normally and `-1` for the
ambiguity scenario. It never returns `0`.

Production maps:

```text
admission  1 -> cleanup after OPWL absence, NOT_IMPLEMENTED (78)
admission  0 -> cleanup after OPWL absence, REFUSED (65)
admission -1 -> no execution/profile cleanup, RECOVERY_REQUIRED (70)
```

The current tests protect the first and third rows only. Changing
`else if (admission > 0)` to admit zero, or otherwise mapping clean refusal to
NOT_IMPLEMENTED, leaves them green. This distinction is private but meaningful:
NOT_IMPLEMENTED claims the pre-execution admission proof completed, whereas
REFUSED says it did not.

### Smallest repair

Add one lifecycle scenario whose admission seam returns zero. Require exact
execution then profile cleanup, release, status/exit 65, and no status-78 path.
Keep the existing `1` and `-1` scenarios so the three-way reducer is closed.
