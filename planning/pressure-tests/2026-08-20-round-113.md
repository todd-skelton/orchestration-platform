## Removal finding: successor chronology is not composed

The successor-origin CONSUMED path accepts structurally complete provenance,
but it does not execute the four chronology comparisons currently confined to
`validateBootstrapSuccessorActiveRetirementBinding`.

Fully rebuilt complete successor graphs, with every affected descendant
rehashed, still return `[]` for each of these invalid histories:

```text
Dsrc independent review before the actual prior owner RETIRED proposal
selected successor owner ACTIVE proposal before that independent review
Dsrp observation before the selected successor owner ACTIVE proposal
Dsrp observation after the retirement Dabs observation
```

These are not stale-fixture artifacts. Each pressure graph was rebuilt through
the complete successor selection, `E0`, `Dgse`, consumption, current CONSUMED
values, and local retirement descendants. The wrapper already receives the
actual records needed for the comparisons:

- prior owner RETIRED proposal;
- successor independent-review core;
- selected successor owner ACTIVE proposal;
- successor post-selection observation; and
- retirement absence observation.

The successor-origin branch therefore validates the structural bindings while
omitting the time-order semantics of the same provenance. This is a trust
boundary defect: a complete but impossible successor history can be admitted
as the provenance for consumed retirement.
