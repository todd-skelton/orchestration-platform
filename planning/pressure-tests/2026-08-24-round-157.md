## Descriptor production semantics

`recovery-attempt-descriptor/v1` is implemented as one LIVE-only record with
the exact eight fields in ascending canonical member order:

```text
attemptId
lifecycle
processStartObservationDigest
reservationPredecessorKey
reservationTipDigest
schemaVersion
sourceToken
transactionId
```

The parser snapshots input before semantic reads. It requires UUIDv7 attempt
and transaction identities, SHA-256 process observation, reservation key, and
reservation tip digests, exact schema v1, lifecycle `LIVE`, and exactly the two
registered recovery sources. READY, READY_ONLY, TERMINAL, UNKNOWN, TOMBSTONE,
unknown source spellings, malformed digests, malformed IDs, nulls, numbers,
missing members, and renamed members refuse.

The exported lifecycle type is exactly `"LIVE"`, and the committed
`@ts-expect-error` proves `READY_ONLY` is not assignable. The public lifecycle
array is exactly `['LIVE']`.

The descriptor's exact path is:

```text
installation/activation-recovery-launches/<transactionId>/<sourceToken>/
attempts/<attemptId>/descriptor.json
```

The path helper parses the exact descriptor first, so malformed identity or
source values refuse before interpolation. The baseline pins the exact path and
independently changes attempt, source, and transaction. Isolated mutants fixing
each path component to the original fixture were killed by those movement
cases. The same three record changes also alter `Ddescriptor`, proving detached
bytes cannot move without changing identity.

The sole descriptor digest is correctly implemented as one canonical record
part under domain `recovery-attempt-descriptor/v1`. Canonical bytes and the
exact tagged golden are pinned. The digest differs from the untagged canonical
digest. Generic serialization returns the exact existing success shape with
canonical bytes and `Ddescriptor`; canonical-byte parsing accepts exact bytes
and refuses reordered JSON.

Isolated mutations of the digest domain and generic serializer branch were
killed. Removing the descriptor schema version from `schemaVersions` was also
killed by canonical parsing and public-version assertions. Hostile reflective
descriptor input returns parser failure without throwing; digest and path
helpers convert invalid input to their normal exception refusal.

## OP-R157-1 — pure-added descriptor members are not closure-discriminated

The test named “closes every member and scalar” removes each member, replaces
it with null or number, and renames it. A rename is implemented by deleting the
original field and adding a renamed field. Therefore it simultaneously creates
a missing required member and an unknown member.

An isolated source mutant removed only the parser's unknown-member issue while
retaining required-member checks and every scalar check. All six descriptor
tests passed. The renamed cases still refused because the original field was
missing, not because the renamed field was unknown. No test supplies all eight
valid members plus a ninth extra member.

This is a definite closure evidence gap. The descriptor ledger and acceptance
item 23 separately require **add** and **rename** attacks and deletion of every
closure check to fail. The smallest repair is one focused case such as:

```text
parseRecoveryAttemptDescriptor({ ...descriptor, extra: true }).ok == false
```

That case isolates unknown-member closure without changing any required scalar.
No parser rewrite or additional snapshot layer is needed.

## Crash-constructible reservation locator

The new `recoveryAttemptReservationPathFromPredecessorKey` helper is the
correct proportional addition for descriptor-before-IN_PROGRESS crash
recovery. Its intended closed input is exactly:

```text
reservationPredecessorKey: sha256
sourceToken: cleanup-gate-pre-fence | recovery-fence
transactionId: uuid-v7
```

It constructs exactly:

```text
installation/activation-recovery-launches/<transaction>/<source>/
reservations/<reservationPredecessorKey>.json
```

No directory enumeration, latest-file rule, reverse `Dt` lookup, global index,
caller path, attempt ID, or filesystem access is introduced. Together with
`reservationTipDigest`, the descriptor has the minimal structural pair needed
for later composition: transaction/source/key reconstruct reservation path and
`Dp`, and `Dt` selects the exact RESERVED snapshot.

The older `recoveryAttemptReservationPath(predecessorEvidence)` now delegates
to the new helper using its independently computed tagged predecessor key. The
focused test recomputes a selected predecessor key, constructs the new-helper
path, and requires byte-identical equality with the older evidence helper.
Severing that delegation by fixing the older helper's key was killed by the
descriptor equality and the reservation-identity alternate-path evidence.

The new helper validates malformed key, source, and transaction values. A key
change alters its output. Its key-input deletion mutant was killed by the
explicit alternate-key assertion.

## OP-R157-2 — the new helper's exact three-field closure is not tested

No test supplies an extra, renamed, missing, null, or numeric member directly
to the new helper as a closed input record. The three invalid cases retain all
three expected fields and change only one scalar to the string `bad` or source
`none`.

An isolated mutant projected the three expected properties into a fresh object
before calling `snapshotClosedRecord`. That mutant preserves missing/scalar
behavior but silently discards every unknown fourth field. All six descriptor
tests passed.

This violates the requested exact three-field closure and permits future
callers to treat proof-bag additions as harmless locator input. The smallest
repair is a focused matrix over the helper itself:

- all three valid fields plus `extra: true` refuses;
- each missing field refuses;
- each null and numeric field refuses; and
- a renamed field with the original removed refuses.

The pure-extra case is the deletion discriminator; the remaining cases pin
the public input contract and type behavior cheaply.

The test changes descriptor source and transaction, but those loop iterations

`computeRecoveryAttemptDescriptorDigest`. They do not call
`recoveryAttemptReservationPathFromPredecessorKey` with moved valid context.

Two isolated helper mutants therefore survive:

| Mutant | Focused descriptor result |
| --- | --- |
| Parent source fixed to `recovery-fence` after validation | 6/6 PASS |
| Parent transaction fixed to the fixture UUID after validation | 6/6 PASS |

Invalid source/transaction cases do not kill these mutants because the local
validators still reject `none` and `bad` before path construction. The one
valid helper golden uses the same fixed fixture values, and the key-only
sensitivity case changes no context.

The smallest repair mirrors the already-cleared reservation-identity path
evidence:

1. call the helper with `cleanup-gate-pre-fence` and require the exact whole
   path with that source and the unchanged transaction/key; and
2. call it with `otherTransactionId` and require the exact whole path with that
   transaction and unchanged source/key.

Exact equality is required. A broad inequality could be confounded if another
path component changed.

## OP-R157-4 — vocabulary registry definition deletion survives

The implementation correctly adds both descriptor registration surfaces:

- `recoveryAttemptDescriptorSchemaVersions` enters `schemaVersions`, which
  drives compatibility/canonical dispatch; and
- `schemaVocabularyDefinitions['recovery-attempt-descriptor/v1']` records the
  exact fields plus closed LIVE literal for vocabulary lint.

The first is deletion-discriminated. Removing the schema-version spread caused
the focused canonical parsing and public-version assertions to fail.

The second is not. An isolated mutant deleted only the descriptor vocabulary
definition and ran both descriptor and vocabulary tests. All eight tests
passed. Vocabulary lint cannot inspect a contract that has silently
disappeared from its census, and the descriptor test asserts exported fields
and `schemaVersions` but never the vocabulary definition.

The smallest repair asserts that the descriptor vocabulary entry exists, uses
the exact exported eight-field census, and has closed value `LIVE`. That kills
registry deletion and prevents the engine vocabulary denylist from being
silently bypassed by omitting this public contract from the lint census.

## Trust, acyclicity, and scope

The descriptor contains only opaque engine identities. A SHA-shaped
`processStartObservationDigest` is not process evidence by itself. Later
ISS-005/ISS-030 composition must parse authenticated observation bytes, prove
native arguments, installed-definition read-back, process-tree/start facts,
and compare its sole start time against selected reservation `recordedAt`.

The descriptor copies no unauthenticated timestamp, raw argv, executable/shim
path, declared user, PID, process tree, installation definition, attachment,
reservation `Dp/Dv/Dr`, release/gate/fence/predecessor triple, authority epoch,
launch-definition digest, or descriptor-input digest.

The graph remains acyclic:

```text
prior terminal/genesis
  -> selected RESERVED
  -> process-start observation
  -> immutable LIVE descriptor
  -> future selected IN_PROGRESS log
```

Neither descriptor nor current attempt log enters its own reservation key. The
new locator is pure path construction and performs no enumeration or IO.

No observation producer, launch value, attempt log, attachment, archive,
tombstone, selected-family/currentness composition, persistence, proposal/CAS,
capability, process operation/adoption, broker call, command, package, runtime
service, release review, or promotion route appears in the delta.

A descriptor, reservation key, tip digest, observation digest, parser result,
or candidate-created bytes cannot certify itself. Only stable external
authority and later authenticated composition can grant mutation or process
adoption. Candidate output is never routed into its own promotion.

No Git, GitHub, repository, consumer, provider product, endpoint, credential-
store, operating-system secret, or adapter vocabulary enters the engine
record.
