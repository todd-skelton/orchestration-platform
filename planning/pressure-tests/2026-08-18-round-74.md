## Independent attack result

### One rotation run is compatible with durable recovery

Rotation's run ID is deterministically recomputed from `G`, the exact target
mutation, ordinal zero, null prior checkpoint, and the selected old-authority
`Dp/Dt/Dv/Dr`. After a crash, the create-once intent, selected checkpoint-5
run-current graph, and exact head-plus-one ROTATION record still name that same
run and transaction. Process death revokes the old in-memory handle, but it
does not require or authorize a new durable run record. After reacquiring the
kernel lock, ISS-004 may issue only the purpose-bound old-epoch context for the
matching transaction and re-drive the already-armed CAS.

A purported second checkpoint-5 run cannot acquire a distinct identity while
preserving those inputs: another run ID is rejected by recomputation, and a
different transaction or mutation no longer matches the selected armed intent,
pending record, expected successor, or target CAS. A positive rotation ordinal
would name a new run but is forbidden by the branch before `Dcommit` or packet
use. Thus the single-run rule neither conflicts with create-once durable paths
nor turns same-transaction resume into a new authority route.

### Ordinal and prior-evidence branches are closed

ORDINARY remains unchanged: ordinal zero requires null prior evidence; every
positive safe canonical decimal requires the complete selected checkpoint
evidence of ordinal minus one. The recomputed prior `Dcore`, selector
`Dp/Dt/Dv/Dr`, and `Dpost` feed the current run ID and checkpoint-zero
predecessor, while exact target, platform, transaction, source, `G`, mutation,
and old epoch equalities prevent skip, reuse, reorder, or coordinated copying.

Every rotation outcome—RESUMABLE, SELECTED, and UNKNOWN—requires literal
ordinal zero and null prior evidence. Ordinary prior evidence cannot be
smuggled into any arm because non-null is rejected by the common branch rule
before outcome validation. Positive values, copied positive values, the safe

signed, padded, fractional, numeric, non-decimal, or above-safe-range values
also fail the shared `safe-decimal` parser before conversion or comparison.
