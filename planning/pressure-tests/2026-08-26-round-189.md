## Why this slice is next

The landed broker already owns the only durable Windows profile lifecycle and
retains the fresh package SID and profile-folder handle across PREPARE. Round
175 orders immutable execution construction before package grant and before
atomic launch. Copying into a stable-only root can be completed and recovered
without an AppContainer token, a candidate process, timing, or Job Object.

The other candidate boundaries are not independently complete:

- a helper-custody caller built against today's profile-only PREPARE would
  freeze an obsolete request/response and still could not prepare executable
  bytes;
- a DACL-only slice could leave candidate-readable executable bytes without an
  actual-token probe or process containment;
- token probes require the actual suspended process created with
  `SECURITY_CAPABILITIES`; and
- a Job Object without the same atomic child creation does not remove the
  pre-assignment execution window.

The native copy lifecycle is therefore the smallest constructible correctness
dependency. The stable caller/helper custody follows once this final PREPARE
shape exists; DACL plus atomic suspended launch/token/job proof follows that.

## Exact protocol change

The outer 16-byte OPWB framing, two process modes, and three operation opcodes
remain unchanged. SERVE PREPARE replaces the profile-only payload with this one
closed execution-prepare value:

```text
magic:"OPWE" | version:u8=1 | arm:u8=1 | reserved:u16=0 |
stateRootUnits:u16le | executionParentUnits:u16le |
runtimePathUnits:u16le | rpcPathUnits:u16le | candidatePathUnits:u16le |
reserved:u16=0 |
stateRootUtf16LE | executionParentUtf16LE | runtimePathUtf16LE |
rpcPathUtf16LE | candidatePathUtf16LE
```

The fixed header is 20 bytes. Each count is `1..1024`; every path is canonical
normalized absolute extended-DOS `\\?\\C:\\...` form under the existing path
rules, and the outer payload length equals exactly 20 plus twice the five count
sum. There is no NUL, optional field, alternate order, trailing byte, UNC,
volume-GUID, device, relative, dot, dot-dot, empty-component, alternate-stream,
wildcard, surrogate, or second arm.

SERVE no longer admits profile-only OPWP PREPARE. RECOVER continues to accept
only the existing OPWP state-root scope on TEARDOWN; it obtains execution paths
only from authenticated canonical journals. LAUNCH and SERVE TEARDOWN retain
zero payload. No caller supplies a token, moniker, SID, target root, target
filename, hash, file ID, phase, or deletion path.

PREPARE/OK changes from OPWR arm 1 to arm 2 and appends to the existing profile
identity fields:

```text
executionRootPathUnits:u16le | executionRootPathUtf16LE |
executionBindingDigest:32
```

The payload is opaque stable-parent data. It is not candidate input and cannot
parse as a portable result, receipt, authority, or timing claim.

## Parent, source, and target custody

The broker opens and retains the execution parent and source files before the
first execution mutation. For every admitted path it requires final-handle path
equality, a fixed local volume, no reparse point, one link, and stable identity
before and after each use. State root and execution parent must be distinct and
nonnested. The three sources must be mutually distinct by path and volume/file
ID and must lie outside both mutable roots. The execution parent must be empty
before construction.

The execution parent and all sources have exact protected stable/SYSTEM-only
security: stable user owner, stable user and SYSTEM full-control allows, the
stable token's exact mandatory label, and no deny, inherited, package,
capability, broad, or additional ACE. Each source is a regular non-reparse file
with exactly the unnamed data stream, one link, nonzero length, and length at
most 512 MiB. The uniform bound is deliberately above the reviewed Node 24
runtime and bundled candidate/RPC inputs while bounding disk, hash, and recovery
work. Copying is streaming; no whole-file allocation is permitted.

The root name is derived internally and exactly:

```text
orch6-execution-<64 lowercase token hex>
```

It is one direct child of the retained execution parent. Its only children are:

```text
node.exe
rpc-runner.mjs
candidate.mjs
```

The root and files are created with exact protected stable/SYSTEM-only security
and no package SID ACE. The broker uses create-new/no-replacement operations,
noninheritable handles, no write/delete sharing, write-through file creation,
bounded streaming copy, file flush, parent/root directory flush, and independent
retained-handle readback. Source-before/source-after and destination digests,
sizes, identities, stream censuses, attributes, links, and security must agree.
The final root census is exactly the three fixed files.

Define private domains over canonical length-prefixed UTF-16 paths and detached
security/identity bytes:

```text
Dsource(role) = SHA256("op.windows-execution-source/v1\0" ||
                       role || path || volume/file ID || attributes || links ||
                       security || size || SHA256(bytes))

Dtarget(role) = SHA256("op.windows-execution-target/v1\0" ||
                       role || fixed path || volume/file ID || attributes ||
                       links || security || size || SHA256(bytes))

Dexecution = SHA256("op.windows-execution-root/v1\0" || token ||
                    parent path/identity/security || root path/identity/security ||
                    Dsource(runtime,rpc,candidate) ||
                    Dtarget(runtime,rpc,candidate))
```

These are private recovery bindings, not portable contract digests.

## Durable execution records

The existing OPWJ profile records remain byte-for-byte and semantically
unchanged. Add a disjoint flat OPWX namespace under the same retained state
root, using the same create-exclusive pending write, file flush, state-root
flush, readback, no-replace publication, final readback, and ambiguity rules:

```text
windows-execution-<Htoken>-00-attempted.opwx
windows-execution-<Htoken>-01-created.opwx
windows-execution-<Htoken>-02-delete-attempted.opwx
windows-execution-<Htoken>-03-absence-proved.opwx
```

Each record is canonical:

```text
magic:"OPWX" | version:u8=1 | kind:u8=1..4 | reserved:u16=0 |
totalLength:u32le | token:32 | priorDigest:32 | Dstate:32 |
profileCreatedDigest:32 |
executionParentPathUnits:u16le | executionParentPathUtf16LE |
parentBinding:32 | executionRootPathUnits:u16le | executionRootPathUtf16LE |
sourceBindings:3*32 | rootBinding:32 | targetBindings:3*32
```

ATTEMPTED contains the three nonzero source bindings and exact parent/root
paths, but zero root/target bindings. CREATED and later kinds contain all exact
bindings. `priorDigest` is zero only for ATTEMPTED and otherwise hashes the exact
preceding OPWX record. Every final phase remains as a never-removed tombstone.
The record binds the exact existing PROFILE_CREATED record digest; an orphan,
wrong token/state/profile predecessor, duplicate, fork, gap, malformed pending,
or execution record paired with USED/ATTEMPTED refuses before mutation.

ATTEMPTED must be durable before directory creation. CREATED must be durable
before PREPARE/OK. DELETE_ATTEMPTED must be durable before the first delete.
ABSENCE_PROVED follows exact child/root absence and a successful execution-
parent durability barrier. A lost write, close, flush, rename, readback, delete,
or absence response retains the latest durable prefix and reports recovery
required.

## Crash-prefix cleanup and composition

All OPWJ and OPWX groups are parsed, paired, and sorted before any recovery
mutation. Existing terminal profile-only groups remain valid. A PROFILE_CREATED
group with no OPWX record means execution mutation was not authorized and may
proceed directly to profile cleanup. Once ATTEMPTED exists, execution cleanup
must complete before profile deletion.

ATTEMPTED recovery admits only an absent root or one stable/SYSTEM-only root
containing a subset of the three fixed stable-only children. It follows no
reparse point, deletes no unknown entry, and trusts no partial content. This
bounded partial admission is safe because the durable intent precedes creation,
the parent is exact and stable-exclusive, and this slice never grants the
package SID access.

CREATED and DELETE_ATTEMPTED recovery require the exact persisted root and
target identities/bindings. Cleanup reopens each current pathname no-follow,
compares it with the retained object, rejects aliases/replacements/extra streams
or entries, deletes the exact child through its handle, then deletes the exact
root through its retained handle. It rechecks parent, state root, and every
remaining retained handle before and after each boundary. Every handle close is
checked; ambiguous close retains recovery state.

The mandatory order is:

```text
PROFILE_CREATED
  -> EXECUTION_ATTEMPTED
  -> root/files constructed and independently verified
  -> EXECUTION_CREATED
  -> PREPARE/OK
  -> EXECUTION_DELETE_ATTEMPTED
  -> child handles/paths absent
  -> root handle/path absent
  -> execution-parent flush/readback/absence
  -> EXECUTION_ABSENCE_PROVED
  -> PROFILE_DELETE_ATTEMPTED
  -> PROFILE_ABSENCE_PROVED
```

Failure stops later phases. Profile deletion before execution absence, an
execution record paired to a terminal profile without execution absence, or an
active in-memory lifecycle offered to RECOVER refuses. EOF and malformed output
after any profile/execution mutation execute the same ordered cleanup and can
return ordinary refusal only after both absence chains are durable.

  partial/short read or write, source mutation between reads, target byte/hash/
  size/identity/security disagreement, file/root flush loss, and directory
  substitution;
- every ATTEMPTED/CREATED/DELETE_ATTEMPTED/ABSENCE_PROVED pending/final
  publication fault; orphan/fork/gap/duplicate/corrupt/cross-token/cross-state/
  wrong-profile pair; and whole-set preflight proving zero mutation on a late
  malformed group;
- crashes after intent, root creation, each file create/write/flush, CREATED
  mutation/readback, before/after each child delete, root delete, parent flush,
  and absence publication; clean reconstruction must recover or retain an exact
  refusal prefix;
- ATTEMPTED subset cleanup, CREATED exact cleanup, unknown/extra/reparse/stream/
  replacement refusal, root-before-child mutant, profile-delete-before-
  execution-absence mutant, every retained-handle close failure, and successful
  retry after each ambiguous terminal barrier; and
- proof that package SID access is never added, LAUNCH remains NOT_IMPLEMENTED,
  the broker remains private/unexported, and no fixture result can become a
  receipt or promotion input.

The opt-in real Windows diagnostic must use the exact tracked PE and external

security, and finish with exact empty execution parent, profile row/folder
absence, and no `orch6-` or temporary test residue. It does not run the copied
Node or emit hosted evidence.

## Proportionality and removal table

| Retained mechanism | Concrete threat | Required deletion test | Smaller alternative and conclusion |
| --- | --- | --- | --- |
| Same native broker and OPWX intent before mkdir | Crash or lost response leaves an unowned executable root while profile cleanup proceeds | Pause/fail every publication and creation prefix; later profile delete must not run | TS state or process exit cannot establish native mutation; the paired four-phase journal is the smallest complete recovery owner |
| Retained source/destination handles and independent byte/profile readback | Path substitution or partial copy changes executed bytes after stable selection | Source/target alias, movement, short I/O, hash/size/security/stream drift | Path strings or one hash pass miss races; one retained-handle double-read is the smallest credible copy proof |
| Stable/SYSTEM-only root with fixed three-file census | A premature package grant exposes incomplete or attacker-added executable input | Add package/broad ACE, extra file/stream, wrong name/type/link | Installing the future DACL now widens risk; stable-only custody is both smaller and independently complete |
| Handle-bound ordered cleanup before profile deletion | Replaced paths, partial roots, or early principal deletion escape recovery ownership | Replacement, reparse, extra entry, root-first and profile-first mutants | Recursive path deletion is broader; fixed retained objects are the least destructive cleanup set |
| Actual-token probes deferred to atomic launch | A synthetic/package-only check falsely predicts composite-token access | Later test must kill omission of every suspended-token/access field before resume | No valid smaller prelaunch token exists; omission is safer than a misleading corroboration layer |

No retained mechanism serves a hypothetical consumer. This slice is consumed by
the Round-175 DACL/atomic-launch dependency and uses the existing private broker
and bundle footprint.
