## Complete repaired-ledger re-audit

The exact IN_PROGRESS census is nine sorted members; TERMINAL is exactly those
nine plus six branch-only members in their sorted positions. Branch-only
members are absent, never null. Genesis is IN_PROGRESS at ordinal `"0"` with
null predecessor. Positive ordinals have one SHA-256 predecessor and are
bounded canonical decimals. Every later edge requires `Dattempt(prior)`,
adjacent ordinal, inclusive time, and one of only
IN_PROGRESS→TERMINAL or TERMINAL→IN_PROGRESS.

Same-attempt terminalization preserves transaction, source, attempt ID, and
descriptor. A later IN_PROGRESS preserves transaction/source, uses a globally
fresh attempt ID, and may bind its new descriptor. The supplied-chain validator
checks a prior-ID set only when admitting IN_PROGRESS, so it accepts
`I(A),T(A)` and rejects non-adjacent `I(A),T(A),I(B),T(B),I(A)` without using
UUID time as order.

The pure validator honestly returns a valid nonempty supplied prefix. It has no
lookup/fullness/currentness input and therefore makes no such claim. Later
ISS-004 composition alone compares its final supplied record to the
authenticated selected current value under a live handle, which is the fact
that can reject a valid truncated suffix or noncurrent prefix as FULL_REQUIRED
`UNKNOWN`.

The standalone record digest is exactly one domain-separated canonical-record
part:

```text

```

Canonical bytes already commit lifecycle, ordinal, and nullable predecessor;
no repeated tag, bounded-decimal frame, or predecessor raw-32 frame remains in

Each standalone path is constructible from its parsed transaction, source,
attempt, ordinal, and lifecycle. The common transaction/source attempt-log

second head. The exact VALUE position is `{mode:"VALUE",parts:{}}`; archive and
