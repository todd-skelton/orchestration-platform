## Exact census, canonical order, and branch closure

Each branch has exactly these five required, non-null members in ascending
canonical JSON member order:

```text
operationId:uuid-v7
recordedAt:timestamp
schemaVersion:recovery-authorization-consume-receipt/v1|recovery-authorization-revoke-receipt/v1
selectedStateTipDigest:sha256
transactionId:uuid-v7
```

The schema member is branch-local. A consume record admits only
`recovery-authorization-consume-receipt/v1`; a revoke record admits only
`recovery-authorization-revoke-receipt/v1`. The otherwise identical shapes do
not make the distinction redundant: the literals select different digest
domains and later lifecycle/operation equalities. A common schema would need a
replacement kind member or an unauthenticated caller-selected branch.

Each remaining field has one separate role:

- `operationId` is a canonical UUIDv7 input to the receipt's own path and the
  later branch-specific operation equality.
- `recordedAt` is the distinct durable receipt-creation observation time.
- `schemaVersion` closes the record, selects the branch, and selects the digest
  domain.
- `selectedStateTipDigest` is the minimum direct identity of the exact selected
  tip read back after selection.
- `transactionId` is a canonical UUIDv7 input to the receipt's own transaction
  root and the later selected-state transaction/path equality.

Deleting any of these loses a distinct closure, path, time, or selected-
observation property. Adding `Dp`, `Dv`, `Dr`, core, gate, native-receipt,
lifecycle, mode, generation, or disposition would copy facts whose sole source
is the actual selected graph. The repair therefore reaches the smallest closed
record that preserves the stated outcome.

identify which exact selected-tip read-back they observe. The own transaction
and operation IDs locate the receipt; they do not identify the selected
snapshot. One selected-tip digest is the smallest direct observation.

## Acyclicity, including the later REVOKED edge

The complete ordering remains a strict chain:

```text
native consume Dnc -> selected CONSUMED Dp/Dv/Dr/Dt -> consume post Drcp
consume post Drcp -> selected REVOKED Dp/Dv/Dr/Dt -> revoke post Drrp
native removal Dnr ------------------------------^
```

No native receipt, core, gate, selected state, selecting proposal, or selected
tip contains its downstream post-selection receipt digest. A later REVOKED
state may carry the already-fixed consume post-selection digest `Drcp`; its
`Dv`, selecting `Dr`, and `Dt` are then downstream of `Drcp`. The revoke post
receipt `Drrp` is created only after that REVOKED tip is selected and never
enters the REVOKED preimage. The graph is therefore
`Drcp -> REVOKED Dt -> Drrp`, not a cycle.

Deleting copied `Dp/Dv/Dr` preserves the order. Receipt `Dt` commits only facts
already fixed upstream by that selection; neither post-selection receipt is
made an upstream member of its own selected state.
