### `OP-R57-001` — `workerHostIdentityDigest` has shape but no exact identity contract

The governing ledger defines an exact three-member
`worker-host-renderer-artifact/v1` row and says both members ending in `Digest`
are SHA-256. It exactly defines `hostRendererArtifactDigest` as SHA-256 of the
host package artifact containing the compiled renderer table and fixed template
bytes. It never defines what bytes, record, framing domain, or stable reviewed
registration produces `workerHostIdentityDigest`:

- the mapping is keyed and deduplicated by that value;
- route selection uses it to choose the row;
- step 7 and `dispatch-plan/v1` bind it;
- ISS-021 and ISS-045 merely say their builds emit it, and their proposed
  "identity digest-equality" checks have no normative expected preimage;
- no current contract source, test, host registration, or other governing
  document defines the value outside the repaired prose.

Consequently two implementations may hash the package name, a host descriptor,
the whole package artifact, or an implementation-selected token and all satisfy
the stated SHA-256 grammar. A coordinated identity substitution across host
output, reviewed mapping, route, and dispatch plan is not discriminated by an
executable formula; if the identity is intended to equal the package digest,
the two-member mapping is redundant and that equality is also unstated. Opaque
to the engine does not mean undefined at its producing boundary.

Bounded repair: define one exact, provider-neutral identity source and digest
formula in the decision ledger—member census, canonical/framed preimage,
domain, version/stability rule, and exclusions—or reuse one already reviewed
stable host-registration digest and name that equality. Cross-bind the exact
host producer output, static host registry, release-manifest row, route output,
and step-7 plan. Add byte/domain/order, moved-registration, coordinated
identity/artifact swap, and cross-host substitution mutants. Keep the identity
opaque in engine contracts. Do not add a dynamic resolver, provider name,
second registry digest, path, or network lookup.

Bounded repair: amend ISS-012's scope/acceptance and producer-consumer census so
