## Fixture worker host wait remains non-authoritative

For real worker-thread handles only, `fixture_admission_WaitForSingleObject`
now passes:

```c
max(protocol_remaining, TERMINAL_CLEANUP_MILLISECONDS)
```

to the host `WaitForSingleObject`. This prevents a contended Windows test host
from expiring a real fixture worker at a tiny synthetic remaining interval.

It does not weaken the modeled protocol:

- the change is compiled only through the fixture macro substitution;
- the production PE and source hashes are unchanged;
- process and Job handles retain their fixed fixture observations rather than
  this host wait;
- all watchdog decisions still come from the fake authenticated stable clock
  read by production `terminal_remaining_before`;
- scheduled wait failures are still returned after the real fixture wait;
- the real wait result is still propagated, so a genuinely nonterminal fixture
  worker fails rather than being certified; and
- no expected result, hard-abort relation, owner census, or mutation assertion
  was relaxed.

The maximum is bounded at the existing 5,000 ms cleanup constant. It is not an
unbounded sleep, candidate-controlled duration, or production fallback.

## Test-local outer bounds are proportional

The two native compile tests now each have a Vitest-local 120,000 ms outer
timeout. Their test bodies, compilation flags, exact-source inclusion,
executable status/stdout/stderr assertions, and cleanup remain unchanged.

The outer bound is only a host scheduling allowance. It does not alter the
broker's five-second stable watchdog, fixture fault schedules, real diagnostic,
or any acceptance relation. A hung compile or executable still fails at a
finite bound.

## Round-216 removal evidence remains discriminating
