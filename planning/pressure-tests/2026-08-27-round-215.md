## Clean exact buffer-ownership oracle

The three buffer modes now prove the required closed relations after production
`release_terminal_buffers` executes:

- stdout failure: stdout equals its originally captured allocation; stderr is
  null;
- stderr failure: stdout is null; stderr equals its originally captured
  allocation; and
- simultaneous failure: both worker fields equal their corresponding original
  allocations.

Every case additionally requires one free attempt for each sibling. Successful
free counts are one, one, and zero respectively. Hard abort, resource ambiguity,
and zero persist/cleanup/restore calls remain mandatory. An unconditional null
after failed free, swapped owner, skipped sibling free, or nominal-but-unreached
simultaneous fault now fails.

The later fixture-only cleanup runs after the validity decision and therefore
does not launder these exact assertions.

## Sole blocker: post-wait deletion still produces the same full-run trace

Fixture clock modes 9 and 10 execute this intended schedule:

```text
start = 100
process-wait precheck = 5,099  # elapsed 4,999
signalled process wait
process-wait postcheck = 5,100 or 5,101
```

With production unchanged, the postcheck returns timeout. `run_active_terminal`
then kills/joins and reproves the Job before returning canonical empty TIMEOUT.
That is useful positive coverage.

It is not a deletion oracle for the post-wait call. If the
`terminal_remaining_before` call after `WAIT_OBJECT_0` is deleted, the process
wait returns success and worker 0's immediately following pre-wait check
consumes the same third clock value, 5,100 or 5,101. It selects the same timeout
path. Cleanup uses the same later clock values, and the fixture asserts neither
which handle reached timeout nor a direct helper return. The result, terminal
kind, hard-abort state, buffer counts, and cleanup outcome are identical.

`rg` confirms `terminal_wait_before_deadline` is invoked only by production
`run_active_terminal`; there is no direct fixture call. No current wait-handle
census distinguishes the process postcheck from worker 0's precheck.

Smallest repair: directly call the real static
`terminal_wait_before_deadline` with the signalled fixture process and a clock
schedule whose two reads are exactly 4,999 -> 5,000, then 4,999 -> 5,001 elapsed.
Require return zero in both cases. Keep modes 9/10 as the complementary proof
that a detected timeout completes trusted kill/join/Job-zero cleanup before an
observation.

This adds no production branch, timer, worker, protocol field, or journal kind.
