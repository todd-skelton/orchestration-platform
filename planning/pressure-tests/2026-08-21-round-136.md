## Tagged identities and generic serialization

The exact implementations are one-part framed digests:

```text
Drcp = SHA256(frame("recovery-authorization-consume-receipt/v1", canonical consume bytes))
Drrp = SHA256(frame("recovery-authorization-revoke-receipt/v1", canonical revoke bytes))
```

Each digest helper first invokes its branch parser and throws on cross-schema
input. It then calls `framedDigest` with the exact literal branch domain and one
`frame.canonical(parsed.value)` part. There is no raw JSON, untagged canonical
hash, field-wise frame, common pointer `Dv`, caller-provided domain, or fallback
inside either helper.

The exact digest goldens are:

```text
Drcp = e31cf3511d29134cd7c1a6ac4eb5efbf4d16124b478477d0c70703ed63f39e92
Drrp = 313d469d3ab729c5a5bb1d8129f2588b81023fd433e47b874e36397c0ef8af81
```

Both differ from their untagged canonical digests and from each other. Those
goldens kill domain deletion, domain swap, framing-shape change, and common-tag
mutants. Cross-branch calls throw, which additionally kills digest route
confusion.

`serializeContract` dispatches the two exact schema literals only after the
generic parser has returned the closed parsed value. Each route returns the
existing exact `{ ok: true, bytes, digest }` arm, with canonical bytes and its
corresponding tagged digest. The committed serializer assertions compare the
complete result objects. Deleting either schema-specific route falls through to
`canonicalDigest` and fails because each tagged golden is explicitly unequal to
that fallback. Swapping routes or tags fails the pinned result digest.

The resulting graph remains a strict order:

```text
native consume Dnc -> selected CONSUMED Dt -> consume post Drcp
consume post Drcp -> selected REVOKED Dt -> revoke post Drrp
```

REVOKED selection receipt and never enters that REVOKED preimage. There is no
self-cycle and no route by which structural bytes certify their own upstream
selection.
