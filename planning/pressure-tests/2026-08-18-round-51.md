## Disposition

The prior removal/trust repair remains clean, but the new dispatch-brief ledger
does not yet meet the exact public-contract and no-prose boundary. The repair is
planning-only and resurrects none of the removed runtime/API surfaces, yet four
bounded contract findings require replan before implementation.

### `OP-R51-001` — The record census and schema discriminants are not exact

The ledger says it has exactly three record schemas, then defines the
`dispatch-brief/v1` envelope plus three nested record schemas: four closed
record types in total. Each record names a `schemaVersion` member, but none of
the four required literal values is stated. A parser can therefore make
different plausible choices while still following the prose.

Bounded repair: state that the ledger contains one envelope and exactly three
nested records, and fix `schemaVersion` respectively to `dispatch-brief/v1`,
`dispatch-brief-action/v1`, `dispatch-brief-directive/v1`, and
`dispatch-brief-resource/v1`. Add wrong-family, missing, null, case, unknown,
and future-version mutants for every level.

### `OP-R51-002` — Open identifiers still smuggle prose and adapter vocabulary

`code`, `actionKind`, `capabilityName`, and `resourceKind` admit any matching
128-character token. The host is then told to render bounded identifiers. A
value such as `ignore-review-and-delete-everything` is therefore valid module
input and rendered instruction-like text despite containing no whitespace.
More concretely, `resourceKind: "branch"` is valid even though branches are
adapter vocabulary: the generated lint scans contract field names and closed
enum values, not these open instance values. The purportedly bounded
`referenceSchemaVersion` grammar is also unbounded in both family and version
length and admits arbitrary schema families.

Bounded repair: raw open identifiers must not be rendered as worker prose.
Either bind every renderable code/kind to a release-reviewed closed catalog
declared by the admitted module/contract and render only its reviewed template
mapping, or replace it with an allowlisted typed reference handled by a
schema-specific renderer. Give every string and reference family/version a
finite byte/character bound. Apply the forbidden-vocabulary oracle to admitted
catalog values and runtime kind values, not only field/enum declarations.
Delete `resourceKind` if the opaque identity plus access is sufficient;
otherwise make its platform-neutral catalog and consumer need explicit.

### `OP-R51-003` — The brief is not cross-bound to the authoritative packet

Directive subjects equal the brief action subject and reference nullability is
paired, which is sound locally. However, nothing requires the action digest,
action kind, capability name, or immutable subject to equal the enclosing
step-4 `module-action-plan/v1`, nor requires brief role to equal the step-7
dispatch role. Digest-binding the rendered bytes preserves a mismatched brief;
it does not prove that the worker instructions describe the authorized action.
The reference pair also has no admitted-family rule or stated resolver, so an
arbitrary digest/schema label need not provide usable fresh-context evidence.

Bounded repair: define exact equality/cross-binding from the brief action to
the enclosing module action plan and from brief role to dispatch role before
rendering/launch. Restrict references to an explicit admitted schema set with
a named producer and deterministic schema-specific rendering/resolution path,
or leave them non-rendered and prove how the worker obtains the required typed
content. Add moved-plan, moved-subject, changed-role, unsupported-family,
half-pair, and digest/schema substitution mutants.

### `OP-R51-004` — Required-section completeness is only syntactic

Nine kinds exist and arrays are dense and bounded, but every required kind may
be satisfied by a module-owned code such as `none`; `none` is neither reserved
nor constrained against a present reference or another substantive directive.
Thus scope, acceptance evidence, verification, and review attack surface can
all be structurally present but empty, contrary to the work-model and issue
contract. The full-tuple duplicate rule is exact but also permits the same
`(directiveKind,code)` repeatedly when only its reference changes; the intended
renderer semantics for that case are unstated.

Bounded repair: distinguish genuinely optional empty sections from sections
that must contain substantive typed directives, define the closed absence
representation and its reference/duplicate invariants, and state whether
uniqueness is by `(directiveKind,code)` or why multiple references under one
code are required. Exercise zero/one/256/257, holes, extras, proxies,
accessors, symbols, mutable/sealed/frozen arrays, each missing kind, duplicate
and conflicting absence, and per-kind minimum mutants.

## Bounded proportionality and consumer check

The concrete threat is instruction or policy text entering a worker outside a
reviewed template, plus a digest-bound brief describing a different action than
the one dispatched. A closed directive union and bounded footprint are a
credible small shape, but the current open tokens recreate the excluded prose
surface and the nested action record duplicates packet facts without equality.
The smallest credible alternative is a four-record census with exact literals,
packet cross-bindings, finite admitted code/reference catalogs, and no raw open
token rendering. The deletion test specifically removes `resourceKind` unless
ISS-011/ISS-021 goldens prove a worker needs a neutral class in addition to the
opaque identity and access. No additional authority record, resolver service,
or repository/host field is justified.

ISS-011 remains the producer and fresh-context consumer of the typed structure;
ISS-021 remains the sole template/renderer owner; ISS-008 remains the rendered-
byte binding owner; ISS-002 owns only schema/parser/canonical contract and
mutant evidence. The repaired acceptance evidence should be split along those
owners rather than moving rendering or launch behavior into ISS-002.
