## Blocking finding

### OP-R153-1 — stale exported lifecycle type retains reservation TOMBSTONE

`packages/contracts/src/definitions.ts` still declares:

```ts
export type RecoveryAttemptReservationLifecycle =
  | "RESERVED"
  | "CONSUMED"
  | "TERMINAL"
  | "TOMBSTONE";
```

`packages/contracts/src/index.ts` exports the definitions module, making that
union part of the public contracts package. This directly contradicts all
three current authorities:

- the reservation value ledger says there is no reservation-schema TOMBSTONE
  branch or fourth lifecycle;
- the implementation's new `recoveryAttemptReservationLifecycles` runtime
  constant is exactly RESERVED/CONSUMED/TERMINAL; and
- the common selected `pointer-tombstone-value/v1`, not a reservation value,
  represents later terminal removal.

The old boolean transition helper and old four-value runtime constant were
correctly deleted. Leaving their type alias is still substantive: typed callers
may construct state machines, exhaustiveness switches, DTOs, or adapter code
that treats reservation TOMBSTONE as a value lifecycle. That creates two
incompatible public contracts even if runtime parsing later refuses the bytes.

The focused test checks `Object.hasOwn` only for several runtime names and
checks the runtime lifecycle array. TypeScript types are erased, so neither
assertion can detect this exported union. The full typecheck also cannot fail
merely because a valid union contains an unauthorized member. A compile-time
negative is required, for example an exact type-equality assertion against
`"RESERVED" | "CONSUMED" | "TERMINAL"` or a checked expected error for
TOMBSTONE assignment.

The bounded repair is unambiguous:

1. remove the obsolete type from `definitions.ts`;
2. export an exact three-literal type from `attempt.ts`, derived from or equal
   to the new runtime lifecycle constant; and
3. add a public type-surface test proving TOMBSTONE is not assignable and no
   duplicate lifecycle type remains.

Simply changing the old union to three literals would also satisfy behavior,
but co-locating the public type with its parser/constant is smaller long-term
ownership and prevents another split lifecycle authority.

## Exact parser and branch census

Apart from OP-R153-1, `attempt.ts` implements the exact closed union.

RESERVED uses the sorted eight-member field list. CONSUMED and TERMINAL reuse
that list plus `selectedAttemptLogTipDigest` as the ninth sorted field. The
parser first takes a hostile-safe detached JSON snapshot, selects a branch
census from lifecycle, compares exact own keys, and then validates:

- exact schema literal;
- lifecycle among RESERVED/CONSUMED/TERMINAL only;
- active-release and cleanup-gate tip SHA-256 values;
- nullable predecessor-log and recovery-fence SHA-256 cells;
- UUIDv7 attempt identity;
- canonical millisecond timestamp; and
- required non-null selected-log SHA-256 for CONSUMED/TERMINAL.

An invalid lifecycle uses the RESERVED census only to obtain deterministic
closure issues, then independently receives `lifecycle:invalid`; it cannot use
that fallback to admit a fourth branch. RESERVED refuses an extra selected-log
member, while both later branches require it. TOMBSTONE, READY_ONLY, and
IN_PROGRESS fixtures refuse.

The registry exposes three branch vocabulary rows with the exact same schema
version and separate lifecycle closed values, while `schemaVersions` contains
one unique `recovery-attempt-reservation/v1`. Generic parse dispatch routes to
the closed parser before any open registry fallback.

## Transition, preservation, and time behavior

The new public transition validator parses both inputs and admits exactly:

```text
null -> RESERVED
RESERVED -> CONSUMED
CONSUMED -> TERMINAL
```

It rejects null-to-later, every self-loop, skip, reverse edge, and every edge
from TERMINAL. Both non-genesis edges preserve exact:

```text
activeReleaseTipDigest
attemptId
cleanupGateTipDigest
predecessorAttemptLogTipDigest
recoveryFenceTipDigest
```

The selected attempt-log tip correctly is not preserved: CONSUMED introduces
the IN_PROGRESS snapshot and TERMINAL replaces it with the TERMINAL snapshot.
The validator compares canonical timestamp text only after both records pass
the exact timestamp parser, so lexical comparison is chronological. Equality
is admitted and a prior-later time produces `recordedAt:before-prior`.

Malformed or hostile previous/next records return frozen sorted issue arrays
without throwing. No transition path invokes IO, allocation, CAS, descriptor,
log, process, or capability code.
