# Pressure round 427 — ISS-023 dependency-retention audit

Status: read-only reduction audit recorded; both existing edges retained. No
probe, provider access, credential operation, contract implementation, roadmap
mutation, or authority claim.

## Audit question and evidence

The owner authorized one bounded audit of ISS-023's direct `ISS-012` and
`ISS-031` edges. The test is whether either edge merely reflects scheduling or
whether it supplies lifecycle timing or external-authority admission that an
alternate path does not establish.

ISS-012 owns the provider contract that separates a requested selector from a
provider-authenticated immutable model identity and represents alias movement,
mismatch, and identity unavailability. Existing ISS-002 host/route contracts
identify an installed worker host and its capabilities; they do not define the
model-identity evidence that ISS-023 must observe at startup and later hand to
routing unchanged. Removing this edge would make the probe invent the provider
contract before its registered owner exists.

ISS-031 selects the exact backend, custody principal, IPC/endpoint controls,
and byte-hashed native-store attack suite that ISS-023 must exercise across all
roles and operating systems. No route through ISS-012 supplies or admits that
external security boundary. Probing a synthetic or same-user substitute would
measure a different topology and could not support credential-isolation
authority.

## Disposition, proportionality, and review attack surface

Retain both edges. They protect different correctness surfaces, neither is
transitively implied by the other, and closure elsewhere does not erase their
semantics. The smallest result is one explicit rationale in the ISS-023 source
draft plus this pressure record; roadmap and board dependency fields remain
unchanged.

Review should attack conflation of host identity with model identity, selector
equality treated as an immutable version, probe-private schema ownership,
synthetic custody substituted for the selected topology, attack-suite drift,
same-user store access counted as isolation, or a retained edge that is actually
implied by another dependency. The audit authorizes no Codex installation,
authentication, probe execution, credential use, provider write, spend, or
operator decision.

## Verification and prediction

`pnpm run planning:check`, live `pnpm run planning:board-check`, format checks,
independent exact-head review, and three-OS hosted CI must pass. Prediction: when
ISS-012 and ISS-031 complete, ISS-023 can consume their exact artifacts without
adding a probe-local provider identity schema or substituting a credential
topology; review again at ISS-023 implementation preflight.
