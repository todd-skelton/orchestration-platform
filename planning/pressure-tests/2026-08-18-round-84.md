## Unicode 15.1 and OS-profile audit

The leaf decoder enforces canonical unpadded base64url, 1–3072 decoded bytes,
shortest-form fatal UTF-8, no leading BOM, no surrogates, no unassigned scalars,
and no noncharacters. It admits exactly one component and refuses separators,
dot components, NUL, drive/URI prefixes, and trailing dot/space aliases.
Windows additionally refuses its C0/character restrictions, alternate streams,
and the complete ASCII-case-insensitive reserved basename census, including
`CLOCK$` and `COM`/`LPT` superscript-1/2/3 aliases.

The algorithm lowercases each scalar independently only for case-insensitive
profiles, then normalizes. That applies Unicode's unconditional full lowercase
mapping without importing contextual final-sigma or locale-specific rules;
`straße` remains distinct from `strasse`. The exact OS relation is enforced as
Darwin/lowercase/NFD, Windows/lowercase/NFC, and Linux/case-sensitive/NFC.

The runtime is Node `v24.15.0` with Unicode `17.0`. Three independent primary-
data checks pressure-tested the runtime-derived 15.1 pin:

- the implementation's exclusion set exactly equals every Age 16.0 or 17.0
  row in Unicode 17 `DerivedAge.txt`: 9,988 official scalars, 9,988 implemented,
  zero missing and zero extra;
- per-scalar Node lowercase was compared with Unicode 15.1 `UnicodeData.txt`
  plus unconditional `SpecialCasing.txt` for all 287,412 assigned non-surrogate
  scalars: zero differences; and
- Node NFC/NFD was checked against all 19,074 rows in Unicode 15.1
  `NormalizationTest.txt`: zero differences.

The official data was read only from versioned `unicode.org/Public` UCD paths.
The implementation fails closed on a runtime Unicode version outside its
explicit `15.1|16.0|17.0` admission set.
