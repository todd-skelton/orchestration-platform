detached parsing, exact scalar/census/identity/time relations, canonical
serialization and framed identity, public registry/compatibility/export
wiring, and focused executable contract vectors. The first scheduled producer
is ISS-036; the eventual protection receipt binder consumes this parsed anchor.

## Acceptance evidence

The public parser snapshots recursively before inspecting supplied data and
returns only detached frozen values. The exact ten-member root, eight-member
asset row, four-member signer and three-member confirmation are closed.
The three OS rows are complete and ordered, with ARM64/X64 treated equally.
Numeric identities are positive canonical safe decimal strings; SHA-256 values
are exact lowercase 64-hex strings; names, repository paths and Git branch refs
enforce UTF-8 limits and exclusions. Signer repository equality and confirmation
no later than creation are independent refusal criteria.

Focused vectors remove, rename, null, change type and add members at every
record; exercise each literal, identity, hash, byte bound and chronology edge;
reject missing/duplicate/reordered OS rows; and apply mutable/sealed/frozen,
proxy/accessor/symbol/hidden-field, subclass/cross-realm, sparse/extra/iterator
and cycle inputs. Accessor and proxy traps must not run. Changing each supplied
content digest changes the framed anchor identity. A consistently changed
repository pair remains only a valid structural claim, never authentication.

Generic parsing, canonical byte parsing, serialization, registry vocabulary,
compatibility and public exports are tested together. The canonical fixture
has 1,856 bytes and an independently calculated single-frame SHA-256 identity
`70be486e417574fa4e1211828b7e3028c7b1b8583f42d440772d514b669e2bd5`.
Removing literal, scalar, nested-closure, OS-order, signer-equality,
confirmation-time or framed-domain checks must make the matching negative or
golden vector fail. Test execution is reserved for hosted three-OS CI.
