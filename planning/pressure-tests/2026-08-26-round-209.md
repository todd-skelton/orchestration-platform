# ISS-006 cross-platform RPC dependency repair review — round 209

## Disposition

`PASS_TO_REPAIR`.

Round 208's exact Windows diagnostic falsified one assumption, not the
isolation design. The stable RPC source has a top-level static relative import
of `./linux-credential-status.mjs`. Node resolves that import before evaluating
the runner's argv/platform branch or reading stdin. Windows custody correctly
copies exactly `node.exe`, `rpc-runner.mjs`, and `candidate.mjs`, so the child
exits during module linking and the stable stdin worker correctly reports the
early close.

Adding `linux-credential-status.mjs` to either execution root is forbidden.
Linux likewise owns only copied `node`, `rpc-runner.mjs`, and `candidate.mjs`
plus `scratch`; its current hosted fixture happens to bundle the relative
module, but the reviewed runtime artifact must remain one self-contained RPC
file. A Linux-only dynamic import would preserve a latent relative runtime
dependency and is therefore not the cross-platform repair.

The smallest repair is to remove the relative import and inline the existing
small pure Linux credential verifier into `iss002-isolated-walk-child.mjs`.
The standalone helper remains test-bundle-only as the hostile-input oracle.
The two verifier bodies are fixed as one byte-equivalent marked region, and
tests compare that region before applying the existing deletion matrix. The
Windows/file-URL argc-3 path then has no relative dependency; the Linux argc-6
path still performs the same kernel credential/capability gate before any
candidate import.

This repairs only the RPC dependency edge. It does not authorize a fourth
execution file, a broader file/root census, a new argv mode, a build step in the
native broker, a weaker Linux gate, candidate self-certification, or any
authority/receipt/promotion claim.

## Exact repair

### One self-contained RPC file

`packages/conformance/src/iss002-isolated-walk-child.mjs` must:

1. delete the static relative import of
   `./linux-credential-status.mjs`;
2. contain no static or dynamic relative import at all; its remaining module
   imports are exact `node:` builtins;
3. inline the complete current credential verifier, including hostile input
   detachment, exact one-group array descriptors, decimal/range checks, all
   real/effective/status UID/GID arms, empty kernel `Groups`, `NoNewPrivs=1`,
   and zero `CapInh|CapPrm|CapEff|CapBnd|CapAmb`;
4. capture every verifier intrinsic before candidate import, preserve the
   current frozen-prototype boundary, and never read a candidate-controlled
   module, iterator, accessor, proxy, environment value, or path to select the
   verifier;
5. invoke that verifier only through the already closed argc-6
   `./candidate.mjs --linux-principal <uid> <gid>` arm, after exact
   `process.platform === "linux"` refusal and before filesystem probing, stdin
   parsing, or candidate import; and
6. retain the argc-3 exact file-URL arm without resolving or opening any Linux
   helper.

Import failure is no longer a possible platform branch. The inline verifier's
false result or any intrinsic/kernel observation ambiguity still throws before
candidate code. The candidate never chooses expected UID/GID, status bytes,
gate order, or whether the gate runs; stable Linux argv and the kernel remain
the inputs.

### Exact equivalence owner

`packages/conformance/src/linux-credential-status.mjs` remains a private
test-bundle source and pure exported oracle. It is not copied into Linux or
Windows execution custody and is not added to the harness or package root.

Place the verifier's captures, constants, detachment/parser helpers, and
`verifyLinuxCredentialStatus` implementation inside an exact marked region in
both files. The bodies inside those markers must be byte-for-byte identical;
the standalone file exports the already-defined function after the region.
Only the runner calls its inline copy. This is deliberately bounded duplication
needed to combine:

- a dependency-free one-file runtime artifact; and
- a directly importable pure hostile-input test oracle.

A test must read both stable sources and compare the exact marked regions.
Removing a field, bound, descriptor check, status arm, capability arm, or
changing either copy independently must fail that comparison or the existing
behavioral matrix. Do not introduce `eval`, `vm`, source generation at runtime,
an environment/test argv seam, or a fourth runtime module to avoid the
duplication.
