# ISS-006 Windows TypeScript authority pre-implementation review — round 221

## Disposition

`BLOCK_REPLAN`.

The four-method TypeScript authority is the correct next consumer of the
landed native broker, but the proposed packet is not constructible under the
existing Round-175 custody requirement. TypeScript/Node can retain, hash,
stat, copy, reread, and compare broker bytes. It has no production Win32
surface that can authenticate the exact owner, protected DACL, SACL/mandatory
label, file ID, link/reparse relation, and retained ancestor security of the
tracked broker and its private copy. The landed broker exposes only the exact
`SERVE` and `RECOVER` modes and contains no pre-service materialization
primitive. Invoking that broker to authenticate its own future copy would
already cross the unproved boundary.

A TypeScript-only implementation would therefore either omit Round 175's
stable-to-private broker custody or introduce an unreviewed shell/tool/FFI
authority. Neither may land behind an opaque interface merely because the
candidate cannot see the interface.

## The exact missing prerequisite

Round 175 item 2 requires the stable adapter to:

1. open the reviewed source and PE from protected stable bytes;
2. capture byte hash, volume/file identity, link count, size, owner, complete
   protected DACL/SACL/mandatory-label profile, architecture, and closed import
   census;
3. copy the PE through retained handles into a stable-only external helper
   root;
4. independently authenticate the copied bytes, identity, security, ancestors,
   and candidate inaccessibility before and after every use; and
5. durably reverse ambiguous partial copy/cleanup prefixes.

The current native broker already has the necessary low-level Win32 security
and identity vocabulary for its profile, execution, and admission objects, but
it does not apply that vocabulary to a pre-`SERVE` broker-copy lifecycle.
`GetModuleFileNameW` is currently used only in the admitted child-token
negative-open proof. It is not a stable-source/helper-copy custody protocol.

Node's `FileHandle`, `stat`, and hashing APIs cannot replace the missing facts:

- `dev`/`ino`/`nlink` and byte equality do not authenticate a Windows security
  descriptor, protected/inherited ACE relation, SACL, or mandatory label;
- `fs.copyFile`/streaming writes do not provide the required durable
  pre-mutation intent, exact no-follow destination publication, or security
  transition proof;
- `icacls`, PowerShell, `cmd.exe`, PATH discovery, a hosted compiler, or an
  arbitrary command adapter are explicitly outside the authority chain; and
- caller-supplied profile/read/copy seams would turn production authority into
  simulation and permit the candidate/stable caller to choose the proof.

No other private Windows custody primitive exists in the current bundle. The
macOS and Linux custody implementations are OS-specific and cannot establish
Windows ACL/file-ID facts.

## The adapter boundary after the prerequisite

The later adapter remains a narrow and appropriate slice once broker-copy
custody is constructible. It should add one private
`windows-isolation-authority.ts`, its focused test, and exact bundle-census
rows, with no package-root export. Its production factory must hard-refuse
before options on a captured non-`win32` platform and accept paths/configuration
only, never syscall, runner, clock, profile, parser, or authority seams.

The factory may implement only the existing opaque methods:

- `createPrincipal()` creates an unforgeable internal handle and one exact
  broker `SERVE` process; it emits no SID/profile/raw custody object.
- `prepare(handle, request)` hostile-detaches the closed request, sends the
  exact OPWB PREPARE/OPWE path frame outside the measured interval, strictly
  parses the bounded OPWR response, and retains the exact prepared request
  binding. It does not return broker metadata.
- `launch(handle, request)` requires exact prepared-request equality, writes
  the one `1..4 MiB` challenge, strictly parses one bounded OPWB LAUNCH frame,
  and converts only the native terminal payload. `EXITED` becomes an exact
  plain `{exitCode:uint32, signal:null, stdout, stderr}` after fatal UTF-8
  decoding. `TIMEOUT` becomes the existing non-success terminal vocabulary;
  status 65/70, malformed framing, duplicate response, output overflow,
  backward/adversarial timing fact, early broker exit, or control ambiguity
  throws. Candidate JSON remains hostile data parsed by `isolated-walk.ts`
  inside the stable monotonic interval.
- `teardownPrincipal(handle)` sends exactly one empty TEARDOWN, closes broker
  stdin to prove EOF, requires the exact zero-payload success response, terminal
  broker exit/control-pipe closure, native recovery when necessary, helper-copy
  reversal, and durable absence before returning. It exposes no raw custody,
  receipt, PASS, SID, Job, or promotion object.

The adapter must distinguish the broker's control stdout/stderr from the
candidate stdout/stderr carried inside the authenticated frame. Broker stderr
can only cause diagnostic refusal; it is never candidate output. All event
listeners, buffers, write callbacks, child handles, and close/error/exit facts
remain stable-owned and are bounded/drained before cleanup.

## Required deletion evidence after replan

The broker-copy prerequisite must first kill deletion mutants for every source,
ancestor, helper-root, destination, profile, alias, stream, hard-link, reparse,
ACL/SACL/label, hash, import, architecture, durable-intent, publication,
readback, close, cleanup, and retry fact. It must execute ambiguous prefixes
before and after destination creation/security transition and prove that a
fresh stable process either completes exact reversal or retains recovery state.

Only then may the adapter tests delete:

- the hard Windows guard and package-root/bundle privacy rows;
- every OPWB/OPWE/OPWR field, reserved byte, size bound, operation/status, EOF,
  duplicate, partial read/write, backpressure, output-drain, and UTF-8 check;
- request/principal ownership, one-prepare/one-launch/one-teardown ordering,
  handle reuse/reflection/accessor/proxy resistance, and exact prepared-request
  equality;
- broker error/exit/close ordering, stdout/stderr separation, every retained
  buffer/listener/handle cleanup, watchdog/recovery transition, and helper-copy
  absence; and
- candidate PASS/time/expected-value/selected-head forgery, raw-custody
  exposure, receipt/provider/workflow/promotion routing, and three-cycle
  freshness.

The Windows hosted diagnostic must invoke the tracked reviewed PE through the
production adapter for three fresh cycles, cover canonical success, timeout or
hanging root, detached descendant, crash/recovery at each adapter-visible
phase, malformed/oversize broker output, and final profile/Job/execution/helper
absence. Simulation remains refusal/deletion evidence and cannot claim hosted
authority.

## Smallest ordered repair

Do not implement the TypeScript authority yet. First pressure-test one fixed
native broker-materialization/custody primitive that establishes the missing
facts without adding a shell, general command surface, caller-selectable proof,
candidate-visible path, receipt, or third broker mode. Round 175 authorizes
exactly `SERVE` and `RECOVER`; adding another mode, silently deleting copy
custody, or directly invoking unprofiled tracked bytes requires a new removal
decision rather than an implementation assumption.

## Proportionality and planning impact

The block is narrow. It does not reopen AppContainer profile, execution-copy,
admission, Job, terminal protocol, RPC, coordinator timing, or cleanup design.
It prevents a TypeScript convenience layer from laundering an unproved native
launch into stable authority.

No ISS-006 draft, sole ledger, roadmap, or board amendment is warranted yet.
The implementation packet is incomplete, not the authority requirement.
Windows/Linux private progress remains allowed; macOS evidence remains required
for ISS-006 completion. This record authorizes no implementation, hosted PASS,
receipt, aggregate, provider authority, certification, installation, promotion,
workflow dispatch, issue completion, or Chase Sets access.
