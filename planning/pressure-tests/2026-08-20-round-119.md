## Blocking finding 1: the exact VALUE position is bypassable

`parseCleanupGateValuePosition` and `parseRecoveryFenceValuePosition` correctly
snapshot and close the position to exactly `mode`, `parts.ordinal`, and
`parts.rootDigest`, with `mode=VALUE`, a safe decimal, and SHA-256 root. Their
specialized digest wrappers parse first and then use the registered family
domain. The common public constructor in `pointer.ts`, however, closes only the
outer `{mode,parts}` record. It accepts arbitrary nested `parts` and hashes
those bytes under the same `cleanup-gate-position/v1` or
`recovery-fence-position/v1` domain.

An in-memory exact-HEAD probe supplied:

```json
{
  "mode": "VALUE",
  "parts": {
    "ordinal": "0",
    "rootDigest": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "extra": true
  }
}
```

Both family parsers refused it with `parts.extra:unknown-field`, but
`computePointerPositionDigest` returned
`cd7c92c454205d4943a6f773c7e71aabe14fc97e5d64bcad8e057f18d42abffc`
for the cleanup gate and
`5dbadeaa23eb338a46a7d0b2b39a70ede8c2159289207cdf367df1845dde6248`
for the recovery fence. A second probe passed that same malformed cleanup
position through an otherwise valid common mutation input;
`computeMutationId` succeeded with
`ef10af4186049839c03d413cc6c62e2e134c8d0282e707d4192e9c12886a117d`.

This is not a harmless low-level alternate encoding. The output carries the
registered authoritative position domain, and the common mutation ID consumes
it. A caller can therefore bypass the exact parser while producing the same
class of identity that the specialized wrapper produces. The ledger requires
extra, missing, wrong-type, unsafe, and otherwise non-exact position members to
refuse.

The smallest bounded repair is to make the public common position-digest path
dispatch the two VALUE kinds through the exact family parser before framing,
and make the specialized wrappers use that same enforcement path. Then prove
that the common digest and `computeMutationId`, not only the specialized
parsers, refuse every malformed gate/fence VALUE position. This repair need
not add a schema, pointer kind, lookup, tombstone position, second digest, or
new module; it can remain within the existing pointer/definition contract and
focused test surfaces.
