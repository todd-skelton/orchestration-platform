## OP-R155-1 removal — constructible reservation location

The exact descriptor census is now:

```text
attemptId: uuid-v7
lifecycle: LIVE
processStartObservationDigest: sha256
reservationPredecessorKey: sha256
reservationTipDigest: sha256
schemaVersion: recovery-attempt-descriptor/v1
sourceToken: cleanup-gate-pre-fence | recovery-fence
transactionId: uuid-v7
```

The fields remain in ascending canonical member order. Every scalar has one
role; no nullable branch or copied selected triple was added.

The descriptor can now reconstruct its upstream reservation without directory
enumeration:

```text
transactionId + sourceToken + reservationPredecessorKey
  -> installation/activation-recovery-launches/<transaction>/<source>/
       reservations/<key>.json
  -> reservation canonical path

canonical path + independently trusted installation/project/state identity
  -> reservation Dp

reservation Dp + reservationTipDigest
  -> exact immutable selected tip alias
  -> parsed tip yields reservation Dv and Dr
  -> exact value/proposal aliases
```

The ordinary global identity scalars are already required by all pointer
composition and are correctly not copied into the descriptor. The repair's
statement that transaction/source/key reconstruct path and `Dp` is read with
that independently trusted common identity, not as a new three-field `Dp`
formula.

This works at the critical crash boundary:

```text
selected RESERVED
  -> authenticated process-start observation
  -> immutable LIVE descriptor
  -> crash before selected IN_PROGRESS
```

The descriptor itself now carries enough path discrimination to locate the
reservation selected graph. It does not depend on a current-attempt log that
may not yet exist, a caller key, a mutable head, directory scan, latest-file
choice, or reverse hashing of `Dt`.

`reservationTipDigest` and `reservationPredecessorKey` are nonredundant:

- the key reconstructs canonical path/`Dp` but does not select a snapshot; and
- `Dt` selects the exact RESERVED tip under that `Dp` but cannot reconstruct
  the path.

Copying reservation `Dp/Dv/Dr`, the full predecessor triple, or canonical path
would be larger. A global `Dt` index or enumeration would add authority
machinery. The two scalar identities are the smallest constructible pair.

## Later predecessor/key equality

The key is structurally SHA-256 at detached parse time. It does not prove that
the reservation path was derived from an authorized predecessor. Later family
composition must:

1. locate the reservation graph from descriptor transaction/source/key/`Dt`;
2. parse the selected value and require lifecycle `RESERVED`;
3. equal-bind reservation attempt ID to descriptor attempt ID;
4. take the reservation's nullable `predecessorAttemptLogTipDigest`;
5. for non-genesis, locate the predecessor attempt-log graph from the trusted
   transaction/source identity and derive its `Dv/Dr`;
6. require the predecessor be selected TERMINAL with complete valid history;
7. recompute the tagged genesis or selected `Kreservation`; and
8. require exact equality to descriptor key and reconstructed path.

Cross-key, cross-source, cross-transaction, changed predecessor, swapped
`Dt/Dv/Dr`, or coordinated wrong key+reservation-tip substitutions therefore
refuse in later composition. Generic structural parsing does not claim lineage,
selection, currentness, or process authority.

The dependency graph stays acyclic. The key commits only tagged genesis or a
completed earlier terminal attempt-log selection. The current descriptor and
current attempt log do not enter their own reservation key. The order remains:

```text
prior terminal/genesis
  -> selected RESERVED
  -> process observation
  -> LIVE descriptor
  -> selected IN_PROGRESS
```

## OP-R155-2 removal — one chronology source

`startedAt` is deleted from the descriptor. The descriptor therefore cannot
pair a real process observation with an independently self-asserted timestamp.
There is no ambiguity between OS/process start time and descriptor-record time.

The authenticated process-start observation is now the sole chronology source.
Later ISS-005/ISS-030 composition must parse that observation under its
independently reviewed contract, authenticate its producer/evidence, and
require its start time to be at or after the selected reservation's
`recordedAt`. Detached descriptor parsing has no timestamp claim to make.

This is smaller than retaining `startedAt` plus an equality and avoids a
second time producer. Deleting the later observation-time/reservation-order
comparison must make a composition mutant survive. No descriptor time field,
clock API, chronology union, or nullable time was added.

## Opaque process observation and self-assertion attack

`processStartObservationDigest` remains the opaque identity of later evidence,
not proof by itself. A lowercase SHA-shaped value can pass structural parsing
without granting LIVE authority. Later composition must locate and parse exact
observation bytes and prove:

- native argument bytes;
- installed definition read-back;
- process-tree identity;
- exact start event and its authenticated time; and
- equality of the recomputed observation digest to the descriptor member.

Missing, malformed, wrong-domain, moved, candidate-created, or self-asserted
observation evidence is `UNKNOWN`. It cannot authorize descriptor use,
attachment, process adoption, capability, broker access, release review, or
promotion.

Keeping only the opaque digest preserves the engine/adapter boundary. Raw argv,
executable/shim paths, declared user, PID, OS process tree, provider vocabulary,
installed definition bytes, or Git/repository terms do not enter this engine
record. The later native observation schema remains independently gated.
