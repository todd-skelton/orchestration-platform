# ISS-006 live-protection recovery review — round 235

## Disposition

`REPAIR_APPROVED; CURRENT_HEAD_BLOCKED`.

The smallest trust-preserving repair is to let the hosted plan and record bind
only GitHub's direct `GITHUB_REF_PROTECTED=true` projection and to make the
administrator-authenticated post-terminal verifier the sole validator of the
full zero-bypass classic/ruleset policy. No run artifact, including the
provider record, is authority before that verifier returns PASS and the exact
revision receives independent review.

Current head cannot produce that evidence. The workflow grants only
`actions:read` and `contents:read`, carries no secret, and run `33131577307`
failed closed in `Select protected candidate`; candidate checkout, observation,
aggregate, and record were skipped. GitHub requires Administration read for
`GET .../branches/main/protection`, while ruleset detail omits
`bypass_actors` unless the caller has ruleset write. The current plan and record
therefore ask the workflow token for facts it cannot authenticate, and the
terminal verifier incorrectly reuses the same reader. Repository ruleset list
rows are summaries, so list pagination alone is not a substitute for detail
reads.

## Minimal repair fence

1. Keep workflow permissions exactly `actions:read` and `contents:read`; add no
   secret, environment, OIDC, or administration permission. Plan must still
   require the exact event, protected `refs/heads/main`, workflow ref, and
   `GITHUB_WORKFLOW_SHA = GITHUB_SHA`, resolve the exact candidate commit, and
   refuse any direct protected-ref value other than literal `true`. Record must
   independently bind the same provider projection.
2. Keep the direct projection semantically distinct from
   `github-conformance-protection-snapshot/v1`. Add a closed direct-ref
   projection/domain and version the affected provider record/run contract;
   do not populate or reinterpret the existing full-policy fields from one
   boolean. The direct marker proves only that GitHub reported some protection
   configured for the triggering ref.
3. Remove full classic/ruleset API reads from plan and record. The required
   verifier runs outside the Actions run with an administrator-authenticated
   credential, after the run is terminal. It must read classic protection,
   terminally paginate all repository/inherited ruleset summaries, fetch every
   ruleset detail, and require `bypass_actors` to be present and empty. Missing
   detail, hidden/omitted bypass data, unreadable pages, unknown applicability
   or enforcement, any administrator/actor exemption, or failure to require
   pull requests and block deletion and non-fast-forward updates refuses.
4. Terminal PASS must retain the existing exact repository/run/attempt/
   workflow-revision joins, unique successful record job and artifact,
   provider-time bounds, retention, live artifact bytes, aggregate replay, and
   clean exact-revision verifier checkout. Prior-attempt, moved-revision, or
   mixed-run evidence remains unusable. `GITHUB_REF_PROTECTED=true` is never a
   fallback for an unreadable full terminal projection.
5. Amend the ISS-006 draft and trusted-harness ledger in the repair that changes
   the contracts and executable mutation evidence. They must say explicitly
   that the provider record is provisional input to terminal verification, not
   pre-terminal authority. Preserve refusal mutants for false/missing direct
   projection, omitted ruleset detail or `bypass_actors`, classic/ruleset
   movement, bypass insertion, weakened restrictions, replay, and any route
   that accepts an artifact without terminal PASS.

Default-branch movement cannot substitute bytes because the run, provider
record, verifier checkout, and independent review remain fixed to the exact
immutable workflow revision and candidate subject. This repair does not claim
continuous historical protection: a transient weaken/restore is not proved by
the direct marker or a current terminal read and grants nothing without the
separate exact-head review. Authenticated historical provenance remains
ISS-029's concern.

## Proportionality

| Mechanism | Threat / deletion test | Disposition |
| --- | --- | --- |
| Administrator secret or broader workflow token | Deleting it must not make candidate/run code the policy reader | reject; it enlarges self-certification and secret exposure |
| Full plan/record policy reads | Current live run proves they cannot authenticate their inputs | delete |
| Direct protected-ref projection | False/missing/substituted provider context must stop before candidate execution or record output | retain as the smallest in-run provider fact |
| External full terminal projection | Hidden bypass, weak classic/ruleset policy, movement at use, and unreadable detail must refuse | retain as the sole policy authority |

No audit-log protocol, signature, attestation, promotion route, or new workflow
credential is proportional to this recovery.
