## Design consequences of the sub-slice 3.3 review receipt

Observation 1, the hung control-fixture child. The decision is explicit, is in
code as `report.mjs`'s exported `nativeLockHungFixtureChildPolicy` constant with
the literal value `ACCEPT_THE_HANG_NEVER_SIGNAL`, and is: accept the hang, never
signal. Signalling is excluded outright — a termination request inside a control
would be a second holder-death attempt hidden in a control, which the ledger
forbids. The alternative the receipt named, detaching the child IPC channel and
de-referencing the child handle, is rejected on two grounds. First, it would let
the hosted observation job's event loop drain while a live child still holds the
OS lock on the fixed file, so the parent would finalize custody, and slice 3.5
would seal an archive, against a file another live process still owns; it also
destroys the channel the retained transcript is read from, converting a loud
hang into a quiet unretained one. Second, the teardown itself lives in
`control-fixtures.mjs#runNativeLockControlFixtureChild`, which is not one of this
sub-slice's seven files, so changing it here would break the exact footprint.
Accepting the hang keeps the failure bounded and visible: the landed per-fixture
watchdog bounds each exchange, the hung child's resource stays open in the
control resource ledger, `enterNativeLockCasePhase` therefore refuses the case
phase, the row reduces to `UNKNOWN`, and the hosted job timeout is the outer
bound. A bounded teardown, if stage four wants one, belongs to a later slice
whose footprint includes `control-fixtures.mjs`.

Observation 4, `substitutions`. The per-OS reducer reads `substitutions` from
every control observation and treats any true Boolean or non-empty array member
as disqualifying for `OBSERVED`. The `seam` member is disqualifying exactly for
`CAPTURED_INPUT` and `SUBSTITUTED_SEAM`; `ABSENT` is not a substitution and is
already refused through that row's nullable arm, and `LANDED_CASE_CONTEXT` is
the honest seam. `report.mjs` additionally discloses its own boundary points and
every key of the control boundary a caller supplied, so the receipt's two
previously undisclosed members, `fixtureChild` and `watchdogMs`, become
disclosed the moment a caller supplies them: `report.mjs` composes its own
`fixtureChild` from its own inputs and never accepts one silently.

Observation 3, the case-phase entry. `report.mjs` never calls
`seam.beginCases()`. Its private `enterCasePhase` helper calls
`enterNativeLockCasePhase` with a one-member seam whose `beginCases` invokes the
landed `runCases`, so the landed 3.3 entry gate — which refuses while a control
left the witness locked or a known resource open — always runs before the landed
`beginCases`, and there is exactly one path into the case phase.

Observation 2, `witnessHeld`. Unchanged and relied on in its fail-closed
direction: a refused reset keeps the case phase closed, and every unexecuted row
then reduces to `UNKNOWN` unless a verified unsupported premise applies.

Observation 5, the deferred halves. The report's `controls` member is the closed
`{controlId,refused,result}` row and cannot carry them, so the reducer's output
carries `deferredControlHalves`, which surfaces the deferred halves of rows 8
(`BUILD_OR_LOADER_SUBSTITUTION`, `POST_LOAD_RETAINED_BYTE_REHASH`) and 11
(`MISSING_OR_MIXED_CENSUS`, `CROSS_OS_CENSUS` and `CROSS_ATTEMPT_CENSUS`)
together with the half that did execute. The reducer also reports
`dischargedPrerequisites` (the landed reducer's first four missing
prerequisites) and `remainingPrerequisites` (the fifth, stage four's three-OS
and provider evidence), so no per-OS `OBSERVED` can be read as discharging it.

Two further readings are recorded so review can attack them directly. First, the
ledger sentence "A control maps `UNKNOWN`, `VIOLATED`, and `UNSUPPORTED` to the
same report result" is implemented as the identity mapping onto the
identically-named report words, with `REFUSED` — the control-local success word
— contributing no failure and never entering a build, case or report row.
Second, the retained-byte join in this slice is over the sealed preparation
census with each loaded output row replaced by its actual post-load rehash; the
full post-case archive census belongs to sub-slice 3.5, which is a declared
non-goal here, so `report.mjs` cannot make that join fail on its own and the
mismatch direction is exercised at the reducer instead.

## Per-OS precedence table

`reduceResults` from the landed `reduction.mjs` applies
`UNKNOWN > VIOLATED > UNSUPPORTED > OBSERVED` over every retained failure. No
failure is ever removed; an empty failure list is the only path to `OBSERVED`.

| Evidence source | Contribution |
| --- | --- |
| Report or sub-record census, order, or a `loaded` row with no load | structural refusal, no result |
| `coordinates` disagreeing with plan, provider or this process | `UNKNOWN` per member |
| `builds[].result` | `BUILT` contributes nothing; `UNSUPPORTED` and `UNKNOWN` contribute themselves; a `BUILT` row missing `argv`, `inputs`, `outputs` or `toolchain` contributes `UNKNOWN` |
| `builds[].loaded` | absent, unevidenced, not this role's `.node`, not equal to the built output, or not the retained post-case row: `UNKNOWN` |
| `custody` | missing member or byte readback: `UNKNOWN`; byte other than `41` or mismatched identities: `VIOLATED`; each retained cleanup failure: `UNKNOWN` |
| `cases[]` with a `WATCHDOG` event | `UNKNOWN` |
| `cases[]` with no events | `UNSUPPORTED` under a verified unsupported premise or after an `UNSUPPORTED` row, otherwise `UNKNOWN` |
| `cases[]` executed | the landed `transcriptResult` for that row; `UNKNOWN` when no landed transcript reduction exists |
| `controls[]` | `REFUSED` contributes nothing; `UNSUPPORTED`, `VIOLATED` and `UNKNOWN` contribute the report word of the same name; each landed control-census or presence issue contributes `UNKNOWN` |
| `prerequisites` | `AVAILABLE` contributes nothing; `UNSUPPORTED` and `UNKNOWN` contribute themselves |
| Retained-byte join | a sealed row missing or changed, or a build `inputs`/`outputs` row not retained: `UNKNOWN` |
| Disclosed substitutions | `UNKNOWN` per disclosure |

A verified unsupported premise is deliberately narrow: the build row for a role
and the stable prerequisite evidence for that same role must independently both
say `UNSUPPORTED`. Either one alone leaves an unexecuted row `UNKNOWN`.

## Review attack surface

Copied from the sub-slice 3.4 definition: collection success upgrading a failed
premise; an observed result reachable with an incomplete control census; the
loaded member filled from the pre-load hash; a case result inferred from the
candidate's own reply; a watchdog row not forcing unknown; vocabulary crossing
between build, case, control and report rows; a per-OS reducer trusting the
submitted result.

Review should additionally attack: the reducer's `gates` boundary, and whether
its existence is safe given that `report.mjs` never passes one; the two-pass
assembly in `produceNativeLockReport`, and whether the byte-identity check
between the draft and final reductions really proves the recomputation ignores
the submitted result; the reading that a control's `UNKNOWN`, `VIOLATED` and
`UNSUPPORTED` map onto the identically-named report words; the narrowness of the
verified unsupported premise; the load evidence this packet accepts for each
role — the custody initial identity for `STABLE_WITNESS` and a `HOLDER` `CALL`
event for `CANDIDATE_BINDING` — and whether either can be forged from a
candidate reply; the single extra metadata barrier `report.mjs` takes after
setup purely to bind the parent's root identity for the landed transcript
reducer; the retained-byte join being over the sealed census plus post-load
rehash rather than the real post-case census, which is slice 3.5's; the
`enterCasePhase` helper, and whether any other path into the landed
`beginCases` exists; the decision to accept a hung control-fixture child; and
the `@ts-expect-error` suppressions in the new test, which are the only way to
import a landed experiment `.mjs` from a `.test.ts` inside this footprint.
