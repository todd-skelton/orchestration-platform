## Concrete production finding: post-create `FreeSid` ambiguity remains unlatched

`forbidden_profile_sid` still accepts `const ROOT_CUSTODY *`. It allocates a
SYSTEM SID, compares it with the returned profile SID, and then does:

```c
if (FreeSid(system_sid) != NULL) return 1;
```

That converts a returning-resource failure into the semantic statement
“forbidden SID” without setting `root->resource_ambiguous`. Both fresh create and
ATTEMPTED create-or-reconcile call this helper after the OS returns a profile
SID. If profile cleanup and root release then succeed, the caller may emit
ordinary refusal `65` instead of recovery-required `70`.

The new `FAULT_SID_FREE` case does not kill this mutant: it is consumed earlier
by `exact_acl` while authenticating records/root security. The test therefore
proves that exact-ACL arm, not the post-create helper.

### Required repair

- Give `forbidden_profile_sid` mutable root custody and latch a non-null
  `FreeSid` result before refusing.
- Add a staged or direct compiled deletion case that reaches this exact helper
  after a modeled successful create and separately through ATTEMPTED
  reconciliation. It must prove cleanup is attempted and terminal status is
  `70`, not `65`.
- Continue to free the returned AppContainer SID and perform all safe cleanup;
  one SID-release failure must not skip later releases.
