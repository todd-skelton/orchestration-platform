## Disposition

`BLOCK_REPLAN` for the recovery-attempt LIVE descriptor ledger at exact
reviewed head `114b27ef5f8ac3b7f98f9d4b43f16b625d6ddf98`.

The proposed record is closed, portable, adapter-neutral, acyclic, LIVE-only,
and appropriately treats `processStartObservationDigest` as deferred structural
identity rather than standalone process authority. The domain-separated digest,
path, serializer, exclusions, and common-tombstone lifecycle correction are
also coherent.

Two definite contract gaps remain:

1. `reservationTipDigest` plus descriptor transaction/source/attempt fields
   cannot construct the reservation canonical path/`Dp` needed to locate that
   `Dt`; and
2. `startedAt` has no selected provenance—later text compares it to the
   reservation but does not say whether it equals authenticated process-start
   observation time or is a separately authenticated descriptor-record time.

The first gap makes post-crash descriptor validation impossible without
directory enumeration or an unstated external input. The second leaves
implementers choosing the meaning and producer of an authority timestamp.
Both are planning defects, not implementation choices.

The smallest repair adds one SHA-256 reservation path discriminator, not a
copied selected triple, and chooses one exact `startedAt` provenance/equality
rule. Then a fresh independent exact-head removal review is required.

## Blocking findings and smallest repairs

### OP-R155-1 — `Dt` alone cannot locate the selected reservation

The descriptor carries:

```text
reservationTipDigest: sha256
transactionId: uuid-v7
sourceToken: cleanup-gate-pre-fence | recovery-fence
attemptId: uuid-v7
```

The reservation pointer path is not keyed by attempt ID. It is:

```text
installation/activation-recovery-launches/<transaction>/<source>/reservations/<Kreservation>.json
```

`Kreservation` commits transaction, source, and the tagged genesis or complete
predecessor attempt-log `Dt/Dv/Dr`. It cannot be derived from attempt ID or
from the reservation tip digest.

The authenticated common selected-object aliases are likewise scoped by `Dp`:

```text
installation/pointer-cas/<Dp>/objects/tips/<Dt>.json
```

Therefore `Dt` cannot even locate its tip alias until the reservation canonical
path and `Dp` are known. `Dt` commits `Dp` inside the tip bytes, but those bytes
cannot be read by digest alone from the registered storage layout. Hashes are
not reversible.

This is observable at the critical crash boundary:

```text
selected RESERVED
  -> process-start observation
  -> immutable LIVE descriptor
  -> selected IN_PROGRESS attempt log
```

A crash after descriptor persistence but before the first IN_PROGRESS
selection leaves no current-attempt log record from which another component
could recover the reservation predecessor. The descriptor path supplies only
transaction/source/attempt. Directory enumeration, latest-file selection, a
caller key, or scanning reservation buckets is explicitly non-authoritative.

The ledger nevertheless says later family composition “locates and validates”
the reservation graph from this descriptor. With the proposed eight fields,
that operation is not constructible.

The smallest repair is one additional SHA-256 field carrying the already
computed reservation predecessor key, for example:

```text
reservationPredecessorKey: sha256
```

Together with descriptor transaction/source, that one scalar reconstructs the
exact reservation path, canonical identity, and `Dp`; `reservationTipDigest`
then locates the exact tip alias and derives `Dv/Dr`. Later family composition
must parse the located RESERVED value, locate its nullable predecessor
attempt-log tip through the transaction/source attempt-log identity, derive
that predecessor's `Dv/Dr`, recompute `Kreservation`, and equal-bind it to the
descriptor key/path.

This ninth field is smaller than any credible alternative:

- copying reservation `Dp/Dv/Dr` still does not reconstruct the canonical
  identity path required by the generic locator;
- copying the full reservation canonical path duplicates transaction/source
  and variable path text;
- copying the full predecessor `Dt/Dv/Dr` adds three fields instead of one;
- adding a global `Dt` index or directory enumeration creates new authority
  machinery; and
- waiting for IN_PROGRESS evidence leaves the descriptor unrecoverable at an
  admitted crash boundary.

The key is not redundant in this descriptor even though it appears in the
reservation path: unlike the reservation value, the descriptor path does not
carry it. Deleting the key must make the crash-recovery constructibility test
fail. Cross-key, cross-source, cross-transaction, and coordinated key+`Dt`
substitution must refuse in later family composition.

### OP-R155-2 — `startedAt` has no exact authority source

The descriptor field is named `startedAt`, and the record also names an opaque
process-start observation. The packet states only:

```text
reservation.recordedAt <= descriptor.startedAt
```

in later composition. It does not state either of these materially different
contracts:

1. `descriptor.startedAt` equals an authenticated canonical timestamp inside
   the parsed process-start observation; or
2. `descriptor.startedAt` is descriptor-record creation time from the
   authenticated ISS-030 injected clock, taken only after successful process
   observation.

A SHA-shaped observation digest does not authenticate an unrelated timestamp.
Without an exact provenance rule, a structurally valid descriptor can pair a
real observation with any canonical time after the reservation. Future
chronology, retry, or audit code would have to guess whether the value means OS
start time or descriptor persistence time.

The smallest repair chooses one rule without adding a field:

- if the process observation contract carries canonical start time, require
  exact equality to `startedAt` plus reservation inclusive ordering; or
- if it does not, rename/define the member as descriptor record time, assign it
  to the authenticated ISS-030 injected clock, and require observation success
  precede record creation plus reservation inclusive ordering.

The first alternative matches the current member name and is preferred if the
planned observation can support it. Detached parsing should continue to prove
only timestamp grammar; the later composition owns provenance and equality.
Deletion of that later equality/order rule must have a focused mutant.

## Eight-field semantic and minimality attack

The current proposed census is exact and closed:

```text
attemptId
lifecycle
processStartObservationDigest
reservationTipDigest
schemaVersion
sourceToken
startedAt
transactionId
```

Seven roles are justified after the OP-R155-1 repair:

- `attemptId`, transaction, and source bind descriptor bytes to the exact
  descriptor path and prevent movement between attempts or contexts;
- `lifecycle:LIVE` makes READY/READY_ONLY/TERMINAL/TOMBSTONE descriptor states
  structurally impossible;
- schema version closes compatibility dispatch;
- reservation `Dt` binds the exact selected RESERVED snapshot once its path is
  constructible; and
- process observation digest binds the later independently parsed process
  evidence without importing native vocabulary.

The time member is justified only after OP-R155-2 selects its exact meaning.
The missing reservation predecessor key is a required locator discriminator,
not an audit convenience.

Transaction/source/attempt duplication between record and descriptor path is
proportionate. `Ddescriptor` hashes canonical record bytes independently of
storage location, so deleting any one allows the same descriptor identity to
move across a valid path context. The path-binding tests provide the deletion
evidence. The future added reservation key would not duplicate the descriptor
path; it identifies a different upstream pointer path.

## Process observation and portability attack

`processStartObservationDigest` is not by itself authority, and the ledger says
so explicitly. Detached parsing checks only lowercase SHA-256. Later
ISS-005/ISS-030 composition must parse exact independently reviewed observation
bytes and prove:

- native argument bytes;
- installed definition read-back;
- process-tree identity; and
- the exact start event.

Only after that proof may the descriptor be treated as LIVE. A missing,
unreadable, wrong-domain, self-asserted, or mismatched observation remains
`UNKNOWN` and cannot authorize attachment/adoption. This deferral is acyclic:
selected RESERVED is upstream, process observation follows the actual start,
then descriptor becomes immutable, then IN_PROGRESS may be selected.

The opaque digest is the correct engine/adapter boundary. Raw argv, executable,
shim, path, declared user, PID, OS process tree, provider result, installed
definition bytes, or Git/repository vocabulary do not belong in the common
descriptor. Exact native and platform-specific observation schemas remain with
their named later owners.

The descriptor also need not copy installed-definition, active-release,
cleanup-gate, recovery-fence, authority, or predecessor triples. Once the
reservation graph is constructible, its RESERVED value binds active-release,
gate, optional fence, predecessor tip, and attempt ID. Family locators derive
the corresponding `Dp/Dv/Dr` and prove currentness/history. Copying those facts
would create coordinated-rehash burden without another replay discriminator.

## Path, digest, and serialization attack

The descriptor path is exact, portable contract-relative text:

```text
installation/activation-recovery-launches/<transactionId>/<sourceToken>/attempts/<attemptId>/descriptor.json
```

Both IDs are canonical UUIDv7 and source is the existing two-token recovery
vocabulary. Alternate case, spelling, traversal, missing/extra segments,
cross-source, cross-transaction, or cross-attempt movement refuses. UUID time
is identity/uniqueness only, not ordering authority.

The descriptor digest is correctly distinct from common pointer `Dv`:

```text
Ddescriptor = framedDigest(
  "recovery-attempt-descriptor/v1",
  canonical descriptor bytes)
```

It has one canonical framed part, no raw JSON shortcut, untagged canonical
hash, alternate schema, or family domain. Detached generic serialization may
return canonical bytes and this tagged digest because the descriptor is a
create-once record with its own identity, unlike reservation pointer values
that require `Dp` context.

## Lifecycle and reconciled planning attack

The LIVE-only descriptor is correct. The selected reservation is the sole
durable pre-launch record, so restoring READY or READY_ONLY would create a
second pre-launch owner. Terminal facts belong in the folded TERMINAL
attempt-log record; descriptor TERMINAL/TOMBSTONE branches would duplicate
later authority.

The reconciliation correctly changes reservation lifecycle from the false
record-state sequence
`RESERVED -> CONSUMED -> TERMINAL -> TOMBSTONE` to:

```text
reservation values: RESERVED -> CONSUMED -> TERMINAL
removal: reviewed archive composition -> common pointer tombstone
```

`docs/architecture/state-machines.md` removes TOMBSTONE as a reservation value
state and names archive/common tombstone as the terminal action.
`planning/drafts/ISS-030.md` makes the same correction and no longer implies a
fourth reservation schema branch. This agrees with the implemented three-
branch reservation parser and common pointer removal model.

The planning and board consistency gates pass. The registered ISS-002 and
ISS-030 board items mirror their drafts; no direct board drift or roadmap edge
change was introduced.

| Later family composition | SHA-shaped members are treated as selected/current/semantic authority. | Deleting graph/key/path/observation equality admits coordinated substitutions. | Retain as named later owner; generic parser grants nothing. |

This slice must remain bounded to one descriptor contract module, public
parser/export/compatibility/serializer wiring, one descriptor path constructor,

census and later equality prose only. It does not justify a process observation
schema, launch pointer, attempt log, attachment, archive/tombstone schema,
selected-family implementation, persistent IO, proposal/CAS, capability,
process operation/adoption, broker call, command, package, or runtime behavior.

A valid descriptor or observation digest cannot select a reservation, prove a
process, issue a live handle, attach credentials, review a release, or promote
a candidate. Stable external mutation and later authenticated composition
remain mandatory. A candidate never certifies itself.
