## Remaining blocker: recovery is not composed with the aggregate abort path

The authority test creates four independent `BrokerCommand` objects and calls
their `hardAbort` methods directly. After all four have already settled, it
creates a new `RecoveryBrokerChild` and calls exported `runRecovery` directly.
There is no shared authority state, call log, or invocation of
`teardownPrincipal` between those operations.

Production cleanup is different. At
`windows-isolation-authority.ts:1071-1100`, TEARDOWN must:

1. retain the original operation failure;
2. attempt and completely observe hard abort;
3. retain its ordered aggregate drain failure;
4. independently invoke native RECOVER after root close even though abort
   refused;
5. retain the principal if RECOVER fails; or
6. after successful RECOVER, close bundle custody, remove the active principal,
   and still return the aggregate control refusal.

No current fake test executes that branch. The protected real diagnostic's
failed PREPARE uses a canonical hard abort, so it also does not reach the
aggregate arm. These concrete mutants survive:

- delete catch-arm `runRecovery` at lines 1080–1085;
- move RECOVER before close-bound abort;
- set `nativeClean` after abort refusal without RECOVER;
- discard `abortFailure` after successful RECOVER; or
- delete the retain-on-RECOVER-failure transition.

The standalone sequence “observe abort refusal, then call recovery” does not
kill any of them.

### Smallest repair

Extract or retain one private production `abortThenRecover` composition used by
TEARDOWN and expose only that exact function to the transformed test module.
Drive it with the existing fake child factory and an ordered event log. Require:

- root close before either drain result and before RECOVER spawn;
- both drain outcomes observed;
- RECOVER invoked once after aggregate abort refusal;
- successful RECOVER still returns the ordered abort AggregateError;
- failed RECOVER returns the fixed combined abort/recovery error and leaves the
  principal recovery-required; and
- canonical abort plus successful RECOVER is clean.

Alternatively drive the real `teardownPrincipal` state core with fixed private
dependencies. Calling the two component functions separately is insufficient.
No native or protocol redesign is required.
