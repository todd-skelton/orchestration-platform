## Blocking finding

### `OP-R90-001` — composed mutation validators throw on a closed global-identity substitution

`parseBootstrapAnchor` correctly treats `globalBootstrapIdentityDigest` as a
closed SHA-256 member; derivation equality is a composition rule rather than a
schema grammar rule. Both `validateBootstrapAnchorMutationBinding` and
`validateBootstrapAnchorConflictBinding`, however, pass such a parsed anchor
to `proposalValueIssues`. That helper calls
`computeBootstrapAnchorDigest`, which throws when the anchor's stored global
identity does not equal the recomputation. The public validators do not catch
or convert that semantic mismatch into their closed issue arrays.

An independent in-memory probe used the candidate's own exported constructors
and valid ACTIVE genesis fixture. It changed only the canonical anchor's
`globalBootstrapIdentityDigest` from the valid derived digest to 64 lowercase
`f` characters while retaining the original proposal, value, null prior
triple, and trusted expectation. The substituted anchor remained a valid
closed schema input:

```text
parseBootstrapAnchor(substitutedAnchor).ok === true
```

Calling the composed mutation validator did not return a nonempty frozen issue
array. It escaped with:

```text
TypeError: globalBootstrapIdentityDigest:mismatch
```

The conflict validator reaches the same throwing `proposalValueIssues` call
for each parsed loser/winner composition, so the same anchor substitution can
escape that public validation entry point as well. This violates ISS-002
acceptance criterion 1, the decision authority's fail-closed rule, and the
repository contract that public validators are total over hostile and
malformed inputs. An exception is not the named structural refusal that an
ISS-020 or ISS-022 composition can safely aggregate.

The committed tests do not exercise either throwing path. Their hostile proxy
case stops in `snapshotClosedRecord`, and their coordinated conflict mutants
retain the valid anchor identity. Consequently every committed test stays
green if this semantic substitution continues to escape instead of refusing.

The smallest repair is local to `packages/contracts/src/anchor.ts`: validate
the anchor's derived global-identity binding before any throwing anchor-digest
helper is used, and return a stable issue from both composition validators when
it fails. Add one direct `expect(...).not.toThrow()` plus nonempty-issue
regression for the mutation validator and one for the conflict validator. No
public field, schema, digest domain, framed part, path, record, coordinator,
receipt, or capability is needed.
