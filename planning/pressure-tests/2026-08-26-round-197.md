The smallest next independently complete slice is one native, durable,
pre-execution admission-and-reversal lifecycle in the existing private broker.
It keeps package-SID DACL installation, the actual composite AppContainer
token and effective-access probes, atomic suspended process creation with exact
`SECURITY_CAPABILITIES`, `JOB_LIST`, and `HANDLE_LIST`, and the named
nonbreakaway `KILL_ON_JOB_CLOSE` Job Object indivisible. On successful admission
it never calls `ResumeThread`; it terminates the suspended process, proves the
job and pipes terminal, revokes the grant, removes the execution/profile roots,
proves absence, reports `LAUNCH/NOT_IMPLEMENTED`, and exits 78.

Candidate protocol, candidate stdout semantics, stable timing, resume, module
load, hostile response parsing, timeout, and live descendant/breakaway workloads
remain one later authority-bearing slice. This split is safe because no
candidate instruction can execute before the omitted `ResumeThread`, while the

A DACL-only slice remains rejected by Round 189: it would durably widen access
without the actual composite-token and atomic-containment proof. A synthetic
token probe is not equivalent to the process token created by
`SECURITY_CAPABILITIES`. A create-suspended slice without the exact DACL would
let the stable caller's image mapping mask candidate-token denial. A Job-only
slice would add an unused ephemeral identity and move launch setup outside the
required timed transition. Those mechanisms therefore stay together.

This authorization is private infrastructure only. It is not Windows authority
at HEAD, a hosted PASS, a receipt, aggregate, capability, certification, or

## Why this is the next complete boundary

The landed PREPARE transition already owns a fresh zero-capability profile,
retained package SID/profile folder, and exact stable-only three-file execution
root. It does not grant package access and LAUNCH remains refusal-only. The next
unresolved fact is whether the supported Windows host can create the exact
AppContainer process atomically inside the required job and prove the intended
access relation before candidate code.

The actual AppContainer token does not exist until `CreateProcessW` consumes
`PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`. Therefore:

- package DACL correctness cannot be authority-tested against a derived SID or
  stable primary token;
- process containment cannot be assigned after creation without reopening the
  pre-assignment execution window;
- `HANDLE_LIST` is meaningful only in the same inherited-handle creation call;
- job membership, token shape, argv/cwd/environment, and effective opens must
  all be checked on that same suspended child; and
- resuming before any one check would execute candidate instructions across an
  unproved boundary.

Stopping after all checks while the primary thread is still suspended is a
real semantic cut. Kernel process/token/job/handle objects and real access
checks exist, but Node, the RPC module, and candidate code have executed zero
instructions. Reversal can be completed and crash-recovered without interpreting
candidate bytes. The later slice can replace the successful reversal branch
with `ResumeThread` plus protocol/timing while reusing the exact admission core.

## Closed production behavior

The broker retains exactly `SERVE` and `RECOVER` and exactly PREPARE, LAUNCH,
and TEARDOWN. No mode, opcode, public record, or caller-supplied security field
is added.

After one successful PREPARE:

1. the first canonical zero-payload LAUNCH is terminal for this slice;
2. the broker runs the durable admission lifecycle below;
3. it never calls `ResumeThread`;
4. on successful admission and complete cleanup it emits one canonical
   `LAUNCH/STATUS_NOT_IMPLEMENTED` empty response and exits 78;
5. a semantic/API refusal with independently complete cleanup emits
   `LAUNCH/STATUS_REFUSED` and exits 65; and
6. ambiguous or incomplete cleanup emits `LAUNCH/STATUS_RECOVERY_REQUIRED` and
   exits 70.

LAUNCH cannot be repeated and TEARDOWN does not follow it. TEARDOWN without
LAUNCH retains the landed execution-before-profile cleanup. EOF or malformed
control input before LAUNCH also retains existing cleanup. A successful
admission response is deliberately NOT_IMPLEMENTED because no candidate ran
and no terminal candidate observation exists. No adapter may translate it to
PASS, UNSUPPORTED authority, a receipt, or a promotion input.

## Durable OPWL admission records

Add one disjoint private flat namespace under the already retained state root:

```text
windows-admission-<64 lowercase token hex>-00-grant-attempted.opwl
windows-admission-<token>-01-granted.opwl
windows-admission-<token>-02-job-attempted.opwl
windows-admission-<token>-03-launch-attempted.opwl
windows-admission-<token>-04-admission-proved.opwl
windows-admission-<token>-05-revoke-attempted.opwl
windows-admission-<token>-06-absence-proved.opwl
```

Pending publication appends `.pending`. Publication uses the landed
create-exclusive, write-through, file flush, retained-state-root flush,
readback, no-replace rename, pending-absence, final reopen/readback, and
returning-resource ambiguity rules. Every final remains a never-removed burned
tombstone.

Each canonical record has this one closed shape:

```text
magic:"OPWL" | version:u8=1 | kind:u8=1..7 | reserved:u16=0 |
totalLength:u32le |
token:32 | priorDigest:32 | Dstate:32 |
profileCreatedDigest:32 | executionCreatedDigest:32 |
Dgrant:32 | Dlaunch:32 |
packageSidLength:u16le | packageSid |
jobNameUnits:u16le | jobNameUtf16LE
```

`packageSidLength` is the exact already authenticated SID length and bytes.
`jobName` is exactly `Local\\orch6-job-<token hex>` with no alternate case,
namespace, separator, NUL, suffix, caller input, or discovery arm. Total length
is exact; all reserved bytes are zero. `priorDigest` is zero only for kind 1 and
otherwise hashes the exact preceding OPWL record. Every nonzero digest is fixed
from kind 1 onward.

Define:

```text
Dgrant = SHA256("op.windows-admission-grant/v1\0" || token || package SID ||
                for parent/root/node/rpc/candidate in fixed role order:
                canonical path || volume/file ID || attributes || links ||
                original security bytes || exact grant security bytes)

Dlaunch = SHA256("op.windows-admission-launch/v1\0" || token || job name ||
                 exact job security bytes || exact job-limit bytes ||
                 application path || command-line UTF-16 bytes || cwd ||
                 canonical environment bytes ||
                 "stdin\0stdout\0stderr" || exact creation flags)
```

The execution parent is included because the live token must either traverse
it through the host's existing bypass-traverse semantics while remaining
unable to list/read/write it, or the host is refused. This slice does not add a
parent ACE. Original/grant descriptors bind owner, protected DACL, SACL/label,
and canonical ACE order, not just access masks.

Whole-set preflight parses and pairs every OPWJ, OPWX, and OPWL group before
mutation. OPWL requires exact matching PROFILE_CREATED and EXECUTION_CREATED
digests. A missing predecessor, orphan, fork, gap, duplicate, pending-only
unknown phase, wrong state/token/SID/job, later profile/execution phase before
OPWL ABSENCE, or profile absence before execution absence refuses before
mutation. OPWL ABSENCE paired with nonterminal OPWX/OPWJ is the admitted crash
prefix after job/grant cleanup and before execution/profile cleanup; recovery
must finish those later phases in order.

## Exact grant and reversal

Before the first security mutation, persist GRANT_ATTEMPTED. Retain every
existing parent/root/target handle and security snapshot. Apply exact package
grants to the three files first and execution root last, so a partial forward
transition does not expose a traversable incomplete root. Stable SID and SYSTEM
retain full control. The package SID receives only:

- execution root: exact directory read/traverse/execute rights; and
- node/RPC/candidate files: exact generic read and execute rights.

No package ACE is added to the execution parent, stable state, broker/helper,
source, authority, or profile-parent paths. No broad application-package,
capability, Everyone, Users, inherited, deny-conflict, write, append, delete,
owner, DACL, SACL, alternate-stream, or additional ACE is admitted. The
profile folder retains only its authenticated OS-created package relation.

After every mutation, use retained-handle and current no-follow pathname facts
to compare exact identity/security/stream/census state. GRANTED is durable only
after all four descriptors equal their grant profiles and every source/stable
object remains original.

GRANT_ATTEMPTED recovery admits each of the four mutable descriptors only as
its exact original or exact grant profile. A third/intermediate profile is a
refusal, although reversal still attempts other independently authenticated
objects and retains recovery state. Reversal removes root access first, then
restores the three files, rechecks exact stable-only profiles, and proves no
package ACE on parent/root/files. This closes traversal before child repair.

The durable forward intent authorizes reversal after any ambiguous prefix.
REVOKE_ATTEMPTED is still persisted before ordinary termination/revocation; a
failure to append it cannot justify leaving a suspended child or grant, so the
earlier GRANT/JOB/LAUNCH intents remain the crash-cleanup authority and the
broker returns recovery-required.

## Exact Job Object and atomic suspended child

Before job creation, independently require `OpenJobObjectW` on the exact name
to return exact not-found, then persist JOB_ATTEMPTED. Create one named job with
an exact protected stable-SID/SYSTEM-only descriptor and refuse
`ERROR_ALREADY_EXISTS`. Retain its handle and exact security observation.

Set and re-read exactly `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; both
`JOB_OBJECT_LIMIT_BREAKAWAY_OK` and
`JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK` are absent, as are every other limit flag
not explicitly required by the fixed structure. Persist LAUNCH_ATTEMPTED only
after the job descriptor and limit bytes are exact and before process creation.

Create three anonymous pipe pairs. Only candidate stdin-read, stdout-write, and
stderr-write are inheritable. Stable ends, broker control handles, state/root/
source/target/profile handles, job handle, token handles, and one explicit
inheritable sentinel are not in the child list. The sentinel exists solely to
kill omission of `HANDLE_LIST`; it is never candidate data or production
authority after the check.

Use one `STARTUPINFOEXW` with exactly three initialized attributes:

```text
PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES
  AppContainerSid = exact package SID
  CapabilityCount = 0
  Capabilities = NULL

PROC_THREAD_ATTRIBUTE_JOB_LIST
  exactly the retained inner job handle

PROC_THREAD_ATTRIBUTE_HANDLE_LIST
  exactly candidate stdin-read, stdout-write, stderr-write
```

`bInheritHandles` is TRUE. Startup flags are exactly `STARTF_USESTDHANDLES`.
Creation flags are exactly `CREATE_SUSPENDED |
EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT | CREATE_NO_WINDOW`;
no breakaway, new console, debug, detached, shell, or token-fallback flag is
allowed.

`lpApplicationName` is the exact copied `node.exe` path and is never NULL.
Command-line quoting is generated by one closed Windows quoting function over
exactly the copied Node path, copied RPC path, and copied candidate file URL;
there is no shell, PATH lookup, extra Node option, caller argv, response file,
or command substitution. Cwd is the exact retained AppContainer `AC` folder.

The UTF-16 environment is sorted case-insensitively, rejects case-duplicate or
hidden drive entries, and is exactly double-NUL terminated. It contains only
the fixed hosted-probed Windows/Node necessities and AppContainer-rerouted
`LOCALAPPDATA`, `TEMP`, and `TMP`. Every user/profile/temp value is the exact
retained scratch folder. It contains no PATH, checkout, provider, credential,
token, cache, helper, state/source/materialization path, job name, candidate
verdict, or authority value. If the current host needs another variable, the
diagnostic refuses and a new review is required; it does not widen dynamically.

After successful `CreateProcessW`, close the broker's copies of all three child
pipe ends and verify every retained stable handle's inherit flag is false. The
primary thread remains suspended throughout this slice.

## Stable pre-execution token and access proof

Open the actual child primary token and detach all queried buffers. Before any
possible resume require:

- `TokenIsAppContainer == 1`;
- exact `TokenAppContainerSid` equality to the retained package SID;
- `IsTokenRestricted == TRUE`;
- exact low mandatory integrity SID;
- zero `TokenCapabilities` rows;
- `TokenElevation.TokenIsElevated == 0` and `TokenUIAccess == 0`;
- no enabled Administrators, stable-authority, SYSTEM, capability, or broad
  authority group;
- the ordinary `TokenUser` relation expected for an AppContainer derived from
  the stable user, while the package-principal SID remains unequal to stable,
  SYSTEM, and every authority SID; and
- `IsProcessInJob(child, exactJob) == TRUE`, with job accounting and the
  completely sized process-ID list containing exactly this suspended root.

Duplicate the child token to the minimum impersonation token required by
`AccessCheck` and actual opens. Stable code owns expected masks. For execution
root and all three files, require exact allowed read/execute/traverse and exact
denial of write, append, delete, owner, DACL, and SACL operations. Require
actual no-follow opens under impersonation, not `AccessCheck` alone.

Require actual denial of execution parent list/read/write, state root, broker
image/helper, all three stable sources, and every stable/authority root exposed
to this native lifecycle. If host bypass-traverse does not permit reaching the
exact granted execution root while preserving those denials, report clean
refusal/UNSUPPORTED diagnostics; do not add a parent or broad ACE.

Under the exact profile folder create one fixed token-derived probe with
CREATE_NEW, write/read/flush it, delete it by retained handle, and prove exact
absence. No probe byte is evidence. Revert impersonation, require the broker
thread has no token, and prove stable root/security observations unchanged.

The attribute-list construction plus the exact parent inherit-flag census and
excluded inheritable sentinel are the authoritative inheritance configuration
proof in this pre-resume slice. No candidate or RPC self-census is authority.
Any additional child-visible handle discovered through an available exact
hosted handle observation is a refusal, but the design does not depend on PID
text or candidate self-report.

Persist ADMISSION_PROVED only after every token, access, job, environment,
argv, cwd, and handle relation succeeds. This phase is a private recovery fact,
not portable evidence.

## Terminal reversal and recovery

The success path persists REVOKE_ATTEMPTED, calls `TerminateJobObject`, waits
the root process handle, requires the thread never resumed, drains stdout and
stderr to exact EOF, and repeatedly queries both active-process accounting and
a completely sized process-ID list until both are zero. The admission child
cannot create descendants, but using the final quiescence reducer here prevents
a second weaker teardown path.

Close every process, thread, token, impersonation, pipe, attribute, and job
resource with ambiguity accumulation. Then require exact job-name not-found.
Use the still-authenticated child token before its final close where needed to
prove the restored execution descriptors deny package access. Remove the fixed
scratch probe, restore root first then files, prove exact original security and
package-ACE absence, and only then run landed execution cleanup followed by
profile deletion/complete enumeration and folder absence. Persist OPWL
ABSENCE_PROVED before profile deletion only after job and grant absence; the
existing execution/profile terminal records then complete the group.

Recovery preflights every group before mutation and follows this order:

```text
authenticate state/profile/execution/OPWL records
  -> open exact named job if present and authenticate descriptor/limits
  -> terminate and prove job accounting/list zero
  -> close job/process resources and prove job name absent
  -> restore exact stable-only execution descriptors
  -> prove package SID denied and scratch probe absent
  -> landed execution root cleanup and parent absence
  -> profile deletion plus moniker/SID/folder absence
```

An absent job is accepted only under a durable phase proving either process
creation was not yet authorized or kill-on-close was configured before durable
LAUNCH_ATTEMPTED. A present job with wrong descriptor/name/limits refuses
without terminating an unrelated object. No numeric PID is signalled or used
as recovery identity. Failures stop later phases and retain all records.
