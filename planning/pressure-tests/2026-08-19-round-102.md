## Blocking finding

### `OP-R102-001` — selected-epoch active release accepts an absent prior

`requireProposal` first proves that the prior `Dt/Dv/Dr` is either all null or
all SHA-256. It separately proves that `SELECTED_EPOCH` has a complete non-null
authority-epoch triple. Its branch-specific restriction then applies only to
`REVIEWED_BOOTSTRAP_GENESIS`; there is no corresponding active-release rule
requiring a complete prior triple for `SELECTED_EPOCH`.

The committed ordinary pointer fixture demonstrates the gap: it constructs an
`ACTIVE_RELEASE` proposal with `producerKind=SELECTED_EPOCH`, three non-null
authority-epoch digests, and three null prior digests, then successfully
computes its proposal receipt. The E0 composition correctly refuses the same
producer kind as an N0 substitute, but that local E0 check does not close the
public common proposal parser used for later mutations.

A read-only in-memory probe against the exact checked-out TypeScript produced
this admission matrix:

| Proposal shape | Public parser result |
| --- | --- |
| `ACTIVE_RELEASE`, `SELECTED_EPOCH`, null prior, non-null epoch | **accepted** |
| `ACTIVE_RELEASE`, `SELECTED_EPOCH`, complete non-null prior and epoch | accepted |
| `ACTIVE_RELEASE`, reviewed-bootstrap, null prior and epoch | accepted |
| `ACTIVE_RELEASE`, reviewed-bootstrap, non-null prior | refused |
| authority rotation, reviewed-bootstrap, null prior and epoch | accepted |
| cleanup gate, reviewed-bootstrap, null prior and epoch | refused |
| selected-epoch active release with a partial prior | refused |

The first row contradicts the active-release authority ledger. The initial N0
proposal must be reviewed-bootstrap with null prior/epoch. Every later
active-release proposal must use the common selected stable-predecessor epoch
and a non-null exact prior selected triple at the same stable active-release
`Dp`. Accepting selected-epoch plus null prior creates an initial-looking
third branch that can discard the selected active-release lineage. Requiring a
stable epoch does not repair that missing predecessor edge.

Smallest repair: in the existing common proposal parser, require the prior
triple to be all SHA-256 whenever `pointerKind=ACTIVE_RELEASE` and
`producerKind=SELECTED_EPOCH`. Preserve reviewed-bootstrap/null-prior as the
only initial active-release branch and preserve complete-prior selected epoch
as the only later branch. Update the current ordinary active-release fixture
to carry a complete prior triple, and commit both the rejected null-prior
selected-epoch case and the accepted complete-prior control. No new schema,
member, digest, path, producer kind, receipt, validator, lifecycle state, or
capability is needed.

## `OP-R97-002` itself is removed

The E0 validator no longer accepts `coreExpectationFields` or any four-digest
active-release expectation. It instead takes the actual value, proposal, and
tip as three closed inputs and derives:

- `Dp` from kind `ACTIVE_RELEASE`, path
  `installation/active-release.json`, the selected anchor's installation,
  project, and state-root identities, transaction equal to installation ID,
  and source `none`;
- the exact empty VALUE position digest from `{ "mode": "VALUE", "parts": {} }`

- `Dr` from the actual proposal; and
- `Dt` from the actual selected tip.

It requires the proposal to be `ACTIVE_RELEASE`,
`REVIEWED_BOOTSTRAP_GENESIS`, `VALUE_PROPOSED`, `SELECT`, with null prior and
authority-epoch triples, and requires `producerDigest` to equal the recomputed
`Dsc`. The tip must carry the exact `Dp/Dv/Dr`. The E0 authority value's
active-release `Dp/Dt/Dv/Dr` members each equal the recomputed graph.

All six direct value bindings are present:

- release digest and release subject equal each other and the parsed reviewed
  operation's release subject;
- release subject also equals `Dsc.reviewedReleaseSubjectDigest`;
- manifest equals the operation and `Dsc` reviewed manifest;
- installed bytes equals the operation and `Dsc` reviewed installer read-back;
- independent review equals the operation and `Dsc` review; and
- reviewed installer equals the exact parsed bootstrap operation's installer.

The operation is independently required to be the selected anchor-bound
`BOOTSTRAP_INSTALL` arm and is recomposed into `Dsc`, so coordinated movement
