### `OP-R55-001` — Stable-release renderer authority is assigned outside the producer footprint

The governing ledger says the ISS-021 build alone produces
`hostRendererArtifactDigest`, stable release assembly binds it into the
independently reviewed `release-manifest/v1`, installation read-back binds the
identical artifact to the selected active release, and step 7 compares the
executing artifact to that active value. The equality and refusal language is
exact, but the producer packet does not put the release-side obligations on the
release owners:

- ISS-021's scope and predicted footprint are only the concrete host package
  and its tests; its AC9 nevertheless says release assembly and install
  read-back bind the digest.
- ISS-014 owns immutable successor release installation and later release
  facts, while ISS-020 owns the N0 release/install. Neither draft names
  `hostRendererArtifactDigest`, its reviewed-manifest binding, exact install
  read-back, or a substitution mutant.
- ISS-008 and ISS-026 correctly own step-7 comparison/composition, but neither
  can manufacture the missing stable-release provenance. A present digest or a
  host assertion is not proof that the independently reviewed active release
  selected those exact artifact bytes.

The contract parser can enforce a field's shape, but that does not replace the
producer evidence showing who computed it from the exact package artifact and
who admitted it into the reviewed release and selected installation. As drafted,
ISS-021 would have to mutate out-of-footprint release/bootstrap code or the
actual release owners could omit the evidence without violating their own
acceptance packets.

Bounded repair: keep the one existing digest and the exact ledger equality.
Add the release-manifest/install-readback production and substitution evidence
to the actual ISS-014 and ISS-020 producer/consumer and acceptance sections;
leave ISS-021 responsible only for deterministic host artifact production and
goldens, ISS-008 for dispatch-plan binding, and ISS-026 for composition. Prove
candidate-supplied, self-reported, stale, moved, wrong-package, and
manifest/read-back-substituted digests refuse. Do not add a second renderer or
registry digest, move release mutation into ISS-021, or add a dependency edge
unless the repaired ownership census demonstrates a missing correctness gate.

### `OP-R55-002` — The claimed sole ISS-021 renderer conflicts with the registered second host

The same governing paragraph says `templateId` selects an ISS-021 renderer and
ISS-021 is the sole producer of `hostRendererArtifactDigest`. The registered,
non-parked ISS-045 draft already requires the Claude host to render the same
`dispatch-brief/v1` through **its own** versioned deterministic template in its
own host package. ISS-045's implementation footprint does not authorize an
architecture/contract amendment, and no current decision says it reuses the
ISS-021 artifact. Both claims cannot hold for the shipped v1 contract.

This is not hypothetical future-consumer prose: ISS-045 is in the authoritative
roadmap and its own-template evidence is an acceptance criterion. Leaving the
collision for that implementation would make the generic dispatch contract
Codex-host-specific or require an implementation-selected renderer authority.

Bounded repair: choose one current v1 rule. Either (a) make the digest the exact
artifact of the selected installed host, name the release-reviewed mapping that
selects one host artifact, retain the same step-7 active-release equality, and
state ISS-021 as the first producer rather than the sole producer; or (b)
explicitly require ISS-045 to reuse the reviewed ISS-021 renderer artifact and
remove its own-template claim. If the second host is intentionally deferred,
park it with an explicit unpark/replacement-decision condition. Do not add
dynamic discovery, a network/filesystem resolver, or an unbound template
registry.

### `OP-R55-003` — The catalog producer lacks acceptance evidence for the repaired resolver census

The ledger and `module-abi.md` now require a dense 1–256 `dispatchCatalog`,
four-part resolver-key uniqueness, a single accessor/template pair per key,
and exact equality between the catalog pair projection and the descriptor's
duplicate-free worker-required action/capability census. ISS-011 is named as the
descriptor/catalog producer, but its draft still tests only generic descriptor
declarations, manifest rows, and closed brief emission. None of its acceptance
criteria names the catalog, the four-part collision mutants, the pair-projection
equality, or descriptor/manifest digest binding of those rows. ISS-002 can own
the pure parser and mutants, but it cannot prove that ISS-011 emits and release-
binds the required catalog.

Bounded repair: add one ISS-011 producer acceptance row covering the exact
closed catalog, accessor/template selection, duplicate-key mutants (accessor,
template, and both), duplicate/missing/extra pair census, and descriptor plus
release-manifest binding. Keep ISS-002's pure admission contract and existing
ISS-011 package footprint; no new registry, schema reference, or dependency
edge is needed.

## Direct contract attack results

- **Action-core schema/digest/framing:** the core is exactly the six closed
  members `actionKind`, `capabilityName`, `immutableSubjectDigest`,
  `moduleDescriptorDigest`, `requestedRole`, and `schemaVersion` in canonical
  member order. `schemaVersion` and digest domain are both
  `dispatch-action-core/v1`. The six ordered framed parts are text schema,
  text action, text capability, raw-32 subject, raw-32 descriptor, and text
  role. The existing public frame primitive supplies the platform prefix, NUL
  delimiters, U32 part count, typed tag, U64 length, and raw digest bytes.
  Brief, self-digest, rendered bytes/digest, dispatch/launch identity, renderer
  artifact digest, and their derived fields are explicitly excluded. No second
  plan or digest was introduced.
- **Catalog uniqueness and pair census:** the governing ledger forbids all
  repeated four-part resolver keys, including exact duplicates and rows whose
  accessor, template, or both differ. Each key selects exactly one closed
  accessor/template pair. The descriptor's separately declared worker pair
  census is duplicate-free and equals the distinct catalog pair projection.
  The remaining finding is producer acceptance, `OP-R55-003`, not local rule
  ambiguity.
- **Nine-kind cardinality:** all eight non-operator kinds require at least one
  unique `PRESENT` row and forbid `ABSENT`. `OPERATOR_ACTION` is exhaustive XOR:
  one-or-more unique present rows or exactly one absent row. Missing operator,
  present-plus-absent, duplicate absent, omitted-kind, duplicate
  `(directiveKind,code)`, and 257-row forms are discriminated.
- **Nonempty rendering/value:** each present row resolves a named nonempty
  digest or closed nonempty role from the exact action core and a fixed UTF-8
  template body of 1–8192 bytes. Rendering contains both; catalog keys, schema,
  action/capability, accessor/template IDs, and resource values are not
  rendered. No open reference schema, arbitrary JSON, module/operator prose,
  empty renderer, or empty typed-value surface remains.
- **Step 4/step 7 and self-certification:** step 4 equal-binds action,
  capability, subject, descriptor, and action-core digest. Step 7 equal-binds
  dispatch role to requested/brief roles and requires executing-renderer
  equality with the installed active-release value before rendering or
  ownership publication. Candidate, worker, stale, moved, substituted, and
  self-reported renderer values are expressly non-authoritative. The missing
  release-producer packet in `OP-R55-001` prevents that value's end-to-end
  provenance from being executable.
- **No-prose/removal:** a repository-wide scoped search outside pressure
  history found no `resourceKind`, `referenceSchemaVersion`,
  `referenceDigest`, old `actionPlanDigest`, or `templateRegistryDigest`.
  Resources expose only closed access plus opaque identity digest. No schema
  resolver, dynamic registry, path/network lookup, superseded authority
  generation, sparse tree, inventory, coordinator, retention/compaction kind,
  or diagnostic namespace was reintroduced.
- **Engine/adapter boundary:** action/catalog vocabulary is release-reviewed
  and denylist-checked; resource identity remains opaque; the host registry is
  installed/static; adapter, filesystem, network, and project vocabulary
  cannot resolve instructions. The only portability defect is the explicit
  cross-host producer collision in `OP-R55-002`.
