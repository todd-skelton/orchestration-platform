## Round-78 removal audit

### `OP-R78-001` — removed

The use-intent census no longer contains `genesisBootstrapInputDigest`, GENESIS
`Dh`, expected E0 `Dv`, `Dbg`, or another downstream digest. Its nested
`bootstrap-proposed-genesis-input/v1` contains only authority path, bootstrap
grant/transaction, genesis position, `G`, and `Dsc`. The normative order is now
constructible:

```text
independent bootstrap facts -> Dsc/G/Dp/genesis position
  -> owner ACTIVE + anchor ACTIVE -> use intent
  -> Dgb -> GENESIS Dh -> E0 value/Dv -> Dbg
  -> proposal/Dr -> tip/Dt -> Dgp
  -> anchor CONSUMED -> owner CONSUMED -> consumption receipt -> Dgse/context
```

`Dgb` consumes the already-computed use-intent digest; GENESIS `Dh` consumes
`Dgb`; the E0 authority value consumes `Dh`; `Dbg` consumes that value plus the
same `Dgb/Dh/Dsc`; and only the proposal consumes `Dbg`. No edge points from an
upstream preimage back to one of those downstream digests.

### `OP-R78-002` — removed

`state-mutation-bootstrap-anchor-consumption-receipt/v1` now has distinct
`runtimePostSelectionReceiptDigest` and
`runtimePostSelectionReceiptReadbackDigest` members. Its exact framing places
`Dgp` with the runtime authority tuple and separately places the persisted
`Dgp` readback after the value/proposal/tip readbacks. The equality matrix
requires the readback to match the parsed persisted receipt; the two meanings
are no longer collapsed into one member.

### `OP-R78-003` — removed for the decided E0 and expired-unused branches

The closed `external-destination-absence-observation/v1` census, digest domain,
ordered parts, create-once path
`state-mutation-destination-identities/<Dphys>/absence-observations/<Dabs>.json`,
producer, lock-held readback boundary, and equalities are explicit. `Dabs`
equal-binds `Dphys`, raw-derived `Ddest`, state root, current admitted `Dobs`,
helper, custody, reason, and observation time. It is produced only by the
ISS-022-admitted helper in the same applicable destination/anchor lock critical
section and is not made fresh merely by elapsed time. E0 selects
`RUNTIME_AUTHORITY_ABSENT`; expired-unused retirement selects
`DESTINATION_STATE_ROOT_ABSENT`. Opaque or stale caller-selected absence
digests refuse.

The separate missing `RETIRE_CONSUMED` branch rule is the fresh finding below;
it does not reopen the removal of round 78's absence-producer finding for the
two branches the amendment actually closes.

### `OP-R78-005` — digest cycle removed; one branch rule remains open

The lifecycle archive no longer names a teardown receipt. Its digest frames the
selected prior anchor triple/lifecycle, `Dabs`, and canonical archive bytes.
The teardown receipt then frames that already-known archive digest. Both are
created and read back before the anchor RETIRED proposal. The remaining chain
is one-way:

```text
Dabs -> prior-anchor lifecycle archive -> teardown receipt
  -> anchor RETIRED value/proposal/tip
  -> owner teardown archive -> owner RETIRED value/proposal/tip
```

Neither archive nor receipt names a future lifecycle or owner value, proposal,
or tip. The lifecycle archive is selected by the prior anchor-tip path; the
teardown receipt path identity is derived under
`bootstrap-anchor-teardown-id/v1` from `Dba`, prior anchor tip, retirement
transition, `Dabs`, and archive digest. The owner archive path is derived from
`Ddest` and the selected prior owner tip. The former archive/receipt fixed point
and crash-before-artifact ambiguity are removed. The fresh finding is not a
cycle: it is the missing exact `Dabs` branch predicate for
`RETIRE_CONSUMED`.

### `OP-R78-006` — removed

`leaf-bytes` now has one portable byte-to-scalar grammar: unpadded canonical
base64url decodes to 1--3072 bytes; those bytes must be shortest-form UTF-8
without BOM, surrogates, or noncharacters. Canonicalization uses pinned Unicode
15.1.0 data, locale-independent full lowercase with unconditional default
special casing for the two case-insensitive profiles, normalization after
lowercase, and exact UTF-8 re-encoding. The only admitted profiles are Darwin
lowercase NFD, Windows lowercase NFC, and Linux case-sensitive NFC.

The exact single-component, separators, dot components, drive/URI prefixes,
trailing-dot/space, Windows control/forbidden-character, alternate-stream,
ASCII-case-insensitive device basename, `CLOCK$`, `COM1`--`COM9`,
`LPT1`--`LPT9`, and superscript-1/2/3 alias rules are fixed. No uppercase or
case-fold round trip changes `straße` into `strasse`; Linux normalization/case
distinctions remain distinct. `Dphys` frames the canonical decoded leaf bytes
under the OS-selected fixed profile and excludes the rotating helper/profile.
ISS-006/022 require cross-OS, cross-helper, alias, invalid-UTF-8, Unicode-version,
and reserved-name mutants, so a helper observes rather than selects the
algorithm.

## Fresh blocking finding

### `OP-R79-001` — `RETIRE_CONSUMED` has no exact destination-absence branch

The anchor transition matrix permits both `RETIRE_UNUSED` from ACTIVE and
`RETIRE_CONSUMED` from CONSUMED. Both successor RETIRED values require a
non-null teardown receipt. The lifecycle archive schema accepts both
`lifecycle:ACTIVE|CONSUMED` but always requires
`destinationAbsenceDigest:sha256`; the teardown receipt always requires
`teardownEvidenceDigest`, which must equal the same-lock `Dabs` named by that
archive. The final order likewise says retirement from either prior lifecycle
creates the archive over a same-lock `Dabs`.

The absence contract, however, gives only these semantic assignments:

- E0 requires `reason:RUNTIME_AUTHORITY_ABSENT`.
- Expired-unused retirement requires
  `reason:DESTINATION_STATE_ROOT_ABSENT`.

Compatibility repeats that `Dabs` is the sole proof for “E0 and expired-unused
retirement.” Neither authority source assigns either reason to
`RETIRE_CONSUMED`, states whether consumed teardown must observe the whole state
root absent or only runtime authority absent, or gives a third closed branch.
The record parses with either existing enum, and the common teardown equalities
do not distinguish which premise authorizes destruction of a consumed
installation.

This is a public authority decision, not an implementation detail. Choosing
`DESTINATION_STATE_ROOT_ABSENT` would require consumed teardown to remove and
durably observe the entire destination before anchor retirement. Choosing
`RUNTIME_AUTHORITY_ABSENT` would permit anchor retirement while other
destination state may remain. Those are different crash/reinstall/data-loss
contracts and yield different canonical `Dabs`, archive, teardown receipt, and
downstream owner bytes.

The smallest repair is one normative branch row: select the exact existing
`Dabs.reason` and state-root/runtime predicate for `RETIRE_CONSUMED`, equal-bind
it to the selected consumed installation and same lock critical section, and
mirror that branch in ISS-002/006/020/022 compatibility evidence. Add no new
record, pointer, reason, receipt, lock, coordinator, or path unless the chosen
existing reason cannot express the required observation. Return the exact
repair head through a fresh independent review before implementation.
