## Round-227 repair verified

### One production abort-and-recovery owner

`abortThenRecover` is not a test duplicate or caller seam. It is a private
production function that:

1. awaits the existing close-bound, two-drain `BrokerCommand.hardAbort`;
2. retains any complete ordered abort AggregateError;
3. invokes `runRecovery(stateRoot)` regardless of abort success or refusal;
4. retains recovery failure independently; and
5. returns one frozen closed result containing only those two stable-owned
   observations.

The transformed test exposes the exact compiled function only through an
esbuild footer. Production exports remain unchanged and package-private.

### TEARDOWN consumes the exact result correctly

`teardownPrincipal` uses this exact function whenever normal native teardown is
not already proved. It does not infer cleanup from abort success.

- Recovery failure sets `RECOVERY_REQUIRED`, retains the active opaque
  principal and bundle handles, releases the operation lease, and throws one
  fixed aggregate containing the original operation, abort, and recovery
  failures in that order.
- Recovery success sets native clean. Any abort failure remains a fixed control
  AggregateError, but bundle custody is still rechecked/closed and the active
  entry is removed before refusal returns.
- A later bundle-close ambiguity becomes permanent failure and cannot advertise
  a retry with destroyed custody.
- Canonical abort plus canonical recovery permits clean teardown only when no
  earlier operation failure exists.

There is no path that sets native clean after abort refusal without RECOVER and
no path that returns candidate semantic success before cleanup.

### Composition deletion evidence is direct

The ordered fake records `ABORT_KILL -> ABORT_CLOSE -> RECOVER_SPAWN`. Because
its stdout and stderr endings are both withheld, RECOVER cannot spawn until the
two independently bounded drain results have settled and the root close is
proved.

The test calls the exact `abortThenRecover` function twice:

- successful RECOVER returns the retained abort AggregateError and no recovery
  failure; and
- failed RECOVER returns both abort AggregateError and recovery refusal.

Deleting RECOVER, moving it before root close, discarding abort refusal, or
discarding recovery refusal now changes the event log or result assertions.
The prior stdout-only, stderr-only, simultaneous, output-error-plus-stderr-
timeout, canonical abort, late diagnostic, input failure, SID binding, and
immediate execution-child mutants remain intact.
