## Why

ISS-110 (#367) repeatedly records host inspection of supervisor PIDs, worker
traces, PR checks, and operator gates to explain the M2 run. Its recovery note
https://github.com/todd-skelton/orchestration-platform/issues/367#issuecomment-5654691269
records an exited idle run while the selected milestone still had open
operator-blocked work. ISS-135 (#435) records the preceding out-of-scope
selection. Todd needs to inspect a detached run without maintaining a host
chat or reconstructing its state from several files.

## Done when

- A read-only status command accepts the existing loop config and is callable
  from Windows for the WSL executor. It offers concise human output and JSON
  from the same observation, without dispatching or changing GitHub/runtime.
- Report run, repository, configured scope, supervisor liveness, current
  issue/attempt and phase, PR/check/deploy links when known, stop reason and
  operator action, and paths to the relevant log and worker trace. Distinguish
  running, paused when supported, idle/exited, stopped, and unavailable evidence.
- Report observation time separately from the last evidenced progress and its
  age. Repeated polls and growing logs are not delivery progress; a live PID
  is not a healthy-worker claim. Missing timestamps or inaccessible WSL/GitHub
  are unknown, not a fabricated time or a healthy/complete result.
- Show the next eligible work and outstanding blockers using the existing
  adapter's scope, readiness, dependency, and ordering policy. Mark this as
  a current preview, not a reservation. Do not build a second scheduler.
- Idle with operator-blocked admitted work is shown as incomplete with the
  relevant issue links. An old final log line must not describe a newer run.
  Prefer existing process observations and records; add only missing timing
  or run identity data necessary for this status surface, outside the checkout.
- Tests cover active author/reviewer/check waits, dead supervisor with saved
  work, provider waiting, old logs, unavailable observations, and the ISS-135
  scoped-idle case. The command does not mutate state or launch workers.
- Extend docs/loop.md with exact status commands and interpretation. Include
  an observed read-only check against a detached run, recording any unavailable
  fields honestly; do not interrupt the active M2 validation to obtain it.

## Out of scope

A web dashboard, chat-session dependency, telemetry service, new scheduler,
automatic restart, credential inspection, or changes to the running executor.
