## Why

17:43Z, M2 run `m2-authority-scan-20260917T0912` had merged PR #8055 and cleaned
its source/review worktrees, but had no cycle-2 completion and remained in
post-merge polling. Issue #8041 was closed. Preserve this distinction if later
observations change; do not retrospectively label the recorded pending state a

deployment or a new release digest. The two CA reconciliation jobs succeeded;
their success is not staging app deployment evidence either.

[Milestone 162](https://github.com/chase-sets/chase-sets/milestone/162) expressly
allows script-only issue delivery with the deployment leg unexercised, requiring
actual trigger/filter and latest-deployment accounting, not a forced deployment.

`deployObservation` only selects non-skipped `Deploy Staging` jobs. This completed
no-deploy run therefore stays pending until the unchanged 45-minute window ends.
ISS-108 introduced the hook, ISS-122 set its window, and ISS-130 fixed the real
immutable-image step name. None covers authoritative no-deployment completion.

## Decision

Constraint: complete legitimate no-deploy delivery without calling a skip an
executed deployment or accepting missing authority. Simplest alternative: accept
any green workflow with skipped staging, rejected because unrelated skips and
trigger-only success do not establish scope. Chosen: add one `not-required`
observation beside the existing deployment/pending/failure observations, derived
from the owning completed release scope decision. Let the existing `afterMerge`
hook complete for that disposition and emit honest accounting to the existing
supervisor log. Keep deployment verification strict when deployment is required.
No new config flag, receipt protocol, provider reader or copied path classifier.

Accepted downside: a small adapter reader for the existing scope-step JSON log
and a narrow retained post-merge resume path. Revisit if the owning workflow's
evidence shape changes or another recorded no-trigger case needs support. A
missing workflow is not this case and remains pending/unknown, not `not-required`.
