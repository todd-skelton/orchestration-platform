## Context and evidence

`ISS-002` defines the pointer graph; `ISS-022` must prove the kernel exclusion
and custody premise. Receipts do not authenticate writers. Production authority
is the selected epoch, canonical state-root custody, private non-serializable
capability, and fixed OS lock.

## Scope fence

In: fixed `installation/state-mutation.lock`, closed pointer registry, private
mutation capability, value/proposal/conflict/tip/tombstone/archive/retention
storage, deterministic mutation/reconciliation, recovery-attempt reservation,
state-authority genesis/rotation mechanism, exact-byte CAS/readback, crash
recovery, and canonical unsupported/unknown results.

Out: record schema ownership, process policy, broker/release production,
distributed/network locks, leases/PIDs/timeouts as authority, and any fallback
not selected by a new replan.

## Decisions already made

The exact ordinary and rotation lock sequences, eleven pointer kinds, Dv/Dr/Dt
graph, proposal classification, canonical paths, durable tombstones, retention,
and epoch crash semantics in `supervisor-contract.md` are mandatory. The old
selected capability performs rotation; the new one is unusable until selected,
read-back, and lock release. Bootstrap genesis/reinstall is external.

## Acceptance criteria and evidence

1. Cross-process races choose one selected tip and classify every competing
   proposal from actual evidence; same mutation+bytes retries idempotently and
   same instance/different bytes refuses. Barrier-controlled tests cover every
   mutation boundary and source/path collision.
2. Ordinary commits acquire the fixed lock, validate authority/custody, reconcile,
   create/read values and proposal, reread the same epoch, CAS/read target,
   classify, reread epoch, and release. Fault injection yields predecessor or
   successor only.
3. Rotation under the old capability proves the new reviewed active release,
   helper/profile/ABI/custody, resolves every pending proposal among the other
   ten kinds, requires zero PENDING/UNKNOWN, selects/read-backs, and releases.
   Rotation-v-target races have one linear order; candidate self-rotation,
   rollback, wrong custody, and mixed epoch refuse.
4. Reservation selection reuses one winner per predecessor triple, resolves UUID
   conflicts, and enforces RESERVED→CONSUMED→TERMINAL→TOMBSTONE without a
   lifetime counter.
5. Terminal removal archives first and selects durable tombstone; crashes on
   every side of archive/tombstone preserve one authority. Bare absence after
   genesis and unauthorized archive selectors refuse.
6. Retention compaction requires selected checkpoint/plan/exact deletion/
   completion, never compacts pending, and emits durable `AUDIT_DEGRADED` only
   for the allowed old-terminal-loss case and exact operation matrix.
7. Unsupported filesystems, lock helpers, or custody guarantees refuse before
   mutation; no PID, age, lease, timeout, symlink, unsigned lock, or silent
   fallback is accepted.
