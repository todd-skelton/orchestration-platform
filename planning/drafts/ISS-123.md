## Why

A typed stop today posts the learning note, adds the `ready` label back, and
exits the supervisor with code 1 (`stopCycle` in
`scripts/dogfood/supervision.ts`, the catch block in
`scripts/dogfood/supervise.mjs`). On restart the same issue is selected first
again, because the adapter's readers know nothing about the stop. On Chase
Sets the `ready` label does not exist, so `restoreReady` fails, the stop
record never completes, and every restart replays the same failed stop. The
incumbent controller parks a failed artifact with one terminal comment and
moves to the next runnable issue.

## Done when

- The seam in `scripts/dogfood/repository-adapter.ts` gains
  `park({ repository, number, reason })` returning the one-sentence unpark
  instruction. The self adapter leaves the issue without `ready` and returns
  "add the `ready` label after acting on the note". The Chase Sets adapter
  adds `status:needs-replan` and returns "remove the `status:needs-replan`
  label after acting on the note". `restoreReady` is deleted from the
  supervision adapter.
- `stopCycle` posts the learning note with the unpark instruction appended,
  calls `park`, and records the stop complete. The note remains one
  paragraph.
- A stop exits the supervisor only when its reason names the run rather than
  the item: `current-main-unavailable`, `issue-observation-unavailable`,
  `native-launch-ceiling-exhausted`, any `malformed-supervision-record:*`,
  and `queue-internal-error`. Every other stop parks the issue and the
  supervisor selects the next candidate in the same invocation. The
  recovery text for `implementation-attempt-ceiling-exhausted` in
  `scripts/dogfood/supervision.ts` no longer tells the person to restart.
- Rule 7 in `docs/loop.md` states that a stop parks the issue with its note
  and the loop continues with the next runnable issue.
- `test/dogfood/supervision.test.ts` proves, with a fake adapter, that an
  item stop parks and the next cycle selects a different issue, and that a
  run stop exits without parking.

## Out of scope

Automatic unparking. A planning lane for parked issues. Changing what counts
as an actionable stop reason.
