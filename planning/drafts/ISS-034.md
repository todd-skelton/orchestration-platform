## Context and evidence

Certified N0 cannot perform its first supervisor tick or self-host work from a
cold session until exact native credential references are provisioned and bound
to its target host, user, installation, project, roles, and capabilities.

## Scope fence

In: execute the frozen production broker/credential runbook and independently
reviewed bootstrap `broker-plan`/`broker-install`/`broker-verify` and
`bind-credentials` commands from the attested candidate bundle; create the exact
custody principal/service/endpoint and install the reviewed broker executable;
provision native API items through its one-use operator channel and separate
implementation/review Codex homes; bind, inspect, cold-session verify,
revoke/rebind/removal-recovery drills, and retain non-secret receipts for N0.

Out: installing N0, putting secrets in files/environment/argv, cloud vaults,
unattended pre-login unlock, broad personal credentials, or source changes after
certification.

## Decisions already made

Bind exact references for `code-host.read`, `code-host.branch-pr-write`,
`code-host.merge`, `ci.read`, `ci.dispatch`, `artifact.read`, and
`artifact.write`, plus distinct
implementation and review Codex-home roles. Every reference binds target-host
fingerprint, current-user and custody identities, installation ID `bootstrap-n0`,
project ID, compatible adapter contract, role, closed capabilities, expiry, and
revocation generation; it is installation-scoped rather than tied to one release.
The separate initial `broker-active-client/v1` binds the certified N0 release,
self-host executable and operation-manifest digests, active-release record, and
generation zero. The human bootstrap grant and release-promotion
authority are not worker credentials.

## Acceptance criteria and evidence

1. With explicit OS administration, the reviewed bootstrap transaction creates
   or upgrades only the exact probe-admitted custody identity/service/endpoint
   from the independently reviewed `ISS-038` reduced service to the candidate-
   bound final broker binary read-only. It preserves and re-verifies the same
   host public key/reference/generation without exporting private bytes; old
   reduced-service bytes lose start/connect authority. Fresh read-back and
   direct worker/endpoint attacks pass before provisioning. Evidence: plan/apply/
   verify/fault transcript and principal/service/process/endpoint/file census.
   The plan consumes the exact `host-custody-retention-receipt/v1`; apply emits
   `broker-upgrade-receipt/v1`, and verify proves a CAS from the reviewed reduced
   identity to the candidate production identity while retaining the exact host
   key public value/reference/generation and never exporting private material.
2. The operator provisions each item through the admitted one-use broker-owned
   native UI/channel or role login path and `credential bind` records only
   reference metadata. Secret canaries
   are absent from source, state, argv, environment, process listings, artifacts,
   and logs. Evidence: before/after census and redaction scan.
3. A real reboot and next eligible user session starts with an empty ambient
   credential environment. The reviewed bootstrap binder calls only broker
   `verifyBoundCapability` for the static certified read-only canary of each
   required reference and receives non-secret role/capability proofs. Evidence:
   before-reboot/cold-session caller-broker-canary transcript, real synthetic
   provider read-backs, and secret/process/environment scans.
4. Missing, locked, moved, expired, revoked, wrong-user/host/project/role,
   aliased home, and extra capability all refuse before external access.
   Evidence: executed production-safe canaries using synthetic companion items.
5. The resulting broker-install and credential-set receipts are immutable input
   to `ISS-027`; N0's
   supervisor cannot start without an exact match. No candidate runtime or
   source-tree process receives a reference; the reviewed bootstrap binder is
   the sole preinstall process and receives only non-secret reference metadata.
   Evidence: preflight and process census.
6. Invoke exactly the bootstrap broker plan/install/verify commands followed by
   `orchestration-bootstrap bind-credentials --request
   <credential-bind-request.json> --output <credential-set-receipt.json>` from
   the target-host staging bundle reviewed in `ISS-037`. The request binds the
   accepted review, candidate, host-custody receipt, user, state-root digest,
   installation, adapter, and closed references. Source-tree, unreviewed,
   wrong-host, or secret-bearing input refuses. Evidence: executable/argv/input
   manifest and target state/credential census.
7. Exercise interrupted install/restart and `broker-remove` against a synthetic
   companion transaction, proving exact recovery and absence of duplicate
   principals, services, endpoints, binaries, items, or live processes without
   removing the healthy N0 broker. Evidence: transaction and teardown census.
8. Prove the same synthetic installation-scoped reference remains secret and
   valid across a promotion-bound N0→N1 active-client generation change without
   reprovisioning: N0 works only before activation, N1 only after, and each
   wrong/replayed/mixed generation refuses. Evidence: broker/reference/client-
   generation transcript with no new secret input.
9. Every reduced-service state (`ABSENT`, live, stopped, changed generation,
   unknown process, stale retention receipt, partial prior upgrade) has one
   explicit plan/apply/verify disposition. Only the exact retained/live identity
   upgrades; unknown or mismatched state refuses without teardown or key copy.
   Evidence: closed state/transition and interruption matrix.

## Predicted footprint and dependencies

Creates no tracked source. Owns only target custody identity/service/endpoint,
installed reviewed broker bytes, native items/role homes, and scrubbed production
broker/binding receipts under the explicit state root. Lifecycle code belongs to
`ISS-032`, bootstrap commands to `ISS-020`, and runbook bytes to `ISS-033`; all
are included in `ISS-019` certification. Blocks N0 install.

## Operator actions

Todd explicitly authorizes the exact OS principal/service installation,
provisions the scoped native items, performs role-specific `codex login`,
approves one real reboot/login test, and retains the independent reference
receipt. Never paste a secret into a platform command or issue.
