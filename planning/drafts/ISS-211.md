## Decision

The loop must tolerate short transport loss at these observations without treating uncertain mutation or wrong authority as success.
A generic retry of every unknown is smaller to call but would repeat semantic refusals and could double-post a note.
Choose a small fixed retry at the two owning GitHub boundaries, with observation-first reconciliation after any uncertain post and no blind mutation retry.
Accept a bounded delay and a non-parking unknown stop when transport remains unavailable or the post outcome cannot be established.
The choice is wrong if an actual adapter/caller regression still requires a per-item host restart after one transient read, or if it duplicates a write or relaxes an identity refusal.

## Done when

1. **AC1 Bounded transport only.** At draft mirroring and learning-note
   reconciliation, retry only classified GitHub transport failure during a
   read, at most three total read attempts with deterministic 1-second and
   2-second waits. This wraps only the primary `observeDraft` read and its
   post-mutation re-observation via `confirmMutation`, and the observations
   inside `postLearningNote` and its reconciliation. The sibling
   `observeSibling`/`loadBoardSnapshot` read is OUT. Shared `gh`, `ghJson`,
   `run` and `repositorySupervisionAdapter().issue` stay single-shot for every
   other caller; those supervision callers retain
   `QueueBlocked("issue-observation-unavailable")` unchanged. No mutation
   command is retried by the read retry; AC3's proved pre-send allowance is
   separate. Use the actual adapter error boundary, not an arbitrary
   `{state:"unknown"}` retry or a generic GitHub framework. An HTTP 5xx on a
   read is retryable transport; a 5xx response to `comment` is uncertain,
   never proof of pre-send failure. Acquired malformed data, wrong issue/key,
   authorization refusal (including 401/403), and semantic drift never become
   retryable success or `needs-mutation`. Preserve the existing request, test
   and job timeouts. Retain only sanitized, bounded
   transport diagnostics through the existing unknown/error evidence path;
   neither tokens nor authorization headers may appear there. Evidence:
   adapter/caller tests inject distinct transport, parse, identity, refusal
   and drift cases, including an exhaustion control, with fake time.
2. **AC2 Draft before and after the write.** A transient transport failure
   followed by an authoritative matching observation works both before a
   draft intent and during post-mutation confirmation without a stop, new
   worker launch or implementation attempt. Observe again before any edit;
   a confirmed draft is a no-op. A lost successful edit response must be
   reconciled by observation without a second edit. Persistent transport
   failure remains the existing explicit non-parking draft state/outcome
   unknown stop, never a fabricated receipt, `needs-mutation`, completion or
   PASS. Preserve sibling draft identity and body-only mirror refusals.
   Evidence: actual `githubDeliveryAdapter` observation and `deliveryStep`
   tests count calls, intents, receipts and writes for both observation phases.
3. **AC3 Marker-first learning note.** Use the existing stop marker and saved
   intent. After a possibly successful comment with a lost response, retry
   observation first; one observed matching comment satisfies reconciliation
   without posting again. At most one additional post per `postLearningNote`
   call is allowed, only after a classified pre-send failure AND fresh
   authoritative absence proving the prior operation could not have been
   accepted; otherwise stop `learning-note-state-unknown` non-parking. Absence
   alone after an uncertain response is insufficient; a 5xx on `comment` is
   uncertain, never pre-send. This in-call rule does not change restart
   reconciliation or add a record field. Retain duplicate-marker,
   wrong-key/number, closed-issue and malformed-observation refusals. Write
   stop-completion only after the matching note is confirmed. Evidence:
   `stopCycle`/`reconcilePendingStop` and actual supervision-adapter tests
   distinguish a pre-send failure, lost successful response, existing note,
   duplicate and unresolved post without duplicate writes; the classified
   pre-send failure plus fresh absence permits no more than one additional
   post in that call, while uncertain responses permit none. Capture the
   authoritative issue/comment probe at the post-response reconciliation
   moment, not from a pre-post or cached observation.
4. **AC4 Discriminating replay regressions.** Exercise one transient read then
   success, persistent failure/exhaustion, wrong/malformed identity, lost
   successful mutation response, pre-existing note, confirmed draft no-op,
   and the pending run-stop first and second invocation paths through the
   owning adapters and callers, not a disconnected helper. Assert no parking,
   invented cycle completion, reset of history/attempts/launches, or duplicate
   writes. Remove just the retry in a targeted mutant: the
   success-after-transient regression must fail while other controls remain
   valid. Freeze unrelated inputs so each refusal test detects its named
   failure rather than an earlier fixture failure. Through the real
   supervision adapter, a transient transport failure at a non-note caller
   (`startCycle` or `completeCycle`) produces exactly one observation call
   and the unchanged `issue-observation-unavailable` stop; a failing
   `gh pr ready` mutation command is called exactly once, and an uncertain
   `comment` 5xx is not resent. Evidence: executed focused tests with fake time,
   call counts and saved-record assertions.
5. **AC5 Compatibility and qualification.** Existing saved config, stop
   intents, markers and receipts resume without backfill or manual edits;
   same-run first/second invocation semantics and the run-versus-item parking
   policy remain unchanged. Run `pnpm typecheck`, `pnpm format:check`,
   `pnpm planning:check` and `pnpm test` foreground in the native M1 author's
   WSL worktree under the existing native loop contract, obtain independent
   exact-head review, and require final-head
   Ubuntu/Windows/macOS bootstrap green before landing. Do not transfer the
   new behavior into ISS-210's historical candidate or treat its old PASS as
   review of this change. Evidence: legacy-shape replay, complete gate
   receipts and exact-head hosted check identities.

operation would risk duplicate mutation. No new public term, UI, schema or
product data path.
