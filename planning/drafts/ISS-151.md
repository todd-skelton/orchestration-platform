## Why

Run m1-intake-refresh-20260914T1635 selected ISS-146 in cycle 2 with a fresh
worktree root and stopped `worktree-collision:source` before any author
launched. The directory did not collide; `git worktree add` refused because
branch `codex/iss-146` is still checked out in the preserved
`/root/orchestration-m1/worktrees/iss-146-attempt-1-source` from the earlier
run that stopped on a host gate. ISS-145 admitted an accepted replan against
its preserved attempt; a fresh run re-attempting a host-stopped issue has no
equivalent, so every preserved attempt makes its issue unrunnable until a
person deletes worktrees the rules say to preserve.

## Done when

- Source, review, and pilot worktrees for a fresh attempt use a run-scoped
  branch name (or a detached checkout with a run-scoped branch created at
  commit time) so a preserved attempt from another run never blocks setup.
  The published branch name and the PR refresh path keep their existing
  identity rules; the change is local branch naming only.
- A preserved worktree that already holds the issue branch is left exactly as
  it is; the fresh attempt does not remove, move, or reuse it, and the stop
  record names the preserved path when a collision is still detected on the
  published branch.
- Resuming a saved attempt in the same run still reuses its own worktrees and
  branch; the run-scoped name only applies when the attempt is being created.
- Regress: fresh run with a preserved attempt for the same issue proceeds to
  author; same-run resume reuses its worktrees; two preserved attempts from
  two runs do not collide with a third; published-branch collision still stops
  with a typed reason.
- docs/loop.md records the branch naming and the preserved-worktree rule.

## Out of scope

Cleaning up preserved worktrees, changing the accepted-replan path from
ISS-145, altering published branch names or PR identity checks, and any
reclamation policy.
