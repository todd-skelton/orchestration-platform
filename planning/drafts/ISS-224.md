## Why

When the attached child exits after a nonterminal status, the parent currently
returns only the child exit code. The host must then infer whether the run was
lost, and can discover it long after the lifecycle moment. The smallest useful
repair is a bounded Windows-side record at the existing EOF/exit join, without
inventing a worker verdict or changing the supervisor's lifecycle authority.

The lifecycle probe is the exact moment the implementation needs: status
`observing-author` was the last emitted line at `17:06:45.171Z`, then the WSL
child disappeared during the update window. The implementation must capture
`observedAt` when the parent has observed EOF and `WaitForExit`, not infer it
from a child timestamp, log mtime, or a later host poll. The child exit code is
read as the required integer at that same join after `WaitForExit()`.

### Options

| Option | Assessment | Choice |
| --- | --- | --- |
| Track the last status in the existing read loop and atomically write one note after EOF/exit only when no terminal status was seen | Reuses the attached boundary, preserves stdout/stderr and exit propagation, and adds no watcher or second authority, but it requires the real terminal stop to be parent-visible. | **Select with the protocol seam below.** |
| Add a watcher/sidecar process that monitors WSL independently | Reject. It duplicates liveness authority, introduces a race and a new process lifecycle, and cannot promise a note when Windows or the parent also dies. |

### Protocol decision

Select reviewer option (i): make the real terminal `blocked` status visible on
the protocol stream. `scripts/dogfood/supervise.mjs` serializes the line once,
writes it to stderr first (preserving the existing `supervisor.log` path), then
best-effort writes the same line to stdout. A stdout write failure is caught so
the stderr copy remains the retained line; the parent-death case still carries
no guarantee. `scripts/executor/run-loop.sh` needs no edit: healthy stdout is
already appended by `tee`, while stderr is already redirected to the log. A
healthy run therefore has the intentional duplicate `blocked` line in
`supervisor.log`; a broken stdout still leaves one stderr line. The parent
echoes exactly that one additional `blocked` protocol line. This is the
declared AC2 output change required to expose the existing terminal stop; all
other status, stderr, native-db and exit output remains unchanged.

The parent-side terminal set is exactly the real statuses `{idle, paused,
blocked}`. `complete`, `supervisor-started`, `observing-*` and
`advancing-attempt` are nonterminal. There are no protocol statuses `stop`,
`cancel` or `pause`; `paused` is the only pause terminal. The producer test in
`test/dogfood/supervise.test.ts` covers dual-write and a broken stdout, and the
consumer tests in `test/executor.test.ts` cross the attached PowerShell
boundary.

### Note location and closed schema

The note directory is supplied to `Start-AttachedSupervisor` as
`-LossNoteDirectory`. The script passes `Join-Path $env:LOCALAPPDATA
'orchestration-platform\supervisor-loss'`, a Windows host path outside the
checkout and the WSL runtime. `config` is the `-Config` argument recorded
verbatim as the WSL-side string supplied. It is never resolved or read on
Windows. `run` is the `run` string of the last accepted status line that
carried one (`^[A-Za-z0-9._:-]{1,128}$`), otherwise `null`. Tests pass a
temporary directory. This is a function parameter only; no new script-level
parameter or WSL access is introduced.

Each attachment that ends without a terminal status writes one note named
`<observedAt as yyyyMMddTHHmmssfffZ>-<parent PID>.json`, via a temporary
sibling and `[System.IO.File]::Move(tmp, final, $false)`. An existing final
name fails the write (reported as a note-write failure) and is never
overwritten or appended. Sequential attachments under the same run therefore
retain one note per attachment.

The JSON object is closed (no unknown keys) and UTF-8 encoded:

```json
{
  "schemaVersion": "supervisor-loss/v1",
  "kind": "supervisor-loss",
  "classification": "supervisor loss/unknown outcome",
  "run": "<run identity>",
  "config": "<verbatim WSL config argument>",
  "observedAt": "<UTC RFC3339 instant ending Z>",
  "lastObservedStatus": "<nonterminal status or null>",
  "childExitCode": 0
}
```

`childExitCode` is the required integer read after `WaitForExit()`; there is no
missing-code state or `childExitCodeAvailable` key. A note is written only
when the exact terminal set `{idle, paused, blocked}` was not observed. A note
is never a native stop, worker verdict, retry permission, or GitHub
instruction. The serialized UTF-8 object has exactly these eight keys and is
at most 4096 bytes;
`run` and `lastObservedStatus` are 1-128 ASCII characters (or `null` for the
status), `config` is the supplied WSL string of at most 1024 characters, and
`observedAt` is one UTC RFC3339 instant. The parent refuses a value outside
these bounds rather than writing an unbounded note; `config` is bounded as the
supplied WSL string and is never interpreted as a Windows path.
