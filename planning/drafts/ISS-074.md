## Context and observed need

PRs #330 and #331 required repeated controller bridges after exact-head worker
review: four package gates, approved draft mirrors, branch and draft-PR
publication, hosted observation, ordinary merge, and verified cleanup. ISS-073
is closed with independent review and actual Windows/macOS/Linux boundary proof.
Its external action helpers are source evidence for this behavioral extraction,
not runtime dependencies or templates.

## Scope and non-goals

In: one private normal-delivery command which consumes an independently reviewed
exact candidate, controller-held authorization bound to the stable controller
revision, an external state directory and an explicit self-repository policy
adapter. The portable transition logic stages
intent before provider mutation, reconciles provider state before retry, runs
the four actual gates around approved draft mirroring, publishes or updates one
draft PR, observes every required hosted check at the reviewed head, performs an
authorized ordinary squash merge, and cleans only resolved selected worktrees
and their branch after confirmed merge. Delivery records support post-cleanup
status without calling the original worker flow.

Out: public-repository adapters, public self capability, general scheduler or
delivery framework, credential broker, setup/repair/queue automation, automatic
N1 promotion, certification, release activation, new worker arguments or
environment rules, and changes to production release/operator fences. The
running stable pilot may build and test this candidate but may not activate or
certify its own successor.

## Acceptance evidence

1. One authorized invocation can advance a reviewed exact head through gates,
   approved planning mirrors, one publication identity, exact-head three-OS
   hosted checks, one ordinary merge and protected cleanup. Worker PASS and
   worktree content never grant mutation authority.
2. Immutable external intent precedes each provider mutation. Restart observes
   existing identities, heads and receipts; unknown, malformed, partial or
   ambiguous outcomes stop closed. Publication, merge and cleanup are not
   repeated when provider state or a receipt already confirms them.
3. Every configured required check is present exactly once, links hosted
   execution, and passes at the reviewed head. Missing, duplicate, skipped,
   failed or drifting checks cannot authorize merge.
4. Cleanup validates the two exact worktree paths, their clean reviewed heads,
   the selected branch and a surviving controller checkout. It preserves every
   unrelated worktree and branch. Confirmed delivery records remain sufficient
   after the selected worktrees are absent.
5. Output contains only typed status, run/issue identity, exact head, review/PR/
   merge identities and required-check links. It contains no raw provider error,
   worker prose, environment value or credential material.
6. External review and hosted proof must precede use of the reviewed successor
   for a genuinely useful subsequent issue. Fixture success alone does not close
   the real-use outcome; actual counts, heads, identities, hosted execution and
   restart evidence must be retained.

## Verification plan

The controller runs `pnpm typecheck`, `pnpm format:check`,
`pnpm planning:check`, and `pnpm planning:board-check` at the exact candidate.
Source work uses installed static TypeScript, pinned Prettier on changed
executable files, and planning entrypoints only; it does not run local Vitest,
`node --test`, native builds, addons, probes or lock experiments. Hosted
Windows/macOS/Linux tests execute the real portable composition and cover the
normal path, direct-Node imports, policy separation, restart/idempotency,
malformed authority, head drift, missing/duplicate/skipped checks, uncertain or
partial provider outcomes, no double publication/merge, and post-cleanup status.
Every changed assertion and the complete exact candidate require independent
review before publication or activation.

## Predicted footprint and review attack surface

Predicted change: private `scripts/dogfood/` delivery flow/composition, one
GitHub CLI adapter and explicit self policy, focused discovered dogfood tests,
this trial note, ISS-074/EPIC-KERNEL/M2 roadmap registration and pressure round
477. No package command, compiler option, public capability registration or
production fence changes.

Attack controller authorization substitution; self-review or stale-head reuse;
gate reordering around board mirroring; missing, duplicate or skipped checks;
credentials crossing worker boundaries; mutation without prior intent; retry
after unknown publication/merge/cleanup; duplicate PR or merge; unapproved
draft text; cleanup before confirmed merge; broad or moved path deletion; state
inside a checkout; and success inferred from advisory prose.

## Falsifiable prediction

The next measured improvement removes the enumerated routine delivery bridges
without changing worker or release authority. Any remaining manual bridge,
duplicate mutation, wrong-head acceptance, unsafe cleanup or need for a general
framework falsifies this bounded extraction and must drive the next recorded
correction rather than be hidden by fixture or terminal success.
