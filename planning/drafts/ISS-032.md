## Context and evidence

ISS-031 selects the only admissible custody topology. Recovery authorization
must be acyclic, broker-authenticated, transaction-bound, and separately
attached to a selected live attempt. Pointer receipts alone do not authenticate
the broker or writer.

## Scope fence

In: confined broker core/service topology selected by ISS-031, credential
references, recovery authorization core, CREATED/CONSUMED/REVOKED state,
native consume/removal and post-selection receipts, authorization attachment,
active-client/successor admission transitions, IPC framing/attestation/replay
defense, teardown, and lifecycle fault/attack tests.

Out: generic pointer CAS/lock/private state capability, contracts, supervisor
attempt creation, release policy, bootstrap workflow, arbitrary callbacks/
network endpoints, secret export, or consumer/project vocabulary.

## Decisions already made

The exact core census/mode unions and consume/revoke/attachment ordering in
`credential-broker.md` are mandatory. ISS-004 performs selections through a
live mutation handle and selected run-current checkpoint. Gate binds the
selected CREATED tip/value/proposal plus core digest; the core excludes gate/
lifecycle/consume/revoke/attachment, so no cycle exists. Historical producers
are scoped sparse-tree projections against the live current nonempty root;
`historyRootKind=EMPTY`/`Dhe` cannot issue a producer projection.
Current projections come from authority value v3/history root v2 and the
thirteen-slot packet. Broker code does not interpret node plans, coordinator
lifecycle, inventory pages, or the authority-run epoch split.

## Acceptance criteria and evidence

1. The selected ISS-031 cross-principal custody topology denies direct store,
   endpoint, handle-duplication, impersonation, copied executable, replay, wrong
   principal, and worker-role attacks on all three OSes. Secrets never cross IPC
   or enter argv/environment/journal/receipt.
2. Core canonicalization validates the exact common census and exact BOOTSTRAP/
   SUCCESSOR unions, including distinct predecessor/successor manifests and
   precomputable fence identity. `candidateOperationManifestDigest` is excluded
   and its presence fails as an unknown field. Every required field, every
   forbidden/excluded field, and coordinated recomputed substitutions have
   executable mutants; excluded fields cannot enter core.
3. CREATED prebinds consumeOperationId/native receipt path. Consumption writes
   and verifies native receipt, requests ISS-004 CONSUMED selection containing
   its digest/core/gate, then writes post-selection receipt over `Dt/Dv/Dr`.
   Partial/reordered/repeated/wrong-native/wrong-gate variants refuse.
4. Revocation writes native removal proof first, selects REVOKED second, and
   writes post-selection receipt third. Archive/tombstone follows exact shared
   removal protocol; bare absence cannot revive authority.
5. Attachment is a separate selected pointer. ATTACHED composes full validators
   for current release, broker, auth, gate/fence roots and ordered histories,
   reservation, LIVE descriptor/launch, argv/process, accumulator predecessor,
   and current epoch. It never accepts a terminal summary as launch authority.
6. First attachment uses explicit accumulator genesis; later attachment binds
   the immediately prior selected terminal summary/accumulator triple. Fixed
   packets validate indefinitely many attempts without full-history arrays.
7. Stable N alone prepares successor admission. The exact selected promotion
   activates N+1 and revokes N; candidate/self-activation, wrong generation,
   moved release/executable/manifest, skipped active pointer, or concurrent
   successor refuses. Pre-fence and abort clients cannot attach or widen scope.
8. All public APIs are total through ISS-002 closed snapshots. Envelope and
   every nested slot test transparent/throwing proxies, symbols, accessors,
   extras, exotics, and mutable/sealed/frozen arrays.
9. Every selected authorization/attachment transition uses `MUTATION_COMMIT`,
   a live ISS-004 handle, and exact run-current core/selector/post evidence.
   Historical-read, serialized, stale-root, copied, or revoked authority refuses.
10. E(n) broker/client authority revokes at authority CAS. The credential
    service accepts E(n+1) only after ISS-004 validates the exact Drh/terminal
    run/Dhand transition; it cannot retain an old client or manufacture
    materialization/coordinator evidence.
