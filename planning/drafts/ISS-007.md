## Context and evidence

Exactly one active controller requires durable session identity, renewal, and
handoff semantics independent from wall-clock narration or host PIDs. See
`docs/architecture/vision.md` and the state primitives from `ISS-004`.

## Scope fence

In: acquire, renew, inspect, release, stale-session handoff, bounded session
duration, and read-only health reduction.

Out: worker ownership, distributed consensus, automatic host selection, or
consumer scheduling policy.

## Decisions already made

Session identity, clocks, freshness, maximum duration, skew bounds, and
transitions are settled in `docs/architecture/contract-decisions.md` and the
`Session lease` table in `docs/architecture/state-machines.md`.

## Acceptance criteria and evidence

1. Concurrent acquisition yields one controller without split-brain. Evidence:
   barrier-controlled race tests on each OS.
2. Renewal, expiry, release, and handoff form a total state machine with a named
   day-after steady state. Evidence: transition-table tests.
3. Clock rollback or excessive forward skew cannot extend authority. Evidence:
   fake-clock negative controls.
4. Read-only health inspection produces no filesystem delta. Evidence:
   before/after manifest comparison.
5. `@orchestration-platform/session` replaces only the static `session`
   command-family placeholder and exports its typed handler registration.
   Evidence: CLI command-census and envelope contract tests.

## Verification plan

`pnpm --filter @orchestration-platform/session test`

`pnpm run test:lease-state-machine`

## Predicted footprint and dependencies

Create implementation in predeclared `packages/session/`, its static CLI
handler registration, and lease fixtures. Blocked by `ISS-003`, `ISS-004`, and
`ISS-006`; blocks dispatch and journal. No shared-manifest or glossary edit.

None.

## Independent review packet seed

Attack stale-writer renewal, wall-clock discontinuity, holder reuse, malformed
timestamps, release races, and a transition without a stable post-transition
state. Use the complete transition table and filesystem-delta evidence.
