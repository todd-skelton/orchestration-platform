## Why

([#439](https://github.com/todd-skelton/orchestration-platform/issues/439)),
was observing hosted checks for [PR #691](https://github.com/todd-skelton/orchestration-platform/pull/691).

`issue-observation-unavailable`, one attempt and no diagnostic, then blocked

and `gh issue view 439 --json number,body,state,labels,comments` returning a

at 17:52:25Z, wrote `cycle-15-stop-1-complete.json`, and exited again with the

completed the cycle and selected ISS-111 for cycle 16. The selected artifact

`/root/orchestration-m1/runtime/m1-iss146-147-20260914T2325/` and the log
is `chase-sets/.orchestrator/platform-runs/m1-iss146-147-20260914T2325/supervisor.log`.

At current `origin/main` `c510f5ef6e23c9e80c158d702aa5c0fbe875e0a1`,
`scripts/dogfood/supervision.ts::repositorySupervisionAdapter().issue` retries
only the `learning-note` purpose. Other selected, in-flight callers of
`adapter.issue(config, number)` catch a failed `gh issue view` once, throw
`QueueBlocked("issue-observation-unavailable")` without the already-classified
`GithubCommandFailure.message`, and leave `stopCycle` no diagnostic for its
stop body or `supervise.mjs` blocked output. `reconcilePendingStop` returns the
completed run-scoped reason, and `supervise.mjs` exits before the saved cycle's
delivery path. This recorded cycle is the blocker for the small mechanism.

## Decision

Give selected in-cycle issue reads the same three-attempt, 1-second then
2-second, classified transport-only read retry that ISS-211 gave learning-note
reads. Keep the retry at the owning `issue()` observation boundary, not around
the whole cycle or a write. Exhaustion preserves the host-scoped stop and
retains a sanitized, bounded originating `gh` category diagnostic in both the
stop body and blocked output. Acquired malformed data, wrong number/key or
unexpected state is never retryable.

The second restart was caused by the same stop's reconciliation boundary and
belongs in this slice: after an unfinished `issue-observation-unavailable`
run-stop note is reconciled on restart, continue the already-selected cycle
in that same invocation. Do not generalize this to item stops, other run-stop
reasons or first-invocation failures. A fresh failure on resumed delivery still
stops ordinarily. This is a narrow completion branch, not automatic restart
of a dead supervisor. The choice is wrong if a short classified read failure
still requires a host restart, if semantic refusal is retried, or if a pending
note takes two restarts or posts twice.

## Done when

1. **Selected observation retry.** `repositorySupervisionAdapter().issue`
   retries a failed `gh issue view` command only when
   `GithubCommandFailure.transport` proves transport loss, at most three total
   reads with deterministic 1-second and 2-second waits. Cover every
   already-selected in-cycle call, including hosted-check observation and
   saved-selection resume; keep learning-note semantics and their existing
   limit. Never retry a mutation or the whole cycle. Exclude pre-selection
   `loadBoardSnapshot`/census, `currentMain`, and unrelated draft/sibling
   reads: they still refuse without polling or fallback under ISS-163. Keep
   existing timeouts. Acquired malformed JSON/issue, wrong number/key,
   unexpected state and authorization refusal are immediate semantic or
   command refusals, not transport retries. Missing/ambiguous command
   provenance fails closed. A successful retry uses a fresh authoritative
   response at that exact observation moment, not cached pre-failure data.
2. **Exhaustion and evidence.** Persistent classified transport failure still
   makes `issue-observation-unavailable` a non-parking run stop with the saved
   selection/history/attempt intact. Propagate the originating sanitized,
   bounded `GithubCommandFailure` category into `QueueBlocked.diagnostics`,
   the existing stop-message diagnostic and blocked output. No raw stderr,
   command echo, token, header or comment body is logged. Distinguish a
   malformed successful response and wrong issue/state from exhaustion; do
   not fabricate completion, PASS or a new attempt.
3. **One-restart pending note.** With a selected open issue and an unfinished
   run stop whose reason is `issue-observation-unavailable`, restart first
   reconciles its marker by fresh issue/comment observation, writes the
   existing stop-completion record once, and proceeds into that same saved
   cycle without exiting on the historical reason. If note state remains
   unknown, stop as before; no duplicate comment, stop ordinal, label,
   mutation or worker launch is created merely by reconciliation. Completed
   notes, item stops, other host/gate stops, closed selections and subsequent
   fresh failures keep their existing paths. Repeated restart is inert for
   the old note and preserves all retained attempt/participant records.
4. **Discriminating production-path regressions.** A visibly **synthetic**
   fixture drives the real `supervise.mjs`/supervision-adapter composition into
   `observing-hosted-checks` with one transport-shaped `gh issue view` failure
   and then a valid selected issue. Baseline must stop
   `issue-observation-unavailable` with no diagnostic; candidate continues
   after exactly one retry and no additional worker/attempt. Independently
   hold all other fixture facts valid and vary persistent transport loss
   (three calls, diagnostic in retained stop and blocked line), successful
   malformed JSON, wrong number/key, unexpected state and authorization
   refusal (one call each), with no duplicate note or mutation. Kill a
   retry-removal mutant with the transient-success control and a
   diagnosis-removal mutant with the exhaustion control. Exercise pending
   note before/after reconciliation and repeated restart through production
   composition, proving a single restart resumes while a nonmatching note
   does not. Historical real #439/PR #691 identities are evidence only, not
   synthetic controls with altered facts.
5. **Author-local handoff.** Add focused `test/dogfood/*` adapter and
   composition regressions, and a short `docs/loop.md` note distinguishing
   selected in-cycle reads from pre-selection authority failures and the
   one-restart reconciliation. Run manifest-resolved `pnpm typecheck`,
   `pnpm format:check`, `pnpm planning:check` and `pnpm test` at the candidate
   head with no timeout increases, skips or weakened assertions. Supply
   red-before/green-after and fake-time call-count/record evidence to the
   independent exact-head reviewer. Final-head hosted bootstrap and host
   installation are later delivery gates, not author-local claims.
