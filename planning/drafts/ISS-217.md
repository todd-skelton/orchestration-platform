At current `origin/main` `c510f5ef6e23c9e80c158d702aa5c0fbe875e0a1`,
`scripts/dogfood/supervision.ts::repositorySupervisionAdapter().issue`
classifies a failed `gh issue view` as `GithubCommandFailure`. Outside the

malformed response throws the same reason with no diagnostic (`:1106-1107`).
`stopCycle` and the `supervise.mjs` blocked line already carry

of a failed learning-note lifecycle (`:422-427`). On restart,
`reconcilePendingStop` completes the late note and returns the run-scoped
reason, and `supervise.mjs:459-463` exits before the saved cycle. The second
restart then resumes that cycle unchanged, because the completed stop is
skipped. This recorded cycle is the blocker for both mechanisms: the dropped
diagnostics left its cause unknown, and the reconciliation exit forced
restart 2.

## Decision

Keep ISS-211's decision that non-note issue reads stay single-shot. This cycle
does not show that a selected-read retry would have removed the stop, because
the identical retry on the note read did not. Instead, make the next
occurrence diagnosable and remove the second restart. Every
`issue-observation-unavailable` thrown by `repositorySupervisionAdapter().issue`
carries a bounded, sanitized diagnostic. A failed command carries the existing
`GithubCommandFailure.message` category. An acquired response that fails the
shape check carries the fixed text `malformed issue observation`. A failed
learning-note lifecycle keeps its `QueueBlocked.diagnostics` beside
`lifecycleReason` in the blocked line.

After an unfinished `issue-observation-unavailable` run-stop note is
reconciled on restart, continue the already-selected cycle in that same
invocation, exactly as the second invocation does today. Do not generalize
this to item stops or other run-stop reasons. Gate stops need explicit grant
authority (ISS-157), and other host stops name a remedy that a restart does
not prove. A fresh failure on resumed delivery stops ordinarily. This is a
narrow completion branch, not automatic restart of a dead supervisor. The
choice is wrong if a reconciled observation stop still needs a second
restart, if a pending note posts twice, or if a failed or malformed issue
observation leaves no category in the stop record and blocked line. A
selected-read retry needs its own intake, after a retained diagnostic shows a
transport-classified failure short enough for it to clear.

## Done when

1. **Observation diagnostics.** `repositorySupervisionAdapter().issue` keeps
   one `gh issue view` per non-note call. Learning-note reads keep ISS-211's
   retry and limit. A failed non-note command throws
   `QueueBlocked("issue-observation-unavailable", failure.message)` with the
   existing sanitized `GithubCommandFailure` category. A successful response
   that fails the shape check throws the same reason with the fixed diagnostic
   `malformed issue observation`. Both reach the stop intent body's
   `Diagnostic:` and the blocked line's `diagnostics` through the existing
   `stop`/`stopCycle`/`blocked` path. No raw stderr, command echo, token,
   header or comment body appears. Add no retry, timeout, poller, schema or
   record field. Pre-selection `loadBoardSnapshot`/census and `currentMain`
   keep their ISS-163 refusal without polling or fallback.
2. **Lifecycle diagnostic.** When a stop's learning-note lifecycle fails with
   a `QueueBlocked`, `supervise.mjs::stop` also returns that error's
   diagnostics, and `blocked` prints them as `lifecycleDiagnostics` beside the
   existing `lifecycleReason`. A non-`QueueBlocked` lifecycle error keeps
   `learning-note-state-unknown` with no diagnostic. The original stop reason,
   scope and saved intent are unchanged.
3. **One-restart pending note.** Take a selected open issue with an unfinished
   run stop whose reason is `issue-observation-unavailable`. Restart
   reconciles its marker by fresh issue/comment observation, writes the
   existing stop-completion record once, and proceeds into that same saved
   cycle without exiting on the historical reason. Place the branch in
   `reconcilePendingStop` beside the ISS-157 early return. If note state
   remains unknown, stop as before. Reconciliation alone creates no duplicate
   comment, stop ordinal, label, mutation or worker launch. Completed notes,
   item stops, other run stops (including gate stops outside ISS-157's grant),
   closed selections and later fresh failures keep their existing paths.
   Repeated restart is inert for the old note and preserves all retained
   attempt/participant records.
4. **Discriminating regressions.** Use synthetic identities only. Historical
   #439/PR #691 are evidence, not fixtures.
   - In `test/dogfood/supervision.test.ts`, drive the real adapter through its
     injected `commands`/`pause`. A failed transport-shaped `gh issue view` at
     `startCycle` and at `completeCycle` is called once, never pauses, and
     yields `issue-observation-unavailable` with the sanitized category.
     Update the ISS-211 case "non-note %s observation stays single-shot"
     (`:306-322`) from `diagnostics: undefined` to that category, keeping its
     one-call and no-pause assertions.
   - In the same file, malformed JSON and a wrong number yield
     `malformed issue observation`. The existing ISS-211 refusal rows
     (`:250-302`) keep their reasons.
   - In `test/dogfood/supervise.test.ts`, the synthetic supervision fixture
     throws `issue-observation-unavailable` with a synthetic diagnostic while
     `observing-hosted-checks`. The retained stop body and blocked line carry
     that diagnostic, and a failed synthetic note adds `lifecycleDiagnostics`.
   - Through the existing saved-selection composition, an unfinished
     `issue-observation-unavailable` run stop reconciles once and the same
     invocation reaches the saved cycle's next step. At baseline it exits
     blocked with the saved reason. An unfinished run stop with another reason
     (synthetic `gate-host-failed:...`, no grant) still exits. A repeated
     restart posts nothing.
   - Kill a continuation-removal mutant with the pending-note control, and a
     diagnostic-removal mutant with the command-failure control.
5. **Author-local handoff.** Amend `docs/loop.md` beside the ISS-211 scope
   (`:153-163`, which stays true) and the resume/pending-stop text
   (`:519-570`). Describe the diagnostics and the one-restart continuation.
   Run manifest-resolved `pnpm typecheck`, `pnpm format:check`,
   `pnpm planning:check` and `pnpm test` at the candidate head, with no
   timeout increases, skips or weakened assertions. Supply
   red-before/green-after and mutant evidence to the independent exact-head
