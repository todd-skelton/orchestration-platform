## Context and evidence

The first completed dogfood loop proved the supervised M0 path through PR #320.
Its required four-key final JSON preserved authority but dropped the worker's
actionable findings from useful terminal output. Progress traces still contained
text, leaving the pilot operator to recover it manually. This observed friction,
not a speculative reporting requirement, justifies one additive diagnostic field.

## Scope and non-goals

In: add one optional bounded worker summary to the private dogfood terminal;
request it in the native adapter's output schema while accepting legacy four-key
verdicts; surface valid text in terminal success/failure output; and cover
compatibility, malformed, overlong, and authority-separation cases.

Out: a reporting framework, structured findings, capture/retention policy,
authority derived from prose, changes to verdict/head/identity checks, production
worker contracts, promotion, candidate activation, or automatic publication.

## Acceptance criteria and evidence

1. The output schema keeps `run`, `role`, `head`, and `verdict` required and adds
   only an optional string summary bounded at approximately 2,000 characters.
2. A legacy four-key verdict parses unchanged. A valid summary reaches the
   durable terminal and useful pilot output; non-string/empty values are omitted
   and overlong text is bounded.
3. PASS/FAIL, exact head, role, run, attempt identity, footprint, review, and CI
   decisions never consult summary text. A failed worker retains the exact named
   `author-failed` or `reviewer-failed` reason while exposing valid diagnostics.
4. Focused fake-adapter tests exercise positive, compatibility, malformed,
   overlong, and misleading-text cases without a native worker or local runner.

## Verification plan

The controller runs `pnpm typecheck`, `pnpm format:check`,
`pnpm planning:check`, and `pnpm planning:board-check`, then executes the intended
tests in hosted macOS/Windows/Linux CI. Independent review attempt 2 attacks every
changed assertion and verifies that diagnostic text cannot grant authority.
This source attempt may run only the installed TypeScript, formatting, and
planning static entrypoints; it does not claim hosted or independent evidence.

## Review attack surface

Attack a legacy verdict rejected for missing summary, summary becoming required,
non-string or huge values leaking through, truncation changing verdict parsing,
diagnostic prose overriding FAIL/wrong head, changed failure reason names, hidden
trace dependence, and claims that this private field is a production receipt.

## Falsifiable prediction and review-by horizon

One optional terminal string, one 2,000-character bound, and additive output
projection will preserve the next worker's actionable findings without changing
any authority decision. The next ordinary dogfood cycle is the horizon. If it
still requires trace archaeology, loses role attribution, or needs structured
machine action, this slice is falsified and must be replanned from that evidence;
do not grow it preemptively.

## Non-completion claims and glossary

`summary` is untrusted advisory worker text. `diagnostics` is its bounded pilot
projection. Neither is a receipt, review, PASS, readiness, publication, promotion,
production certification, or self-promotion signal. No new milestone is created.
