## Why

The 2026-09-14 handoff restart of self run m2-supervised-20260913 resumed its
saved cycle-2 selection ISS-129 (#421), although that issue had closed outside
the unfinished run. Executor ff873c421d3e1467f68bea3c8bf86d9bd2eaa836, launched
as PID 735161 at 2026-09-14T13:11:31Z, stopped with candidate-workspace-drift
and lifecycleReason stopped-issue-state-unknown instead of continuing. The
learning note is on #421; the stopped run and worktrees remain preserved.

## Done when

- On native resume, observe a saved selection's issue before reconstructing
  or validating its stale source workspace. If the same issue is already
  closed, reconcile that selection as complete using the existing cycle
  mechanism and continue to current eligible work or ordinary idle.
- Preserve accumulated participant history, consumed launches and attempts,
  failed reviews, source state and prior stop records. This reconciliation
  recognizes external closure; it does not invent author/reviewer PASS,
  hosted green, merge, deployment or milestone exit evidence.
- Repeated resume is idempotent. A still-open selection follows the existing
  source/delivery recovery path and its ordinary checks. Unknown issue state
  or mismatched identity must not be treated as closed.
- Regress the recorded closed-selection case with a stale or unavailable
  candidate workspace, an existing pending stop, repeated resume, successor
  selection and exhausted idle. Prove the closed item launches no worker or
  source repair and that the successor retains prior budget/history. Cover
  still-open and unavailable/mismatched issue observations.
- Document the behavior and the actual preserved-run observation in
  docs/loop.md, distinguishing external closure reconciliation from native
  end-to-end delivery. The host resumes the old run only after the reviewed
  implementation lands; workers do not edit its runtime or the executor.

## Out of scope

Changing milestone order, bypassing readiness or dependencies, reopening or
reimplementing closed work, raising attempt ceilings, automatic restart,
editing the running executor, and hand-written delivery receipts.
