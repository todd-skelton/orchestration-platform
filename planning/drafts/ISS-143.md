## Why

The JPEG native cycle twice stopped at `missing-or-duplicate-check:PR Required`
just after local gates and publication succeeded. A later API observation showed
the exact linked workflow and a same-run host restart could continue. The
recurring incident is
https://github.com/todd-skelton/orchestration-platform/issues/367#issuecomment-5662310822;
the earlier occurrence is comment `5660812394` on the same issue. The current
publication is Chase Sets PR #8005, exact candidate
`ac2c54ce80865c0501d71aae4676c719b0d1eaf1`, workflow run `34831336666`.
The initial API snapshot was not captured, so this does not establish that all
check rows were absent; advisory checks can appear before the required check.

## Done when

- Automatically reobserve the narrow startup state where required checks and
  workflow runs are not yet visible, including when advisory check rows exist.
  Keep a fixed short bound in the current attempt, without new configuration,
  runtime migration, workers or publication replay.
- Use the real checks adapter and delivery engine in regression tests: initial
  invisibility, linked pending workflow, actual required green, and ordinary
  delivery proceed without host restart. Prove absence beyond the bound still
  stops and wrong-head/PR, duplicate, malformed, failed or skipped required
  evidence never becomes success.
- Preserve exact candidate and publication checks, actual required green,
  independent review, ordinary local gates, merge and deployment requirements.
  Document the actual bound and restart limits in docs/loop.md.
- Run typecheck, format:check, planning:check and test. Do not edit, restart or
  install over the running native supervisor or alter its runtime/product.

## Out of scope

Indefinite missing-check tolerance, CI waivers, new retry budgets, workflow
provenance frameworks, product edits, publication, merge, deployment or M2
completion claims.
