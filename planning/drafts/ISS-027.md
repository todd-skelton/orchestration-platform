## Context and evidence

After the complete source—including bootstrap workflow and installer—has one
final certification, a distinct reviewer and human operator may authorize only
that digest. Bootstrap mechanisms are frozen by `ISS-020`; certification is
`ISS-019`.

## Scope fence

In: consume the accepted exact-candidate review from `ISS-037`, exact human
grant, bootstrap authorize/install/recover/verify invocations, installed-byte read-back, authority grant,
receipt, and executed pre/post-mutation recovery drills.

Out: tracked source changes, rebuilding or recertifying, N0 orchestrating N1,
package publication, or manual file substitution.

## Decisions already made

All evidence binds one candidate/source digest. The reviewed bootstrap
executable performs authority transitions; candidate runtime code cannot grant
itself authority. No tracked source may change between certification and grant.
The production path is one operator-visible, immutable transcript; an approval
authorizes identifiers and digests, never a mutable branch, tag, or latest run.
Bootstrap state uses the selected state-authority epoch and common pointer
protocol. Genesis selects `pointer-current-tip/v1` over `active-release/v2`;
terminal cleanup retains durable tombstones. Recovery authorization uses
`recovery-authorization-state/v2` CREATED/CONSUMED/REVOKED with ordered native
and post-selection receipts, and attempts use reservation plus linked accumulator.
Before E0, the reviewed installer consumes the ISS-020 stable physical identity,
one selected destination owner, external anchor/use intent, acyclic E0 core, and
runtime/external post-selection receipts. Production never infers authority from
state-root absence or an unsigned history row.

## Production operator transcript

1. Read the completed `ISS-019` certification and accepted `ISS-037` review
   receipts. Record their numeric workflow run/artifact IDs, actors, candidate,
   certification, review, installer/test, workflow, host, and source digests.
   Refuse absent, rejected, duplicate, expired, nonterminal, or mismatched
   identities; certification itself contains no semantic-review result.
2. The pinned authorization workflow is dispatched only by the accepted pinned
   review-workflow identity admitted by `ISS-029`, whose attested upstream is the
   certified workflow run. It takes the certification and accepted
   review numeric identities/digests as immutable inputs, and waits in the one
   admitted protected environment `bootstrap-n0`. It re-verifies source,
   workflow, certification, review, actor separation, target-host fingerprint,
   target current user, installation `bootstrap-n0`, and destination-state-root
   digest before showing an approval.
3. Todd signs in to GitHub, opens that exact waiting deployment, and compares
   every displayed run/artifact/actor/host/state-root identifier and digest with
   the independently retained certification and review receipts. Approve within
   15 minutes only when they match. Self-review and administrator bypass are
   disabled; timeout, rejection, or mismatch emits a refusal with no target
   mutation.
4. The authorized workflow emits only the attested one-use grant bundle and its
   numeric artifact identity; it never receives target credentials or installs.
   On the declared target host, Todd creates a permission-restricted staging
   directory and downloads candidate, certification, review, and grant only by
   their recorded numeric repository/run/artifact IDs. The target-host verifier
   admitted by `ISS-029` checks all attestation claims and rehashes every byte.
5. Confirm the candidate/grant inputs declare installation ID `bootstrap-n0`,
   the ISS-022-admitted `Dphys/Dobs`, and a destination whose selected owner is
   absent or the exact reviewed RETIRED predecessor, then invoke the canonical
   manifest grammar exactly: `orchestration-bootstrap authorize --candidate
   <candidate.json> --certification <certification.json> --review <review.json>
   --grant <grant.bundle> --output <install-input.json>`;
   `orchestration-bootstrap install --input <install-input.json> --output
   <install-result.json>`. Exit 0 makes that output the bootstrap receipt and is
   followed by `orchestration-bootstrap verify --receipt <install-result.json>`.
   If and only if install exits 6, the output is the recovery transaction with
   its already-selected `recovery-authorization-state/v2` `CONSUMED` value,
   native-consume receipt, and post-selection consume receipt; invoke
   `orchestration-bootstrap recover --transaction <install-result.json> --output
   <bootstrap-receipt.json>` on the same target host, then verify that receipt.
   Each command consumes the preceding bound envelope; no implicit cwd, latest
   artifact, ambient grant, alternate executable, or raw recovery secret exists.
6. An operator cancellation is valid only before the first recorded destination
   mutation. Cancellation proves authoritative destination absence and drives
   selected pre-gate `CREATED` through native removal, selected `REVOKED`, and
   post-selection revoke receipt, or post-gate CREATED/CONSUMED state through
   durable `ABORTING` plus the same broker-ordered revoke and selected cleanup
   archives/tombstones. Todd invokes only canonical `orchestration-bootstrap abort
   --input <install-input.json> --output <abort-receipt.json>` using the same
   immutable install input produced in step 5; the command derives and reads
   back transaction/authorization/gate/destination state. Interruption
   reruns that exact command and resumes only the same abort. The live execution proves
   authorization-created → gate create/read-back → consume/read-back → first
   mutation ordering. Once mutation begins, interruption/process kill/host reboot may only
   prove the native-broker pre-consumed transaction binding and run canonical `recover` for
   the same transaction/digests. Missing, locked, copied, replayed, substituted,
   or wrong-host/user capability remains `RECOVERY_REQUIRED`; no new install may
   start and no artifact or staging directory may be substituted.
7. Verify selected owner/anchor CONSUMED, E0 core/proposal/tip, runtime and
   external post-selection receipts, installed bytes by read-back, and the exact
   `ISS-034` credential-set and broker-active-client receipts. Install/read back
   the immutable
   supervisor shim/native definition, externally select genesis
   `pointer-current-tip/v1` over `active-release/v2` for N0 under the reviewed
   state-authority epoch, grant only that installation lease eligibility,
   start its supervisor, and observe a 30-minute watch containing
   at least one terminal no-work tick. Run source-tree and one-byte-altered
   installer canaries; neither may acquire the lease or produce a valid tick.
8. Retain only attested packet/receipts under the state root. Remove staged

## Acceptance criteria and evidence

1. One bootstrap receipt binds exact source/candidate, workflow/installer/test
   bytes, all OS receipts, reviewer attempt, human grant, installed bytes, and
   capabilities. Evidence: schema plus independent read-back.
2. One-byte source/installer change, moved review subject, reused author/reviewer,
   stale grant, or mixed certification refuses before install. Evidence: one
   executed mutation per field.
3. Pre-mutation abort changes no authority; post-mutation interruption resumes
   only the same reviewed transaction. Evidence: complete bootstrap fault matrix.
4. Installed N0 alone acquires the self-host project lease and completes its
   next no-work cycle. Evidence: source-tree/altered-bundle canaries and receipt.
5. The complete production transcript is replayable from numeric run/artifact
   IDs and signed envelopes, and every path before first mutation is proven to
   leave the destination and authority unchanged. Evidence: transcript validator
   plus pre-mutation filesystem/authority snapshots.
6. Every path after first mutation either reaches verified N0 or resumes the same
   immutable transaction; substitution and restart-as-new are impossible.
   Evidence: barrier-controlled crash matrix at every recorded mutation.
7. Staging creation, access, transfer, retention, and cleanup permissions are
   least-privilege and journaled without secret material. Evidence: ACL/mode
   receipts and credential/approval-token canary scans on all three OSes.
8. Missing/rejected/substituted review, wrong protected environment, cloud-runner
   install, wrong target host/user/state root, and artifact-transfer substitution
   refuse before mutation. Evidence: joined actor/host/digest timeline and one
   executed mutant per custody boundary.
9. Initial activation proves the scheduler definition binds only immutable Node/
   shim/installation identities while active-release and broker-client generation
   both name exact N0. Missing/mixed/tampered records or a scheduler definition
   that embeds the N0 executable/release digest refuses before the first tick.
   Evidence: installed-definition/active-record/broker read-back and process trace.
10. Every interrupted recovery selects/reuses the exact
    `recovery-attempt-reservation/v1` for its predecessor accumulator triple and
    verifies a bounded linked `recovery-attempt-accumulator/v1` packet. There is
    no lifetime generation/array cap; collision, fork, stale attachment, and
    full-history assumptions refuse.
11. Terminal uninstall/abort retains selected active-release, authorization,
    gate/fence/attempt archives and `pointer-tombstone-value/v1` tips. Pointer
    deletion, bare absence, v1 authority records, or missing/reordered native and
    post-selection receipts refuse.
12. The production transcript proves one destination lock/winner, pre-expiry
    anchor intent, every crash reconciliation, selected owner/anchor CONSUMED,
    and exact reinstall reuse. A competing installation ID, loser replay,
    helper/profile observation change, stale owner, retired reinstall, or
    review-core/anchor cycle refuses.
