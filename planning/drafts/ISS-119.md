## Why

The first ISS-106 unattended run selected ISS-113
[#378](https://github.com/todd-skelton/orchestration-platform/issues/378) at
`b4b8bb33ba6c7ec34a2a886925fae67236eebf7f`, then stopped before any worker
or pull request with `overlapping-setup-paths`. The retained
`cycle-1-stop-1.json` records the failure. The self-repository queue
intentionally uses the stable executor as both `repositoryRoot` and
`controllerRoot`, but setup compares those two references to the same
directory and rejects the supported configuration.

## Done when

- A queue derived from one self-repository loop config can pass setup and
  launch work when `repositoryRoot` and `controllerRoot` name the same stable
  executor.
- The redundant comparison is deleted. The controller, state, pilot, source,
  and review boundaries remain enforced, and the existing author-private temp
  boundary is unchanged.
- A regression builds the real composed queue configuration and passes its
  setup request through the real Git setup adapter; it does not substitute a
  hand-built setup config or fake adapter.
- No exception list, guard, record, schema, authority, or framework is added.

## Out of scope

Editing or recovering the stopped ISS-106 runtime. Changing worktree or temp
layout. Changing worker, review, retry, or publication behavior.
