## Simplest shape

Extend the existing gate-stop authorization with a source-stage admission
branch and one additive continuation reservation. Reuse the native refresh,
gate runner, review admission, and ordinary delivery path; do not create a
second launcher, a manual replay format, or a parallel recovery mechanism.

## Scope fence

In scope: `scripts/dogfood/queue.ts`, `scripts/dogfood/supervision.ts` as
needed, focused tests under `test/dogfood`, and the gate-stop section of
`docs/loop.md`.

The source branch admits only a pre-review stop whose reason is exactly a
`gate-host-failed:<gate>` or `gate-attribution-unknown:<gate>` source-stage
failure, with a host grant naming the exact state directory, stopped candidate
head, landed repair SHA, and authority URL. Before any reservation or worker,
it fetches main and proves the repair is on fetched main and absent from both
the stopped candidate and its recorded base. It refuses, by named reason, for
wrong phase, repair absent from main, repair already in candidate/base,
mismatched state directory, stale grant, or any other stop class.

On admission it preserves the original stop, gate logs, terminal, source
history, attempt/retry/ceiling records, and all prior evidence. It records one
single continuation reservation, refreshes the candidate onto repaired main
through the existing native refresh, reruns the pre-review gates, then requires
the ORIGINAL complete independent review (not DELTA) and all ordinary delivery
gates. It consumes no implementation attempt, renews no ceiling, and does not
rewrite or delete retained records. A later failure is a separate ordinary
stop and cannot spend a second source continuation.

Non-goals: hand-editing runtime records; resetting attempts, retries, charges,
ceilings, or history; manual worker launch; broadening to unrelated stop
classes; changing reviewer, provider, registry, hosted-CI, publication, merge,
deployment, or executor-install authority; changing the existing delivery
grant semantics; or adding a heavy verifier, ControllerBattery, or
ControllerPrecursor path.

## Not built

| Not built | Reason |
| --- | --- |
| Hand-edited runtime/config records or manual launch | The retained stop and native lifecycle remain authoritative. |
| New attempt, retry, charge, ceiling, or reset path | This is a continuation of the saved attempt only. |
| DELTA review | No review existed at the source stop; the original complete independent review is required. |
| Broad stop-class admission | Only the demonstrated pre-review gate-host-failed/gate-attribution-unknown class is in scope. |
| Heavy verifier or controller wrapper | Heavy reproduction belongs to the host implementation/verifier lane and exit 73 is non-execution. |
| Parallel/background evidence work | Evidence must remain bounded, foreground, and on disk. |

## Done when

1. **Baseline reproduction.** On current main, the retained stop fixture
   reproduces the source-stage rethrow and unchanged replay (red) before any
   reservation. The implementation lane owns the heavy reproduction; this
   planning lane records only the bounded evidence paths.
2. **Candidate continuation.** With a valid host grant and repair SHA on
   fetched main, the source candidate is refreshed through the existing native
   refresh, pre-review gates rerun, and the original complete independent
   review plus ordinary delivery gates are required. The original stop,
   history, logs, terminal, attempt count, retry state, and ceiling are
   byte-preserved; no implementation attempt is consumed and no ceiling is
   renewed.
3. **Fail-closed negatives.** Focused tests prove named refusal before
   reservation for wrong phase; repair absent from fetched main; repair already
   in candidate; repair already in base; mismatched state directory; stale or
   reused grant; wrong stop class; changed candidate head; and an existing
   continuation reservation. A second observation is inert.
4. **Lifecycle and authority.** The grant is bound to repository, run, issue,
   source state directory, stop identity/reason, candidate/base heads, repair
   SHA, fetched main, authority URL, and complete retained history. Main is
   fetched immediately before admission. Main movement, missing evidence,
   malformed grant, or contradictory lifecycle data refuses without write,
   reservation, launch, charge, or attempt consumption.
5. **Direct verification.** Changed tests are rerun directly by the reviewer;
   no ControllerBattery or ControllerPrecursor is used. Planning/review/docs
   lanes run only cheap focused checks. A heavy command refuses with exit 73
   before reservation and returns to the host. The implementation lane records
   baseline-red, candidate-green, all refusal negatives, and direct changed-test
   reruns; hosted checks and ordinary delivery remain required.

## Defect-class constraints

The overlapping ledger constraints from `references/defect-classes.md` are
part of this issue, not merely dispatch guidance:

- **state-machine-steady-state-missing:** enumerate source-stop, admitted,
  refreshed, reviewed, delivered, refused, and re-stopped states; prove the
  admitted steady state is inert on replay and routine operation.
- **lifecycle-repair-misses-sibling-retained-state-entrypoint:** exercise fresh
  source admission, retained stop replay, source/review callers, and the
  supervision path; do not fix only ordinary delivery.
- **retry-events-double-count-terminal-outcome:** preserve the one charged
  implementation attempt, retry history, terminal records, and ceiling; no
  duplicate continuation or refund.
- **retained-artifact-schema-ratchet:** keep all old records byte-for-byte;
  make the reservation additive, versioned, and closed-schema validated.
- **temporal-join-ignores-causality:** bind grant to exact run, issue, stop,
  state directory, candidate/base, fetched main, repair, authority, and history.
- **stale-review-bound-to-wrong-head:** refresh onto the repaired main and
  require a fresh original review at the resulting exact head; old review
  evidence is not authority.
- **closed-schema-shallow-validation:** reject unknown, missing, malformed,
  stale, duplicate, or contradictory nested grant fields before writes.
- **presence-evidence-treated-as-completeness:** require complete stop,
  attempt, candidate, base, gate log, terminal, and history evidence, not mere
  file presence.
- **missing-fail-closed-regression-evidence:** freeze the retained fixture,
  prove baseline-red/candidate-green, and keep one-variable refusal mutants
  red.
- **mandated-external-assertion-contradicts-authority:** captured authority and
  fetched-main ancestry govern; contradictory external claims refuse unchanged.
- **unrunnable-verification-command:** keep planning/review/docs checks cheap;
  heavy commands exit 73 before reservation and return to host attribution.
- **worker-tool-ceiling-kills-heavy-verifier-wrapper:** do not wrap, extend,
  or background heavy verification to bypass its ceiling.
- **claude-background-task-dies-on-session-exit:** no detached or background
  evidence task; retain complete foreground evidence on disk.
- **parallel-node-verifiers-exhaust-host-memory:** no parallel verifier or
  ControllerBattery/ControllerPrecursor route.
- **vitest-wall-clock-timeout-under-parallel-host-load:** use bounded focused
  direct reruns and report timeout as evidence, never increase timeout or turn
  silence into PASS.
- **future-capability-documented-as-current:** docs describe source admission
  only as an implementation target until exact-head code and evidence prove it.
