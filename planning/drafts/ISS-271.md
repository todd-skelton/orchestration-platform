## Decision

A pre-review source-stage gate stop is retained on every replay, and no
installed grant admits it, even after its repair lands on main. The simplest
viable alternative is a fresh run identity, which consumes no attempt for a
stop before any hosted or exact-head review verdict but discards and re-runs
the completed author work. This issue adds one `sourceStage` grant member
that continues the saved attempt after a refresh, the pre-review gates and the
original complete review. The downside accepted is one more continuation
branch and reservation in the queue state machine. The choice is wrong if
source-stage stops with landed repairs prove rare enough that fresh runs cost
less than maintaining this branch.

## Simplest shape

Extend the existing gate-stop authorization with one additive `sourceStage`
member, checked in the chase-sets `beforeReview` before the retained-stop
rethrow (`queue.ts:5721-5722`). On admission, write one single-writer
`source/gate-stop-continuation.json` reservation and use the sibling
`source/gate-stop-continuation/` as the new source state directory. The
reservation and directory follow the pre-review `gate-correction` layout
(`queue.ts:5864-5922`); both names are already admitted by `queue.ts:548`
and `:1460`. Unlike `gate-correction`, which re-enters `step`
(`queue.ts:5717-5719`) to run a correction author (`flow.ts:970-997`),
this continuation launches no author.

Refresh the stopped candidate onto the recorded main with the existing
`currentMain` + `rebaseOnto` primitives (`refresh.ts:20-48`).
`refreshDelivery` requires `SourceEvidence.reviewId` and is not called
pre-review. No review evidence is fabricated.

Then re-enter through the existing reviewer-only `reviewRefresh`
(`flow.ts:927-940`, ISS-148), with:
- the sibling `SourceConfig` `{ ...current, base: <recorded main>,
  mainBase: <recorded main>, stateDirectory: <sibling> }`;
- the unmodified source reviewer prompt (no DELTA suffix);
- `inherited` set to the retained `source/` directory;
- the retained source retries.

That records the sibling `candidate.json` for the refreshed head, reruns the
pre-review gates through `beforeReview`, and launches the original complete
review against the recorded main. The sibling records no `author-intent`,
`author-attempt` or author participant. After review, continue through the
ordinary acceptance and delivery path bound to the sibling (see the
transitions below), including its own native refresh. Do not create a second
launcher, a manual replay format, or a parallel recovery mechanism.

Post-admission transitions:
- A refresh conflict records `rebase-conflict` as a separate stop in the
  sibling and grants no conflict-resolution authority.
- Admission neither spends nor renews the pre-review gate-correction
  allowance.
- A candidate-attributed gate failure in the sibling follows the existing
  gate-correction rules unchanged.
- Any other failure is a separate ordinary stop in the sibling.

## Scope fence

In scope: `scripts/dogfood/queue.ts`, `scripts/dogfood/supervision.ts` as
needed, focused tests under `test/dogfood`, and the gate-stop section of
`docs/loop.md`.

The source branch is selected only by one additive closed member,
`gateStopAuthorization.sourceStage: { cycle, stop, base }`, alongside the
unchanged four fields. It is mutually exclusive with `executorRepair`,
`hostedNonExecution` and `hostedExecutedFailure`, and it is refused with
`acceptedReplan`, `integrationContinuation`, `verificationOnly`,
`terminalAttemptAdmission`, `conflictContinuation` or a non-`chase-sets`
adapter.

`stateDirectory` must be the attempt's `source` directory holding the
`gate-stop.json` written by `beforeReview`. `candidateHead` must equal
`source/candidate.json` head. `base` must equal the source config
`mainBase ?? base`. `cycle`/`stop` must name the earliest run-scope stop
record whose reason equals `gate-stop.json`'s reason, and every later stop
record of that cycle must carry the identical reason. These stop-record
bindings are evaluated before the reservation write. Once the reservation
exists, replay compares only the reservation's recorded authorization with the
current grant, then surfaces any sibling stop unchanged, mirroring
`queue.ts:6900-6911`.

The reason must be exactly `gate-host-failed:<gate>` or
`gate-attribution-unknown:<gate>`. Repository, run and issue are derived from
the retained `attempt.json` and config, never from the grant. A bare
four-field grant (without `sourceStage`) keeps refusing every source-phase
stop exactly as today. A `sourceStage` grant never admits a delivery-phase
stop.

Before any reservation or worker, admission fetches main and proves the
repair is on fetched main and absent from both the stopped candidate and
`base`, with main != base. It records that main in the reservation. Later
forward main movement neither renews nor invalidates the reservation. A
non-descendant main at refresh refuses with the existing
`current-main-incompatible`.

It refuses, by named reason, for:
- wrong phase or stage;
- repair absent from main;
- repair already in candidate or base;
- a mismatched state directory, candidate, base, cycle or stop;
- a reservation whose recorded authorization differs from the current grant
  ("stale grant");
- any other stop class.

On admission it records one single continuation reservation, refreshes
the candidate onto the recorded main through `currentMain` + `rebaseOnto`
in the reservation's sibling, then re-enters `reviewRefresh`, which reruns
the pre-review gates and requires the ORIGINAL complete independent review
(not DELTA) and all ordinary delivery gates.

On admission it keeps byte-for-byte:
- `source/gate-stop.json`;
- the `source/gate-<sha256>/` logs and terminal;
- `source/candidate.json`;
- every author record, trace and participant terminal;
- `source/config.json`;
- every `cycle-*-stop-*` and `-complete` record.

`attempt.json` advances only through the existing `advance` and `record`
lifecycle. Admission, the refresh, the rerun gates and the review launch
leave `item` and `candidateAttempt` unchanged; retries never decrease,
history is append-only and keeps the retained prefix, and no field is reset
or backfilled.

The review verdict then follows the ordinary source lifecycle, bound to the
sibling:
- PASS advances to `phase: "delivery"` with `stateDirectory` set to the
  sibling and `head` set to the refreshed candidate.
- BLOCK_FIXABLE follows the ordinary `fixable-review` transition
  (`queue.ts:4922-4950`) unchanged, including its `candidateAttempt + 1` and
  ceiling checks.

The source readers that build the BLOCK_FIXABLE transition (the
`reviewer-failed` handler at `queue.ts:6686-6715` and `buildRepair` at
`:6227-6260`) read the candidate and reviewer pair from the sibling named by
`source/gate-stop-continuation.json`, never from the pre-refresh
`source/candidate.json`. The repair's `mainBase` is the recorded main.

Admission consumes no implementation attempt, renews no ceiling, and does
not rewrite or delete any record listed above. A later failure is a separate
ordinary stop and cannot spend a second source continuation.

Non-goals: hand-editing runtime records; resetting attempts, retries, charges,
ceilings, or history; manual worker launch; broadening to unrelated stop
classes; changing reviewer, provider, registry, hosted-CI, publication, merge,
deployment, or executor-install authority; changing the existing delivery
grant semantics; or adding a heavy verifier, ControllerBattery, or
ControllerPrecursor path; granting against, replaying or continuing
`m2-pilot-137-20261024-r1` (it is historical evidence only; r2 owns #10415).
The r1 records are a shape reference for a synthetic test fixture, never a
live target.

## Done when

1. **Baseline reproduction.** A synthetic fixture mirroring r1's shape
   (no copied runtime bytes) is red on the pre-change base: it rethrows the
   retained stop on fresh entry and on an unchanged replay, before any
   reservation. The fixture has `attempt.json` `phase: "source"` with
   `reviewId`, `acceptedStage` and `stateDirectory` null, `head` equal to
   base, and `candidateAttempt: 1`. Its `source/` directory has
   `gate-stop.json` reason `gate-attribution-unknown:verify:static:scoped`,
   a `gate-<sha256>/` log and terminal, `candidate.json`, and author records
   only. There are two completed run-scope stop records with that identical
   reason.
2. **Candidate continuation.** Both a completed-stop restart and a pending
   (uncompleted) stop intent are covered; the pending intent finishes its
   learning note before native admission, mirroring ISS-157. With a valid
  host grant and repair SHA on fetched main, the source candidate is
  refreshed through `currentMain` + `rebaseOnto` in the reservation's
  sibling, and `reviewRefresh` reruns the pre-review gates and launches
  exactly one original complete independent review (no DELTA instruction).
  No author is launched: the sibling has no `author-intent.json` or
  `author-attempt.json`, and history gains no author participant for the
  item. Ordinary delivery gates remain required. The listed retained
  records are byte-preserved. Admission, refresh, gates and review launch
  leave `attempt.json` `item`, `candidateAttempt` and its history prefix
  unchanged, consume no implementation attempt and renew no ceiling. A
  sibling PASS advances `attempt.json` to `phase: "delivery"` with the
  sibling `stateDirectory` and the refreshed head. A sibling BLOCK_FIXABLE
  advances to `phase: "repair"` with `candidateAttempt: 2`, whose repair
  base is the sibling candidate head, not `source/candidate.json`.
3. **Fail-closed negatives.** Focused tests prove named refusal before
   reservation for wrong phase; repair absent from fetched main; repair already
   in candidate; repair already in base; mismatched state directory; stale or
   reused grant; wrong stop class; changed candidate head; and an existing
   continuation reservation. A second observation is inert.
4. **Lifecycle and authority.** The `sourceStage` grant validates as a
   closed schema (unknown, missing, malformed or combined-variant members
   refuse with `invalid-gate-stop-authorization` or
   `gate-stop-authorization-mismatch` before any write). Every binding in the
   scope fence is checked against retained records. Main is fetched
   immediately before the reservation write and recorded in it. Missing or
   contradictory evidence refuses without write, reservation, launch, charge,
   or attempt consumption. A regression test proves a bare four-field grant
   against the source fixture still rethrows the original stop unchanged.
5. **Regression evidence.** Focused tests in `test/dogfood/queue.test.ts`
   and `test/dogfood/supervision.test.ts` named "source-stage gate-stop
   continuation" are red on the pre-change base and green on the candidate.
   Reverting only the source-stage admission branch turns the AC2 test red,
   with the original stop reason rethrown. Each AC3 refusal is a one-variable
   mutant of the admitted fixture.

## Defect-class constraints

The overlapping ledger constraints from `references/defect-classes.md` are
part of this issue, not merely dispatch guidance:

- **state-machine-steady-state-missing:** enumerate source-stop, admitted,
  refreshed, reviewed, delivered, refused, and re-stopped states; prove the
  admitted steady state is inert on replay and routine operation.
- **lifecycle-repair-misses-sibling-retained-state-entrypoint:** exercise fresh
  source admission, retained stop replay, source/review callers, and the
  supervision path; do not fix only ordinary delivery.
- **retry-events-double-count-terminal-outcome:** preserve the one charged
  implementation attempt, retry history, terminal records, and ceiling; no
  duplicate continuation or refund.
- **retained-artifact-schema-ratchet:** keep the listed old records
  byte-for-byte; advance `attempt.json` only through the existing lifecycle,
  and make the reservation additive, versioned, and closed-schema validated.
- **temporal-join-ignores-causality:** bind grant to exact run, issue, stop,
  state directory, candidate/base, fetched main, repair, authority, and history.
- **stale-review-bound-to-wrong-head:** refresh onto the repaired main and
  require a fresh original review at the resulting exact head; old review
  evidence is not authority.
- **closed-schema-shallow-validation:** reject unknown, missing, malformed,
  stale, duplicate, or contradictory nested grant fields before writes.
- **presence-evidence-treated-as-completeness:** require complete stop,
  attempt, candidate, base, gate log, terminal, and history evidence, not mere
  file presence.
- **missing-fail-closed-regression-evidence:** freeze the retained fixture,
  prove baseline-red/candidate-green, and keep one-variable refusal mutants
  red.
- **mandated-external-assertion-contradicts-authority:** captured authority and
  fetched-main ancestry govern; contradictory external claims refuse unchanged.
- **unrunnable-verification-command:** keep planning/review/docs checks cheap;
  heavy commands exit 73 before any heavy-verifier slot reservation (lane
  harness) and return to host attribution.
- **worker-tool-ceiling-kills-heavy-verifier-wrapper:** do not wrap, extend,
  or background heavy verification to bypass its ceiling.
- **claude-background-task-dies-on-session-exit:** no detached or background
  evidence task; retain complete foreground evidence on disk.
- **parallel-node-verifiers-exhaust-host-memory:** no parallel verifier or
  ControllerBattery/ControllerPrecursor route.
- **vitest-wall-clock-timeout-under-parallel-host-load:** use bounded focused
  direct reruns and report timeout as evidence, never increase timeout or turn
  silence into PASS.
- **future-capability-documented-as-current:** docs describe source admission
  only as an implementation target until exact-head code and evidence prove it.
