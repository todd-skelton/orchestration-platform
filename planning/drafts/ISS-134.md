## Why

The resumed M2 run reached Chase Sets PR #7973 at reviewed b3bd4bed with
PR Required green. Its queue merge command (`gh pr merge --squash`) returned:
`GraphQL: Auto merge is not allowed for this repository (enablePullRequestAutoMerge)`.
A host retry at the same exact head reproduced that error. GitHub shows no
queue entry and no added/removed queue timeline event for the PR.

The loop swallowed the command error, then treated its own merge intent plus
an absent queue entry as a source failure. It fabricated a `merge-queue:1`
finding with text `absent` and launched cs-7821:2 against the already-approved
candidate. The host stopped that unnecessary author and supervisor before
any publication change. This is queue admission failure, not a source defect.

## Done when

- Queue policy uses GitHub's native enqueue operation at the exact approved
  PR/head, without requesting repository-disabled auto-merge or bypassing the
  queue. Existing squash policy behavior remains unchanged.
- An enqueue/host failure preserves its actionable diagnostics and produces
  a typed host stop. Queue absence or removal is not fabricated as a source
  finding and does not consume an implementation attempt or dispatch an author.
- Existing merge intent without confirmed admission is reconciled correctly;
  absence alone cannot claim the PR was removed from a queue it never entered.
  A confirmed queued entry is observed until actual merge; actual removal or
  rejection is surfaced honestly, without unbounded automatic re-enqueue.
- Tests compose the real adapter and delivery/queue path for native enqueue,
  pending then merged, the observed auto-merge-disabled failure, lost/absent
  admission, exact-head drift, and no-author/no-attempt-consumption on host
  admission failure.
- Document the concrete recovery of the preserved PR and the falsely advanced
  scheduling state. Historical review/gate/publication records and the stopped
  successor attempt remain preserved; no failed author is relabeled PASS.

## Out of scope

Enabling repository auto-merge, changing branch protection or CI, direct merge
outside the queue, changing the approved Chase Sets source, broad retries,
or a general state migration/approval framework.
