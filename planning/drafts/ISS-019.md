## Context and evidence

Early harness conformance proves primitives, not bootstrap N0. Before a stable
predecessor exists, pinned bootstrap workflow/test bytes, distinct review, and
operator grant certify every shipped package and module against the immutable
candidate. The complete bootstrap workflow/installer source is frozen by
`ISS-020`; the routine engine is complete in `ISS-026`. See the bootstrap root
and release state machine.

## Scope fence

In: pinned bootstrap test-bundle assembly, exact runner-environment inventory, complete
package/module census, macOS/Windows/Linux execution, receipt aggregation, and
candidate/test-bundle binding.

Out: candidate installation, independent semantic review, consumer shadow mode,
or accepting an unsupported required capability.

## Decisions already made

Pinned default-branch bootstrap workflow and test-bundle bytes define and
aggregate the suite before N0 exists. Candidate code cannot select, omit,
rewrite, or aggregate certification. The distinct bootstrap reviewer verifies
the census and aggregate; every required target emits a receipt.

## Acceptance criteria and evidence

1. The suite census covers every file included by the candidate manifest and
   every public contract/module. Evidence: manifest-to-suite coverage report.
2. All three exact runner environments emit receipts binding candidate digest,
   stable test-bundle digest, environment image, contract versions, and result.
   Evidence: aggregate manifest with independently checked hashes.
3. Missing OS, omitted package, altered test bundle, moved candidate, mixed
   receipts, skipped capability, or candidate-authored aggregation refuses
   certification. Evidence: one executed mutation per case.
4. Repeating the complete certification from clean environments produces the
   same semantic receipt set. Evidence: two-run normalized comparison.
5. The exact certified source census contains the bootstrap executable,
   installer, wrappers, workflow, schemas, engine, every package/module, and no
   tracked change occurs before review/authorization. Evidence: path coverage,
   source digest, and post-certification Git ref guard.
