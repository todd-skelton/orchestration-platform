## Decision

The constraint, under Todd's two 2026-10-29 rulings relayed by the controller thread, is that `gpt-6-astra`/xhigh is not admitted, an author rung may never use a non-admitted effort, and a failure not directly due to model selection (including host load, flaky tests, harness or infrastructure faults, quota or session problems, and environment-tooling) retries at the same configuration. The simplest viable alternative, keeping only the existing count and relying on ladder refusal, still escalates non-model failures, misroutes the retained ISS-265 attempt to a skipped rung, and does not distinguish planning failures that retry from those that stop or replan. The chosen option uses one raw-terminal hold classifier for new counts and legacy read-only derivation, holds `mechanical`, `environment-tooling`, `external-dependency`, malformed, non-refused dead, and any `brief`, `slice`, `design`, or `product-scope` failure that current routing sends to another author, while `implementation-known-remedy` and model refusal advance one rung, and makes `resolveRole` skip a family rung whose effort the registry does not admit. The accepted downside is that retained evidence that is missing or unreadable is conservatively not held and records a bounded reason, while an inaccurate non-model attribution may retry once at the same configuration and a planning failure may require host review instead of an automatic rung change. This choice would be wrong if evidence showed a held non-model or planning-failure retry should escalate to improve quality, or if an admitted model or effort refusal were held rather than advancing.

## Simplest shape

1. Add one shared idempotent count-and-hold helper around `failAuthor` that accepts
   the author id and raw terminal evidence. Its classifier reads only the raw
   terminal: a `failed` terminal uses `terminal.defect.defectClass` from
   `outcome.ts:6-15`; `mechanical`, `environment-tooling` and
   `external-dependency` hold; `implementation-known-remedy` and
   `modelRefused` do not hold; `malformed` is `mechanical`; and `dead` is
   `environment-tooling` unless `modelRefused` is set. The `brief`, `slice` and
   `design` classes map to ISSUE, SET and EPIC in
   `planning-repair.ts:22-26`; `queue.ts:2853-2921` diverts them to planning
   recovery, `planning-repair.ts:1298-1313` retries a malformed/dead planning
   worker once and `planning-repair.ts:1325-1328` stops a semantic FAIL for the
   next planning level, so a planning retry holds its rung and a stop/replan does
   not invent a rung. `product-scope` is not in that mapping, so
   `queue.ts:2881-2897,2987-3004` keeps the ordinary failed-attempt path and
   `supervision.ts:1100-1113` parks it until explicit unpark; its next author
   therefore holds rung 0. When a reviewer FAIL has one of these planning or
   other non-model classes and established routing sends the issue to another
   author, pass that reviewer terminal to this helper and hold the associated
   author id. A reviewer failure attributable to author/model quality, including
   `implementation-known-remedy`, remains unheld and escalates; `modelRefused`
   always overrides its status and is never held. The helper increments `count` and `ids` exactly as today and
   appends the id once to optional `authorFailures.held` only when the route
   admits another author attempt. It does not read the separate retained
   `outcome.ts:178-207` projection, because `flow.ts:691-740` writes that record
   separately from the raw terminal passed by `queue.ts:5993-6004`.
2. Route `syncParticipant`, the spent-integration reconstruction at
   `queue.ts:2751-2763`, the failed conflict-continuation author at
   `queue.ts:3011-3016`, and any planning-repair author retry through that helper,
   passing the raw failed terminal when available and the retained terminal
   evidence for composition paths. In the reviewer branch at
   `queue.ts:6057-6062`, pass the reviewer terminal as the evidence for the
   associated prior author: planning `brief`, `slice`, `design`, and any other
   non-model reviewer class whose established route makes an author retry is
   held, while an author/model-quality reviewer failure is unheld and escalates.
   Keep the no-rewrite rule: historical files remain byte-identical and only the
   new reservation receives the derived count/hold state.
3. When a legacy `authorFailures` record has no `held`, first validate the
   retained participant history (`participant-<ordinal>-terminal.json`) and select
   the failed author rows for this item in ordinal order. For every id already in
   `ids`, and for each missing id required by a count-only record such as the
   retained ISS-265 `{count: 1}`, require one matching retained raw
   `<stage>/author-terminal.json` with the same id and validated attempt/terminal
   identity; parse that terminal and apply the same classifier. Thus the actual
   count-only replay recovers its id from participant history plus its validated
   raw author terminal, rather than assuming an id or reading the separate outcome
   projection. If the count cannot be matched uniquely to terminal-backed author
   rows, derive no invented id, leave that portion unheld, and record a bounded
   `authorFailures.holdDiagnostics` reason such as
   `retained-author-terminal-unavailable` or
   `retained-author-terminal-unreadable`; do not rewrite the historical attempt or
   terminal. A present `held` set remains authoritative, is intersected with the
   recovered `ids`, and is deduplicated before rung arithmetic.
4. Rung equals `min(count - effectiveHeld.length, last)` in both rung sites, with
   a held class staying on rung 0 and an escalating class moving to rung 1 in
   the two-rung fixtures; repeated observations and repeated derivation are
   idempotent.
5. `resolveRole` reads `models[current].admittedEfforts` for each used family
   and `continue`s past a family rung whose effort is absent there. This applies to
   both roles; no reviewer rung is unadmitted in the cited snapshot.
