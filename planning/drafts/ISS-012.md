## Context and evidence

Routing should select a capability and evidence-backed configuration without
embedding one vendor's model aliases, prices, or host assumptions. See module
packaging from `ISS-011` and journal evidence from `ISS-010`.

## Scope fence

In: provider adapter contract, requested selector versus provider-authenticated
resolved model identity, alias/snapshot semantics, capability matrix,
installed active-release worker-host census and opaque host-identity selection,
placement and effort selection, escalation ladder, experiment records, cost
estimates, and degraded telemetry behavior.

Out: provider credentials, billing enforcement, prompt content, and hard-coded
public pricing.

## Decisions already made

Routing records selectors separately from resolved identities. Alias equality
never proves an immutable model; only a provider-authenticated snapshot/version
observed for the attempt may inherit versioned evidence. If unavailable, model
identity is advisory and route evidence cannot make an authority claim. Cost is
an estimate unless a project adapter supplies a policy gate. A successor model
receives no predecessor evidence automatically.

## Acceptance criteria and evidence

1. The same task/capability input yields a deterministic route from the same
   evidence snapshot. Evidence: golden routing cases.
2. Unknown, aliased, or mismatched reported models cannot inherit quality
   evidence. Evidence: identity mutation tests.
3. Provider and pricing outages degrade estimates without blocking unrelated
   dispatch. Evidence: fault-injection tests.
4. Escalation records the failed rung and never exceeds adapter policy.
   Evidence: table-driven ladder tests.
5. The provider contract names the attempt-time authority surface and represents
   selector-only, immutable-resolved, alias-moved, and unavailable identity
   separately. Evidence: schema fixtures consumed unchanged by `ISS-023`.
6. `route-selection/v1` carries exactly one `workerHostIdentityDigest` selected
   from the complete installed active-release host census. The routing package
   recomputes `worker-host-identity/v1` from each exact installed artifact
   digest, separately validates its embedded static contract/capability census,
   requires the requested action capability, and keeps the identity opaque.
   First-host and two-host goldens plus missing, duplicate, unknown, stale,
   moved-registration, capability-mismatch, cross-host, coordinated identity/
   artifact, and route/manifest substitution mutants prove no provider/model
   evidence can manufacture the key.
