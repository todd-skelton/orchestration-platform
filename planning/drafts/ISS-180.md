## Decision

Constraint: keep the retained pilot worktree, setup plan, source config
fingerprint, author attempt and trace byte-identical; keep executor drift
refusals for the controller (`controller-executor-revision-moved`,
`queue-executor-drift`) and the pilot HEAD and cleanliness checks in force.
Simplest alternative: the host re-points the pilot worktree to the new executor
revision, rejected as a runtime edit that still leaves the pinned fingerprint
stale; narrowing AC1 to bypass setup is also rejected because it abandons the
accepted real-replay outcome. Chosen: when composition finds a saved setup plan for the attempt slug,
it takes `pilotRevision` from that plan alongside `sourceBranch`, verifies it
resolves to a commit in the executor repository, and composes setup and source
against it; a fresh attempt keeps pinning the live executor revision. Before
the real setup adapter's executor assertion, the setup caller establishes exact
saved-plan agreement using its existing comparison with only `controllerRevision`
exempt. Convey that matched-replay fact transiently through the existing caller
boundary. For a matched replay whose repository and controller are the same
canonical checkout, validate repository HEAD against the current
`controllerRevision`, while the retained pilot still resolves to A. Every fresh
setup and every distinct-repository setup retains repository HEAD equal to the
pilot revision. No persisted replay flag, schema addition or file-presence bypass.
Accepted
downside: a resumed attempt's pilot stays at the revision that created it,
which is already what its pinned records assert, and the setup caller must
establish replay before the assertion rather than after it. Revisit if a real
distinct-repository replay requires separating its HEAD from the retained pilot;
that broader authority is not granted here. Missing commits, mismatched plans
and worktree HEAD drift remain refusals, never repins.
