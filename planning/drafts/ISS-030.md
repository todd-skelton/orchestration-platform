## Context and evidence

The installed shim must recover every interrupted attempt with exact verified
evidence. Numeric generation or an unverified history array is not authority;
the selected reservation and the full append-only `attempt-log/v1` chain are.
Attempts are rare, so each operation verifies the whole log cheaply.

## Scope fence

In: reservation requests, attempt launch records, the LIVE descriptor,
authorization attachment request, IN_PROGRESS/TERMINAL attempt-log appends
with folded terminal facts, process adoption/absence/exit proofs, gate/fence
head rebinding, retry/handoff/abort/complete behavior, native re-entry
trigger emission and definitions with their periodic fallback, and runtime
packets.

Out: pointer mutation, contracts, broker secrets/operations, release policy,
bootstrap genesis, OS lock implementation, and any attempt ordinal bound other
than safe-integer refusal.

## Decisions already made

ISS-004 selects reservations/pointers through a live mutation handle. A
reservation is keyed by transaction, source, and predecessor attempt-log
record/genesis and selects one prebound random UUIDv7; UUID time provides
uniqueness only. The CAS-selected reservation is durable before process
creation and carries the selected descriptor inputs; the descriptor exists
only as LIVE and binds the selected RESERVED tip plus the exact process-start
observation digest. Attachment binds LIVE.
`attempt-log/v1` records are IN_PROGRESS or TERMINAL and chain by predecessor
digest and canonical safe-integer ordinal; the TERMINAL record carries the
folded terminal facts, so no separate summary document exists and
summary-as-launch-authority is structurally impossible. Each operation
verifies the full log, which stays small because attempts are rare. No
membership proof, sparse tree, or separate fixed-slot attempt-history packet
exists; operations still use the shared eleven-slot `pointer-evidence-packet/v1`.

Re-entry is event-based with a periodic fallback. Each native definition
registers both the five-minute periodic trigger and its OS's queued start
primitive: a systemd user path unit on the exact
`<state-root>/installation/tick-request` artifact, a launchd queue
directory, and a Task Scheduler queued on-demand run requested through the
COM API under the queued-instance policy. After persisting a terminal
receipt that names a pending follow-up cycle request or a cleared fence,
the shim emits one trigger; the tick consumes its trigger artifact at
start. A trigger is timing advice only: it starts the same installed
definition with the same bound identities, so scheduler authentication is
unchanged, a missing trigger degrades to the periodic fallback, and a
spurious, early, duplicated, or foreign-written trigger costs at most one
bounded no-work tick. Frontier discovery still arrives on the periodic
fallback; an external trigger writer changes timing only and grants
nothing.

## Acceptance criteria and evidence

1. The supervisor requests one reservation per predecessor triple and reuses its
   selected attempt ID/descriptor inputs on retry. Concurrent UUID proposals,
   ID collision/fork, wrong source, wrong predecessor, and numeric ordering
   refuse.
2. The CAS-selected reservation is the durable pre-launch record. LIVE binds
   the selected RESERVED tip and exact process-start observation; composition
   proves its argv, installed-definition read-back, process-tree/start identity,
   and reservation-carried release/gate/fence/authority facts. Adoption admits one exact
   process; zero yields retryable proof and multiple/moved yields UNKNOWN.
3. Attachment is requested only for selected LIVE and verifies exact auth,
   reservation, descriptor, launch, release, broker, gate/fence roots and full
   histories/current heads. Pre-fence and abort sources cannot attach.
4. The TERMINAL attempt-log record folds the terminal facts: descriptor,
   optional selected attachment, terminal chain, process exit/absence, channel
   denial, revocation, and handoff/abort/complete proof. No separate summary
   document exists, and the record cannot retroactively authorize attachment.
5. First IN_PROGRESS appends the explicit attempt-log genesis record with no
   prior TERMINAL record; later IN_PROGRESS binds the previous selected
   TERMINAL record and its folded terminal facts by predecessor digest and
   next safe-integer ordinal. Gap, fork, reorder, and refusal above the
   ordinal bound execute as mutants.
6. Each operation verifies the exact `ORDINARY` commit arm and packet purpose,
   live ISS-004 handle, selected
   run-current checkpoint, current epoch and selected authority head, gate/
   fence, launch, and the selected reservation, LIVE descriptor, attachment,
   latest prior TERMINAL record with its folded terminal facts, and full
   attempt log. Scale tests reference the ISS-006-published 1,000-record
   golden and budget plus refusal above the safe-integer bound.
7. Reservation lifecycle is RESERVED→CONSUMED→TERMINAL; later removal selects
   the common pointer tombstone after reviewed archive composition. Crash and
   scheduler races at every transition resume one selected value; bare absence,
   reordered histories, stale heads, mixed attempts, and self-asserted prior
   pointers refuse.
8. No degraded-audit mode exists. Loss of required attempt, gate, fence, or
   authority history is `UNKNOWN` and blocks the affected operation; every
   blocked operation has an executable negative.
9. Cold-host re-entry consumes the selected authority value and walks the full
   `authority-history/v1` chain from genesis against the selected head. An
   interrupted run invokes only ISS-004 exact recovery; UNKNOWN authority or a
   failed chain walk blocks scheduler work. The supervisor never appends,
   mutates, or reinterprets history itself.
10. Each OS definition registers the periodic fallback plus its native queued
    trigger, and the shim emits a trigger only after its terminal receipt
    persists naming a pending follow-up or cleared fence. The tick consumes
    the trigger artifact at start, and follow-up latency through the trigger
    path is bounded by scheduler start rather than the periodic interval.
    Missing, early, duplicated, flooded, or foreign-written triggers change
    timing only: mutation still requires the full state protocol, and floods
    collapse to bounded single-instance no-work ticks. Evidence: three-OS
    trigger-definition goldens plus flood, forgery, and pre-exit-race
    negatives.

## Predicted footprint and dependencies

Owns predeclared supervisor/runtime package, `test/supervisor/`, and exact
ISS-030 slots. It consumes ISS-004's private state mechanism through the
existing transitive-reduced dependency graph; no additional direct edge is
claimed. No contracts, state,
broker, release, root, planning, or glossary edits.

## Producer and consumer ownership

ISS-030 produces attempt descriptor/attempt-log and launch facts and
requests reservation/attachment transitions. ISS-004 supplies scoped handles,
selects run-current/target state, and verifies the authority-history chain;
ISS-032 validates/performs attachment; ISS-014 supplies gate/fence/release
facts; the shim consumes all through ISS-002 validators and ISS-004
projections.
