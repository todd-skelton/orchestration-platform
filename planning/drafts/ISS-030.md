## Context and evidence

The installed shim must recover indefinitely many attempts with a bounded
verification packet. Numeric generation or a full-history array is not lifetime
authority; a selected reservation and rolling accumulator are.

## Scope fence

In: reservation requests, attempt launch records, READY/LIVE descriptor,
authorization attachment request, terminal summary, IN_PROGRESS/TERMINAL
accumulator requests, process adoption/absence/exit proofs, gate/fence head
rebinding, retry/handoff/abort/complete behavior, and bounded runtime packets.

Out: pointer mutation, contracts, broker secrets/operations, release policy,
bootstrap genesis, OS lock implementation, and array/history caps that limit
installation lifetime.

## Decisions already made

ISS-004 selects reservations/pointers through a live mutation handle. A
reservation is keyed by transaction, source, and predecessor accumulator
triple/genesis and selects one prebound random UUIDv7; UUID time provides
uniqueness only. Descriptor is READY_ONLY or LIVE. Attachment binds LIVE,
never terminal summary. Accumulator is IN_PROGRESS or TERMINAL with exact
tagged formulas. The current packet uses thirteen fixed slots and live sparse-tree
producer projections rather than replaying lifetime history.

## Acceptance criteria and evidence

1. The supervisor requests one reservation per predecessor triple and reuses its
   selected attempt ID/descriptor inputs on retry. Concurrent UUID proposals,
   ID collision/fork, wrong source, wrong predecessor, and numeric ordering
   refuse.
2. READY is durable before process creation. LIVE binds READY, initial LIVE,
   exact argv/process tree/start identity and current release/gate/fence/authority
   triples. Adoption admits one exact process; zero yields retryable proof and
   multiple/moved yields UNKNOWN.
3. Attachment is requested only for selected LIVE and verifies exact auth,
   reservation, descriptor, launch, release, broker, gate/fence roots and full
   histories/current heads. Pre-fence and abort sources cannot attach.
4. Terminal summary binds descriptor, optional selected attachment, terminal
   chain, process exit/absence, channel denial, revocation and handoff/abort/
   complete proof. It does not retroactively authorize attachment.
5. First IN_PROGRESS has explicit accumulator genesis and no terminal summary;
   later IN_PROGRESS binds the previous selected TERMINAL triple/summary.
   Rolling digests use exact first/later domain tags and raw digests.
6. Each operation verifies exact packet purpose, live ISS-004 handle, selected
   run-current checkpoint, current epoch/root, gate/fence, launch, reservation,
   descriptor, attachment, accumulator, READY/initial LIVE, and latest prior
   summary. Historical producers use current-root projections. Tests exceed
   former caps and prove constant packet shape.
7. Reservation lifecycle is RESERVED→CONSUMED→TERMINAL→TOMBSTONE. Crash and
   scheduler races at every transition resume one selected value; bare absence,
   reordered histories, stale heads, mixed attempts, and self-asserted prior
   pointers refuse.
8. `AUDIT_DEGRADED` permits only the exact existing forward recovery/retry/
   cleanup/selected-attachment and ordinary non-release operations; all blocked
   operations have executable negatives.
9. Cold-host re-entry consumes the selected authority value v3/history root v2
   and validates the singleton materialization coordinator. STARTED/FINISHING
   invokes only ISS-004 exact recovery; UNKNOWN, missing selected nodes, or a
   failed authenticated inventory census blocks scheduler work. The supervisor
   neither enumerates nodes nor advances the coordinator itself.

## Predicted footprint and dependencies

Owns predeclared supervisor/runtime package, `test/supervisor/`, and exact
ISS-030 slots. Adds ISS-004 as a direct dependency because reservation and
accumulator selection require its private state mechanism. No contracts, state,
broker, release, root, planning, or glossary edits.

## Producer and consumer ownership

ISS-030 produces attempt descriptor/summary/accumulator and launch facts and
requests reservation/attachment transitions. ISS-004 supplies scoped handles
and selects run-current/target/coordinator state and node census; ISS-032 validates/performs attachment;
ISS-014 supplies gate/fence/release facts; the shim consumes all through
ISS-002 validators and ISS-004 projections.
