lifecycle work; filesystem/path/cleanup contention; unresolved children/promises
or event-loop stall. Separate hook/body/cleanup/file time: 1610.77 s is a file

time. Flush bounded partial evidence during execution; missing phases, dropped
records or pending children remain unknown. Sanitize paths/arguments, never
environment or secrets. Cheap synthetic controls prove inertness, known phase/
child capture, failed-case retention and overflow detection. ISS-212 covers only
source4/unpark and rejects non-PASS before writing; do not inherit that gap.

Opt-in candidate PR Windows jobs run one fixed-order baseline/candidate diagnostic
pair per named case: at most 18 executions, unchanged 30,000 ms test/hook limits,
one worker/file-serial. Baseline is 1feb3df8 plus identical diagnostic-only
plumbing, no remedy: bind base SHA plus patch hash. Bind candidate SHA/settings.
Use existing shards; added diagnostics get at most 15 minutes per shard within
the unchanged 100-minute job, 1 MiB per case with explicit overflow failure.
Preserve partial artifacts and original exits. Expected baseline red is evidence,
not candidate failure or PASS; candidate diagnostic failure blocks acceptance.
Always run the ordinary unfiltered shard gate with diagnostics off. No retries,
until-green loops or contention; default diagnostics off. `planning:check` is static.

excess setup, slow spawns and stalls. Preserve transitions. Focused baseline
PASS is not reproduced red/contention proof; unknown attribution returns to host.
