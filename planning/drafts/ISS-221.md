## Defect-class constraints

The overlapping ledger constraints are binding in the issue text:

- **`vitest-wall-clock-timeout-under-parallel-host-load`:** before any full
  heavy gate, acquire the exclusive machine verifier slot; preserve the first
  timeout output; run the exact unchanged file alone; classify load-sensitive
  only after a clean pass with a large timing collapse; then run the complete
  foreground gate with file parallelism disabled and one worker. Never raise
  the timeout, weaken a test, skip it, steal an ambiguous lock, or count the
  mechanical retry as a repair attempt.
- **`parallel-node-verifiers-exhaust-host-memory`:** all direct Vitest and
  other memory-heavy commands require the host-wide admission slot and must
  run foreground. On refusal, do no work and wait for the exact owner. Never
  kill unrelated processes, raise limits, or call a failure load-sensitive
  without the unchanged isolated and complete serial evidence above.
- **`aggregate-failure-dismissed-as-environmental-without-a-discriminating-control`:**
  calling a failure environmental requires either the same aggregate green at
  the unchanged head or the same failure on a branch without the diff. A
  narrower run that passes is not a control; whole-host limits require a
  hypothesis that explains why unaffected branches are green.
- **`worker-tool-ceiling-kills-heavy-verifier-wrapper`:** preserve foreground
  ownership and wait for every admitted child to finish; a worker ceiling,
  forced termination, or incomplete receipt is not a passing gate or a load
  explanation.
- **`presence-evidence-treated-as-completeness`, `production-profile-failure-hidden-by-narrowed-test-profile`,
  and `skipped-result-counted-as-failed-spec`:** retain the complete file and
  test inventory, full Windows profile, existing skips, and each reporter
  result. Focused diagnostics and shard subtotals never replace the complete
  serial gate or relabel a skip.
- **`mandated-external-assertion-contradicts-authority`:** probe the owning
  job, artifact, and run at the lifecycle moment consumed; bind exact head,
  IDs, timestamps, duration, conclusion, and fetched log, and report
  unavailable or contradictory authority rather than inventing success.
- **`mutable-reference-breaks-candidate-identity`, `stale-review-bound-to-wrong-head`,
  `format-check-not-run`, `unrunnable-verification-command`, and
  `future-capability-documented-as-current`:** bind all evidence and review to
  immutable heads, rerun fresh gates after any change, and use only manifest
  commands and capabilities actually present at that head.
