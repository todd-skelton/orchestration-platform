## Context and evidence

Decision #302's readiness audit (§3, CF-5) identifies the synthetic BUILD and
REVIEW workflow bytes, and the issue form `ISS-036`'s live window enables,
as byte content that can be written and reviewed without ever being enabled
on a triggerable ref. This issue lands those bytes.

## Scope fence

In: the exact bytes of the synthetic BUILD workflow (`on: pull_request` with
activities `[opened, reopened, synchronize]`) and the synthetic REVIEW
workflow (`on: workflow_run` with `[completed]` and
`requiredConclusion: SUCCESS`, sourced from the BUILD workflow's exact
path/ref/digest) — `contract-decisions.md:6761-6770` — each with an explicit,
complete seventeen-name permission block including every effective implicit
`NONE` (`:6712-6760`). Plus `.github/ISSUE_TEMPLATE/self-host-work.yml`
producing the exact fenced `orchestration-work/v1` block
(`docs/architecture/self-host-github-contract.md:3-10`). Landed on a
non-default branch or under a path the default `on:` triggers cannot reach,
so the bytes are reviewed without being live.

Out: any enablement, any run, any `workflow_dispatch`, any arbitrary input
(`planning/drafts/ISS-036.md`'s scope fence). `ISS-036`'s operator action O3
enables these bytes live; this issue only lands and reviews them.

## Acceptance criteria and evidence

1. A test parses each workflow's YAML and asserts the trigger row and the
   seventeen-row permission array the receipt will bind.
2. The already-implemented `test:harness-workflow-mutations`
   (`test/conformance/workflow-structure.test.ts`) stays green against these
   two new files.
3. The issue-form template produces the exact fenced `orchestration-work/v1`
   block shape `self-host-github-contract.md:3-10` requires; a test parses a
   fixture submission and rejects a malformed block.

## Verification plan

No command is registered for this issue yet. Local verification is the
ordinary planning, formatting, typecheck, and diff gates plus independent
exact-head review; the existing `test:harness-workflow-mutations` command
(already registered by `ISS-006`) runs against these new files without any
new root-script registration.

## Predicted footprint and dependencies

implicit default the receipt cannot represent; a REVIEW workflow triggerable
