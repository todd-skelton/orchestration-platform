## Decision

Constraint: keep the four-attempt ceiling, native launch ceiling, retained
history, failure ladders and old source/review/repair evidence authoritative.
Simplest alternative: recognize repair FAIL only for parking, rejected because
explicit planning unpark would then re-enter the same stale repair record.
Chosen: extend the existing retained-author-failure observation to the pinned
repair phase, reuse normal stop reconciliation and cycle completion, and extend
ISS-179's pre-scan failed projection for subsequent explicit unpark. Ordinary
composition then admits only `candidateAttempt + 1` within the configured
ceiling, retaining the rejected head/full-diff base and using new worktrees.
For this narrow failed-repair successor, an explicitly accepted in-place brief
repair governs changed guidance; unchanged governing requirements and still-applicable
prior findings remain binding. Historical prescriptions cannot unconditionally
restore a constraint the accepted brief repair changed, nor may the successor
silently ignore an unresolved blocker that still applies.
Accepted downside: the unsuccessful repair consumes its recorded implementation
attempt even without a repair review; this is existing accounting, not a new
allowance. Revisit only if an observed repair failure cannot be represented by
the existing failed receipt and bounded successor without changing authority.

## Retained-record boundary

Use persisted records, not live Git/worktree inspection, for this observation.
For containing directory number N (2 in the incident):

- Queue run/issue and item `<key>:N` match the selected key/number and loop run;
  candidate attempt is N+1, accepted stage and directory are null. Setup plan
  and source/repair configs agree on run, repository and issue. Their state
  directories are respectively this queue's `setup`, `source` and `repair`.
- Setup base equals queue base and source config base. Its source-role worktree
  path equals both source and repair config worktree paths; setup `sourceBranch`
  equals that source-role worktree record's branch. Neither source config nor
  candidate has a branch field: do not add or demand one. Source and repair
  configs retain the same recorded full-diff `mainBase`.
- Queue head equals source candidate head, source reviewer terminal head, repair
  config base and failed repair author terminal head. Queue `reviewId` equals
  source reviewer attempt ID and terminal ID; that source terminal is FAIL.
  Repair author attempt ID equals its FAIL terminal ID. Existing reviewer
  findings remain historical findings; no repair reviewer result is invented.
- Existing history reduction retains the complete participant sequence and
  matches the queue's accumulated history. The source reviewer binds the same
  item/stage `source`/role `reviewer`/outcome `failed`; the repair author binds
  the same item/stage `repair`/role `author`/outcome `failed` (ordinals 5 and 6
  here, not fixed ordinals in code). Keep all earlier participants, including
  source authors and the malformed reviewer. Reuse existing history validation.
- Saved-cycle recovery additionally uses existing stop-selection/history
  validation and note reconciliation; composition does not infer a saved stop
  from queue history. A completed stop is not a completed cycle. Pair identity,
  head, branch, participant and exhausted-budget mismatches with negative controls.
