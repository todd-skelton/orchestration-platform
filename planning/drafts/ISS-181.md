## Decision

Constraint: keep the four-attempt ceiling, native launch ceiling, retained
history, failure ladders and old source/review/repair evidence authoritative.
Simplest alternative: recognize repair FAIL only for parking, rejected because
explicit planning unpark would then re-enter the same stale repair record.
Chosen: extend the existing retained-author-failure observation to the pinned
repair phase, reuse normal stop reconciliation and cycle completion, and extend
ISS-179's pre-scan failed projection for subsequent explicit unpark. Ordinary
composition then admits only `candidateAttempt + 1` within the configured
ceiling, retaining the rejected head/full-diff base and using new worktrees.
For this narrow failed-repair successor the current selected brief governs;
historical reviewer prescriptions and failed-author traces are evidence, not
an unconditional instruction to restore a constraint the accepted replan changed.
Accepted downside: the unsuccessful repair consumes its recorded implementation
attempt even without a repair review; this is existing accounting, not a new
allowance. Revisit only if an observed repair failure cannot be represented by
the existing failed receipt and bounded successor without changing authority.

## Done when

1. **AC1 Native stop and saved recovery.** A synthetic fixture drives native
   source review FAIL then repair author FAIL, reproducing directory attempt 2
   with candidate attempt 3. Both a fresh stop and resume with the incident's
   old run-note completion park the item and complete its cycle through ordinary
   supervision, then select an unrelated runnable item (or idle if none).
   Replay reuses the original author stop marker/body/ordinal, reconciles pending
   notes, retains all participants and launches no worker for the failed cycle.
   Repeated resume neither duplicates the note nor replays the failed repair.
   Evidence: real repository-queue/native repair and supervision fixture, failing
   on the unchanged base; not merely a stub returning a failed receipt.
2. **AC2 Matching boundary.** Observe the repair's pinned config, matching author
   attempt and FAIL terminal: run/repository/issue/item/directory agree,
   `candidateAttempt` is directory number plus one within the existing ceiling,
   accepted stage is null, and terminal head equals repair config base and the
   retained rejected head, not the original source base. Missing terminals,
   unfinished/live authors, non-FAIL terminals, mismatched worker/head/pin,
   accepted stages and unrelated issue/run records do not establish recovery.
   The ordinary source-failure, repair-review-failure, host/provider stop and
   accepted-replan paths retain their behavior. Evidence: bounded paired
   positive/negative controls through the actual observation and stop callers.
3. **AC3 Explicit unpark only.** With the failed cycle completed and the issue
   still unready, selection skips it. After explicit planning unpark, composition
   advances only the queue projection to `phase: "failed"` once, retaining
   candidate attempt 3, rejected source head, historical review ID/findings,
   history, retries and author-failure identities, with no accepted stage.
   It creates the ordinary attempt-4 successor only if the configured ceiling
   permits and remaining native launch budget admits it; at ceiling 3 or after
   attempt 4 it refuses with existing exhaustion behavior. There is no automatic
   retry of the parked item, renamed-run workaround, new fifth allowance or
   accepted-replan packet. Interruption before successor setup and resume after
   its creation select the same successor without double charging or renewal.
   Evidence: moved-main, intervening-issue and repeated-composition cases.
4. **AC4 Honest continuation.** The successor's newly pinned prompt uses the
   current brief and names the containing predecessor attempt plus its source,
   reviewer and failed-repair records/traces. Old findings remain inspectable
   but this successor does not unconditionally apply them verbatim over a changed
   accepted brief. No saved prompt/fingerprint is edited. Rejected-head rebase
   and the full implementation diff follow ordinary composition; original dirty
   worktrees are never reset or reused. Accumulated participants, author ladder
   count/identities, reviewer rung and spent retry/launch allowances retain their
   existing scope and remain charged. Ordinary review-FAIL successors retain
   their current prescribed-fixes behavior. Only fresh independent exact-head
   review and all ordinary local/after-mirror/hosted/merge/deployment gates can
   accept the successor; historical PASS grants nothing. Evidence: prompt and
   launch-boundary assertions plus byte comparisons of retained source, setup,
   repair, terminal, stop and completed-stop records. Only normal failed queue
   projection/rebase bookkeeping and new recovery/successor records may change.
5. **AC5 Delivery.** Add one standing `docs/loop.md` sentence covering terminal
   repair-author FAIL parking and explicit same-run unpark within the existing
   ceiling. Pass `pnpm typecheck`, `pnpm format:check`, `pnpm planning:check`,
   complete `pnpm test`, independent exact-head review and executed
   Ubuntu/Windows/macOS bootstrap jobs at the final implementation head. Use
   synthetic identities and unchanged timeouts; never run the incident to prove
   the fix during implementation.
