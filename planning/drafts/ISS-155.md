## Done when

- **AC1: Bound literal matching.** `withinConflictHunks(before, after)` keeps its
  boolean API and recognizes resolutions of the existing supported Git hunks
  without compiling source-derived regexes or backtracking over placements.
  Fixed prefix and suffix remain anchored to the exact start/end; intervening
  fixed segments occur in order, without overlap or reusing suffix bytes.
  Fixed LF/CRLF, whitespace and metacharacters are literal and immutable.
  Evidence: exported-function table tests in `refresh.test.ts`, including
  repeated fixed segments and suffix text also occurring inside a resolution.
- **AC2: Preserve acceptance and refusal.** One or multiple hunks, empty
  resolutions, adjacent hunks, empty prefix/suffix, and a whole-file hunk are
  accepted when otherwise valid. Inputs without a recognized hunk and outputs
  retaining existing recognized conflict markers remain false. Separate
  negatives change only the prefix, suffix, a middle fixed segment, segment
  order, or outside-hunk line endings; include trailing extra text and an
  overlapping/reused fixed-segment placement. Evidence: positive/negative
  table pairs holding all other inputs constant, retaining the existing
  `limits edits to actual hunks with line ending %j` tests.
- **AC3: Regress the real failure and scale.** A read-only replay of the exact
  retained input above through the candidate function accepts the host's
  empty-hunk resolution without throwing, and rejects a one-byte fixed-text
  change. Keep its hash, exact candidate head, command and output in external
  review evidence, not a committed copy of `queue.ts`. Add deterministic
  generated controls at 128 KiB and 1 MiB of fixed text, one and many hunks,
  metacharacters, repeated near-matches and a late missing suffix/segment.
  Evidence: regressions pass under existing timeouts; the old matcher fails
  the size regression. Record measured sizes/timings and the monotone scan
  bound; no benchmark framework, timeout increase or size-cap workaround.
- **AC4: Exercise both callers without changing lifecycle.** Large supported
  text reaches the existing resolution author from `resolveConflict`'s
  preflight, then passes its post-author validation; an outside-hunk edit
  stops `conflict-resolution-scope-escape` before review/publication. No-hunk,
  binary, missing-side and unsupported-mode conflicts retain
  `conflict-resolution-unsupported`, never success by catching an exception.
  Evidence: extend the existing local-Git refresh fixture for the large-file
  path and focused unsupported/scope controls. Existing fresh/resumed,
  unpublished/published, lost-commit and exhausted-resolution tests remain
  green: one resolution allowance, original records/participants, exact-head
  delta review, new local gates, forward-only publication and hosted checks
  remain required. Gate correction and accepted-replan restrictions are unchanged.
- **AC5: Deliver only verified implementation.** The implementation candidate
  passes the platform verification commands below and hosted `bootstrap` on
  Ubuntu, Windows and macOS at its exact head. Evidence: complete local outputs
  and three actual hosted results, inspected independently.
