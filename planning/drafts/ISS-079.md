## Scope and observed need

Allow one later, externally admitted bounded-queue implementation attempt to
refresh the exact open draft PR left by an earlier failed delivery attempt. The
queue and delivery authority bind the PR number, repository-derived URL and
prior reviewed head. The repository adapter accepts only a candidate that is
forward from that prior head and pushes it under an exact remote-head lease.
The existing source/review path, four controller gates, hosted Windows/macOS/
Linux checks, merge and cleanup remain the only completion path.

ISS-079 is registered as #341 under EPIC-KERNEL/M2 and is blocked by
ISS-078/#338. Pilot `iss079-reviewed-refresh-20260909` uses accepted c024 queue
authority and source base `0273760e97e9a91a024671f2062ef2b12e75e786`.
Stable controller authority remains external; this source cannot review,
certify, publish or activate itself.

## G0 and smallest complete shape

G0: PASS. The smallest complete correction is one optional exact refresh
identity in the existing private queue/delivery authority, plus the existing
GitHub repository adapter's forward-ancestry and exact remote-lease checks.
Write-once publication intent already supplies the required restart fence.
Creating a parallel publisher, general retry framework or new workflow would
duplicate accepted behavior and enlarge mutation authority.

Not built: generic retry/publisher framework; arbitrary PR adoption; backward
or replacement pushes; provider-independent public publication contract;
credential broker; scheduler; candidate promotion; setup Git selection; failed
native-launch adoption; public package/compiler/environment/native-permission
change; or a claim that fixture success proves later unattended real use.

## Non-goals

No credential inspection/validation/rotation, permission expansion, public
package or toolchain change, generic retry framework, parallel publisher,
arbitrary adoption, force replacement, release promotion, candidate
self-certification, fabricated failure, erased attempt/spend history, raw trace
or private output ingestion, or weakening of review/gate/three-OS requirements.

## Acceptance evidence

1. The accepted queue and delivery authority bind an optional exact existing-PR refresh number, URL and prior head to one later implementation attempt whose source base is that prior head. Missing, malformed, substituted or first-attempt refresh authority fails closed before source/provider mutation.
2. Only an independently reviewed exact candidate may enter the existing delivery path. The original source/review identity, four-or-repair join, four controller gates, exact required hosted Windows/macOS/Linux checks, merge and cleanup requirements remain unchanged.
3. The GitHub adapter selects only the bound open draft on the approved source/base branches, proves the candidate is forward from the bound prior head, confirms the remote branch is still exactly that head and pushes with the same exact lease. A moved, absent, closed, duplicate, divergent or substituted target blocks without creating another PR.
4. Publication intent precedes the refresh. Lost responses and delayed/unknown old-head observations reconcile on restart without another push; only observed candidate-head identity may finish metadata reconciliation, hosted checks and later effects. Earlier participant outcomes, attempts and known/unavailable spend remain immutable queue lineage and advisory telemetry never grants authority.
5. Preserve later genuine refresh/restart evidence through the accepted c024 queue, including the earlier failure history and the later successful reviewed head. Hosted fixtures establish compatibility only and do not satisfy automatic real-use completion; stable external review and promotion remain required.

## Review attack surface

Refresh authority omitted from either queue or delivery binding; same-number
foreign repository/URL; source/base substitution; stale or moved remote head;
non-forward or replacement history; a lease checked but not supplied to push;
old-head visibility treated as permission to push again; candidate metadata
accepted before exact head; bypassed review, gate or hosted OS evidence; earlier
failed participants/attempt/spend erased; candidate used as stable executor;
fixture claims presented as genuine later automatic use; or a hidden parallel
publisher/retry path.
