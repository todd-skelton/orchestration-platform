## Why

ISS-112 made the author sandbox work, but by generating `pnpm.cmd`, a POSIX
`pnpm` shell script and `pnpm.cjs` into the temp root and running a 55-line
preflight that probes `mkdtemp`, writes the wrappers, and compares
`pnpm --version` to `packageManager`. The observed failure was corepack
reaching for the network; `COREPACK_ENABLE_NETWORK=0` plus a writable temp
root is the fix. The PATH, TEMP, TMP and TMPDIR values are also set twice
(observer environment and `shell_environment_policy.set`) and
`COREPACK_ENABLE_NETWORK` three times. The Windows sandbox mode was changed
without a note in the draft.

## Done when

- `dispatch-adapter.ts` sets the writable temp root and the offline corepack
  variables once, in `shell_environment_policy.set`; the observer environment
  carries only the startup allowlist.
- The generated wrappers and the preflight are deleted. If corepack's cache
  is cold the first gate fails with corepack's own error, which the loop
  already reports as a gate failure.
- The Windows sandbox mode in use and the reason for it (captured
  child-process output is refused under `unelevated`) are stated in one
  comment beside the flag.
- A real author run on this host completes all three gates; its learning note
  is posted on this issue.

## Out of scope

Widening the sandbox beyond the worktree and its temp root. Non-Codex hosts.
