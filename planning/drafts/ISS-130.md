## Why

During M2 recovery preflight on 2026-09-13, the current Chase Sets adapter's
`deployObservation` returned `failed` for the actual successful staging deploy
run 34756521966, commit e27679b356ab603987387891645a89c2d83f91c8:
https://github.com/chase-sets/chase-sets/actions/runs/34756521966/job/103722170354.
The job and its immutable-image verification succeeded. The adapter searches
for a step named `Verified immutable active release`, but the workflow's step
is `Verify immutable active release image`. Its test fixture repeats the wrong
name, so it cannot detect this mismatch. M2 would stop with `deploy-not-verified`
after a successful merge and deploy.

## Done when

- Deployment verification recognizes the current workflow's exact
  `Verify immutable active release image` step and requires its success along
  with the completed successful real `Deploy Staging` job and matching commit.
- Tests use the observed workflow step name and prove a missing, failed, or
  skipped image-verification step does not establish successful deployment.
- A read-only probe against run 34756521966 and its actual commit reports
  verified; do not change provider or repository state to manufacture evidence.

## Out of scope

Changing Chase Sets deployment workflows. Weakening commit matching or accepting
trigger-only success. A new deployment evidence protocol.
