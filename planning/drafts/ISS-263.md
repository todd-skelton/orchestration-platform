## Decision

At the current head, `flow.ts` initializes `retry` from a retained attempt with
`retries === 1` (`scripts/dogfood/flow.ts:434-441`), then the dead-worker branch
retains and rewrites the terminal and raises `launcher-failed` when retry is
already spent (`scripts/dogfood/flow.ts:691-711`). Queue composition only
recognizes a source author terminal whose status is `failed`
(`scripts/dogfood/queue.ts:3834-3844`); `pinnedRepairFailure` delegates to that
predicate (`scripts/dogfood/queue.ts:3926-3989`). The repair projection at
`scripts/dogfood/queue.ts:2901-2910` therefore leaves the attempt in
`phase: repair`, so successor calculation at
`scripts/dogfood/queue.ts:2987-3002` is never reached. Saved-cycle supervision
selects the issue again and runs the ordinary queue (`scripts/dogfood/supervision.ts:539-689`),
which reproduces the same stop.

The smallest viable shape is an additive, read-only retained-stop predicate
and one composition projection at those existing seams. It accepts only an
explicit planning-unpark admission packet for a completed same-run
`launcher-failed` stop whose retained worker is dead, whose retry is spent,
whose launch/terminal/history/stop identities match, and whose process census
proves no survivor. It projects the existing attempt to `phase: failed` once,
preserving its head/history/charges and then using the existing successor
calculation to reserve exactly the next unused implementation attempt. The
packet is not a verdict and does not replace the existing
`terminalAttemptAdmission` route, which remains limited to its current
continuation kinds (`scripts/dogfood/queue.ts:1217-1269`; `docs/loop.md:1880-1928`).

No automatic ready restoration or ordinary restart may invoke this projection.
The `launcher-failed` stop table remains retry/legacy-parking
(`scripts/dogfood/fault-class.ts:107-110`), and the loop's existing explicit
planning-unpark boundary remains authoritative (`docs/loop.md:714-721,
736-743`). No timeout, ladder, provider policy, heavy-verifier,
ControllerBattery or ControllerPrecursor behavior changes.
