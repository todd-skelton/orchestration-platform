## Why

ISS-135 (#435) records the M2 supervisor selecting #4382 immediately after
delivering #7821 while the intended milestone still had operator-blocked work.
The host had to stop the supervisor and new worker and reconcile the preserved
selection. Scope enforcement fixes that incident, but Todd still lacks a normal
way to finish current work and stop before the next selection to change
priorities. ISS-110 (#367) also records repeated manual same-run recovery.

## Done when

- Provide a small operator pause-after-current control for the configured run.
  The supervisor finishes its current issue through existing delivery or item
  stop handling, then exits paused before selecting or dispatching another.
  With no active issue it pauses immediately. A host failure remains a host
  failure rather than being relabeled a successful pause.
- A pending pause and its acknowledgement are visible through ISS-136 status.
  The request survives a supervisor restart until explicitly cleared. Keep
  operator requests separate from supervisor-owned scheduling records, all
  outside the checkout; no locks, distributed control plane, or receipt edits.
- Explicit resume clears the pause and uses the existing launcher/recovery
  path. Do not launch a second supervisor for an already-running configured
  run. Preserve in-flight selection, worker outcomes, and attempt budgets;
  pause/resume must not reset failures or regenerate work already completed.
- Extend docs/loop.md with a tested workflow: inspect status and next work,
  request pause, await acknowledgement, change existing GitHub priorities or
  readiness, preview selection, and resume. For Chase Sets explain p0 through
  p3 ordering and issue-number ties inside the selected outcome; for self
  explain earliest milestone, ready/dependencies, and issue-key ordering.
  Board card order and self priority labels are not scheduling controls.
- State when edits take effect: new selections read current authority, but
  priority edits do not preempt active work. Target/config changes require a
  stopped supervisor and restart; a saved selection is still resumed or gets
  the existing typed scope stop, never silently discarded. Urgent interruption
  remains explicit host intervention with supervisor and child inspection.
- Tests cover pause before selection, request during active work, item stop,
  host stop, restart with pending pause, explicit resume, and reprioritization
  of the next eligible Chase Sets issue without bypassing readiness, dependency
  or target-milestone constraints. Verify no successor author launches while
  paused and no budget/history resets occur.

## Out of scope

Mid-worker instruction injection, cancellation/rollback framework, automatic
selection migration, a new priority system, automatic restart after idle or
failure, or changing any live product priorities or executor during this task.
