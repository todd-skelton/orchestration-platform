## Why

The loop still needs a person to pick the next issue, and when it stops the
reason lives in a state directory nobody reads. Selecting from GitHub and
writing the stop reason back to the issue closes the loop's own intake.

History: four candidates on 2026-09-10 failed only on regex-routed recovery
text. The 2026-09-11 restatement asked for "one row per reason the loop can
emit"; that was over-specified and produced a 341-row table plus a test that
parses source files. This second restatement replaces that criterion. The
retained candidate on `codex/iss-105-self-selection` (PR #377) has the correct
selection, label and note behavior; trim it to this draft and land it.

## Done when

- On each cycle the loop lists open issues on the repository with label
  `ready`, keeps those whose `blocked_by` (from the draft frontmatter) are all
  closed, orders by milestone then issue key, and takes the first.
- It removes `ready` while working and restores it on a stop that is not
  completion.
- On merge it closes the issue. On any stop it posts one comment on the issue
  with the stop reason, attempt count, and what a person should change; that
  comment is the learning note.
- The recovery text comes from a small exact-match table, about a dozen rows,
  covering only the reasons a person acts on differently:
  `completed-issue-state-unknown` (check the PR; if merged, close the issue by
  hand and restart; never reopen), `issue-observation-unavailable` (restore
  `gh` auth or network and restart; never edit issue state),
  `selected-base-unavailable` (fetch origin or restore the pinned commit;
  never change the selection), `current-main-unavailable`, the typecheck and
  format gate failures, malformed reviewer output, missing exit receipt, the
  native launch ceiling, and the implementation attempt ceiling. Every other
  reason gets one generic sentence naming the evidence directory and the
  reason verbatim. No pattern matching on reason strings anywhere.
- The set of stop reasons is a single exported string-literal union (or
  `as const` array) in `queue.ts`, and the table is typed against it so
  completeness is a compile-time check. No test parses source code.
- Tests assert public behavior only: selection order, blocked skipping, label
  handling, close on merge, the three prescribed actions above and their
  forbidden advice, and the generic fallback. Tests do not assert record file
  names, call counts, or note wording beyond those rows.
- The hosted-test inventory guard (`expected-hosted-tests.json` and the
  candidate inventory adapter) is deleted; the required checks on the PR are
  the only hosted proof.
- `supervise.mjs` stays a thin entrypoint: one composition of the selection
  into a queue config, one loop, no special-cased terminal paths.

## Out of scope

Creating new issues from notes; a person does that. Repository-specific
selection rules (ISS-107). Any new state, schema or mechanism beyond the
reason table.
