## Why

The loop still needs a person to pick the next issue, and when it stops the
reason lives in a state directory nobody reads. Selecting from GitHub and
writing the stop reason back to the issue closes the loop's own intake.

Four candidates were authored on 2026-09-10. Selection, restart ordering and
focused coverage passed review; the last FAIL was only that the stop note's
"what a person should change" text is derived from regex matches on the reason
string, so three exact reasons land in the wrong bucket. The clean candidate
is retained at `4ba4e81ad1b0de5073e9f24c9f47b17895b503fe` on
`codex/iss-105-self-selection`. Start from it. This restated draft resets the
attempt count; the next attempt is 1 of 4.

## Done when

- On each cycle the loop lists open issues on the repository with label
  `ready`, keeps those whose `blocked_by` (from the draft frontmatter) are all
  closed, orders by milestone then issue key, and takes the first.
- It removes `ready` while working and restores it on a stop that is not
  completion.
- On merge it closes the issue. On any stop it posts one comment on the issue
  with the stop reason, attempt count, and what a person should change; that
  comment is the learning note.
- The recovery text is chosen by an exact match on the stop reason first, in
  a table with one row per reason the loop can emit. Pattern matching is
  allowed only as the fallback for reasons not in the table, and a fallback
  note says the reason is unmapped so that becomes its own learning note.
  The table must at least get these right:
  - `completed-issue-state-unknown`: the PR merged but the loop could not
    confirm the issue closed. Action: check the PR on GitHub; if it merged,
    close the issue by hand and restart so the cycle reconciles. Never say
    to reopen the issue.
  - `issue-observation-unavailable`: GitHub could not be read. Action:
    restore `gh` authentication or network access and restart. Never say to
    edit issue state, labels or markers.
  - `selected-base-unavailable`: the pinned base commit in the durable
    selection is not present in the executor checkout. Action: fetch
    `origin` (or restore the pinned commit) and restart. Never say to change
    the selection record.
  - `current-main-unavailable`, gate failures, malformed reviewer output,
    missing exit receipts, ceilings, setup, hosted checks and delivery keep
    the actions the candidate already gives, but each by exact reason rather
    than by pattern.
- A test enumerates every reason the loop can emit and asserts each has an
  exact row; a second test asserts the three reasons above produce the
  actions stated here and none of the forbidden ones.
- The hosted-test inventory guard (`expected-hosted-tests.json` and the
  candidate inventory adapter) is deleted; the required checks on the PR are
  the only hosted proof.
- Tests cover selection order, blocked skipping, label handling, and the note.

## Out of scope

Creating new issues from notes; a person does that. Repository-specific
selection rules (ISS-107). Any new state, schema or mechanism beyond the
reason table.
