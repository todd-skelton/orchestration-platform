## Why

Today the author prompt forbids running tests, so the delivery gates and
hosted CI are the first time a candidate is typechecked, formatted or tested.
Every failure there becomes a multi-launch repair. Letting the author run the
same commands the gates run removes most of those launches.

## Done when

- The author prompt built in `scripts/dogfood/flow.ts` (`workerPrompt`) tells
  the author to run `pnpm typecheck`, `pnpm format:check` and `pnpm test` in
  its worktree before reporting, and to fix what fails. The sentence banning
  local test runners is gone.
- The Codex launch in `scripts/dogfood/dispatch-adapter.ts` keeps the author in
  `workspace-write` with no additional writable roots; running `node_modules`
  binaries inside the worktree needs no new permission.
- The reviewer prompt is unchanged except for the removed ban.
- `scripts/dogfood/delivery.ts` still runs the four gates as a re-check.
- Tests under `test/dogfood/` cover the new prompt text and the unchanged
  reviewer prompt.

## Out of scope

Retrying a failed gate (ISS-103). Changing the review verdict shape (ISS-102).
