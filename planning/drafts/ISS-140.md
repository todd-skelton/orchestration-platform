## Why

ISS-110's M2 JPEG cycle stopped on #7766 after two reviews could not discover
already-executed mutation evidence. ISS-139 fixes evidence discovery, but the
recovery inspection found no material product edit required by either finding.
The rejected candidate is `bdc0e2973562a70a494d37b04c863230326bbc85`, based on
product main `5ae2519d4f8f15b70bcc3c6c0e7a7e4355f14589`. Native trace items 22,
26 and 28 in the repair author trace prove mutant failures and restored success.
The recorded incident is
https://github.com/todd-skelton/orchestration-platform/issues/367#issuecomment-5658580279.

The next native attempt starts at the rejected candidate, but flow.ts requires
a nonempty author diff and then a head different from that corrective base.
An author honestly confirming the existing source and providing evidence
therefore cannot reach independent review. Manufacturing source or comment
churn just to satisfy these checks would not fix the recorded failure.

## Done when

- A fresh or resumed corrective attempt may hand the existing rejected
  implementation candidate to independent review after its author actually
  finishes with PASS and no source changes. Reuse the existing candidate and
  recorded lineage, not an empty commit or a new version of the old verdict.
- Keep initial no-change/no-implementation submissions from becoming a
  delivery. There must still be real candidate work relative to its delivery
  base. Preserve the distinction between author corrective base, full
  implementation diff and delivery/main base through source and repair paths.
- Exact-head review, all applicable product gates, publication, hosted CI,
  merge queue and deployment remain mandatory. Reviewers receive the current
  author's execution evidence. A reviewer can still FAIL; author PASS never
  supplies review authority. The full existing implementation is not omitted
  from the review or verification footprint because the corrective delta is
  empty. Nonempty corrective changes retain the ordinary path.
- Regression tests reproduce #7766's zero-diff corrective handoff, then prove
  independent review and ordinary delivery can proceed with the existing
  candidate. Cover source continuation, immediate repair and persisted resume,
  initial no-op rejection, reviewer failure, and unchanged attempt accounting.
  Use existing configuration/records where possible; add no new receipt,
  recovery service, product mutation framework or manual PASS import.
- Run typecheck, format:check, planning:check and test. Document the small
  recovery behavior in docs/loop.md. Do not change any failed #7766 runtime
  record, verdict or consumed attempt count, unpark it, or start a loop as part
  of implementing this repair.

## Out of scope

JPEG source changes, retroactive review PASS, attempt reset or ceiling increase,
automatic unpark, bypassing readiness or delivery gates, and M2 completion claims.
