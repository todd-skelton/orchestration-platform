## Context and evidence

A review is mutation authority only for the immutable closed target it examined:
`worker-result-subject/v1` or `release-candidate-subject/v1`, plus the distinct
review attempt. A code-host revision is evidence only
when its canonical tree/ordered patch/artifact materializes that identical
result digest. See the receipt contracts from `ISS-002`, cycle protocol, and role
isolation from `ISS-008`.

## Scope fence

In: review request, independent attempt identity, accepted/rejected/unknown
engine receipt, opaque module disposition payload, complete-history reducer,
closed `review-subject/v1` authorization for worker results or release candidates,
optional code-host materialization proof, and stale or contradictory evidence refusal.

Out: provider prompting, code-host merge APIs, project-specific review rubrics,
and release installation.

## Decisions already made

Workers never self-certify. Engine authority follows the `Review authority`
table in `docs/architecture/state-machines.md`; repair/replan taxonomy belongs to
planning modules rather than the engine.

## Acceptance criteria and evidence

1. A pass authorizes only one exact `worker-result-subject/v1` digest and author
   attempt. The request and receipt bind base revision, resulting tree or ordered
   patch/artifact digest, terminal worker receipt, reviewer attempt, and review
   packet. Evidence: one-byte, reordered-patch, rematerialized-result,
   moved-head, and reused-attempt negative controls.
2. When a pull request/commit is present, a canonical materialization receipt
   proves its exact tree or ordered diff/artifacts equal the worker-result digest
   immediately before review reduction and mutation preflight. A revision string
   alone never authorizes. Evidence: raw code-host-to-result proof and moved-
   revision/substituted-artifact mutants.
3. `release-candidate-subject/v1` binds landed source SHA/tree, immutable
   candidate/manifest/test-bundle/certification digests and is reviewed only by
   a distinct later review-role attempt. Missing landing/certification, pre-merge
   or moved candidate, worker-result review reused as release review, and
   candidate-authored review refuse. Evidence: subject-union and cross-kind
   authority mutation matrix.
4. Missing, truncated, contradictory, future-version, or ambiguously ordered
   histories reduce to unknown authority. Evidence: exhaustive reducer fixtures.
5. Reviewer and author identities cannot collapse through aliases. Evidence:
   canonical identity tests.
6. Every block contains stable finding IDs, reproduced evidence, and a bounded
   disposition. Evidence: schema and semantic fixture validation.
7. `@orchestration-platform/review` replaces only the static `review`
   command-family placeholder. Evidence: registry census and exact-subject
   command-envelope tests.

## Independent review packet seed

Attack stale passes, duplicate physical rows, contradictory attempts, malformed
worker-result identity, revision/result mismatch, review self-certification, and truncated pagination. Use a
mutation-generated receipt corpus with one negative control per field.
