of `allowedPaths` can reach it. This is a capability boundary, not a

## Done when

- **AC1: A futile integration continuation is refused before any worker
  launch.** When the merge of `candidateHead` with current main is computed and
  the configured `localGates` fail on the merged tree at one or more paths that
  carry **no marked conflict hunk**, the loop stops with a typed reason before
  dispatching the integration author. Zero author or reviewer launches are
  recorded for that cycle, and the native launch ceiling is not charged.
  Evidence: a focused test reconstructing the ISS-146 shape (a candidate whose
  marked hunks are resolvable but whose auto-merged file fails a gate),
  asserting zero launches; red before, green after.
- **AC2: A viable integration continuation still dispatches unchanged.** When
  the merged tree passes the configured gates, the author is dispatched with the
  same prompt, the same `allowedPaths`, the same attempt numbering and the same
  claim behaviour as today. Evidence: the existing
  `test/dogfood/integration-continuation.test.ts` cases stay green, plus an
  explicit positive control asserting the dispatched prompt is byte-identical to
  today's for a viable packet.
- **AC3: The refusal names the unreachable paths and the failing gate.** The
  stop carries the failing gate command and the specific paths that failed
  without a marked hunk, so the next decision is derivable without reading the
  runtime. This must not depend on the 500-character published excerpt; the
  complete evidence is retained at a stated artifact path. Evidence: a test
  asserting both the retained artifact and the paths it names.
- **AC4: Fail closed in both directions.** An unreadable, empty, or erroring
  pre-dispatch gate run does **not** silently admit the dispatch and does not
  silently refuse a viable one; it stops with a distinct typed reason naming the
  failure. A gate failure at a path that **does** carry a marked hunk is
  **not** treated as futile, because the author can still reach it. Evidence:
  negative controls for each case, each asserting the exact reason string.
- **AC5: No authority, budget, or lineage semantics change.** Attempt ceilings,
  `nativeLaunchCeiling`, the consumed-claim guard at `queue.ts:984-997`, the
  `authorityUrl` contract, parking behaviour, and the `continuation-failed`
  refusal at `queue.ts:1096-1097` are all unchanged. This slice does not unpark
  ISS-146, does not reset any ceiling, does not restart a run, and does not
  install an executor. Evidence: existing queue, supervision and
  integration-continuation suites.

## Review packet

This slice adds a refusal in front of a dispatch, so the two failure directions
are refusing a viable integration (a false stop that strands a landable
candidate) and admitting a futile one (today's behaviour, which burns a launch
and parks the issue). AC2 and AC4 exist for exactly that pair. Full-path review
should attack the marked-hunk determination itself: a path that conflicts **and**
fails a gate must not be called futile; renames, deletions and mode changes must
not be misread as unmarked; and the pre-dispatch gate run must not mutate the
executor checkout, the candidate, or any retained runtime. The
omission-revealing artifact is the preserved cycle-10 evidence, where every
authorized hunk was resolved correctly and the dispatch was still futile.
