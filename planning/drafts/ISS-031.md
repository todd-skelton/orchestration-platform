## Question

Which exact native-store custody topology can meet the availability, identity,
role/capability, revocation, direct-store denial, and zero-leak contract in
`docs/architecture/credential-broker.md` on macOS, Windows, and Linux after a
reboot and next eligible user session?

## Probe method and lifecycle timing

Using the trusted OS harness and the runtime mechanism selected by `ISS-022`,
provision unmistakably synthetic secrets/references in Windows Credential
Manager, macOS Keychain, Linux Secret Service, and isolated Codex homes. Capture
native user/store/item identities at bind, availability immediately at tick
start, bounded retrieval only inside a broker operation/host launch,
lock/revocation immediately before access, and zeroization/no-leak after
completion. From implementation, review, observer, adapter, and unlisted
processes, invoke the byte-hashed direct attack helper against every item:
`CredReadW` on Windows, `SecItemCopyMatching` on macOS, and
`org.freedesktop.Secret.Service` D-Bus on Linux. This probe owns and publishes
the shared native-store attack-suite fixture (one byte-hashed helper per OS);
`ISS-021`, `ISS-023`, `ISS-032`, `ISS-035`, and `ISS-038` rerun that suite
instead of restating these APIs. The suite is a deliberate durable output at
canonical path `probes/credentials/attack-suite/`, consumed at certification
and install time with its digest recorded in the bootstrap manifest census;
it is not probe residue. Run both current-user and a
separately confined broker-principal topology where the OS supports them. Reboot
or restart the user session and rerun from an empty ambient credential environment.
For a cross-principal result, freeze the exact native IPC kind, endpoint/handle
creation, owner/ACL identities, client/process attestation, request framing,
replay fence, restart, and teardown contract; attack endpoint discovery, handle
duplication, impersonation, replay, and wrong-principal calls.
On Windows x64, the only candidate is `WinSW-x64.exe` v2.12.0 wrapping the
absolute byte-hashed Node 24 executable and broker `.mjs` under the declared
virtual service account. Record the asset SHA-256/license, exact XML and SCM
read-back, `ServiceMain` lifecycle supplied by WinSW, start/stop/restart/crash/
reboot behavior, process tree, and unsupported-architecture refusal. A bare
`.mjs`, scheduled task, unpinned wrapper, or shell command cannot pass.

## Required durable evidence

Publish no secret. Retain exact OS image/API/helper source and binary identity,
literal argv, custody-principal identity, reference and
fingerprint receipts, role/capability matrix, native-store lock/unlock/revoke
events, process/environment/argv/journal canary scans, cold-session receipts,
IPC/endpoint attack receipts where applicable, and one normalized capability
result per backend/OS bound to probe/test digests.
Windows evidence additionally binds the WinSW asset/config, Node executable,
broker script, SCM service/process-control, and release-manifest digests.

## Disposition rule

- PASS a backend/topology only on the OSes where every contract property,
  direct-store attack, and cold-session lifecycle is proven; `ISS-032`
  implements the exact admitted matrix. Same-user storage is inadmissible if
  any worker or unlisted process can read an item directly.
- A locked/unavailable store may be a named safe refusal after reboot, but cannot
  count as successful unattended access.
- If any required OS lacks a safe backend/reference path or independently
  confined broker/role boundary, `BLOCK_REPLAN` and narrow cold-host automation
  or add a separately reviewed portable broker identity.
  Plaintext files, ambient environment secrets, prompts, and logs are forbidden
  fallbacks.

## Negative controls

Direct native read from every non-grantee role/unlisted process, wrong user,
moved/renamed item, changed fingerprint, locked store, expired
reference, revoked generation, extra capability, missing role, inherited token,
argv/log/journal canary, stale Codex home, and concurrent revoke/read.
