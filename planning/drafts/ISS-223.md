## Why

Hosted-check observation is a read-only, identity-bracketed operation. A
short GitHub transport loss in either identity read or attributed workflow/job
read currently stops the run even though a later ordinary observation can
recover. Retrying only the failed read would need a per-read wrapper and continue a bracket whose earlier reads predate the pause; restarting the whole bracket keeps one catch site and a single-moment observation.
Retrying the complete bracket keeps
the existing fail-closed identity comparison and gives a classified transport
failure the same bounded three-read, 1-second/2-second retry already accepted
by ISS-211.

The smallest safe behavior is wrong if a transport failure can return a mixed
bracket, a non-transport error is retried, a conflict or identity drift is
masked, a mutation is replayed, or an exhausted retry loses the
`hosted-observation-unavailable` category diagnostic.

## Decision

Reuse ISS-211's `GithubCommandFailure` classification and pause schedule at the
owning `checks()` boundary, but retry the whole `readIdentity()` /
`attributedChecks()` / `readIdentity()` observation. Retry only when the caught
error is a classified transport failure and only twice after the initial read.
On a successful retry, return the same checks result and preserve the existing
`startupInvisible` rule and 10-second polling cadence. On exhaustion, stop with
`hosted-observation-unavailable` and the sanitized category diagnostic.
`published-candidate-conflict`, `publication-state-unknown`, publication
identity drift (`publication moved`), malformed responses, and all other
non-transport errors retain their current immediate fail-closed disposition.

### Options

| Option | Assessment |
| --- | --- |
| Reuse ISS-211 classification around the whole checks bracket | **Select.** It retries only the owning read operation, keeps one catch site and a single-moment observation, changes no caller contract, and uses the existing three attempts with 1 s/2 s waits. |
| Retry each `commands.ghJson` read centrally | Reject. It broadens ISS-211's deliberately local boundary to publication, merge, log and mutation-adjacent callers. Retrying only the failed read would need a per-read wrapper and continue a bracket whose earlier reads predate the pause; restarting the whole bracket keeps one catch site and a single-moment observation. |
| Add both per-read and whole-bracket retries | Reject. It multiplies reads and waits, duplicates classification, and expands scope without improving the fail-closed contract. |

No retry is added to `commands.gh`, `publish`, `merge`, queue admission,
comment/draft mutations, or any other mutation. No timeout, polling cadence,
startupInvisible limit, attempt ceiling, record format, or supervisor restart
policy changes.

## Scope and don't rebuild

ISS-211/#662 already ships the classifier and a bounded three-read,
1-second/2-second retry for draft and learning-note observations; reuse its
semantics, not its callers or records. ISS-188/#580 separates same-run hosted
status progress from immutable workflow identity; it does not retry a GitHub
transport read. ISS-217/#693 intentionally keeps non-note issue reads
single-shot and retains diagnostics; it does not cover hosted checks.
ISS-220/#704, delivered by PR #707 (`e9f92797`), owns queued-merge reconciliation and explicitly excludes transport retries.
None is a prerequisite and none is
replaced by this issue.

The adjacent reads were inspected. `failedCheckLog()` first calls
`this.checks` (therefore it benefits from the checks bracket retry) but
then performs its own selected-run `gh api` read and log read between two
`verify()` brackets under an all-error catch that stops as
`hosted-check-log-unavailable:<name>`. `observeMerge()` reads
`gh api graphql` for queue policy or `gh pr view` for squash and maps
every error, including classified transport, to `unknown`. The pre-mutation
`confirmMerge` observation and the saved-green merge reconciliation in
`delivery.ts` then stop as `merge-state-unknown`; the post-mutation observation
stops as `merge-outcome-unknown` (or preserves a queue mutation failure).
A transport loss there still stops the run. Both remain single-shot here because no cycle has recorded a
transport stop on either path (AGENTS.md: add a mechanism only when a real
cycle recorded the blocker it removes). A recorded stop on either path is
a separate fixed-scope intake. `observePublication`, `publish`, `merge`,
and cleanup similarly remain unchanged. `observeDraft()` already has the
ISS-211 retry. The only change is the checks boundary itself, where run
`m1-iss219-20260930T1030` recorded the stop.
