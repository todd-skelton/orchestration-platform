## Why

Hosted-check observation is a read-only, identity-bracketed operation. A
short GitHub transport loss in either identity read or attributed workflow/job
read currently stops the run even though a later ordinary observation can
recover. Retrying only one read would allow a before/checks/after result to
mix observations from different moments. Retrying the complete bracket keeps
the existing fail-closed identity comparison and gives a classified transport
failure the same bounded three-read, 1-second/2-second retry already accepted
by ISS-211.

The smallest safe behavior is wrong if a transport failure can return a mixed
bracket, a non-transport error is retried, a conflict or identity drift is
masked, a mutation is replayed, or an exhausted retry loses the
`hosted-observation-unavailable` category diagnostic.

## Decision

Reuse ISS-211's `GithubCommandFailure` classification and pause schedule at the
owning `checks()` boundary, but retry the whole `readIdentity()` /
`attributedChecks()` / `readIdentity()` observation. Retry only when the caught
error is a classified transport failure and only twice after the initial read.
On a successful retry, return the same checks result and preserve the existing
`startupInvisible` rule and 10-second polling cadence. On exhaustion, stop with
`hosted-observation-unavailable` and the sanitized category diagnostic.
`published-candidate-conflict`, `publication-state-unknown`, publication
identity drift (`publication moved`), malformed responses, and all other
non-transport errors retain their current immediate fail-closed disposition.

### Options

| Option | Assessment |
| --- | --- |
| Reuse ISS-211 classification around the whole checks bracket | **Select.** It retries only the owning read operation, prevents mixed before/after data, changes no caller contract, and uses the existing three attempts with 1 s/2 s waits. |
| Retry each `commands.ghJson` read centrally | Reject. It broadens ISS-211's deliberately local boundary to publication, merge, log and mutation-adjacent callers, and can return a mixed identity bracket. |
| Add both per-read and whole-bracket retries | Reject. It multiplies reads and waits, duplicates classification, and expands scope without improving the fail-closed contract. |

No retry is added to `commands.gh`, `publish`, `merge`, queue admission,
comment/draft mutations, or any other mutation. No timeout, polling cadence,
startupInvisible limit, attempt ceiling, record format, or supervisor restart
policy changes.

## Done when

## Scope and don't rebuild

ISS-211/#662 already ships the classifier and a bounded three-read,
1-second/2-second retry for draft and learning-note observations; reuse its
semantics, not its callers or records. ISS-188/#580 separates same-run hosted
status progress from immutable workflow identity; it does not retry a GitHub
transport read. ISS-217/#693 intentionally keeps non-note issue reads
single-shot and retains diagnostics; it does not cover hosted checks. ISS-220/#704
and its open implementation PR #707 own queued-merge reconciliation and
explicitly exclude transport retries. None is a prerequisite and none is
replaced by this issue.

The adjacent reads were inspected. `failedCheckLog()` first calls `this.checks`
(therefore it benefits from the checks bracket retry) but then performs its own
selected-run `gh api` read and two log observations under an all-error catch;
retrying that separate sequence would require a second identity contract and is
not included. `observeMerge()` reads `gh api graphql` for queue policy or
`gh pr view` for squash, then maps every error to `unknown`; its ordinary next
observation is already the fail-closed recovery boundary, so an in-call retry
would change merge timing and scope. `observePublication`, `publish`, `merge`,
and cleanup similarly remain unchanged. `observeDraft()` already has the
ISS-211 retry. The only common smallest change is the checks boundary itself.

### Not built

| Not built | Reason |
| --- | --- |
| Central `ghJson` retry helper | Would cross publication, merge, log and mutation-adjacent callers and risk mixed observations. |
| Retry of mutations or uncertain responses | No command write, enqueue, readiness, comment, publication or merge is repeated. |
| Merge/log/failed-check retry policy | Their state contracts and fail-closed catches are separate; only nested `checks()` receives this bounded retry. |
| New timeout, polling loop, startup rule, schema, receipt, attempt or restart | Existing cadence, records and supervisor recovery remain authoritative. |
| Network/proxy/TLS repair or live-run operation | The transient transport stop is evidence for a bounded code change, not permission to edit or operate runtime state. |
