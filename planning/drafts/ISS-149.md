## Why

Todd ruling 2026-09-14 (orchestration-platform#368): the loop must use the
same model placements the incumbent's model-routing skill already proved,
instead of one static author/reviewer pair per run. The executor's Codex home
reaches the Claude models through the same `account_pool` provider as the GPT
models (probed 2026-09-14: `claude-opus-5`, `claude-sonnet-5`,
`claude-fable-5-1` advertised), so no second launcher is needed; ISS-109 is
superseded by this issue.

## Done when

- The loop config accepts a row table alongside the existing static pair. Each
  row names author `{model, effort}`, reviewer `{model, effort}` with one
  fallback, and repair `{model, effort}`. The static pair remains valid only
  as the self adapter's fallback; a chase-sets run with a row table and no row
  for the selected issue fails closed before setup.
- The repository adapter returns a routing row per selected issue.
  `chase-sets` reads one `<!-- routing: {"version":1,"row":N} -->` marker from
  the issue body, set at planning; absent, duplicate, or malformed markers
  make the issue not runnable, with a typed diagnostic. `self` returns the
  fixed policy: author `gpt-6-astra/high`, reviewer `claude-opus-5/high`
  with fallback `gpt-5.6-sol/high`, repair `gpt-6-astra/high`.
- The shipped chase-sets row table follows the incumbent routing table:
  rows 7, 14, 15 author `gpt-6-astra/high`; rows 4, 10 author
  `gpt-5.6-sol/high`; row 2 author `gpt-5.6-terra/medium`; row 3 author
  `claude-sonnet-5/medium`; row 11 review `gpt-5.6-sol/high` fallback
  `claude-opus-5/high`; row 12 review `claude-opus-5/high` fallback
  `claude-sonnet-5/medium`. Which review row applies is part of the marker
  (`"review":11|12`). Repair uses the author's config. Fable and Terra are
  never reviewers; the reviewer's model never equals the author's.
- Reviewer fallback is used only when the primary launch is refused by the
  provider (models probe or launch error), never on a review verdict.
  Challenger quotas, reserves, and spend telemetry from the incumbent skill
  are out of scope; the loop gets row defaults only.
- Every attempt record and learning note carries the routing row and the
  exact author/reviewer models used. Tests cover marker parsing and refusal,
  self policy, fallback on provider refusal only, and author/reviewer
  distinctness. docs/loop.md documents the marker, the row table, and how
  the operator sets a row at planning.

## Out of scope

Automatic row classification from labels or issue text, per-token cost
accounting, the incumbent's challenger quotas and Fable reserve, model
identity verification beyond what the launch already reports, mixing models
within one attempt, and any change to the Claude Code CLI launcher (ISS-109
closes as superseded when this lands).
