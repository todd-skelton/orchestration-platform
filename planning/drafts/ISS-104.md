## Why

Running one item today needs a hand-authored setup request, queue request,
queue authority with two digests, per-item source config, repair config,
delivery policy and delivery authority. The host wrote about forty lines of
bespoke script per item to produce them. The loop can derive all of that from
a short config plus the issue it is working on.

## Done when

- `node scripts/dogfood/supervise.mjs <loop.json>` accepts a single file:
  repository, stable executor root, external state root, author and reviewer
  model/effort, Codex executable, Git executable (Windows needs Git 2.53+ for
  the NUL-delimited worktree listing), native launch ceiling and attempt
  ceiling.
- The queue derives setup, source, repair and delivery configs and their
  authority records itself from that config plus the selected issue, using the
  exported `queueDigest`, `itemAuthority` and `participantIdentity` helpers in
  `scripts/dogfood/queue.ts`. No digest is computed outside the loop.
- Author and reviewer prompts are built by the loop from `docs/loop.md` rules
  and the issue draft; there are no external prompt files.
- Worktrees and state directories are created under the configured roots with
  names derived from the issue key and attempt.
- The old multi-file request shape is removed along with its validators; tests
  are updated to the new config.

## Out of scope

Choosing the issue (ISS-105). Multiple repositories per config (ISS-107).
