## Context and observed need

ISS-073 and ISS-074 required controller-written setup helpers to create a pinned
reviewed pilot checkout, an author branch/worktree, an independent review
worktree, external run state, and offline frozen dependencies. Those repeated
bridges remain after normal delivery was extracted. ISS-074 is externally
accepted; its issue remains open only until this expressly designated real-use
consumer completes. The executing stable pilot stays externally pinned, and a
mutable candidate request cannot authorize or certify its own pilot.

## G0 and smallest complete shape

G0 is feasible before implementation for every acceptance criterion:

| Criterion | Smallest discriminating implementation and evidence                                                                                                                                            |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1         | One private command composes a policy-neutral setup transition with one Git/pnpm adapter; hosted fixtures prepare the three exact portable paths.                                              |
| 2         | Write-once per-role intents precede Git/install mutation; observation before and after each effect proves restart without duplicate branch/worktree creation.                                  |
| 3         | The existing launcher receives only `install --offline --frozen-lockfile --ignore-scripts`; missing cache, nonzero exit, and uncertain spawn stay incomplete.                                  |
| 4         | External authority binds stable/base/branch and all roots; canonical disjointness, Git membership, cleanliness, branch and head checks refuse collisions and drift before dependent work.      |
| 5         | Results contain only closed status/reason/phase, run/issue, selected paths and approved heads; subprocess text is discarded.                                                                   |
| 6         | The executor must be the clean externally named stable revision, distinct from base; hosted proof and later useful consumption remain controller evidence, never candidate self-certification. |

The selected shape is one transition file, one adapter, declarations/re-export,
and a thin direct-Node composition. An engine-only function would not provide
the required runnable controller invocation. A single monolithic command would
mix portable restart semantics with Git, installer, and repository policy and
therefore fail the explicit adapter criterion. No smaller shape satisfies all
six criteria.

Not built: dispatch or worker behavior; scheduler or queue; generalized
workspace registry; dependency cache manager; cleanup/reclamation; provider or
credential work; environment inspection; automatic repair; public capability
registration; package/compiler changes; release, promotion, or operator
authority. The command never removes a pre-existing path.

  - Too little: An unbounded query or per-item I/O on a measured hot path.
  - Too much: An optimisation with no measurement on a path that is not hot.
  - Evidence: setup has exactly three sequential roles and adds no concurrency,

- ROLLOUT [High] — Rollout safety vs cleanup.
  - Too little: A schema, event, or contract change is not backward-safe or

  - Too much: A dead path, flag, or legacy branch remains once safe to remove.
  - Evidence: private v1 records fail closed, the candidate receives no

- CONSISTENCY [High] — Consistency vs improvement.
  - Too little: A departure from local convention is unstated.
  - Too much: A convention is followed where the brief called for a stated

  - Too little: A changed UI surface misses a state (loading, empty, error,

Deletion test: removing the transition loses durable ownership/restart semantics;

## Scope and non-goals

In: one private portable preparation command using explicit controller
configuration and the existing pnpm launcher. It prepares only the expressly
named pilot/source/review worktrees and their dependency state for one bounded
issue, validates the externally supplied stable revision and base, preserves
existing prompts/configuration and sandbox flags by not touching dispatch, and
emits narrow setup identities and phase status.

Out: dispatch, self-promotion, production activation, credential work, provider
authentication tests, environment inspection, permission expansion, general
scheduler, queue framework, automatic repair worker, issue mirroring, duplicate
delivery implementation, worker environment/launch changes, packages/compiler
options, public registration, cleanup, or release/operator boundary changes.

## Acceptance evidence

1. One controller invocation prepares explicitly selected pilot/source/review
   worktrees at exact approved revisions, the named source branch, and external
   state. macOS, Windows and Linux use the same behavior with portable paths.
2. Intent is durable before each setup mutation. Resume reconciles exact Git
   worktree membership, branch/head and dependency receipts. It neither creates
   a duplicate worktree/branch nor silently adopts unrelated or dirty state.
3. Dependency setup uses the existing launcher and offline, frozen-lockfile,
   ignore-scripts options. A missing cache or uncertain failure remains a typed
   incomplete result, never an implicit network fallback or success receipt.
4. State and worktree paths are resolved and disjoint. Existing unrelated files,
   branches and worktrees are preserved. Malformed authority, a moving base,
   unexpected existing paths, candidate-as-pilot selection, or ambiguous partial
   setup fail closed before dependent work or dispatch.
5. Output contains only bounded phase/status, approved heads and selected run/
   worktree identities. Raw process output, provider errors, worker prose,
   environment values and credentials do not cross the controller display.
6. The candidate does not set itself up as trusted authority. An externally
   reviewed, hosted-proven successor must later prepare a genuinely useful
   subsequent issue. Preserve real execution, restart and partial-failure
   evidence; fixture success alone does not satisfy the real-use outcome.

## Verification

Require an independent exact-head native review, controller `pnpm typecheck`,
`format:check`, `planning:check`, and `planning:board-check`, and actual hosted
Node 24 tests on Windows/macOS/Linux. Hosted fixtures exercise real temporary
Git worktrees and portable paths, exact-head/path guards, interrupted setup and
resume, dependency failure/reconciliation, collisions, dirtiness,
checkout-contained state, unknown authority, and direct Node composition. The
four real multi-cycle fixture cases use a local 30-second per-test ceiling because
the observed Windows setup exceeded the default five seconds; the global
timeout and every assertion remain unchanged. No local tests, builds, native
experiments, credential probes, provider writes, or network checks are allowed.

Apply one implementation sweep, then only prescribed-delta review over changed
lines and direct callers while inheriting the complete sweep. The controller
owns all four gates and hosted evidence. Preserve the ordinary eight-attempt
ceiling and all predecessor attempt/spend history; author 1 and independent
reviewer 2 are the initial ISS-075 reservations in this packet. Corrective
author 3 failed before a presence report or source change, with launcher 3
usage unavailable; its identity, failure, and spend remain counted. Author 4
repaired the runtime path comparison and dependency-state handling, and
independent reviewer 5 accepted those runtime repairs. This author 6 and
independent reviewer 7 checkpoint corrects the stale issue history and the
host-filesystem case-branch evidence gap; it does not grant release authority.

## Predicted footprint and review attack surface

Predicted change: one small setup transition/composition and explicit Git/pnpm
adapter under `scripts/dogfood`, focused discovered tests, this draft, the
kernel roadmap registration, the supervised note, and pressure round 478. No
package command, compiler option, public contract family, adapter capability,
dispatch flow, delivery behavior, or production policy change.

Attack unreviewed-pilot substitution, stale revision reuse, branch/worktree
collision, symlink/case/path aliases, checkout-contained state, adoption of
dirty/unrelated paths, repeated setup after uncertain outcomes, false dependency
success, online fallback, mutation without intent, and raw output leakage.
Reconcile from current Git/filesystem state before retry. No cleanup or recursive
deletion of pre-existing paths is authorized.
