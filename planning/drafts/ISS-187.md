## Decision

Quality profile: `core-library`. Constraint: unblock the native prerequisite
without replacing cycle 5, losing consumed work or creating a second executor.
Chosen minimum: one explicit prerequisite declaration on the existing loop
config and a small additive supervision record namespace for this detour.
The declaration binds the existing run's blocked cycle and completed run-stop,
one prerequisite issue key/number, and its host authority reference. It is not
an arbitrary next-issue override. Resolve current eligibility through the self
adapter, pin current planning/base once, and route that same selected prerequisite
through the existing queue in the ORIGINAL run and worktree root. Only its
supervision selection/stop/completion records use the additive detour namespace;
queue attempts keep their ordinary same-run paths and lifecycle.

Reuse native setup, source, repair, review, delivery, issue start/park/close and
stop-note semantics. Do not reuse cycle 3 or cycle 5 filenames for the detour's
selection or completion. A terminal detour retains an explicit hold on the
blocked selection. A subsequent separately authorized resume must supply a new
host grant reference for that blocked cycle; omission, the original detour
grant or a repeated completed detour cannot release the hold. This is operator
configuration, not an approval service, signed receipt protocol or worker power
to issue grants. All entry remains through `supervise.mjs` and its canonical
launcher. New records are for restart, not a second process auditing the loop.

Accepted cost: one exceptional selection path and small persisted progress for
a demonstrated stopped-run dependency. Revisit only when another recorded run
needs a different dependency shape; do not prebuild nesting, graph scheduling,
priority overrides, recurring recovery or a generic migration system.
