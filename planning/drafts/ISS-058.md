## Context and evidence

Decision #302's readiness audit (§3, CF-3) identifies the offline
negative-control matrix as a credential-free prerequisite for `ISS-036`'s
live matrix (acceptance criterion 2 of the repaired `ISS-036` draft): every
control that can be expressed as a transcript mutation and checked purely,
run against `ISS-059`'s producer, with no live provider response.

## Scope fence

In: each of the twenty-eight controls named in `planning/drafts/ISS-036.md`'s
`## Negative controls` list expressed as a transcript mutation plus the exact
expected refusal, run offline. Covers the pagination, ETag, run-correlation,
workflow-identity, artifact, merge-method, protection-change,
permission-widening, trigger-substitution, and reviewer/actor-identity
families, plus the ISS-054 closed snapshot corpus at every protection and
verifier-anchor entry point.

Out: the two controls only the binder can judge — a live ruleset change
after receipt creation, and the anchor variable set or moved after the
producer run (`ISS-061` owns those offline, and `ISS-036` owns them live).
Any control needing a live provider response is also out.

## Acceptance criteria and evidence

1. One row per control naming the mutated transcript cell, the entry point
   it exercises, and the exact issue code the producer returns.
2. A deletion mutant per gate makes the control's row fail — an assertion of
   `ok === false` alone, without the issue code, does not satisfy this
   criterion (the exact weakness Round 460 found and corrected in ISS-054,
   `planning/drafts/ISS-054.md:774-778`, is not repeated here).

## Verification plan

No command is registered for this issue yet. Local verification is the
ordinary planning, formatting, typecheck, and diff gates plus independent
exact-head review; a verification command is registered together with
`ISS-062`'s scaffold amendment once this issue's source lands.

## Predicted footprint and dependencies

Creates `probes/self-host-github/test/negative-controls/**`. No root script
change. Blocked directly by `ISS-059`, whose producer this matrix drives
through every refusal path. Consumed by `ISS-062`, which runs this matrix
inside the offline `:verify` implementation.
