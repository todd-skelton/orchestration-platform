## Question

Can designated Windows, macOS, and Linux user hosts prove canonical host/user/
state-root identity, worker-inaccessible non-exportable Ed25519 custody, and
scheduler-initiated signed-receipt feasibility without a reboot, plaintext
keys, manual starts, or ambient credentials? The single physical three-host
reboot drill belongs to `ISS-038`.

## Probe method and lifecycle timing

Probe the closed `docs/architecture/host-custody.md` algorithms without
implementing a production package. Enroll one designated host per OS through the pinned nonce/
attestation challenge, have Todd compare fingerprints, install a synthetic
user-scoped collector, let the scheduler initiate the next eligible collection
tick without any manual start or reboot, verify the signed receipt, then
teardown. Repeat wrong-user/root, copied key/reference, manual-start,
upload-failure, replay, and revoked-key controls.
From each worker role and an unlisted same-user process, rerun the
ISS-031-owned shared native-store attack suite directly against the host-key
item, extended with the host-key-specific broker-endpoint, process-memory,
copied-reference, and wrong-principal surfaces; the private-key canary must not
return even though the reference is known.

## Required durable evidence

Exact OS image/native API/helper source, argv, and package digests; direct-store
denial receipts from every role/unlisted process; scrubbed canonical-input maps;
host/user/state/enrollment receipts; public keys and native non-secret
references; workflow/run/artifact/nonce identities;
scheduler/process/credential/tick receipts; signature verification; operator
comparison; upload and local-collection results; teardown census.

## Disposition rule

- PASS only if all three OS hosts independently satisfy the exact algorithms,
  non-exportable Ed25519 key custody, scheduler-initiated signed receipt,
  verification, and teardown contract; the single physical three-host reboot
  drill belongs to `ISS-038`.
- Any OS lacking worker-inaccessible Ed25519 custody, deterministic identity, or
  scheduler-initiated receipt returns `BLOCK_REPLAN`; backend inadmissibility
  follows the ISS-031 disposition, and another OS cannot substitute. A read
  success requires `BLOCK_REPLAN` toward a separately confined broker principal
  or non-exportable app-bound signing key.

## Verification plan

`pnpm run probe:host-custody`

`pnpm run probe:host-custody:verify-receipts`

## Predicted footprint and dependencies

Own only `probes/host-custody/`, a synthetic enrollment workflow/collector, and
scrubbed evidence. Blocks `ISS-038`; no production package or root manifest is
implemented.

## Operator actions

Select the three designated noncritical user hosts, authorize any probe-scoped
custody-principal setup, compare enrollment fingerprints, collect fallback
receipts if upload fails, and approve teardown. No unreviewed service or
plaintext key.

## Glossary impact

None; host custody and re-entry receipt are already registered.


## Independent review packet seed

Attack direct native-store reads, cloned machine IDs/keys, wrong user, path
aliases, manual start, unsigned or upload-only evidence, stale challenge,
source-tree collector, key leakage, teardown omission, and one OS standing in
for another.
