## Question

Can designated Windows, macOS, and Linux user hosts prove canonical host/user/
state-root identity and return signed scheduler-initiated evidence after a real
reboot without plaintext keys, manual starts, or ambient credentials?

## Probe method and lifecycle timing

Probe the closed `docs/architecture/host-custody.md` algorithms without
implementing a production package. Enroll one designated host per OS through the pinned nonce/
attestation challenge, have Todd compare fingerprints, install a synthetic
user-scoped collector, reboot, enter the next eligible user session, verify the
signed receipt, then teardown. Repeat wrong-user/root, copied key/reference,
manual-start, unchanged-boot, upload-failure, replay, and revoked-key controls.
From each worker role and an unlisted same-user process, run the byte-hashed
native attack helper directly against the host-key item using `CredReadW`,
`SecItemCopyMatching`, or Secret Service D-Bus; the private-key canary must not
return even though the reference is known.

## Required durable evidence

Exact OS image/native API/helper source, argv, and package digests; direct-store
denial receipts from every role/unlisted process; scrubbed canonical-input maps;
host/user/state/enrollment receipts; public keys and native non-secret
references; workflow/run/artifact/nonce identities; before/after boot IDs;
scheduler/process/credential/tick receipts; signature verification; operator
comparison; upload and local-collection results; teardown census.

## Disposition rule

- PASS only if all three OS hosts independently satisfy the exact algorithms,
  key custody, real reboot, signed re-entry, verification, and teardown contract.
- Any OS lacking worker-inaccessible Ed25519 custody, deterministic identity, or
  scheduler-initiated receipt returns `BLOCK_REPLAN`; plaintext/exported keys,
  same-user direct-read success, simulated reboot, or another OS cannot
  substitute. A read success requires `BLOCK_REPLAN` toward a separately
  confined broker principal or non-exportable app-bound signing key.

## Verification plan

`pnpm run probe:host-custody-real-reboot`

`pnpm run probe:host-custody:verify-receipts`

## Predicted footprint and dependencies

Own only `probes/host-custody/`, a synthetic enrollment workflow/collector, and
scrubbed evidence. Blocks `ISS-038`; no production package or root manifest is
implemented.

## Operator actions

Select the three designated noncritical user hosts, authorize any probe-scoped
custody-principal setup, compare enrollment
fingerprints, approve one reboot/login each, collect fallback receipts if upload
fails, and approve teardown. No unreviewed service or plaintext key.

## Glossary impact

None; host custody and re-entry receipt are already registered.
