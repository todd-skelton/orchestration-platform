## Why

The first M2 launch on 2026-09-12, with `/root/orchestration-m2/loop.json`
naming the `chase-sets` adapter and `/root/orchestration-m2/repo` as
`stableExecutorRoot`, stopped at once with `queue-internal-error` and no
note. Reproducing the pre-cycle steps one at a time found that the loop is
single-repository by construction; the self adapter never exercised two
roots.

- `nextCycle` in `scripts/dogfood/supervision.ts` passes `executingRoot`,
  the platform checkout, as `executorRoot` to `selectCandidates`, so the
  adapter imported the product readers from the platform root and failed
  with a plain module-not-found error.
- `validateLoopExecutor` in `scripts/dogfood/queue.ts` demands
  `stableExecutorRoot` is the same path as `executingRoot`
  (`controller-executor-mismatch`).
- `assertExecutor` in `scripts/dogfood/setup-adapter.ts` demands the
  controller and the repository share one git common directory
  (`setup-repository-mismatch`).
- `assertControllerExecutor` in `scripts/dogfood/delivery-adapter.ts`
  demands the same, and delivery runs its worktree, branch, cleanup and
  status operations against `controllerRoot`.
- `currentMain` fetches `origin/main` inside `executingRoot`, so the base
  commit would come from the platform, not the product.

## Done when

- Two roots exist end to end. `controllerRoot` is the platform checkout that
  runs the loop, pinned by `controllerRevision` and required clean.
  `repositoryRoot` is `stableExecutorRoot`, the checkout of the delivered
  repository, required on `main` and clean. `validateLoopExecutor` validates
  both and no longer demands they are one path; `loop-roots-overlap` covers
  both roots against the state and worktree roots.
- Every git operation on the delivered repository uses `repositoryRoot`:
  worktree add, list and remove and branch delete in setup and cleanup,
  `currentMain`, the selected-base verification and the pre-repair rebase in
  `queueConfigFromLoop`, `verifyWorkspace`, and the publication and merge
  checks. `DeliveryConfig` gains `repositoryRoot`. The
  `setup-repository-mismatch` demand is deleted.
- Controller checks stay on `controllerRoot`: revision unmoved and tree
  clean before each setup and delivery step.
- Supervision passes `config.stableExecutorRoot` as `executorRoot` to
  `selectCandidates` and `issueContext`, never `executingRoot`.
- A stop raised before a cycle is active from an error without a `reason`
  reports `queue-internal-error` with the error message as diagnostics in
  the stderr line, so the next such failure is readable without a
  reproduction.
- The supervise, queue, setup and delivery tests run one cycle where the
  controller and the repository are two different git repositories on disk,
  proving the worktrees, branch, base commit and cleanup land in the
  repository while the controller checkout is untouched. The self case, both
  roots one path, stays green.

## Out of scope

Adapter changes (ISS-122 covered them). More than one repository per run.
