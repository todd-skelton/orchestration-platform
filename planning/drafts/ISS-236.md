## Decision

Classification must describe every non-PASS without changing its disposition.
A reason-to-class table alone is simpler but cannot distinguish a brief defect from a code defect in the same reviewer-failed result.
Choose one additive outcome classification contract shared by typed producers and worker verdict ingestion beside the existing fault-class table.
Accept a small new runtime record for information old terminal formats cannot carry without rewriting them.
Revisit if any producer needs its own taxonomy or classification changes a launch or park in this slice.

## Done when

1. **AC1: one causal class, separate authority.** Define the closed enum
   `mechanical | environment-tooling | implementation-known-remedy | brief |
   slice | design | product-scope | external-dependency`. Every newly observed
   author FAIL, review FAIL, failed required local/hosted gate and failed
   refresh/continuation has exactly one primary `defectClass`, a bounded
   explanation, root-cause identity and source evidence references. A mixed
   failure retains all findings but names the cause determining the next step.
   Neither `FaultClass` nor verdict PASS/FAIL is replaced. PASS, pending and
   non-execution are distinct; exit 73 is not a failed execution or counted attempt.
2. **AC2: real producers, not keyword inference.** Extend new worker output
   ingestion/prompts with causal data on FAIL; retain old report parsing for
   existing saved launches. Typed mechanical and transport outcomes use their
   existing discriminators. Gate environment attribution still requires the
   existing immutable-base control (`docs/loop.md:469`); a timeout or passing
   subset is not proof. Unresolved attribution carries environment-tooling
   with explicit `unresolved` evidence status, never candidate exoneration or
   permission to retry. Preserve a malformed source verbatim and classify the
   protocol failure, rather than fabricating a semantic worker verdict.
   No extra model launch or diagnostic gate occurs merely to populate a field.
3. **AC3: additive, once per outcome.** Use one small recovery/outcome record
   outside the checkout, bound to repository, issue, run, attempt/stage and
   exact terminal/head when one exists. This is the shared record extended by
   ISS-237 through ISS-241, not a new event ledger. Observation replay finds
   the same outcome; it cannot create another classification or charge.
   Legacy records without this field remain readable and byte-identical;
   first recovery may classify retained evidence into a new record without
   backfilling terminals, prompts, config fingerprints or posted stop bodies.
4. **AC4: source-derived coverage ratchet.** Extend the existing parsed
   inventory at `test/dogfood/fault-class.test.ts:93` and :149 to enumerate
   non-PASS producers, including dynamic worker reports, red gates, refresh,
   correction, conflict and all special continuations. Inventory at the
   implementation head, not just the cited baseline. Each producer points to
   one class-producing boundary or an explicit non-execution/pending exclusion.
   A new uncategorized producer fails a focused test. Exercise production
   ingestion, duplicate observation, old/new mixed records and nested malformed
   data; no hand-picked eight-row fixture substitutes for caller coverage.
5. **AC5: no behavior change.** Freeze baseline stop/park/retry/launch outcomes
   and compare them through actual queue/supervision calls after classification.
   Existing five fault classes, legacy parking, budgets, reviewer independence,
   delivery checks and posted body bytes stay unchanged. Named negative
   controls remove a producer's class, accept two classes, classify a pending
   result as failure, and omit the new field from production persistence;
   each must fail its owning test. Document only the new descriptive field.
