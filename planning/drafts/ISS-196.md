## Why

The hosted Windows bootstrap job failed a case the change under test never
touched. [PR #599](https://github.com/todd-skelton/orchestration-platform/pull/599)
(branch `codex/iss-195`, head `a1b856c9fa91dab0855b007ef09e53ab64b171dd`) ran
[run 35508034783 / job 106071031079](https://github.com/todd-skelton/orchestration-platform/actions/runs/35508034783/job/106071031079),
where `test/dogfood/queue.test.ts:64` - "binds repair FAIL to its retained
setup, source, review, author and complete history" - reported
`× ... 30293ms` and `Error: Test timed out in 30000ms.` inside
`❯ test/dogfood/queue.test.ts (175 tests | 1 failed) 973905ms`, closing the run
at `Tests 1 failed | 1214 passed | 17 skipped (1232)` and
`Duration 2880.84s`. The ISS-195 diff did not touch that case, its fixture
(`repairFailureFixture`, `test/dogfood/fixtures/source-failure.ts:341`) or any
setup path it exercises. The identical head was republished as
[PR #600](https://github.com/todd-skelton/orchestration-platform/pull/600)
(branch `codex/iss-195-attempt-2`,
[run 35512910475 / job 106083868812](https://github.com/todd-skelton/orchestration-platform/actions/runs/35512910475/job/106083868812))
and the same case passed at `10422ms` inside
`✓ test/dogfood/queue.test.ts (175 tests) 827956ms`, `21 passed (21)`,
`Duration 2859.82s`; that run merged as
`32e071be43e80fae4dfd4c12b1ccdd1caa58ecef`, which is `origin/main` today. The
loop charged one full attempt for a green change: attempt-2 authors 5.8M + 3.7M
input tokens, reviewer 3.1M, 48 Windows minutes.

The two runs discriminate the cause from generic host load. Total Windows suite
wall clock was effectively identical (2880.84s failing vs 2859.82s passing,
0.7% apart), and across the 146 named `queue.test.ts` cases whose durations both
runs printed the aggregate moved only 1.17x (969918ms vs 826962ms) - but the
`:64` case alone moved 2.91x (30293ms vs 10422ms). The case is not uniformly
slowed; it is the file's single largest cost and its most variance-exposed one,
and at 10422ms of a fixed 30000ms budget it enters every Windows run with 65%
headroom and leaves none for a normal hosted excursion. The same head in the
same passing run measured `2430ms` on Ubuntu and `2086ms` on macOS
(`97506ms` and `181082ms` for the whole file against Windows's `827956ms`, an
8.5x Windows/Ubuntu file ratio), so the exposure is Windows process-spawn cost,
not test logic.

The gate is not negotiable and the timeout is not the defect.
`docs/loop.md:238-243` holds that timeouts stop as
`gate-attribution-unknown:<gate>` and that "No timeout increase, test skip,
passing subset or author opinion establishes attribution";
`docs/loop.md:697-699` fixes serial files and one worker with every existing
test and hook timeout in place (ISS-160). The only supported remedy is to make
the case do less real work.

## Decision

Constraint: `test/dogfood/queue.test.ts:64` must keep asserting exactly what it
asserts today - `attempts: 3`, `f.cycle.initialHistory`, the full mutated-control
set over `attempt.json`, `expect(await f.stop()).toBe("item")` and the
byte-identical `snapshot(directory)` equality
(`test/dogfood/fixtures/source-failure.ts:289-299`) - against real Git
repositories, real worktrees, a real bare remote and two complete `queueStep`
lifecycles, under the unchanged 30000ms `testTimeout`/`hookTimeout`,
`fileParallelism: false` and `sequence.concurrent: false` in `vitest.config.ts`.
Simplest alternative: pin the case's own budget with a per-test timeout, an
`it.retry`, or a Windows-only `it.skipIf`, rejected because
`docs/loop.md:238-243` refuses exactly that class of move as attribution,
because it would leave the next hosted excursion to spend another full attempt
on an unrelated change, and because the class
`vitest-wall-clock-timeout-under-parallel-host-load` requires an unchanged
isolated timing collapse and a complete one-worker/file-serial gate before load
is even admissible as a cause - neither of which any dismissal here supplies.
Chosen: apply the landed ISS-171 idiom (`af3bcd23`,
`test/dogfood/queue.test.ts`) to `test/dogfood/fixtures/source-failure.ts`,
which never received it - memoize the one-time `where.exe`/`which git`
executable lookup (`source-failure.ts:32-36`) in a module-level
`Promise<string>` resolved once per worker instead of once per fixture entry,
and replace the two `git config user.name` / `git config user.email`
subprocesses (`source-failure.ts:41-42`) with a single append of the identical
`[user]` stanza to the freshly initialized private repository's `.git/config`,
then count and collapse the remaining per-entry setup spawns the same way
ISS-194 collapsed `rev-parse HEAD` + `status --porcelain` into one
`status --porcelain=v2 --branch` (`20c98df2`), keeping every generated byte, the
effective committer identity and every lifecycle Git operation unchanged.
Accepted downside: the fixture stops asking Git what its own local identity is
and asserts it by construction instead, so a future Git release that changes
`.git/config` parsing would be caught by fixture commits failing rather than by
a config subprocess erroring, and the saving is a per-entry constant rather than
an asymptotic one - it shrinks setup, not the two real lifecycles that dominate
the case. What would show this wrong: a measured before/after in which removing
these spawns does not move the Windows `:64` wall clock materially - which would
mean the cost is in the lifecycle's own `gitSetupAdapter` work
(`scripts/dogfood/setup-adapter.ts:464-487` already batches seven
`rev-parse`/`branch` probes per assertion) rather than in fixture setup, and the
author must then report that measured contradiction and the remaining bounded
candidate instead of claiming a speedup.

## Evidence and footprint

Hosted per-test durations are already retained - **do not add an artifact.**
`docs/loop.md:274-279` (ISS-141) puts complete failed-run logs in the delivery
runtime's `hosted-failure.log`; `scripts/dogfood/delivery.ts:836` resolves it as
`resolve(config.stateDirectory, "hosted-failure.log")` and writes it atomically
with the repository, run, issue, head, publication and per-check logs;
`scripts/dogfood/delivery-adapter.ts:1455-1462` fills it from
`gh run view <run> --attempt <n> --log-failed`; and
`scripts/dogfood/queue.ts:822` hands the absolute path to corrective workers. The
`--log-failed` capture of run 35508034783 was checked directly: it carries 585
per-test duration lines across the 21 test files, including every
`queue.test.ts` duration vitest printed - 146 lines summing 969918ms against the
file's own `973905ms`, i.e. 99.6% of file time. The 29 unprinted cases are
vitest's sub-threshold fast tests, not truncation: the same 146 names print in
the passing run, summing 826962ms against that file's `827956ms`. Nothing needs
to be added, and the author must not add a second evidence file.

Implementation footprint: `test/dogfood/fixtures/source-failure.ts` only, plus
whatever assertion-free adjustment the measurement proves necessary in the tests
that already call it. Forbidden in this fence: `vitest.config.ts`, any
`scripts/` runtime file, any workflow file, Git mocks, cached HEAD or status,
prebuilt or shared fixture repositories across tests, dropped assertions or
checkpoints, artificial delays presented as causation, and executor
install/restart.

Planning footprint: this draft plus one `M2` row in `planning/roadmap.json`. No
dependency edge is claimed, so `blocked_by` is empty; ISS-195 is merged and is
not a blocker, and no open issue gates this work.

## Verification and sequencing

The M1 self loop implements this; the planner runs no repair gates. The author
measures on one host with one profile: baseline, candidate and a
reverted-control comparison for the `:64` case, so that reduced setup cost is
distinguished from run noise
(`aggregate-failure-dismissed-as-environmental-without-a-discriminating-control`).
Temporary spawn counting is instrumentation, not a shipped change, and must not
survive into the diff.

```bash
node node_modules/vitest/vitest.mjs run test/dogfood/queue.test.ts -t 'binds repair FAIL'
node node_modules/vitest/vitest.mjs run test/dogfood/queue.test.ts
pnpm typecheck
pnpm format:check
pnpm planning:check
pnpm test
```

Sequencing: host publishes this draft and the roadmap row through the
planning-only path, then registers the GitHub issue and reconciles the board
(`pnpm planning:board-check`) before any readiness. Readiness is explicit and
host-owned; it is not implied by this landing. Three-OS hosted bootstrap at the
final repair head is the acceptance gate, and a focused green run, a skipped job
or an aggregate summary without per-case durations does not substitute. No
executor install or restart, no runtime edit, no CI rerun and no retry authority
is granted by this issue. The closed PR #599 carries no stopping-review findings
- it was closed after a `gate-attribution-unknown` hosted timeout and its exact
head was republished and merged as #600 - so no finding IDs are answered here
and #599 remains read-only history.

## Not built

| Not built | Reason |
| --- | --- |
| Raised `testTimeout`/`hookTimeout`, or a per-test or per-file timeout | `docs/loop.md:238-243` refuses timeout increase as attribution; it hides the cost instead of removing it and leaves the next unrelated change to pay for it |
| `it.retry` or a suite-level `retry:` for the case | A retry converts a measurable cost into a coin flip, doubles the Windows minutes it already burns, and is the same non-attribution move as a timeout raise |
| `it.skip` / `it.skipIf` for the case on Windows | The case guards retained-state binding on the OS where the cost actually bites; skipping it deletes the only coverage that would catch the regression |
| Windows-only conditional fixture path | A platform branch makes the Windows fixture a different fixture, so a green Ubuntu run would stop being evidence about the Windows one, and divergence would be invisible until the next timeout |
| Shared or cached fixture repository across tests | Each case needs its own real divergent history, preserved worktrees and bare remote; a shared seed would couple cases and weaken the `snapshot()` equality this issue must keep byte-identical |
| Git mocks or a cached HEAD/status layer | The value of these fixtures is that real Git establishes the states under assertion; mocking them would make the suite pass while proving nothing |
| Reordering cases so `:64` no longer absorbs cold start | Reordering hides an excursion behind whichever case lands first and is a presentation change, not a work reduction |
| A second hosted evidence artifact for per-test durations | `hosted-failure.log` already retains them in full, verified against run 35508034783 (146 of 146 printed `queue.test.ts` durations, 99.6% of file time) |
