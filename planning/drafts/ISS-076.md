## Scope and observed need

Extract one private repair continuation that consumes a completed, exact-head,
fixable source-review failure and prepares and dispatches exactly one corrective
author followed by one fresh independent delta reviewer. Preserve the issue,
main base, distinct corrective base, complete predecessor review, acceptance
criteria, source footprint, participant and usage history, and controller-held
admission. The transition calls the reviewed dogfood flow and native dispatch
adapter; repository and source-report joins remain behind an explicit adapter.

ISS-075 is externally accepted as the stable pilot at
`ce4996c36c05df09d4db4b1b99e48a84f4fb2373`. This issue is registered as #335
under EPIC-KERNEL/M2 and remains blocked by ISS-075 for controller admission.
The initial AUTHOR1/REVIEWER2 pair is retained as historical evidence. The
corrective AUTHOR3/REVIEWER4 pair is the whole current allowance. This source
packet does not launch either pair, grant promotion, or close the real-use
obligation.

## G0 and smallest complete shape

G0: PASS. One policy-neutral repair transition, one explicit filesystem/Git and
dispatch adapter, TypeScript-through-Node declarations/re-exports, and one thin
command are the smallest shape meeting every criterion. The transition validates
the closed failed-review contract before its durable intent, then delegates the
actual author/reviewer lifecycle to the existing reviewed flow. A report-only
validator leaves reservation, continuation and delta review manual. A monolithic
command would mix private lifecycle state with repository/native policy. A new
scheduler, launcher or delivery engine duplicates accepted behavior.

Criterion evidence:

| Criterion | Smallest discriminating implementation and hosted evidence                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1         | Closed v2 report validation recomputes the source config/prompt fingerprint and binds source context, terminal, candidate, participants, profile, G0, twelve pairs, findings and lines.    |
| 2         | External authority binds the loaded controller root, both current prompt paths, adapter executable, bases, worktrees, acceptance, footprint, history and the exact two-slot reservation.   |
| 3         | The adapter calls the reviewed flow and native dispatch adapter, appending only the bounded source/delta report contracts; it never launches a worker itself.                              |
| 4         | The immutable handoff carries all prior participants, outcomes and known/unavailable usage; implementation attempts and cumulative native launches remain separate counters.               |
| 5         | A write-once intent precedes the handoff and dispatch. Existing flow attempt/terminal records reconcile known identities; an intent without an attempt remains an unknown-outcome refusal. |
| 6         | Only a complete structured delta PASS at the exact corrective head produces `awaiting-delivery`; hosted gates, PR refresh, merge, cleanup and promotion remain external.                   |
| 7         | The issue stays open until an externally accepted successor handles a genuine later repair with restart evidence; fixtures cannot satisfy this criterion.                                  |

Not built: scheduler or queue; new model router; new native launcher; generic
private-output reader; unbounded retries; automatic assertion/scope changes;
delivery, existing-PR refresh, promotion or activation; hosted-proof bypass;
credential/environment/provider behavior; cleanup; public capability, package,
compiler or production-policy changes. Existing-PR refresh and selected Git
toolchain observations remain explicit controller follow-ups in criterion 6.
ISS-077/#337 owns the queued cleanup-observer defect and is outside this change.

## Contract profile and source Quality Packet

Profile: `contract` under `quality-contract/v2`. `High` blocks on either
canonical subcase, `Med` blocks only on too little, and `Low` records notes on
both sides. Confirmed incorrect SCOPE behavior and confirmed SECURITY exposure
always block. No additional score applies.

- SCOPE [High] - Correctness vs scope. Little: all seven criteria map to source
  assertions and hosted probes. Much: only the private handoff and named joins
  ship; refresh, delivery, scheduling and cleanup remain follow-ups/non-goals.
- ROBUSTNESS [High] - Simplicity vs robustness. Little: malformed, incomplete,
  stale, dirty, exhausted, duplicate and uncertain states have typed refusals.
  Much: each guard names one of those concrete failure modes.
- DEPTH [High] - Depth vs flexibility. Little: transition state is independent
  of filesystem/Git/native policy. Much: the explicit adapter has the direct
  composition and hosted adapter-join tests as real callers.
- READABILITY [Med] - Readability vs brevity. Little: command to effect crosses
  only composition, adapter and transition; exported names state repair terms.
  Much: identifiers use the existing authority, intent, attempt, terminal,
  candidate, finding and delta-review vocabulary.
- TESTS [High] - Coverage vs test weight. Little: every new surface has hosted
  transition, adapter-join and direct-composition coverage. Much: assertions
  pin external contracts and effects rather than private call arrangement.
- OBSERVABILITY [High] - Observability vs noise. Little: every refusal exposes
  one bounded typed reason and incomplete phase. Much: success does not alert or
  expose report/trace content.
- SECURITY [High] - Boundary security vs friction. Little: exact closed input,
  authority, loaded controller, prompt and source locations are checked at
  policy/adapter boundaries.
  Much: trusted transition logic receives an already validated handoff.
- PERFORMANCE [Low] - Performance vs clarity. Little: fixed-size history,
  report, pair and finding bounds prevent unbounded work. Much: no optimization
  or concurrency is added to this non-hot path.
- ROLLOUT [High] - Rollout safety vs cleanup. Little: new private v1 records are
  write-once and fail closed without changing retained flow/delivery records.
  Much: no compatibility flag, fallback reader or replacement path remains.
- CONSISTENCY [High] - Consistency vs improvement. Little: reuse write-once JSON,
  explicit adapters, `.mjs` re-exports and thin commands. Much: the required
  separate main/corrective bases and implementation/native counts are stated
  departures from the older one-base flow config.
- EXPERIENCE [Low] - Design-system fidelity vs local override. No UI surface is
  changed; closed CLI result states cover blocked, observing and ready outcomes.
- LANGUAGE [High] - Ubiquitous language vs convenience. Public names retain the
  published quality/review terms and existing flow terms; no synonym is coined
  for authority, attempt, terminal, finding, repair or delta review.

This packet is source planning evidence only. Hosted Node 24 on Windows, macOS
and Linux and an independent complete implementation review remain required.

## Non-goals

No production promotion, credential work, environment or provider probes, raw
trace/prose ingestion, general queue framework, native sandbox change, arbitrary
workspace adoption/removal, assertion weakening, invented verdict, automatic
delivery, or mutation authority from a worker/candidate/failed report.

## Acceptance evidence

1. Consume only a completed exact-head failed source review whose terminal,
   recomputed config/prompt fingerprint, source context, candidate and distinct
   participants match external authority.
2. Bind main and repair bases, stable executor, workspaces, model/effort,
   prompt paths, adapter executable, acceptance, source footprint, prior sweep
   and remaining admission externally.
3. Prepare and dispatch one corrective author and one fresh delta reviewer by
   calling the reviewed flow/dispatch adapters.
4. Retain every prior participant, verdict, slot and known/unavailable usage;
   repairs/reviews do not consume the four-attempt implementation ceiling.
5. Persist intent before effects and reconcile known attempts on restart without
   duplicate launch, commit or review dispatch; unknown outcomes refuse.
6. Emit delivery eligibility only after structured independent exact-head delta
   acceptance; retain notes while leaving four gates and hosted proof external.
7. Retain actual useful successor repair/restart evidence after external
   acceptance; do not substitute synthetic fixtures or manufactured failure.

## Review attack surface

Attack forged report/context joins, source-location injection, missing quality
dimensions, stale/wrong head, candidate-supplied admission, conflated bases,
scope/acceptance narrowing, history or usage reset, exhausted ceilings, reused
participants, incomplete predecessor sweep, duplicate effects after timeout,
unbounded output, loaded-root or prompt-path substitution, prefix footprint
escape and premature delivery authority. Verify the concrete adapter and direct
command in addition to the transition model.
