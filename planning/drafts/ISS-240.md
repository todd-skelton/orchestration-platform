## Decision

Only an explicit operator deferral may park committed work.
Retrying every failure would be smaller but would replay uncertain effects and hide real blockers.
Choose bounded classified retry of the existing step, then native blocker waiting, with one existing notification route for product questions.
Accept that unknown or unsafe executor state still halts its affected execution path instead of guessing progress.
Revisit if a second restart supervisor, notification service or generic dependency registry is needed.

## Done when

1. **AC1: retire automatic parking.** Newly produced attempt/replan/retry/wait
   failures never park. Remove every `legacyParking` policy entry and the
   new-outcome `parksItem` interpretation once its replacement route is covered.
   Parked means an explicit operator deferral with the authority reference,
   scope and nonempty un-park condition. Do not infer deferral from old labels,
   a count, reviewer exhaustion, environment failure or a missing credential.
   Existing posted stop bodies stay unchanged; status distinguishes historic
   parking from current active recovery/waiting. Unsafe `halt` still protects
   the affected host/executor mutation path without parking an issue.
2. **AC2: bounded retry of a step, not new attempts.** For ISS-225 `retry`
   outcomes, first reconcile pending native worker/publication/comment/merge
   effects. Permit at most one outer retry of that same failed step, persisted
   across restart, after its existing internal read retries finish. No nested
   retry allowance per reason or reset on main movement. Unknown mutation
   response is observation-only until reconciled, never blind replay. At
   exhaustion retain diagnostics and the pending operation and enter WAIT on
   one linked native tooling blocker; no count-only park or fresh run.
   A changed-head candidate failure is not a transport retry. No process
   restart/kill is added; involuntary WSL loss remains ISS-226/227's domain.
3. **AC3: native blocker wakeup.** Environment-tooling and external-dependency
   outcomes name an existing owner/blocker, or the loop files one bounded
   blocker through the adapter when the recorded failure has none. Reuse
   existing native issues and dependency edges, not per-poll duplicates.
   Secrets/credentials are requested only as a packaged operator action;
   workers gain no provider authority. While open, skip only blocked work and
   continue the ordinary frontier. At fresh observed closure, recheck current
   authority, readiness and the blocked operation, then automatically resume
   its saved step or judged replan as appropriate. Closure alone is not proof
   that an executor repair is installed or a provider assertion holds; require
   the existing capability/evidence check at use. If still unresolved, retain
   the named blocker relationship and report the remaining condition without
   a busy retry loop or duplicate issue.
4. **AC4: one product question, not a process ceiling question.** A product-
   scope conflict records one question with options, evidence, recommendation
   and affected issues in the configured operator tracking destination. Reuse
   ISS-138's marker observation/pending-comment pattern and attention surface;
   loop application owns the question, watcher reports its link without posting
   another question. Only an operator answer changes accepted scope/priority.
   Process remedies, attempts and step-back verdicts remain agent-owned.
   RECOMMEND_NOT_COMPLETING retains the open issue and all dependent obligations
   until explicit operator disposition. No global delivery pause while waiting.
5. **AC5: real failure controls.** Replay the ISS-219 r6 network failure,
   receipt timeout, launcher failure, malformed reviewer, executed missing
   hosted logs and deploy-not-verified shapes. Separately retain ISS-230's
   never-executed cancellation distinction. Prove one bounded retry, wait,
   unrelated selection, blocker-close re-observation and same-step wakeup;
   do not call them candidate PASS. Test lost dependency/question responses,
   watcher restart, partial/unknown closure reads, stale repair installation,
   explicit deferral/condition not met and answered scope question. One-variable
   bypasses of pending-effect reconciliation, retry accounting and operator
   authority must each fail a named test. Provider fixtures are synthetic and
   use absolute test transports, never inherited provider credentials.
