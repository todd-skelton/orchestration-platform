## Decision

Same-run recovery must reconcile interrupted work without creating new effect
or attempt authority. The simplest alternative is to keep manual restart and
the current supervisor-absence check. Select shared native recovery admission
followed by an opt-in attached-parent loop in ISS-227. Accept that unknown
ownership or external outcomes require attention and that parent death remains
outside the guarantee. If the admission duplicates native lifecycle decisions
instead of reusing their readers, the chosen split is too large.

### Reconciliation contract

Reconciliation means observing durable phase, identity, ownership and uncertain
effects before allowing the existing phase to continue. It is not replaying
all steps, writing substitute receipts, completing a worker on its behalf,
or declaring a historic PASS current. The admission observation is read-only;
normal resume subsequently writes only its ordinary reconciled records.

| Interrupted phase | Required observation and permitted continuation | Never replay while uncertain |
| --- | --- | --- |
| Selection/setup/launch intent | Read saved cycle selection, pinned config/source, attempt and launch intents and participant history. An unresolved launch intent without an attributable outcome refuses. A proven completed setup is reused. | Another workspace reset, author launch or selected-issue change to escape unknown launch ownership. |
| Author running | Complete invocation census must prove no live/uncertain worker. Read attempt, trace, exit receipt, terminal and candidate together. Native ISS-222 grace starts at first observed death and survives another restart. Complete output is consumed normally; proven death can use only the remaining native retry, preserving tracked partial patch/discard evidence and untracked files under the existing host-preservation contract. Unpreserved untracked work requires attention before any clean-base retry. | A second author beside a survivor, a synthesized verdict, or a clean reset before preservation. |
| Review, repair or refresh review | Follow the saved accepted-stage/continuation directory, exact candidate head, reviewer attempt/terminal and full participants. Reuse completed exact-head verdicts only where native rules allow; otherwise the existing reviewer lifecycle and remaining allowance apply. Grace or missing terminal output is not a PASS. | A parallel reviewer, self-review, author-history cleansing or a new allowance for an exhausted continuation. |
| Local gates/native-db/provider or production boundary | Observe saved gate intent/result, correction/continuation grants and executing head. Existing native checks own any gate rerun. Unknown host verifier ownership, pending operator evidence, provider refusal/window, or production authority returns attention, not recovery admission. | A heavy/native-db request with unknown prior owner, a provider/production mutation, or automatic use of an operator-only grant. |
| Publication/hosted observation | Read publication intent/target/receipt and exact current remote PR/head. Observe authoritative hosted workflow/run/attempt/jobs using the existing adapter. Pending observations may continue; unavailable identity returns attention. Confirmed effects are reconciled without repeating them. | Push, PR creation/update, draft/body/label/comment mutation, CI rerun or worker repair based on an uncertain response. A fresh authoritative `needs-mutation` observation under existing rules is distinct from uncertainty. |
| Merge queue | Read merge intent, queue admission and exact PR/head through `observeMerge` before OPEN-only check reads. Confirmed pending stays observing; confirmed merged proceeds to retained cleanup/deploy observation. Missing previously admitted entry keeps `merge-queue-removed`. | Re-enqueue, merge, close or publish when queue outcome is unknown, or treating removal as permission to enqueue again. |
| Post-merge/closed item | Retained native merge/cleanup/deploy obligations precede external closure and new selection. Reuse ISS-144/ISS-184; a closed issue alone proves neither native delivery nor deployment. | Re-merge, redeploy, duplicate cleanup or erase consumed history to select fresh work. |

## Done when

1. **One native read-only admission.** Extend `control.mjs` with a
   `recovery` action callable as `node scripts/dogfood/control.mjs <config>
   recovery`. It reports one structured result: `eligible`, `hold` or
   `attention`, with run, observation time, retained cycle/attempt/phase,
   evidence paths and bounded reason. It launches nothing, clears nothing,
   and reserves no attempt. Reuse native config, phase and intent readers;
   do not use status prose or file mtime as authority. The ordinary `start`
   path applies the same vacancy and uncertain-effect predicates when resuming
   saved interrupted work, so this slice is useful without ISS-227. Explicit
   manual continuation keeps its existing authority rules; the stronger
   no-terminal-restart policy belongs to the `recovery` action, not a ban on
   authorized manual recovery. Fresh runs keep their existing start behavior.
   Tests exercise the real control entrypoint and
   assert zero runtime/GitHub writes and zero launches on every refusal.
2. **Prove vacancy, including changed boot.** Extend ISS-219's ownership
   reader, not a second process inventory. Same-boot invocations require its
   complete stable cgroup-v2 census; live/suspended survivors, unreadable or
   unresolved bindings, namespace/cgroup drift and injected-directory
   evidence never mean vacancy. For a prior boot, retain the historical
   binding, report `ended-prior-boot` separately from an empty current
   membership, and accept it only when the current observation is in the
   configured Ubuntu host namespace on the same armed executor/state root,
   with positive kernel boot identity different from that binding. Prove no
   current-boot supervisor or member is competing, across every retained
   invocation, using the existing outside-boundary supervisor refusal.
   All declared ownership must remain cgroup-v2, including old bindings;
   changed boot never upgrades injected or unresolved evidence.
   PID reuse cannot identify a prior-boot worker as live or accepted. Missing
   pre-ISS-219 evidence stays attention, with no backfill: the historical r6
   run is incident evidence, not automatically eligible. Test mixed prior
   and current boots and real reader wiring, not just a pure predicate.
3. **Phase and authority fences.** Implement every row of the reconciliation
   table through shared native observations. Preserve current selection,
   exact config, stable installed executor validation and continuation
   directory identities. Pending or acknowledged pause, intentional cancel,
   idle completion and terminal block cannot be admitted as loss recovery.
   Stops in `attempt`, `replan`, `wait`, `halt`, any `legacyParking` stop and
   unknown reasons refuse automatic recovery. Even `retry` is insufficient
   by itself: this intake admits involuntary loss only, not a normal
   terminal `blocked` exit. Existing one-off continuation instruments require
   their existing authority and are not widened. Table-driven controls keep
   every fence green at the real start boundary.
4. **Preserve accounting and effects.** Compare saved cycle/attempt,
   participants, failed-author/rung counts, worker retry, native launch count,
   accepted review/head, gate/refresh allowances and terminal history before
   and after repeated admission and ordinary same-run continuation. Admission
   changes none; actual native worker launches retain their normal charges.
   No stop body or saved config is rewritten. Drive each lifecycle row through
   disposable real supervisor/queue entry tests with synthetic adapter
   transports, interrupt at its retained boundary, then re-enter twice.
   Confirmed effects occur once, unknown effects cause zero new mutations,
   and consumed budgets never decrease. Do not introduce another accounting
   ledger or reinterpret the existing consumed-attempt rules.
5. **Discriminating red-before evidence.** Before production edits, capture
   the existing `control start` admitting a synthetic exited supervisor with
   a surviving owned child or unresolved publication intent. The same public
   path must refuse afterward. Use unmistakably synthetic run/PR/worker
   identities, disposable runtime roots and harmless fixture children;
   never kill WSL or a live run. Name one bypass mutant per governing fence:
   ignore survivor, conflate boot mismatch with vacancy, clear pause, ignore
   unknown publication/queue outcome, and reset a consumed retry. Freeze
   all other inputs; candidate green and mutant red must discriminate each.
   Keep idle, paused, blocked, cancellation, late receipt and ordinary fresh
   start controls green. Host-executed Windows/kernel proof is separate from
   author Linux evidence; a platform-gated skip is not Windows proof.
6. **One documented entry and no activation.** Update the Executor/resume
   sections of `docs/loop.md` with the admission command, phase matrix,
   prior-boot evidence limits and refusal actions. Old readers/records remain
   valid; any additive ownership rendering must not relax existing signal
   consumers. Tests retain the old ISS-219 fail-closed signal contract.
   This slice installs no recovery parent, watcher or trigger, starts no
   preserved run and grants no automatic action until ISS-227 is separately
   reviewed and explicitly activated.
