## Context and evidence

Runtime slices require real macOS, Windows, and Linux evidence before their
implementation choices can be trusted. The repository bootstrap supplies the
runner skeleton; contract decisions define canonical receipts.

Evidence: `docs/architecture/contract-decisions.md`,
`docs/architecture/state-machines.md`, and `ISS-000`.

## Scope fence

In: stable harness bundle, exact environment inventory, job/receipt contract,
canonical aggregation, artifact retention, local harness entrypoint, and
negative workflow fixtures.

Out: certifying a complete release candidate, implementing runtime primitives,
or allowing candidate code to select required tests. Final release certification
belongs to `ISS-019`.

## Decisions already made

Harness definition and aggregation execute from trusted default-branch bytes.
Receipts bind exact test-bundle digest, source subject, OS image, architecture,
Node version, contract versions, and capability result. A missing required job
is not success.
The harness preserves exact raw-byte framing and closed-array reflective
semantics; JSON semantic equality is insufficient for authority.
It also preserves canonical safe-integer decimal ordinals, linear
`authority-history/v1` chain framing, destination identity/observation
separation, and selected run-current crash evidence identically on every OS.
The 1,000-record chain golden verifies within five seconds per walk on hosted
runners; ISS-002 and ISS-004 reference this published golden and budget.

## Acceptance criteria and evidence

1. A clean fixture executes the same harness contract on current macOS,
   Windows, and Ubuntu hosted runners. Evidence: three receipts and aggregate.
2. Receipts use canonical bytes and normalize semantic results without hiding
   platform-specific diagnostics. Evidence: cross-OS fixture hashes.
3. Missing OS, skipped job, altered harness, mixed-run receipt, unsupported
   capability, or candidate-authored aggregate fails. Evidence: one executed
   mutation per case.
4. A package can register a future conformance suite without editing shared
   workflow logic. Evidence: fixture package registration and census test.
5. Cross-OS goldens cover every ISS-002 pointer digest domain, raw 32-byte
   framing, NUL/tag/count/type/length boundaries, auth core, reservation,
   attempt-log, archives, tombstones, FULL_REQUIRED loss refusal, and authority
   rotation.
6. The record/array corpus accepts exact mutable, sealed, and frozen arrays and
   rejects proxy, cross-realm, subclass, hole, symbol, extra, accessor,
   custom-iterator, and malformed descriptor inputs identically on all OSes.
7. Epoch-lock receipts bind exact OS image, filesystem, helper/profile/ABI, and
   custody inputs so ISS-022 cannot combine unlike environments.
8. Cross-OS vectors cover stable `Dphys` with multiple admitted helper/profile/
   custody observations, destination-owner two-process races, E0 core/post
   framing, every literal external-ledger schema/member/nullability/lifecycle
   branch, canonical physical-leaf/profile rule, same-lock absence receipt,
   acyclic use-intent/genesis order, exact review candidate, and one-way
   retirement archive, exact
   `Dop`/`Dsc`/`Dgb`/`Dgse`/`Drot`/branch-`Dh` formulas,
   downstream GENESIS selection evidence, and chain appends,
   safe-integer ordinal boundaries including `2^53 - 1` with refusal above,
   the ordinary nine-stage versus rotation checkpoint-5-only commit union,
   all single-epoch commit-run crash prefixes, and packet-purpose/handle
   separation.
9. Goldens cover full-chain walks from genesis against the selected head,
   fork/gap/reorder/truncation and crash-prefix refusal, the eleven-kind
   registry census, the rotation run's CAS-armed rest state and derived
   resumable/selected/UNKNOWN terminal truth, refusal of rotation stage6–8/
   resolution/later-selector/new-epoch artifacts, and a 1,000-record chain
   verifying identically within the published budget on macOS, Windows, and
   Linux.

## Independent review packet seed

mixed run artifacts, candidate-controlled selection, and unsupported capability
normalized to pass. Also attack domain-crossing digests, decimal truncation,
chain-record order and head substitution, physical aliases, two-owner races,
