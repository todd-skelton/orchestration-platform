## Context and evidence

Runtime slices require real macOS, Windows, and Linux evidence before their
implementation choices can be trusted. The repository bootstrap supplies the
runner skeleton. Round 165 found that the former packet named receipts and a
trusted default-branch harness without fixing their bytes, provenance join,
writer topology, registry ownership, diagnostics, retention, or timing rules.
The approved repair uses a protected `repository_dispatch` provider record as
bounded pre-ISS-029 evidence; status-check names are presentation, not
authority.

Evidence: `docs/architecture/contract-decisions.md`,
`docs/architecture/state-machines.md`, `ISS-000`, and
`planning/pressure-tests/2026-08-24-round-165.md`.

## Scope fence

In: stable harness/test manifests, exact vector and required-job registries,

## Decisions already made

The literal ISS-006 ledger in `contract-decisions.md` is sole authority. It
defines nine portable closed records, the adapter-only protection/provider
records, their exact members/enums/domains/bounds, and the derived aggregate
reducer. `Dsubject` is the complete canonical regular-file candidate tree with
the sole Git projection `100644 -> executable:false` and
`100755 -> executable:true`; every other mode/type or truncated tree refuses.
`Dcontracts` is the stable ISS-002 schema-version census; fixture bytes and
stable generator source/parameters have separate exact domains. The core sees
only opaque SHA-256 identities; GitHub/repository/workflow/run/job/artifact
terms remain in the GitHub Actions adapter.

The sole hosted entry is `repository_dispatch` type
`conformance_candidate`. GitHub supplies default-branch `GITHUB_REF` and
`GITHUB_SHA`; the plan job additionally requires protected `main`, exact
workflow ref/path, and `GITHUB_WORKFLOW_SHA = GITHUB_SHA`. The closed payload
has the sole member `candidateRevision`, naming one lowercase 40-hex commit in
this repository. Stable and candidate
bytes use separate credential-free roots. The stable registry alone derives
the matrix. Candidate child processes receive no secrets, provider metadata,
write token, OIDC, cache, environment, or aggregate authority.
Every remote workflow action is pinned to a reviewed full commit SHA; mutable
tags/branches/short hashes and installs outside the frozen integrity graph
refuse.

Candidate jobs upload only attempt-qualified untrusted observation artifacts.
A fresh stable-only job recomputes manifests and provider metadata, creates
portable receipts, and derives at most one aggregate. A later stable-only job
queries the exact run-attempt jobs/artifacts and writes the provider record.
The provider record binds `Daggregate`; the aggregate does not bind its
downstream provider record, so there is no digest cycle. Aggregate bytes alone
are never hosted authority and never grant a capability or promotion verdict.
After the run is terminal, the independent verifier requires the exact
successful record job and attempt-qualified provider-record artifact through
live API digest/length/time/expiry checks. Observation and aggregate provider
identities are their explicit ZIP archive bytes plus exact extracted layouts;
the single provider record uses pinned `archive:false`, so its API digest/length
bind canonical JSON directly. `recordedAt` is the provider `Date` header of the
last pre-upload jobs query, and the inclusive provider-time order is exact.
That post-job observation terminates the chain without asking the record to
attest itself.

The stable registry contains one `iss002-contracts` suite and exactly Linux,
macOS, and Windows required jobs. Future suites land through reviewed stable
registry/handler/vector/requirement rows without changing workflow logic. Each
receipt matches its own suite's `Dvector`; `Dregistry` commits the mapping and
the aggregate does not repeat one false global vector digest. Suite rows also
close helper/custody `REQUIRED|UNUSED` and `NONE|WALK_1000` arms, including
nullable timing. Candidate package discovery never changes the required
census. The stable 22-row vector census covers the exact ISS-002 domains,
ledgers, reflection cases, crash prefixes, and 1,000-record walk named by the
authority ledger.

The raw manifest has exact environment/report JSON and stderr/stdout text rows;
the environment row digest must equal the portable environment's
`osImageDigest`. Bytes are hashed without newline, encoding, locale, path, or
diagnostic normalization. Normalized result is only
`PASS|FAIL|UNSUPPORTED`; missing, duplicate, skipped, cancelled, timed-out,
unreadable, expired, mixed-run, or non-PASS evidence cannot produce an
aggregate. Local mode creates no record: it starts diagnostics with exact
`ADVISORY CONFORMANCE RESULT`, returns 0 only for all-PASS and 1 otherwise, and
cannot invoke a hosted serializer.

The 1,000-record vector runs exactly once in each of three fresh Node processes
per OS. Each interval uses `process.hrtime.bigint()` around JSON parse, full
genesis-to-head validation, and selected-head equality. Every interval must be
at most 5,000,000,000 nanoseconds; there is no warmup, averaging, best-of, or
retry. Provider-verified artifacts and metadata retain at least 30 days.

GitHub check names do not establish provenance because required checks do not
bind one event or workflow. The independently reviewed provider record plus the
protected-main ruleset snapshot is the bounded pre-ISS-029 evidence. The
harness never promotes a candidate or routes the candidate's verdict into its
own authority. Actor identity is retained only in raw provider diagnostics; it
is not an authority member or part of `DproviderRun`.

## Acceptance criteria and evidence

1. Parsers and canonical serializers enforce every exact member, enum,
   nullability arm, order, bound, digest domain, raw byte, and hostile
   reflective rule for bundle/candidate/contract/vector/registry/environment/
   raw/job/aggregate records. The GitHub adapter separately enforces its exact
   protection/provider records and formulas; engine-facing exports contain no
   GitHub/Git/repository/workflow/run/job/artifact vocabulary. Evidence: fixed
   byte/digest goldens, type assertions, hostile inputs, cross-domain negatives,
   exact Git mode/tree projection, array ceilings, and member-level deletion
   mutants.
2. A clean protected-dispatch fixture uses exact stable workflow/harness bytes
   to execute the fixed registry on hosted Linux, macOS, and Windows; the
   stable-only reducer emits three PASS receipts, one PASS aggregate, and a
   provider record whose exact `aggregateDigest` equals recomputed
   `Daggregate`. Evidence: provider run/job/artifact API snapshots and retained
   artifacts from one exact run attempt. A post-terminal verifier additionally
   requires the successful record job and unique non-archive provider-record
   artifact by exact name, run/attempt, digest, length, inclusive provider-time
   order, and expiry.
3. Workflow-structure tests prove exact `repository_dispatch` type/payload,
   protected-main ref/workflow SHA, least permissions, credential-free separate
   checkouts, stable registry-derived matrix, allowlisted candidate environment,
   attempt-qualified immutable artifacts, stable-only aggregate/record jobs,
   no candidate execution after observation, and no status/promotion/capability
   writer. Every remote action is a full reviewed SHA. Mutable action refs,
   unpinned downloads, or dependencies outside the frozen lockfile/integrity
   graph refuse. Every deletion/substitution fails.
4. Missing/duplicate/extra OS or suite, skipped/cancelled/timed-out/unreadable
   job, altered stable bundle/test/vector/registry bytes, candidate registry or
   aggregate, `continue-on-error`, matrix exclusion, mixed candidate/run/
   attempt/workflow/repository/artifact/protection snapshot, prior-attempt replay,
   expired evidence, unsupported capability, and local-hosted substitution all
   refuse without a hosted PASS aggregate. Evidence: one executed mutation per
   relation.
5. A fixture package registers one future suite through stable package-local
   handler/vector/registry rows without editing shared workflow logic. The row
   declares its vector, helper/custody requirements, and optional walk arm, and
   becomes required only from the landed stable harness revision; a candidate-
   only registration changes no matrix. Two distinct suite vector censuses
   compose in one aggregate because each receipt matches its own registry row.
   Evidence: registry/census and workflow derivation mutations.
6. Canonical receipts normalize only the closed semantic result and portable
   identities while binding exact raw environment/stdout/stderr/report bytes.
   The exact four raw rows pin media types, and the environment row digest
   equals `osImageDigest`. Observation/aggregate ZIPs have exact safe extracted
   file censuses, while provider-record bytes are explicitly non-archive. Line
   ending, encoding, locale, file order, image inventory, archive mode/layout,
   and platform diagnostic substitutions change the bound identity and refuse
   reuse; diagnostics remain non-blocking except when their required bytes are
   missing or mismatched.
7. The exact 22-row stable vector census executes once per required OS. It
   covers every ISS-002 pointer digest domain, raw-32/NUL/tag/count/type/length
   framing boundary, safe-decimal boundary, auth core, reservation, descriptor,
   attempt log, archive/tombstone, FULL_REQUIRED loss, linear history,
   authority rotation, and run-current/commit crash prefix. Deleting, adding,
   renaming, duplicating, or not executing a row refuses the job.
8. The record/array corpus accepts exact same-realm mutable, sealed, and frozen
   arrays and rejects proxy, cross-realm, subclass, hole, symbol, extra,
   accessor, custom-iterator, malformed descriptor, and exotic prototype input
   identically on all OSes. Evidence: stable generator digests and per-case
   receipt/raw hashes.
9. Environment receipts bind exact OS family, architecture, raw image inventory,
   Node/pnpm, ABI, filesystem, and suite-required helper/profile/custody inputs.
   Null helper/custody is legal only for a registry row that declares it unused;
   ISS-022 cannot combine differing environment/profile identities.
10. Cross-OS vectors cover stable `Dphys` with multiple admitted helper/profile/
    custody observations, destination-owner two-process races, E0 core/post
    framing, every literal external-ledger schema/member/nullability/lifecycle
    branch, canonical physical-leaf/profile rule, same-lock absence receipt,
    acyclic use-intent/genesis order, exact review candidate, and one-way
    retirement archive, exact
    `Dop`/`Dsc`/`Dgb`/`Dgse`/`Drot`/branch-`Dh` formulas,
    downstream GENESIS selection evidence, and chain appends,
    safe-integer ordinal boundaries including `2^53 - 1` with refusal above,
    the ordinary nine-stage versus rotation checkpoint-5-only commit union,
    all single-epoch commit-run crash prefixes, and packet-purpose/handle
    separation.
11. Goldens cover full-chain walks from genesis against the selected head,
    fork/gap/reorder/truncation and crash-prefix refusal, the eleven-kind
    registry census, the rotation run's CAS-armed rest state and derived
    resumable/selected/UNKNOWN terminal truth, refusal of rotation stage6–8/
    resolution/later-selector/new-epoch artifacts, and a 1,000-record chain
    verifying identically within the published budget on macOS, Windows, and
    Linux. Each of three fresh-process intervals per OS is independently at most
    five seconds; warmup, averaging, best-of, retry, and excluded parse/validation
    work are executable mutants.
12. Local `harness:test` emits no record, starts with the exact advisory marker,
    exits 0 only for all-PASS and 1 otherwise, and is rejected by every hosted

## Producer and consumer ownership

ISS-006 owns conformance evidence schemas, stable suite/vector/job censuses,
portable harness/reducer code, and the GitHub Actions adapter record. ISS-002
owns the platform contracts and golden meanings tested by that census. ISS-022
owns the independently reviewed capability decision; ISS-004 owns the
production helper/lock; ISS-019 owns final certification; ISS-029 owns later
authenticated bootstrap provenance. The harness never promotes a candidate,
accepts aggregate bytes without their provider record, or weakens unsupported/
missing/expired evidence.

## Operator actions

After the workflow lands on `main`, an administrator must:

1. verify the active default-branch ruleset requires pull requests, blocks
   deletion and force-push, and has no bypass that would let candidate bytes
   replace the reviewed workflow revision;
2. configure Actions artifact retention to permit at least 30 days; and
3. dispatch the exact independently reviewed candidate revision, retain the
   run/provider record, then run the post-terminal verifier over the successful
   record job, unique provider-record artifact, all three required jobs, and
   aggregate.

Do not configure a status-check name as conformance authority. Check names may
be displayed for convenience, but the provider record and independent review
remain required.
