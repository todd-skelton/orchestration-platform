## Context and evidence

The reference controller has 112 tracked artifacts and more than one hundred
recent changes. File-by-file translation would preserve accidental boundaries
and miss implicit authority relationships.

Evidence: `docs/architecture/reference-inventory.md`,
`docs/architecture/vision.md`, `docs/planning/first-consumer.md`, and the
read-only container snapshot identified there at commit
`216887080f0570edbbac1c4e3a74a17add242ce3`.

## Scope fence

In: enumerate commands, state schemas, mutations, external authorities,
recovery transitions, tests, and project-specific assumptions; classify each as
platform mechanism, adapter policy, historical compatibility, or obsolete.

Out: port code, choose target module boundaries from filenames, or publish
consumer secrets and local paths.

## Decisions already made

The inventory describes behavior and authority, not source-file parity. Any
ambiguous mutation authority is recorded as unresolved evidence rather than
guessed.

## Acceptance criteria and evidence

1. Every tracked artifact maps to at least one behavior family or an explicit
   obsolete disposition. Evidence: a machine-readable manifest validated for
   complete source coverage.
2. Every mutation names its authorizing observation, failure mode, and recovery
   transition. Evidence: complete mutation-call and script-entrypoint census;
   untraced rows fail validation.
3. Consumer-specific terms and paths are replaced with neutral capability
   names without losing their owning policy. Evidence: a complete source-term
   to neutral-capability map generates the forbidden-vocabulary oracle used by
   package scans.
4. Unknowns become linked probes or decisions. Evidence: manifest validation
   rejects unclassified `unknown` entries.

## Verification plan

`pnpm run inventory:check`

`pnpm run inventory:redaction-check`

## Predicted footprint and dependencies

Create only `reference/manifest/`, `test/reference-inventory/`, and
`test/capability-slots/ISS-001/inventory%3Acheck.mjs` plus
`test/capability-slots/ISS-001/inventory%3Aredaction-check.mjs`. These are
test/reference inputs, not runtime contract exports, and package-inspection
tests prove they are absent from every publishable package and module bundle.
Generic inventory schema ownership remains in `ISS-002`. Blocked by `ISS-000`;
this slice does not edit root manifests or `docs/glossary.md`. The bootstrap
slot runner is a prerequisite; slot output must preserve neutral redaction and
must not expose consumer-specific data.

## Operator actions

Provide filesystem read access to the exact container snapshot named in
`docs/planning/first-consumer.md`. No credentials may be copied into fixtures.

## Glossary impact

None; the neutral inventory terms are registered in `docs/glossary.md`.

## Independent review packet seed

Attack missing artifacts, mutations mislabeled as observations, accidental
publication of local or consumer data, and compatibility behavior incorrectly
classified as obsolete. The omission-revealing artifact is the complete source
path-to-manifest coverage report.
