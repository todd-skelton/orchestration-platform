## Why

The M2 author on chase-sets#7821 stopped in run
`m2-payout-fees-supervised-20260913` with `author-failed`:
https://github.com/chase-sets/chase-sets/issues/7821#issuecomment-5653650642.
The author completed its source changes, typecheck and focused tests, but the
worker prompt requires `verify:static:scoped` before reporting while forbidding
staging or committing. The actual Chase Sets static guard requires a clean,
committed candidate (`scripts/check-structure/brand-foil-proof.mjs`). Those
instructions cannot both be satisfied. A host rerun confirmed this failure.
The executor already commits the candidate and runs the adapter's local gates
before publication; the pre-commit demand duplicates that authority at an
invalid lifecycle point.

The same worker's two compiler subprocess tests failed on sandbox `spawnSync`
EPERM; the host reran the full public-presence suite successfully. A sandbox
limitation must be reported honestly without changing product source merely
to work around the worker environment.

## Done when

- For a repository adapter that supplies `localGates`, the author prompt says
  the executor runs those required gates on its committed candidate. It does
  not require a commit-bound gate to pass before the author can report code
  readiness and leave HEAD unchanged.
- Authors still run applicable focused checks and describe limitations and
  failures honestly. A concrete source defect remains a failing author
  outcome; unavailable sandbox operations or checks requiring the executor's
  committed snapshot are reported for that executor gate, not claimed passed.
- Existing executor gate execution, failure handling and publication ordering
  remain mandatory. No failing or omitted gate can publish a candidate.
- Tests prove the custom-gate prompt respects the commit boundary, the default
  self-repository prompt keeps its local checks, and a candidate's configured
  local gate runs after the executor commit and prevents publication on failure.

## Out of scope

Weakening the Chase Sets static guard. Disabling the worker filesystem sandbox.
Changing source to evade environment failures. Rewriting failed worker reports
as successful. A new gate runner or approval protocol.
