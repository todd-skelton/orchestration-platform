## Context and evidence

Cutover cannot discard or duplicate the incumbent's active cursors, breaker
holds, ownership terminals, or recovery evidence. Sanitized source histories
come from `ISS-016`; generic adapter/import hooks come from `ISS-013`; atomic
mutation authority comes from `ISS-004`.

## Scope fence

In: authoritative source-state census, sanitized quiescent-export fixtures, provenance/schema and
digest binding, explicit source-to-target mapping, deterministic import plan,
create-once/CAS application, replay/equivalence verification, pre-mutation abort,
post-mutation forward recovery, and day-after behavior.

Out: live export/import or authority transfer itself, platform schemas that name the consumer,
discarding unknown source state, or post-mutation rollback.

## Decisions already made

The first-consumer adapter owns source vocabulary and mapping. The platform owns
generic import transaction mechanics. Import follows the `Consumer state import`
table and must commit before successor authority can activate.

## Acceptance criteria and evidence

1. The census classifies every incumbent state family and maps every required
   active cursor, breaker hold, worker terminal, discrepancy, and recovery event
   to a target record or explicit non-authoritative archival disposition.
   Evidence: source-path/state-family coverage report.
2. Repeated plan/apply/replay over the same export is byte-stable and creates no
   duplicate authority. Evidence: golden import digest and idempotency run.
3. Moved, partial, malformed, unknown, or provenance-mismatched export refuses
   before authority transfer. Evidence: one mutation fixture per field/family.
4. Fixture crash injection at every target write resumes only the same
   transaction and reaches `IMPORT_COMMITTED`; pre-write abort leaves the
   fixture incumbent cycle valid. Evidence: complete synthetic fault/recovery
   matrix and next-cycle receipts. No live export is retained for later cutover.
