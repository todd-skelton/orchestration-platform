## Context and evidence

Pressure Round 21 assigned `repository-protection-receipt/v1` and
`bootstrap-verifier-anchor/v1` schemas and parsers to ISS-002 so ISS-036 could
produce durable protection evidence for ISS-038. Live reconciliation after
ISS-002 closed found no schema, parser, registry entry, serializer, digest, or
executable contract vector for either family. The nearby implemented
`github-conformance-protection-snapshot/v1` is advisory conformance evidence and
cannot substitute for the pre-N0 authority boundary.

## Contract boundary

The literal `Pre-N0 repository-protection and verifier-anchor ledger` in
`docs/architecture/contract-decisions.md` is the sole implementation authority.
It closes every top-level and nested member, order, scalar grammar, enum,
array bound, uniqueness rule, nullability cell, time relation, digest domain,
semantic projection, exclusion, and pure binding relation for both families.

`repository-protection-receipt/v1` has exactly fourteen top-level members. It
binds 1-based safe-decimal repository/ruleset/producer/workflow identities; the
framed ruleset semantic digest; bounded protected path and workflow arrays;
complete seventeen-key versioned permission snapshots; closed REST/GraphQL
request identities, ordered page chains, and terminal pagination evidence; the
live REVIEW producer workflow/run/attempt/start and intended artifact name; its
distinct completed successful BUILD trigger-source run; the exact pre-run
protected-environment anchor binding; strict issued/expiry times no more than
seven days apart; and closed
`ACCEPTED|REJECTED|BLOCK_REPLAN` disposition. It excludes enclosing artifact
ID/archive identity because those exist only after upload.

`bootstrap-verifier-anchor/v1` has exactly ten top-level members. It binds
literal GitHub CLI `2.93.0`/release `v2.93.0`, exactly one official asset/
checksum/executable identity for each of Windows, macOS, and Linux, repository
numeric identity, literal OIDC issuer and default online Sigstore/TUF trust
mode, exact allowed signer workflow identity, creation time, and a closed
operator-confirmation claim. It accepts no custom trust root, candidate/kit
digest, local credential, mutable latest-version selector, or executable path.

The pure four-input binder compares parsed receipt/anchor values to one fresh
closed supplied observation, recomputes semantic/family/terminal identities,
requires `issuedAt <= evaluatedAt < expiresAt`, and binds `evaluatedAt` to a
fresh at-most-five-minute terminal read-back. It compares immutable request and
effective-semantics identities while independently validating fresh times,
ETags, Link/cursor chains, and terminal evidence; historical capture metadata
is never required to equal fresh metadata. Its return contains only detached
parsed values and digests.

The fresh anchor-variable source update must remain no earlier than anchor
creation, strictly before the historical REVIEW producer start, and no later
than fresh observation start. Historical and fresh ETags/update times need not
match, but a post-producer same-value rewrite or retarget-then-restore is stale
substitution and refuses by its moved source update time.

The binder also enforces
`confirmation <= anchor creation <= anchor-variable publication < REVIEW producer start <= receipt issue`.
The WORKFLOW_RUN historical observation binds the separate completed successful
BUILD run that triggered REVIEW. The producing REVIEW run has no conclusion or
completion member because it writes and uploads the receipt while still live;
its run ID must differ from the triggering BUILD run ID.

Parser success proves only structural and identity consistency over supplied
records. It never proves API freshness, protection existence, operator action,
artifact authenticity, public attestation verification, or effective authority.

Round 445 closes the remaining digest precision without changing either value
schema. Every derived identity now has an exact domain, ordered `FramePart`
recipe and closed canonical projection. Canonical record-key insertion order is
irrelevant; frame-part tag or order changes are protocol changes. GraphQL page
request identities recompute from request identity plus the nullable cursor.
The first REST page request identity recomputes from request identity plus null
position; later REST request identities are supplied leaves linked exactly from
the prior sole `NEXT` relation because the compact receipt carries no raw Link
target request bytes.

Request-material, response-body, raw-Link-header, and later REST-request hashes
are supplied opaque SHA-256 claims where their preimages are absent. Historical
PULL_REQUEST and PULL_REQUEST_REVIEWS reduced-value digests are also opaque
claims whose closed preimages remain in the ISS-036 authenticated archive.
Opacity does not prove provenance, completeness, or that a request was made or
followed. ISS-036/038 composition owns those checks. The pure parser checks
grammar and exact joins and recomputes request identity, the first/GraphQL page
identities, complete reduction, terminal pagination, WORKFLOW_RUN and all six
shared semantic reductions, ruleset semantics, family identities, and fresh
terminal evidence.

Independent review attempt 3 at
`b5f6f8d5112a30f8a4e58283e88d935938a01039` returned BLOCK: REST relation-row
tuple uniqueness still admitted duplicate relation labels and globally cyclic
request chains, and fresh variable update time was not bound before the
historical producer. Definition repair attempt 4 adds relation-name uniqueness,

NEXT, global page/NEXT uniqueness, and the fresh update chronology. It preserves

## Acceptance criteria and evidence

1. Both families have one literal closed field census, total parser, canonical
   serializer route, framed identity, schema registry entry, compatibility
   entry, and public export. Evidence: exact canonical goldens and registry/
   surface census.
2. Numeric IDs, hashes, versions, paths, refs, timestamps, pagination, ETags,
   permissions, triggers, workflow identity, asset identity, disposition, and
   seven-day expiry constraints refuse independently. Evidence: one-axis
   mutation matrix plus boundary-time vectors.
3. Protection receipt policy and observation arrays are dense, bounded,
   canonical, duplicate-free, and reflectively closed before semantic reads.
   Evidence: mutable/sealed/frozen positives and proxy, cross-realm/subclass,
   holes, symbols, extras, accessors, custom iterators, and descriptor traps.
4. The receipt cannot contain post-upload artifact identity or archive digest,
   and the anchor cannot contain candidate-controlled trust or executable
   fields. Evidence: extra/renamed/substitution refusal vectors and public type
   census.
5. Pure supplied-record relations bind the receipt to one parsed anchor and
   exact synthetic workflow/ruleset observations without performing lookup or
   granting authority. Evidence: digest, identity, time, path, permission, and
   producer substitution vectors.
6. The receipt vectors pin the exact fourteen-member top level, every nested
   census, 1/64 path/request/page bounds, exactly two BUILD/REVIEW workflows,
   complete seventeen-row effective permission snapshots, REST version/method/
   Link chains, GraphQL document/variables/cursor chains, terminal reduction,
   BUILD-to-REVIEW source identity, pre-producer chronology, expiry at 1 ms and
   seven days, and refusal at zero/reversed/seven-days-plus-1-ms. Evidence:
   canonical goldens, one-axis matrices, and deletion mutants for each equality
   and chronological edge.
7. The anchor vectors pin the exact ten-member top level, three-row
   `LINUX|MACOS|WINDOWS` census, asset/checksum/executable identities, fixed CLI
   release/OIDC/trust/confirmation literals, signer equality, and comparison
   time. Evidence: canonical goldens and absent/duplicate/substituted OS,
   mutable-selector, custom-root, executable-path, and combined-substitution
   negatives.

## Verification plan

### Definition precision and source follow-on — Round 445

Definition acceptance requires independently calculated canonical and digest
goldens for request identity, first REST page identity, null/non-null GraphQL
cursor identities, complete reduction, both terminal-pagination branches, the
seven recomputable purpose reductions, ruleset semantics, fresh terminal
evidence and the receipt family. Frame-type, frame-order and projection-member
deletion/substitution mutants must change or refuse the relevant digest, while
record-key insertion-order variants retain identical canonical bytes.

Pagination vectors cover 1, 2 and 64 pages; refuse 0/65, skipped, duplicated or
reordered ordinals, duplicate REST relation names, incorrect or
boundary-forbidden FIRST/PREV/NEXT/LAST targets, globally repeated request or
NEXT-target digests, `A -> B -> A`, REST NEXT/target/next-row disagreement,
early or missing terminal cells, GraphQL cursor mismatch/repetition, and
terminal digests formed from a count. Positives cover omitted optional
FIRST/PREV/LAST on eligible pages and no invented links on one-page, first-page,
or final-page boundaries. Opaque-leaf vectors prove only grammar and join
behavior: mutate each leaf independently and require all enclosing recomputable
digests to move; no pure positive may assert authenticated response, Link
origin, reducer preimage or completeness. The binder vectors pin its exact
six-member frozen return census and delete or mutate every chronology,
equality, freshness, semantic and terminal-evidence relation, including fresh
update before anchor, equal to/after producer start, after observation start,
same-value rewrite, and retarget-then-restore with a moved update time.

After this definition packet lands and receives independent review at its exact
head, the smallest source follow-on is the standalone protection-receipt parser
and digest surface; fresh observation and the four-input binder remain a later
slice. Its footprint is exactly seven files: new
`packages/contracts/src/repository-protection.ts`, new
`test/contracts/repository-protection.test.ts`, existing contract `index.ts`
and `registry.ts`, existing
`packages/conformance/src/iss002-bundle-paths.mts`, this draft, and one additive
source-attempt pressure record. The source packet adds no schema, runtime,
