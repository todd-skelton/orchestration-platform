## Decision

The constraint is the unchanged 30,000 ms per-test and per-hook limit on
hosted Windows. The old AC4 projection counted the same setup in every row and
the r4 seed/copy repair then introduced an impossible relocation boundary.
The corrected phase-hook census keeps each row independent and puts every
window below 24,000 ms at the retained lower-bound paces. For example, the
largest corrected history hook is 170 x 78.3 = 13,311 ms and the largest
row-local window is 118 x 64.9 = 7,658.2 ms; the reentry local phases are
smaller still.

The chosen shape is the existing generator-hook pattern used by
`queue.test.ts:4774-4791`: each logical row allocates a fresh fixture,
repository, runtime records, authority observations, process state, and
in-memory counters once, then its phase hooks pass only explicit row-local
lineage values. No state is shared across tests. The phase hooks are extended beyond Q/Q2 to R, history,
allowance, retry, reentry, and all named published-family rows. Every row
still runs its complete positive control, every negative assertion, every
fault, and every replay. There is no shared seed, byte copy, relocation, or
mutation-leak negative to make the unsafe r4 contract executable.

### Option analysis

1. **Per-row phase hooks with no cross-test state — chosen.** It removes the
   repeated whole-row setup from each bounded window without deleting a fault
   or control. The existing queue generator-hook precedent supplies the
   lifecycle boundary; each hook creates fresh state, so no copy or relocation
   contract is needed.
2. **Shared immutable seed or relocated copy — rejected.** The r4 review
   reproduced absolute remote/worktree/record paths and in-memory counters
   leaking from a byte copy into a new root. A relocation scheme would add a
   new path-rewrite mechanism and a mutation-leak negative, contrary to the
   host ruling's "No other lever" constraint.
3. **Cached/pre-built repository or runtime fixture — rejected.** The
   [#764 [ISS-235] Isolate native launch budgets between issues while preserving same-run recovery](https://github.com/todd-skelton/orchestration-platform/pull/764)
   precedent admits phase/row separation, not a shared mutable repository or
   cached authority facts. Earlier fixture plans explicitly reject shared
   repositories because they couple divergent histories. This option would
   either weaken real-Git coverage or cache facts across an external mutation.
4. **Measured wall time as the only AC4 basis — rejected.** Hosted wall time
   is required evidence, but a wall-time-only rule has no deterministic guard
   against a faster sample or load-sensitive pass. The repaired AC4 keeps the
   child-count projection with a stated 24,000 ms margin and also requires
   completed hosted evidence at the final head.
