## Decision

The constraint is the unchanged 30,000 ms per-test and per-hook limit on
hosted Windows. The old AC4 projection was a useful 20% headroom guard, but it
counted one deterministic setup once per row even though the rows are
independent observations of the same immutable seed. That made the admitted
shape unsatisfiable: for example, 347 x 72.0 = 24,984 ms for the R
missing-declaration row, and even the cheapest R row was 334 x 72.0 = 24,048.

The chosen shape is a finer split with one immutable setup seed per table or
family, itself divided into two bounded setup hooks: fixture-plus-queue
topology, then moved-main/publication/allowance setup. The seed contains only
deterministic fixture bytes and initial topology. Each row receives a fresh copy in a distinct temporary root,
worktree, state directory, and branch; no row shares a mutable repository,
runtime record, authority observation, process, or cached HEAD/status fact.
Every row still runs its complete positive control and every negative assertion.
The shared setup is counted at its own hook boundary, and the row-local
control/fault/replay phase is counted separately. Both boundaries retain the
same 24,000 ms projection margin and the final 30,000 ms Vitest limit.

### Option analysis

1. **Shared immutable seed and finer rows — chosen.** It removes the repeated
   294-child deterministic setup without deleting a fault or control. The
   required mutation-leak and fresh-root negatives make isolation observable.
2. **Cached/pre-built repository or runtime fixture — rejected.** The
   [#764 [ISS-235] Isolate native launch budgets between issues while preserving same-run recovery](https://github.com/todd-skelton/orchestration-platform/pull/764)
   precedent admits phase/row separation, not a shared mutable repository or
   cached authority facts. Earlier fixture plans explicitly reject shared
   repositories because they couple divergent histories. This option would
   either weaken real-Git coverage or cache facts across an external mutation.
3. **Measured wall time as the only AC4 basis — rejected.** Hosted wall time
   is required evidence, but a wall-time-only rule has no deterministic guard
   against a faster sample or load-sensitive pass. The repaired AC4 keeps the
   child-count projection with a stated 24,000 ms margin and also requires
   completed hosted evidence at the final head.

  not prove row-level timing or AC6.

  evidence.
