## Question

Can the exact GitHub/Actions contract and work-record representation in
`docs/architecture/self-host-github-contract.md` provide fresh, paginated,
correlated authority for the complete self-host lifecycle, and can the
repository enforce and publicly attest the exact independent-review controls
needed by the pre-N0 host-custody kit without a target-host project credential?

## Probe method and lifecycle timing

Using a synthetic `orchestration:self-host` issue and unmistakable fixture
branch/PR/workflow in the platform repository, execute every read/mutation at the
declared lifecycle moment. Capture raw REST/GraphQL requests/responses, page
boundaries, IDs, correlation, protection, checks, run/job/artifact attestations,
worker-result materialization, admitted merge result, final SHA/tree, and issue
completion. Remove/close only the synthetic resources after evidence capture.

In the same probe, configure the bounded repository ruleset for the exact
host-custody source/build/review paths: required non-author approval, dismissal
on source movement, self-review prevention, no admin bypass, immutable workflow
path/ref, least-privilege run-scoped `GITHUB_TOKEN` read and attestation
permissions, and build-success-only review trigger. Exercise synthetic accepted,
rejected, dismissed, self-authored, moved-tree, incomplete-pagination,
permission-expanded, and trigger-substitution cases. Emit and retain
`repository-protection-receipt/v1` only after live ruleset/API read-back. The
closed `ISS-002` schema binds repository/ruleset numeric IDs and semantic digest,
protected path-policy and reviewer/actor rules, the ISS-036 synthetic probe
workflow paths/refs/digests/triggers/permissions (not future ISS-038 production
workflow bytes), complete API routes/page counts/ETags, producer workflow/run/
attempt and intended artifact name, verifier-anchor digest, issued time,
maximum seven-day expiry, and disposition. The probe uploads it as the sole file
in that named artifact; the receipt never contains its enclosing artifact ID or
archive digest. Before the producer run, the operator sets and reads back
`VERIFIER_ANCHOR_SHA256` in protected environment
`host-custody-bootstrap-root`; the receipt binds that environment name, variable
value, API ETag/update time, and anchor digest. After GitHub finalizes upload,
the operator independently reads back the artifact and sets the four post-upload
values `PROTECTION_RUN_ID`, `PROTECTION_ARTIFACT_ID`,
`PROTECTION_RECEIPT_SHA256`, and `PROTECTION_ARTIFACT_ARCHIVE_SHA256` in the same
environment. Arbitrary workflow inputs and latest-artifact
lookup are forbidden. ISS-038 build/review workflows retrieve only that numeric
artifact, prove its producer run/attempt and intended name, sole-file shape,
archive and receipt hashes, parse the closed receipt, and require unexpired live
ruleset read-back to equal its semantic digest before use.

Before the synthetic run, the operator creates
`bootstrap-verifier-anchor/v1` at the target's canonical
`<state-root>/bootstrap/verifier-anchor.json`, independently of candidate/kit
bytes, after comparing GitHub CLI 2.93.0 official per-OS assets/checksums. The
anchor pins version, official asset/checksum identities, repository numeric ID,
expected OIDC issuer, allowed signer workflow identity, creation time, and
operator confirmation; it forbids custom roots and verifier substitution. Build a
synthetic public attestation bundle and verify it on clean Windows, macOS, and
Linux with pinned GitHub CLI 2.93.0 and exact per-OS executable hashes, no local
GitHub login/token, and no target API re-query. Use a downloaded bundle with the
CLI's default online Sigstore/TUF trust bootstrap and the full repository/
predicate/signer-workflow/signer-digest/source-digest/source-ref/hosted-runner
constraint set. Treat predicate
fields as workflow-controlled; prove they are admitted only when certificate
claims bind the exact protected, independently reviewed reducer workflow and
source digest. If public credential-free
verification cannot prove the bound workflow/source/predicate, block and replan
rather than granting a credential to the reduced broker.

## Required durable evidence

Exact API version/documents/routes, app/token permission census, repository/
actor/resource numeric IDs, full pagination, ETags/times/digests, work-record
schema/body/label receipt, plan/apply/read-back records, workflow correlation,
artifact attestations, merge protection/final tree proof, rate-limit/unavailable
results, exact ruleset/configuration before-and-after, review/API pagination and
actor IDs, workflow permission/trigger census, credential-free three-OS public-
bundle verification receipts, independently operator-retained verifier anchors,
numeric protection receipt artifact and environment-variable read-back, and scrubbed teardown
report bound to probe/test digests.

## Disposition rule

- PASS only the exact operations, merge method, permissions, and timing whose
  positive and negative paths are proven; `ISS-033` implements that matrix.
- If branch protection/merge queue, exact run correlation, pagination, artifact
  subject, or final tree cannot be proven, `BLOCK_REPLAN`; do not use names,
  latest-run polling, partial pages, or operator interpretation as authority.
- PASS the pre-N0 protection surface only when the configured ruleset and
  synthetic workflow yield `repository-protection-receipt/v1`, all negative
   controls refuse, and all three target OSes verify the downloaded public bundle
  with no project credential. The verifier anchor must predate and be independent
  of candidate bytes, and combined anchor/root/verifier/bundle substitution must
  refuse. That receipt and anchor are prerequisites for `ISS-038`.

## Negative controls

Duplicate/malformed work block, moved base/head, existing branch, wrong repo/
actor, pagination truncation, stale ETag, delayed/duplicate run, wrong workflow,
skipped/neutral/missing check, altered artifact, merge-method movement,
protection change, rate limit, close-before-promotion, and reused work ID.
For the pre-N0 lane also mutate reviewer/source/build actor identity, dismiss an
approval, add a commit after approval, truncate review pages, widen workflow
permissions, change trigger/workflow ref, enable admin bypass, inject a local
token, and substitute verifier or attestation bundle.
Also substitute anchor plus verifier plus bundle consistently, supply a custom
root, move/expire the protection receipt, change its numeric artifact variables,
change the live ruleset after receipt creation, or set/move the anchor variable
after the producer run.

All protection and verifier-anchor entry points also run the ISS-002 closed
snapshot corpus. Exact same-realm mutable, sealed, and frozen arrays pass;
proxies, cross-realm/subclass arrays, holes, symbols, extras, non-enumerables,
accessors, custom iterators, exotic records, and descriptor traps refuse before
provenance reads.

## Scope fence

In: live, read-only repository/workflow/protection/verifier probing, synthetic
negative controls, canonical receipts, and scrubbed evidence. Out: production
bootstrap mutation, state authority, candidate certification, provider policy,
secret capture, or weakening a protection result to advisory success.

## Predicted footprint and dependencies

Owns only `probes/self-host-github/`, the synthetic issue form/workflows/
fixtures, repository ruleset/environment configuration and verification runbook,
canonical verifier-anchor helper, exact protection-receipt producer/artifact,
and scrubbed evidence. Closed schemas/parsers belong to `ISS-002`. Blocks the
concrete self-host adapter and `ISS-038`; no production
adapter or generic engine behavior is implemented.

## Producer and consumer ownership

ISS-036 produces probe facts and the protection receipt through ISS-002
parsers. ISS-002 owns reflective closure; ISS-038 consumes the receipt; ISS-029
and ISS-020 consume only its selected outcome. The probe cannot certify its own
workflow or candidate.

## Operator actions

Authorize creation and teardown of the named synthetic issue/branch/PR/workflow
resources in the new repository. Supply the smallest probe-scoped GitHub app or
token permissions and revoke them after capture. Authorize the exact persistent
ruleset only after the synthetic matrix passes; record its numeric ID/digest and
do not weaken or bypass it for the pre-N0 paths. Independently compare and retain
the official verifier asset/checksum anchor before any kit candidate exists, then
set/read back the anchor variable before the producer run, then set/read back
the four artifact values only after upload finalization.

## Glossary impact

None; capture provenance, frontier, and authority terms are registered.

## Independent review packet seed

Attack latest-run confusion, partial pagination, moved refs, issue-body
ambiguity, broad token scope, merge protection races, artifact substitution,
candidate-controlled checks, and successful mutation without final read-back.
Also attack every envelope/nested array with proxy, descriptor, prototype,
symbol, hole, custom-iterator, sealed, and frozen variants.
