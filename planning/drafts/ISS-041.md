## Context and evidence

The proportionality review (pressure round 34) found that no issue produces an
observable end-to-end cycle before `ISS-026` and that
`@orchestration-platform/contracts` has no runtime consumer.
Every composition and protocol decision therefore defers its first integration
evidence to the most expensive slice. This slice buys that evidence early with
a deliberately disposable vertical fixture.

## Scope fence

In: one quarantined fixture composition that acquires a lease via create-once
file semantics, reads a stub adapter frontier from fixture JSON, invokes one
inline trivial plan function shaped as `orchestration-module/v1`, launches an
echo worker process, reduces a stub review acceptance, appends and replays a
journal through the published `ISS-002` parsers, and tears down a disposable
state root. Crash/resume at each step boundary against a published skeleton
step table.

Out: the production state service, pointer protocol, broker, credential
handling, real Codex dispatch, module registry admission, promotion,
supervision, and any authority claim. The skeleton produces evidence, never
authority, and no production slice may depend on its code.

## Decisions already made

The skeleton lives at `fixtures/walking-skeleton/` and declares
`@orchestration-platform/contracts` as a real workspace dependency, making it
the first runtime consumer of the published parsers. Its workspace membership
lands through the declared shared-scaffold amendment path in
`docs/planning/work-model.md`: one reviewed change adds a predeclared
`fixtures/*` workspace glob and updates every census table restating it in the
same change. Its step order follows `docs/architecture/routine-cycle.md`
ordinals with stub owners; a divergence between skeleton behavior and the
published cycle contract is replan evidence filed against the cycle document,
and the divergence ledger is a declared input of `ISS-026`'s independent
review packet. The skeleton is deleted or demoted to a conformance fixture
when `ISS-026` lands; it never ships in a release bundle.

## Acceptance criteria and evidence

1. A clean checkout runs one complete skeleton cycle on macOS, Windows, and
   Linux, producing a joined journal whose every record round-trips through the
   published contracts parsers. Evidence: three-OS transcripts plus a workspace
   dependency census showing contracts consumed by name, not relative path.
2. Killing and restarting the skeleton at every step boundary resumes exactly
   once or reaches a named refusal per the published skeleton step table; no
   step repeats an external side effect. Evidence: boundary fault matrix.
3. Malformed frontier records, a rejecting stub review, and a second concurrent
   lease each produce a typed refusal, never a partial cycle. Evidence:
   executed negative controls.
4. All skeleton writes stay inside one disposable state root; the run leaves no
   delta outside it. Evidence: before/after filesystem manifest comparison.
5. Every observed divergence between the skeleton and `routine-cycle.md` is
   filed as a replan record in the divergence ledger, a declared input of
   `ISS-026`'s independent review packet that `ISS-026` cites. Evidence:
   divergence ledger, empty or resolved.
