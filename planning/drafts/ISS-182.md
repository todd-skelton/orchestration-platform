## Decision

Quality profile: core-library (test infrastructure only). The original decision
stands unchanged and is restated with the measurement it invited:

- Constraint, unchanged: retain both closure variants, real private Git
  histories and worktrees, all current assertions and delivery/replay
  checkpoints under unchanged gates, including the 30000ms test/hook limits,
  `fileParallelism: false`, `sequence.concurrent: false` and the 17 existing
  platform skips. No configuration change is proposed, because none has been
  proven to be the only honest remedy.
- Simplest alternative, still rejected: split the case or move setup to a hook.
  Moving timed work is not reducing it and can hide this end-to-end cost.
- Chosen shape, unchanged: measure the owning fixture setup and complete cases,
  then remove demonstrably redundant fixture construction or make its completion
  deterministic without replacing native delivery.
- The named concrete candidate - prepare the final sibling candidate before the
  existing fixture's initial source commit and evidence pin, rather than build
  an intermediate candidate and then rewrite, recommit and repin it in
  `siblingRegression` - has now been implemented and measured at
  `465f1beb2f16c6d77a8b3e79bfac247884976f08`. Its measured effect is -7 of 670
  Git spawns per case, about 1%. It is spent as a remedy and must not be
  re-proposed as one.
- The pre-registered revisit clause is exercised here. The reported
  dominant-cost blocker is `verifyWorkspace` Git spawn volume in
  `scripts/dogfood/delivery-adapter.ts` at 86.7-87.2% of per-case spawns as
  measured pre-ISS-189, and about 85% (544 of about 638) on current main, which
  is outside this fixture-only fence. The residual fixture-only budget is about
  89 spawns, all of which AC1 requires the fixture to keep, so no remaining
  change inside this fence can clear the unchanged gate.
- Consequence: this issue is blocked, not moot and not completable as scoped. It
  stays parked without the `ready` label. Un-park condition, with a pass
  threshold: a registered issue owning the runtime `verifyWorkspace` per-call
  spawn volume lands, and at that owner's final head both closure variants are
  measured on a hosted Windows runner under the unchanged 30000ms test/hook
  limits, `fileParallelism: false` and the 17 platform skips, with worst-case
  headroom stated and normalised against a runner at least as adverse as #576's
  observed 10.8-11.9% slowdown. Arithmetic form: worst observed closure case
  duration x 1.12 must stay under 30000ms - i.e. the worst observed case must
  land at or below about 26785ms - and that margin must be named in the
  evidence. Landing alone is not the threshold: ISS-189 landed, reduced this
  very volume, was never measured against these two cases, and left them at
  2187ms of worst-case headroom. Once the threshold is met, ISS-182 is either
  completable inside its unchanged fence or closed as achieved by that owner.
  That owner does not exist yet, so no `blockedBy` entry can name it, and
  filing it is host-owned.
- Still excluded, as before: this is an implementation candidate record, not a
  measured speedup promise and not authority to change runtime Git behavior
  under this key.
