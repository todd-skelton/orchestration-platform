## Decision

Constraint: retain both closure variants, real private Git histories/worktrees,
all current assertions and delivery/replay checkpoints under unchanged gates.
Simplest alternative: split the case or move setup to a hook, rejected because
moving timed work is not reducing it and can hide this end-to-end cost.
Chosen: measure the owning fixture setup and complete cases, then remove
demonstrably redundant fixture construction or make its completion deterministic
without replacing native delivery. A concrete candidate is to prepare the final
sibling candidate before the existing fixture's initial source commit/evidence
pin, rather than build an intermediate candidate and then rewrite, recommit and
repin it in `siblingRegression`. Accepted downside: a small change to that shared
fixture helper needs the whole owning test file checked. Revisit if measurement
shows that this bounded fixture-only reduction cannot clear the unchanged gate;
report the actual dominant-cost/semantic blocker, not a timeout increase or a
diagnosis-only success. This is an implementation candidate, not a measured
speedup promise or authority to change runtime Git behavior.

   complete-case and setup timings for both variants, plus actual fixture Git

   timing and the existing `commands` capture where sufficient; label fixture-only
   counts rather than claiming they include all runtime Git calls. Account for

   introduce a fixture framework. Retain repeated bounded samples and identities

   sufficient, implement a smaller measured equivalent change within this fence

## Footprint and verification

construction and directly owning assertions. No production, frozen input,
workflow, timeout, worker, skip, package or `docs/loop.md` change is needed.

Use the supported native toolchain, one admitted full verifier at a time.
Preserve failed evidence and do not infer causation from runner speed alone.
No new product or architecture decision is required inside this fixture-only
fence. M2 registration, implementation through the M1 self loop; no dependencies.
Host publication, three-OS planning landing, issue/project registration and board
consistency precede readiness. This brief grants no rerun, #552 body sync,
executor install, unpark, restart or new native author by the planning worker.
