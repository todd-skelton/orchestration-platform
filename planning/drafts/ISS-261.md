## Why

At the observation stop, a repair author had already been launched, yet the
supervisor recorded `issue-observation-unavailable` while the worker's launch
identity and terminal state were not joined to the stop. On restart, the loop
could see a launch intent or trace without an explicit owner observation and
could dispatch a second worker beside a still-live first worker, or classify an
uncertain worker as dead. The retained records distinguish the launch and its
PID, but presence of a process file, trace, intent, or absent receipt is not a
verdict. The ordinary dead-worker retry is safe only after the exact PID is
observed absent and no terminal exists.

This slice makes the launch-to-stop-to-restart join durable and observable. It
does not create a generic retry policy, change the single retry allowance, or
make an observation stop an implementation PASS.

## Decision

Extend the existing launch intent, attempt, process identity, trace, terminal,
and stop/restart readers once. The `scripts/dogfood/observe-process.mjs`
producer writes one atomic, flushed identity snapshot before the adapter
returns a launched worker, and before an observation stop is durable. On the
supported Linux runtime, the process start-time field is `/proc/<pid>/stat`
`starttime` (decimal ticks since boot, not wall-clock time); a supported
non-Linux runtime uses its native process-creation-time field without changing
the owner-join meaning. The stop record carries a bounded pointer to the exact
launch identity, not a copied verdict. On restart, the same owner reader checks
the launch id, PID, platform start-time field, and trace path against the
retained record and current process evidence. A live or identity-uncertain owner remains
observing/attention and cannot launch another worker. A terminal is consumed by
the ordinary observer. Only an absent PID with no terminal, after the existing
receipt window and exact identity check, may enter the existing single
dead-worker retry. A retry keeps the same implementation attempt and all prior
launch charges; it never rewrites the original stop or invents a worker result.

Keep the existing process reader, no-global-inventory constraint, old-record
compatibility, and retry semantics unchanged. No new process inventory,
watcher, supervisor, retry class, attempt ceiling, charge ledger, verdict
schema, or external authority is admitted. Runtime state remains outside the
checkout and the one-host/one-writer design remains in force.

## Done when

1. **Durable launch identity before a stop.** For author, reviewer, and repair
   launches, persist and flush one exact identity containing launch id, PID,
   process start time, `launchedAt`, and absolute trace path before the
   supervisor can record `issue-observation-unavailable` (or any observation
   stop) for that in-flight worker. Bind the identity to run, issue, attempt,
   stage, role, head/config fingerprint, and the existing process/trace/exit
   artifacts. Old records remain readable without backfill; malformed or
   incomplete identity is unknown, never a permission to launch.
2. **Owner observation through stop and restart.** When a stop is recorded, and
   again before restart dispatch, observe every retained launched worker by the
   exact identity: PID existence and process start time, launch id/process
   artifact, trace path and terminal/exit receipt. Record bounded evidence paths
   and an observation timestamp in the existing stop/reconciliation evidence;
   do not copy raw process output into a verdict. A surviving worker is an
   owner and remains the only worker for that role. An identity mismatch,
   unreadable owner, partial trace, or uncertain terminal returns attention and
   launches nothing.
3. **No duplicate and narrow dead-worker retry.** A restart must refuse a
   second author, reviewer, or repair launch beside any surviving owner,
   including when the survivor is in a sibling retained stage. Only after the
   exact PID is absent, the existing receipt window has elapsed, and no
   terminal exists may the existing ordinary single dead-worker retry run. It
   preserves the existing attempt number, worker retry allowance, participant
   history, launch charges, candidate/head, partial-work preservation and stop
   ordinal. A live, unknown, terminal, or merely missing process file never
   enters that retry.
4. **No invented outcome or rewritten stop.** The fix must not synthesize a
   PASS/FAIL/dead verdict, close an absent terminal, reset attempts or charges,
   refund a launch, alter the selected issue, rewrite the original stop body,
   or create a second stop/terminal. Repeated reconciliation after a completed
   observation is inert. A later ordinary retry has its own launch identity and
   evidence while the prior launch and stop remain byte-stable history.
5. **Regression matrix at real entrypoints.** Add red-before/green-after
   regressions that exercise the production supervisor, launch adapter and
   retained runtime, not a helper-only predicate. Cover live, retained,
   resumed, and day-after entrypoints for each author, reviewer, and repair
   role: live owner through an observation stop; retained launch with no
   terminal; restart with a surviving owner; restart with an absent PID and no
   terminal; terminal present before restart; identity/PID/start-time/trace
   mismatch; duplicate-launch mutant; and repeated day-after reconciliation.
   Each positive control proves one owner and no second launch; each negative
   varies only its governing input and remains fail-closed. Assert exact
   attempt/charge/history/stop/terminal equality before and after every
   observation-only path.
6. **External authority timing and gates.** At the exact lifecycle moment a
   stop and restart consume issue/owner state, capture the issue observation,
   stop marker, launch identity, process census, terminal/exit state, and UTC
   bounds together. A later process census or a current GitHub read cannot stand
   in for the stop-time join. The implementation lane records baseline-red
   reproduction and changed-test evidence, runs the configured local gates, and
   obtains the required independent exact-head review and hosted bootstrap.
   Planning, review, and row-13 documentation lanes inspect evidence and run
   cheap focused checks only; heavy commands refuse with exit 73 before
   reservation. Exit 73 is non-execution, not PASS and not a consumed attempt.
   The host implementation/verifier lane owns heavy reproduction. Controller
   reviewers rerun changed tests directly, never through ControllerBattery or
   ControllerPrecursor.
