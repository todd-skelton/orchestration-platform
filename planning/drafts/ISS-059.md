## Context and evidence

Decision #302's readiness audit (§3, CF-4) identifies the offline assembly
path for `repository-protection-receipt/v1` and its artifact shape as a
credential-free prerequisite for `ISS-036`'s live producer window: everything
about assembling and canonicalizing the receipt that does not require a live
GitHub read.

## Scope fence

In: assemble the fourteen-member receipt
(`contract-decisions.md:6662-6681`) from `ISS-057`'s reduced observations plus
operator-supplied producer/environment facts; canonicalize; compute
`Dprotection`; define the artifact shape — exactly one file, and the receipt
never carries its enclosing artifact ID or archive digest
(`planning/drafts/ISS-036.md`; `contract-decisions.md:6774-6777`). Includes
the `disposition` selection logic for all three of
`ACCEPTED|REJECTED|BLOCK_REPLAN` (`:6685-6689`) and the at-most-604,800,000ms
expiry window.

Out: any upload, any live run, any environment read, any live ruleset read.

## Acceptance criteria and evidence

1. A byte golden for the assembled receipt from a fixed offline input set.
2. The producer refuses to emit `ACCEPTED` when any negative control in
   `ISS-058`'s matrix passed on the same input set.
3. A vector proves the producer cannot write an `artifactId`, `archiveDigest`,
   or any producer-conclusion member; the closed census refuses
   `unknown-member`.
4. A producer that back-dates `issuedAt`, reuses the BUILD run ID for
   `producer.runId` (the ledger requires them distinct,
   `contract-decisions.md:6770-6772`), or sets a producer conclusion is
   refused by a named negative vector.
