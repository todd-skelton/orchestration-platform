## Why

The loop currently publishes every pull request with only `Closes #<number>`.
The unattended-run gap was recorded on
[#363](https://github.com/todd-skelton/orchestration-platform/issues/363#issuecomment-5634427146),
and the shrink issues now require the pull-request body to state the actual
line reduction. Without automatic counts, those issues need per-item host
editing before their acceptance can be assessed.

## Done when

- The existing self-publication body includes added, deleted, and net line
  counts for the whole candidate, `scripts/`, and `test/`.
- The counts compare the candidate with its pull-request merge base. They are
  per pull request in later cycles and remain correct for a repaired candidate
  and a same-candidate gate correction; the stable executor revision is not
  used as the diff base.
- Publication uses the exact configured Git executable. A completed restart
  reuses the body already held by the existing delivery plan.
- Public body tests cover the counts and a later-cycle candidate whose stable
  executor predates its merge base.
- No record, schema, authority, preflight, or per-item file is added.

## Out of scope

Other delivery behavior. A pull-request body formatting framework. Generic
diff reporting outside self-publication.
