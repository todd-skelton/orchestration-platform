## Decision

Every Linux run descendant must retain kernel-backed membership when parents exit or children detach, without the loop acquiring stop authority.
A dedicated session plus root records is smaller but cannot retain worker descendants that create their own sessions, while an application spawn ledger cannot intercept arbitrary helper grandchildren.
Choose one cgroup-v2 leaf per canonical launcher invocation, entered before run subprocesses start, with one immutable run binding and read-only membership observations exposed by status.
Accept Linux-only ownership availability and a separately qualified host cgroup boundary rather than a portable process manager or claimed proof from sandbox fixtures.
The choice is wrong if the canonical launch cannot enter the leaf before spawning, an ordinary descendant escapes it, or the status census reports completeness without stable kernel identities.

### Options and WSL2 evidence

| Option | WSL2/Linux fit and limitation | Choice |
| --- | --- | --- |
| Dedicated session/group | No delegation required; SID/PGID survive reparenting, but `detached: true` observers and worker-created sessions escape a single group. Removing only observer detach does not constrain worker tools. | Reject: not complete ownership. |
| Append-only pid/starttime spawn ledger | Can wrap direct native spawns, but a PID exists only after fork; a pre-spawn intent is not a child identity. Arbitrary gh/git/worker grandchildren can fork and exit between observations. | Reject: either incomplete or requires a new process-interception framework. |
| Per-invocation cgroup-v2 leaf | Fork/exec, reparenting and setsid retain kernel membership without patching each spawn site. Requires writable cgroup delegation in the launch namespace and a complete same-namespace census. | Select; no resource controllers or systemd service. |
