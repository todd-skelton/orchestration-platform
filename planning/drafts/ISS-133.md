## Why

After ISS-132 landed, the host updated the stopped executor from 761f8eb to
67223b1 and resumed the same M2 run, publication, and product candidate.
The run stopped at `conflicting-delivery-config` before observing CI:
https://github.com/chase-sets/chase-sets/issues/7821#issuecomment-5654081294.

The saved delivery-config fingerprint is reproduced exactly using the original
controllerRevision. Changing only controllerRevision to the newly installed
main commit changes the fingerprint. The saved source evidence also binds
that old revision through an equality against the current executor config.
The product candidate, PR, gates, issue, paths, policy, and retry count did not
change. Rule 9 allows restart; this binding prevents adopting the host repair
needed to make that restart useful.

## Done when

- A delivery already published under the former executor can resume on an
  authorized updated stable main after the old supervisor has stopped.
- The existing source/review, successful gates, delivery plan, publication,
  and stop records remain intact. The fix works with the records already
  written by the prior executor; it requires no manual receipt rewrite,
  reauthoring, republishing, or new implementation attempt.
- The live executor is still checked as the configured stable main. Historical
  executor provenance is not confused with the version currently executing.
- Candidate, repository, issue, source review, publication, required-check,
  and merge bindings still prevent accepting different work as this delivery.
- A composed regression creates the real pre-upgrade saved delivery records,
  changes only the executor revision, and resumes through actual required-check
  observation and landing. Negative coverage retains material delivery drift
  and invalid-current-executor failures. The reproduction matches the saved
  M2 record shape, not a new-only format.

## Out of scope

Changing Chase Sets source or CI, weakening review/required checks/merge queue,
rewriting historical records, editing an active executor, a general migration
framework, or a second authority/approval protocol. Prefer removing the
unnecessary coupling over adding a guard for the loop disagreeing with itself.
