## Scope and observed failure

Correct the bounded queue-to-repair location contract after useful review
finding #348 named a test-file defect that the scripts-only `sourcePaths`
interpretation could not admit. The retained v1 key remains stable for restart
compatibility, but it now carries exact authorized review locations. The
repository queue adapter admits only explicit dogfood runtime, test,
documentation and planning files already present in the source allowed
footprint. Generic repair policy remains repository-neutral.

Pilot `iss085-review-location-20260909` starts source implementation 1/4 at
`5d25a402f0c76a86df1469c7ff5d4c7a6882ed2f` with fresh AUTHOR1 and an
independent REVIEWER2. Stable external controller authority, the independently
promoted b4 queue, all earlier source/review attempts, outcomes and spend
observations remain immutable. This source change neither accepts #348 nor
manufactures a replacement failed review.

## G0 and smallest complete shape

G0: PASS. Broaden one repository-neutral exact-path validator, add one closed
repository repair-template predicate at queue admission, append the existing
complete contract to the initial source reviewer, and retain the exact-head Git
line census in the repair adapter. This fixes the handoff without a second
repair engine, schema fork, receipt migration or assertion relocation.

Profile: `contract` under `quality-contract/v2`. High-weight boundaries are
location/footprint authority, exact reviewed-head Git existence, line bounds,
closed review shape, early template refusal, immutable lineage and distinct
external acceptance.

## Acceptance evidence

1. The authority-bound v1 `sourcePaths` list denotes unique exact review files,
   not directories. The repository queue admits dogfood runtime and test
   TypeScript, planning documentation, issue/pressure Markdown and
   `planning/roadmap.json` only when each exact path is also in the source
   allowed footprint and item authority digest.
2. Complete-review findings and notes are accepted only for a configured file
   changed by the candidate, present in Git at the exact reviewed head, and on
   a valid one-based line at that head. Missing, deleted, substituted,
   out-of-footprint and out-of-bounds locations fail closed.
3. An incompatible repair template is rejected during closed queue validation,
   before adapter authority entry, setup, source dispatch, durable cursor or
   participant reservation. The initial reviewer receives the exact authorized
   locations plus complete scope, contract profile, G0 and all twelve ordered
   quality pairs before launch.
4. Repair handoff and delta review preserve the original main/corrective heads,
   acceptance criteria, allowed footprint, complete predecessor sweep, every
   participant/outcome and known or unavailable usage. Repair/review slots stay
   separate from the four-attempt implementation ceiling; no original failure
   or attempt history is rewritten.
5. Only independent exact-head review, the controller's four static gates,
   hosted Node 24 Windows/macOS/Linux execution and external stable promotion
   can accept this implementation. A later genuinely needed accepted
   repair/DELTA/restart remains separate evidence; focused fixtures cannot close
   #348 or grant delivery, merge, promotion or execution authority.

promotion.

acceptance evidence.

## Review attack surface

Attack source/review-path semantic confusion; directories, duplicate paths,
prefix siblings, backslashes and traversal; unsupported roots/extensions;
allowed-footprint substitution after digest; findings in unchanged, deleted or
wrong-head files; zero/stale/out-of-range lines; missing G0/profile/pairs;
template validation after setup or dispatch; prompt omission; main/corrective
head conflation; predecessor, participant, usage, attempt or spend loss;
fixture proof presented as genuine repair acceptance; and any worker or
candidate self-certification.
