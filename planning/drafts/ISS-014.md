## Context and evidence

Stable N may stage reviewed N+1, but only the external review and stable
promotion path grant authority. Promotion must request shared state transitions
rather than writing release/gate/fence pointers directly.

## Scope fence

In: immutable release installation, active-release transition requests,
cleanup-gate and recovery-fence roots/history facts, exact twelve-edge cleanup
reducer, cleanup archive-head requests, successor handoff, forward recovery,
and reviewed state-authority rotation requests after promotion.

Out: pointer CAS/lock implementation, contracts, broker custody, attempt launch,
bootstrap genesis, policy adapters, candidate self-certification, and rollback
by restoring an old epoch.

## Decisions already made

`supervisor-contract.md`, `state-machines.md`, and `credential-broker.md` are
authoritative. The active release is a selected pointer. Cleanup has exactly ten
states/twelve write edges and no self-loop append. Removal selects tombstones.
Authority rotation is a reviewed forward transition performed under the old
capability only after the new active release is selected. Execution is solely
the canonical `Authority rotation` protocol in `supervisor-contract.md` and
`state-machines.md`; this issue emits only its reviewed request.
The rotation request supplies the exact reviewed-operation inputs for `Dop` and
shared successor core `Dsc`; ISS-004 derives `Drot` and owns every state write.
Candidate/helper bytes and serialized history never authorize themselves.
The request uses the literal `reviewed-authority-operation/v1` branch and
`state-mutation-successor-authority-core/v1` member names/types from the
supervisor ledger. It never supplies `Dop`, `Drot`, history-record bytes, or
successor selection/readbacks as caller-chosen authority.

## Acceptance criteria and evidence

1. Stable N stages and verifies immutable N+1 without granting it authority;
   candidate/self-review/moved bytes/manifests refuse.
2. Promotion requests exact active-release/gate/fence/cleanup transitions with
   installation/project/state, release/executable, split manifests, broker,
   transaction, source, root/head, and pointer `Dt/Dv/Dr` cross-bindings.
3. Exhaustive 100-cell cleanup pair matrix accepts ten states and exactly twelve
   mutation edges; crash resume reduces to `NO_APPEND`. Fence accepts only
   PREPARED→POST_ACTIVATION. Missing/reordered/partial histories refuse.
4. Active-release, gate, and fence cross-bind expected fence root, authorization
   core/CREATED triple, consumed identity, broker admission/generations,
   predecessor cleanup archive head, and selected release facts. Six
   single-pair coordinated recomputed mutants plus one all-six mutant (seven
   total) refuse.
5. Abort versus activation races one selected proposal. Abort is clientless,
   terminalizes the exact source, revokes authorization, archives, and selects
   tombstones; activation is forward-only once selected.
6. After selected N+1 and independent review, N requests state-authority
   rotation binding old authority/head, shared successor `Dsc` over reviewed
   release manifest/bytes/subject/review/`Dop` plus new helper/profile/ABI/
   custody, derived `Drot`, next safe-integer ordinal, and lifetime-stable `G`.
   Tests prove only the request bindings and that N+1 cannot self-rotate;
   execution conformance belongs to ISS-004 against the canonical rotation
   section.
   Field-census tests prove the release producer emits the exact STABLE_PROMOTION
   operation branch and successor core without conceptual aliases, missing
   members, nullable substitutions, or any selecting/downstream field.
7. Crash tests cover every proposal, head, fence publication, broker activation,
   archive/tombstone, rotation/run-current/context-revocation boundary without
   bare-absence or mixed-epoch recovery.
