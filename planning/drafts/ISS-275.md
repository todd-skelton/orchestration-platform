## Scope fence

In scope: a closed `gate-stop-successor/v1` packet in the self loop config, its
read-only pre-reservation evaluator, one exclusive reservation, composition of
one successor implementation attempt in the same run, retained stop/evidence
bindings, replay/refusal behavior, focused regression fixtures, and one
post-PASS sentence in `docs/loop.md` documenting the admission boundary.

The packet has an exact key set and binds: `repository`, `run`, `issueKey`,
`issueUrl`, `attemptDirectory`, `stopMarker`, `stopReason`, `gate`,
`candidateHead`, `priorAbsoluteAttempt`, `nextAbsoluteAttempt`,
`historyDigest`, `attemptCeiling`, `authorityUrl`, `authorityAuthor`,
`authorityBodySha256`, `briefRevision` (`sha256` and `updatedAt`),
`cause: "candidate-internal"`, and an evidence object containing the retained
gate terminal path, complete log path, their SHA-256 digests, and the changed
path digest. The packet is accepted only for the latest completed ordinary
delivery `gate-host-failed:<gate>` or `gate-attribution-unknown:<gate>` stop,
with a host-interpreted independent implementation/verifier attribution that
the stop cause is candidate-internal. The evaluator freshly reads the open
issue body/revision, stop, attempt, source config, terminal, complete gate
evidence, and authority comment immediately before the sole reservation.

The successor uses the same `run`, current selected issue and unchanged
`attemptCeiling` (the normal maximum of four), sets
`nextAbsoluteAttempt = priorAbsoluteAttempt + 1`, inherits the prior queue
history and spent allowances, and creates a distinct successor attempt
directory. The original stop, attempt bytes, gate terminal/log, source/review
records, and history remain byte-identical. A later failure is an ordinary new
stop and cannot renew this reservation or admit a second successor.

Non-goals: `gateStopAuthorization`, terminal-attempt or accepted-replan
semantics; source-stage, repair-stage, verification-only, base-failed,
workspace, hosted, malformed, or historical-stop admission; reset/transfer of
attempts, charges, native launches, reviewer ladders, ceilings, or evidence;
automatic retry, parking, readiness, publication, merge, deployment, provider
credentials, TCGplayer integration, or product behavior.

One closed packet validator plus one composition/reservation seam beside the
existing stopped-gate lookup. Reuse the existing saved-cycle and successor
history machinery; do not add a second gate-stop writer, a fresh-run bypass, or
a parallel grant family.

## Done when

1. `gate-stop-successor/v1` has the exact closed schema above. Immediately
   before reservation, the evaluator matches the current issue/body revision,
   run, issue, stop marker, latest stop ordinal, stopped attempt/head/base,
   gate reason, source directory, complete terminal/log bytes and digests,
   changed-path digest, history digest, and authority comment. Missing,
   malformed, stale, mismatched, later, or contradictory packet/evidence
   refuses with no reservation and leaves every retained byte unchanged. A
   positive fixture proves an ordinary candidate-internal gate stop admits;
   missing authority, wrong authority hash, changed stop, changed head,
   changed evidence, path escape and packet-field mutants are red.
2. Composition calculates the successor from the retained lineage rather than
   the new config alone: `nextAbsoluteAttempt` is exactly one greater than the
   stopped attempt, `nextAbsoluteAttempt <= attemptCeiling`, and the inherited
   history/charges/native launches/reviewer progress remain present. An
   exhausted 4-of-4 lineage, `nextAbsoluteAttempt` 5, a changed ceiling, a
   second reservation, a fresh run/worktree, or a packet that omits historical
   attempts refuses before reservation. No arithmetic path resets, transfers,
   exceeds, refunds, or silently spends the historical ceiling.
3. Route selection remains disjoint. A stopped gate with a landed main repair
   refuses this packet and routes to existing `gateStopAuthorization`; a
   `gate-base-failed:<gate>`, source/repair/verification-only stop,
   `verification-only-candidate-failed`, ordinary non-gate stop, prior stop
   that is not latest, or a non-candidate-internal cause refuses. No packet can
   retroactively admit the [#860 ISS-273 supervisor diagnostic repair](https://github.com/todd-skelton/orchestration-platform/issues/860)
   stop or any past stop, and no other stop class gains an admission.
4. A successful admission creates exactly one distinct successor attempt and
   retains the original stop, evidence, review, history, publication lease and
   accounting. Replaying the same run observes the existing reservation without
   another attempt, author, reviewer, launch, charge, reservation, or mutation;
   a changed packet or later failure cannot renew it. The successor still
   requires ordinary independent exact-head review, local gates, hosted checks,
   landing and deployment, and a new failure follows the ordinary stop path.
5. Heavy-command boundaries remain explicit: planning, review and row-13
   documentation lanes use evidence inspection and cheap focused checks only.
   A heavy verifier refusal exits 73 before reservation and is recorded as
   `NOT_EXECUTED`, never PASS, a gate result, a retry, a reservation, a charge,
   or a consumed attempt. Heavy reproduction returns to the host for an
   attributed implementation/verifier lane. Controller reviewers rerun changed
   tests directly and never through ControllerBattery or ControllerPrecursor.
6. After exact-head implementation PASS and independent review, `docs/loop.md`
   gains one concise section sentence naming the packet, latest-stop and
   candidate-internal restrictions, preserved history/ceiling/evidence, the
   `gateStopAuthorization` distinction, and exit-73 non-execution. The text is
   not added early and does not claim a future capability is shipped before
   landing.
7. The candidate runs only the focused changed tests and direct callers,
   `pnpm typecheck`, `pnpm format:check`, and `pnpm planning:check`; no local
   full `pnpm test`, ControllerBattery, ControllerPrecursor, or heavy
   reproduction. Baseline is red for the new positive admission at current
   `origin/main` and candidate is green; exhausted-lineage, mismatched-packet,
   landed-repair-route, replay, historical-stop and ceiling mutants are red.
   The exact-head reviewer reruns changed tests directly and checks the whole
   implementation diff and all retained-evidence bindings.

## External authority probe & evidence timing

Before implementation dispatch, the host captures bounded slices and hashes of
the retained latest stop, attempt, source config, gate terminal, complete gate
log, candidate head/base and history, plus the current issue body/revision. At
the exact pre-reservation lifecycle moment it freshly reads the authority
comment and compares every packet field and digest; a missing, stale,
contradictory, incomplete or heavy-refusal witness is an inert refusal, not
synthetic candidate attribution. The host's independent implementation/verifier
lane owns any heavy reproduction and records whether it executed; this issue
does not manufacture that result.

## Glossary impact

`gate-stop successor` means one same-run next implementation attempt admitted
from the latest candidate-internal ordinary delivery gate stop by a complete
authority packet. `Inert` means the ordinary queue refuses the retained stop
without that packet; it does not mean the stop is forgotten or non-evidence.
No existing public term changes.
