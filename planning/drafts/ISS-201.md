## Decision

The constraint is to retain the real-Git setup, resume and preservation proof
under unchanged 30000ms test and hook budgets without product changes.
The simplest alternative is reducing redundant fixture Git calls, but
`loopFixture` already uses ISS-171's memoized executable lookup and direct
local identity configuration, and ISS-196's different fixture is already repaired.
Choose one independently initialized setup/resume case per run name and one
composition-only case for cross-run branch uniqueness and Git ref validity.
Accept repeated fixture initialization and preserved-worktree checks across
the cases, not a claimed reduction in aggregate work or nine installs.
The choice is wrong if any original lifecycle assertion or install disappears,
the cases still exceed the unchanged budget, or required regression gates fail.
