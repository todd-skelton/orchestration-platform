## Context and evidence

The host-custody probe must become a released package before bootstrap,
supervisor, review, or production credential evidence may trust host identity.

## Scope fence

In: implement only the exact OS/backend/algorithm matrix passed by `ISS-035`;
canonical host/user/state identities, enrollment, native Ed25519 key custody,
challenge/sign/verify, reboot collector, local/upload receipt paths, revocation,
teardown, and receipts; independently reviewed pre-N0 host-custody client and
reduced broker-service compositions plus their exact private CLI/wrapper.

Out: project scheduler installation, project credentials, any service beyond the
exact reduced broker lifecycle, plaintext/exported private keys, remote host
management, or unsupported fallback.

## Decisions already made

The public contract is `docs/architecture/host-custody.md`. Native key access is
closed to `host.evidence-sign`; host enrollment cannot confer project mutation,
worker, install, or promotion authority. Host-custody observations may supply
ISS-022 physical/custody facts, but neither a receipt nor a serialized producer
epoch substitutes for the ISS-004 live state context.

## Acceptance criteria and evidence

1. Canonical algorithms produce byte-stable identities and refuse malformed,
   cloned/moved, symlink-aliased, wrong-user, or unsupported inputs on each OS.
2. Private Ed25519 bytes are generated/stored only through the broker's closed
   `host.evidence-admin`/`host.evidence-sign` APIs and never enter the host-
   custody package, process environment, argv, source, logs, artifacts,
   or receipts. Evidence: secret-canary and backend lifecycle scans.
3. Signed real-reboot receipts prove changed boot ID, scheduler invocation,
   exact installed collector, user/state/release/credential/tick identities, and
   lifecycle times; upload failure preserves locally verifiable evidence.
4. Teardown is disposition-specific. `retain-for-n0` removes and proves absence
   of only collector/challenge/uploader/test-scheduler resources while verifying
   the exact reduced service and host-key reference/public key/generation remain;
   `remove` cancels and proves service/key absence from `PLANNED`, removes the
   service with key-absence proof from `INSTALLED_REDUCED`, and from each key-
   bearing state revokes the exact key before proving signing denial plus
   complete key/process/service/scheduler absence. Evidence: one transition and
   interruption fixture per predecessor state. Copied/replayed/unsigned/manual-
   start or cross-disposition receipts refuse.
5. `@orchestration-platform/host-custody` fills only its predeclared package and
   passes exact exports, schema, CLI-independent API, and three-OS conformance.
6. The installed package reruns the ISS-031-owned shared native-store attack
   suite as extended by the passed `ISS-035` broker-endpoint, process-memory,
   copied-reference, and wrong-principal surfaces. No worker or unlisted
   process can recover private-key canary bytes or obtain an unauthorized
   signature. Evidence: exact helper/API/argv and unchanged secret/signature
   census on every OS.
7. The two pre-N0 build entries emit only the exact host-custody bootstrap and
   reduced broker-service bundles. An independent review bound to both bundle/
   source/lifecycle/Node/WinSW digests is required before any real enrollment.
   The client receives only host-evidence admin/sign clients; the reduced service
   contains only host-evidence core methods. Evidence: bundle/method/client/
   service/command census plus unreviewed, extra capability/operation/entry,
   runtime/deep import, alternate target, source-map, and tarball mutants. The
   reduced bundle is built only through
   `createHostCustodyBootstrapBrokerService({ hostMethodManifest })` with
   profile `host-custody-bootstrap/v1`; production factory/manifest arguments,
   cross-profile values, and all downstream operations refuse.
8. The exact seven-command private kit installs/verifies the reduced confined
   broker, enrolls/signs/verifies real reboot evidence, and tears down or leaves
   one upgradeable reviewed service. It runs before `ISS-029` with no dependency
   on `ISS-020`/`ISS-033`. Evidence: clean-host three-OS lifecycle/fault matrix
   and an upgrade fixture proving the later final service preserves only the
   public key/reference/generation while old bytes lose authority. The exact
   argv/schema/actor/state table and teardown `retain-for-n0`/`remove`
   dispositions in `docs/architecture/host-custody.md` are exhaustive; every
   missing/extra flag, invalid transition, stale prior record, incomplete
   teardown, and wrong disposition refuses.
9. The pinned build/review workflows produce and target-verify
   `host-custody-bootstrap-review-receipt/v1`. It binds the landed source/tree,
   both bundles, lifecycle definitions, host method manifest, Node/WinSW assets,
   actual ISS-038 production workflow path/ref/digests/run, PR/review, distinct
   numeric reviewer identity, and the passed `repository-protection-receipt/v1`
   whose workflow identities are explicitly synthetic and whose ruleset/path-
   policy semantics govern these production paths; target verification uses the pinned GitHub
   CLI against the downloaded public attestation bundle and requires no project
   credential or local API re-query. Evidence: valid attestation plus unsigned,
   stale, dismissed, self-review, incomplete-pagination, protection/tree/
   workflow/asset substitution, and rejected-review controls.
   Both workflows accept the receipt only by the protected environment's exact
   run/artifact/archive/receipt/anchor digest variables, retrieve that numeric
   artifact, prove its run/attempt/name and sole-file shape without expecting
   the receipt to self-contain enclosing artifact identity, and compare an
   unexpired receipt with fresh complete ruleset read-back.
   Arbitrary input, latest-artifact selection, expired/moved receipt, changed
   environment variable, or consistent candidate-supplied anchor/verifier/root/
   bundle substitution refuses.
10. Any state-authority join uses stable `Dphys` plus the current admitted
    versioned observation, exact selected destination owner where applicable,
    and a scoped ISS-004 producer projection. Helper/profile/custody rotation
    changes observation evidence without changing `Ddest`; copied/stale
    projections and receipts-as-authority refuse.

## Producer and consumer ownership

ISS-038 produces verifier-admission/custody evidence through ISS-002 contracts
and consumes ISS-036 protection facts. ISS-022 admits any physical locator
observation used by state authority; ISS-004 alone issues live projections.
ISS-029 and ISS-020 consume only selected outcomes. Candidate artifacts cannot
supply parser structure, trust roots, or verifier authority.
Host-custody facts may populate lock/custody fields in a reviewed successor
subject, but this package cannot append or supply `authority-history-record/v1`
records or chain state, or retain E(n) authority after the rotation CAS.

## Operator actions

Authorize installation of the exact reviewed reduced broker service, repeat
bounded enrollment/reboot/teardown on the designated hosts selected in
`ISS-035`, and compare exact fingerprints. Confirm the passed `ISS-036`
repository-protection receipt is current. Supply no GitHub/project credential to
the target verifier; a verification path that requests one is a blocking defect.
