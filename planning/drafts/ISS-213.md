## Decision

**Not ready: mechanism/evidence stop.** The retained results demonstrate
variable Windows verification outcomes, not a common timing/EPERM mechanism.
The failed unpark case wrote no observer JSON (`iss212-windows-phase1-run-r1.report.md:29-34`);
the ISS-212 observer measures a passing source4 case and its queue/Git phase,
not the failed refresh closure cases or the intent-file rename. Its ledger
(`docs/diagnostics/iss212-windows-timeouts.md:342-365`) does not isolate an
avoidable operation on a failing Windows path. No unchanged isolated timing
collapse together with a failing complete serial gate, holder/process identity
for the rename, or demonstrated safe rename-specific remedy was captured.
Thus neither host load, antivirus, sharding, redundant Git work nor a shared
root cause is established. Do not invent an optimization, retry policy or a
new campaign to make this draft runnable. Planning resumes only if already
retained or separately authorized evidence identifies **one** mechanism or
avoidable operation in a named manifestation and permits a bounded remedy
with before/after proof under unchanged limits.

## Done when

1. **Mechanism before readiness.** Independent planning review identifies a
   demonstrated avoidable operation or failure mechanism for at least one
   named Windows manifestation, with exact immutable evidence and a bounded
   remedy; otherwise the draft remains not-ready at the stop above. Timing
   and EPERM remain separate until evidence connects them. A passing rerun,
   narrower test, or same-base green control alone is not a mechanism.
2. **Preserved semantics and regression plan.** A subsequently reviewed
   fixed-scope implementation brief specifies before/after regression proof
   at unchanged 30,000 ms test/hook limits, one-worker/file-serial profile,
   assertions, default skips, lifecycle ordering, saved intents, authority
   observations, attempt accounting and mutation/reconciliation semantics.
   A real failure still fails closed. No timeout increase, test weakening,
   skip, retry policy, runner change or gate waiver is a remedy under this
   intake.
3. **Independent handoff.** The new scope and its actual proof receive
   ordinary independent planning and exact-head code review, local
   `pnpm typecheck`, `pnpm format:check`, `pnpm planning:check`, `pnpm test`
   and required final-head three-OS CI before any implementation claim.
   Historical or failed-only rerun results do not replace those gates.

## Defect constraints and review

`references/defect-classes.md` is absent from this checkout. The overlapping
constraints already recorded in ISS-212's draft apply: a Vitest wall-clock
timeout is not load attribution without an unchanged isolated timing collapse
and complete serial gate; heavy host work remains foreground under the exact
exclusive admission; aggregate failure is not dismissed as environmental by
presence of a later green result; artifact presence is not completeness;
focused/filtered profiles and default skips are not full-gate passes or failed
specs; external run/job facts require observation at the lifecycle moment;
negative controls and independent review bind exact immutable heads. No
future capability is described as shipped. The reviewer should challenge the
EPERM-versus-cleanup boundary, each provenance and censored duration, any
unproved mechanism, the no-new-campaign limit and ISS-211's priority.
