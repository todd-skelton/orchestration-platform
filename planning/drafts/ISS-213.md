## Decision

The constraint is that retained evidence shows real, variable Windows native
verification failures on unchanged runtime inputs (timeouts and one `EPERM`
rename) but no demonstrated mechanism or avoidable operation for any of them.
The simplest viable alternative is a speculative remedy such as a rename
retry, a Git-work cut or a longer limit, which the governing decision's
condition 6 excludes without a named mechanism and unchanged-limit proof.
The chosen outcome is one registered M1 defect intake that stays **not ready**
at the exact mechanism/evidence stop below, with no repair and no new
diagnostic campaign.
The accepted downside is that the defect remains open and may block another
Windows gate until retained or separately authorized evidence isolates one
mechanism, while ISS-211 and other deliveries continue on their own gates.
The choice is wrong if already-retained logs, per-test JSON, ISS-212 observer
output or campaign records in fact identify one avoidable operation or
failure mechanism in a named manifestation that permits a bounded remedy
under unchanged limits.

## Done when

1. **Mechanism before readiness.** Independent planning review identifies a
   demonstrated avoidable operation or failure mechanism for at least one
   named Windows manifestation, with exact immutable evidence and a bounded
   remedy; otherwise the draft remains not-ready at the `## Mechanism stop`
   below. Timing and EPERM remain separate until evidence connects them. A
   passing rerun, narrower test, or same-base green control alone is not a
   mechanism.
2. **Preserved semantics and regression plan.** A subsequently reviewed
   fixed-scope implementation brief specifies before/after regression proof
   at unchanged 30,000 ms test/hook limits, one-worker/file-serial profile,
   assertions, default skips, lifecycle ordering, saved intents, authority
   observations, attempt accounting and mutation/reconciliation semantics.
   A real failure still fails closed. No timeout increase, test weakening,
   skip, retry policy, runner change or gate waiver is a remedy under this
   intake.
3. **Independent handoff.** The new scope and its actual proof receive
   ordinary independent planning and exact-head code review and local
   `pnpm typecheck`, `pnpm format:check`, `pnpm planning:check` and
   `pnpm test` before any implementation claim.

## Mechanism stop

**Not ready: mechanism/evidence stop.** Each manifestation lacks a different
piece of evidence:

- **Hosted refresh timeouts** (#667 attempt 1, main run 36178089834, #663).
  Each is a censored Vitest 30,000 ms timeout. The retained complete logs and
  per-test JSON give case outcome and duration only; the opt-in ISS-212
  observer produced no capture for any failed case. Missing: a phase,
  process or Git account of one failing case.
- **Host-campaign queue unpark timeout.** Its observer finish hook reported
  `ISS212 case-not-passed` and wrote no queue observer JSON (`queue.log:8,202-204`;
  `iss212-windows-phase1-run-r1.report.md:22,26`). The only observer JSON
  measures a passing source4 case (report `:28`), and the ISS-212 ledger
  (`docs/diagnostics/iss212-windows-timeouts.md:342-365`) does not isolate an
  avoidable operation on a failing Windows path. Missing: the phase account
  of the failing unpark case.
- **Host-campaign `EPERM` rename** (`refresh.log:253-268`, asserted from
  `test/dogfood/refresh.test.ts:1421`, reached from `:1492`). The failing
  rename is `scripts/dogfood/flow.ts:174-179` `replace()`, reached at
  `flow.ts:527` when the reviewer launch selection is persisted after
  `flow.ts:436` created the same intent with an awaited exclusive `wx` write.
  The intervening reviewer work (`flow.ts:494-514`) is awaited Git work in the
  candidate and review worktrees, not the state directory, so the platform's
  own code shows no holder. The Windows holder of the source or destination
  at that instant was not captured. Missing: holder/process identity or
  another demonstrated cause, plus a remedy for this runtime lifecycle record
  that is not a retry policy.
- **Across manifestations.** No unchanged isolated timing collapse was
  captured together with a failing complete serial gate; the campaign's full
  serial gate passed. Host load, antivirus or indexer interference, sharding,
  redundant Git work and a shared root cause are all unestablished.

constraints already recorded in ISS-212's draft apply: a Vitest wall-clock
