## Context and evidence

N0 is the only installation genesis. It must be built, certified, independently
reviewed, granted to one target, and installed by externally reviewed bootstrap
bytes; no candidate record or unsigned receipt grants authority.

## Scope fence

In: reproducible N0 build/aggregate/review/grant verification, target-bound
installer, stable destination identity/observation consumption, custody-root
destination-owner and anchor lifecycles, broker-first installation, acyclic E0
state-authority selection, recovery authorization bootstrap mode, reviewed N0
worker-host renderer artifact mapping and install read-back, genesis active
release, exact reinstall, native scheduler/shim, terminal cleanup, and receipts.

Out: defining contracts, general CAS/lock mechanics, probe conclusions, broker
core, provider policy, successor promotion, or candidate self-certification.

## Decisions already made

The attested grant/verifier and `supervisor-contract.md` external lifecycle are
mandatory. ISS-020 implements destination-owner/anchor CAS under the selected
ISS-022 helper; ISS-004 implements runtime pointers. `Ddest` derives only from
stable `Dphys`; versioned `Dobs` is transition evidence. One destination lock
serializes installation IDs. E0 has an immutable core and bootstrap proposal
producer without a self epoch. No bare absence is reused after owner genesis.
Exact reinstall reuses owner/anchor CONSUMED and is not epoch rollback.
The reviewed external bootstrap writes and reads back the
`authority-history-record/v1` `GENESIS` record, digested under
`authority-history/v1`, before E0 selection, using the bootstrap producer with
no selected epoch. Its `Dgb` binds exact selected
owner/anchor ACTIVE, use intent, bootstrap identity/transaction/grant, and the
shared successor core `Dsc`; `Dsc` binds reviewed N0 release manifest/bytes/
subject/review, derived BOOTSTRAP_INSTALL `Dop`, helper/profile/ABI/lock/state-
component, and custody facts. Bootstrap cannot expose a live E0 context until
the downstream genesis-selection evidence binds that record, `Dbg`, E0
selection/readbacks/`Dgp`, owner/anchor ACTIVE and CONSUMED, consumption
receipt, and consumed readbacks exactly.
Every external record is emitted only from the normative external-bootstrap
schema ledger incorporated by `contract-decisions.md`; ISS-020 may not infer a
member name, nullability branch, nested record, digest order, or lifecycle
equality from conceptual prose.
ISS-020 emits the exact `reviewed-authority-operation/v1`
BOOTSTRAP_INSTALL branch, `state-mutation-successor-authority-core/v1`,
`authority-history-genesis-bootstrap-input/v1`, and
`authority-history-record/v1` GENESIS member sets from the supervisor ledger.
It composes but does not persist
`authority-history-genesis-selection-evidence/v1`. The GENESIS file hashes
under domain `authority-history/v1`; that domain literal is never serialized as
its `schemaVersion`.

## Acceptance criteria and evidence

1. N0 build/certification/review/grant artifacts bind exact source, workflow,
   test bundle, all required OS receipts, reviewer separation, target identity,
   nonce, expiry, verifier anchor, and installer bytes; all substitution/replay/
   self-review variants refuse before mutation.
2. The installer verifies stable physical identity plus a current admitted
   observation and same-lock closed absence evidence, selects one
   destination-owner ACTIVE winner, creates/read-backs
   the downstream successor receipt where applicable, then selects anchor
   ACTIVE and a pre-expiry use intent. Two concurrent/staggered installation IDs
   yield one winner and a retained real loser.
3. Under destination→anchor→runtime lock order, it selects acyclic E0 from the
   immutable core, completes runtime post receipt, selects anchor then owner
   CONSUMED, and completes external consumption receipt. ISS-004 context remains
   unavailable until every readback agrees.
4. Bootstrap recovery core includes the exact BOOTSTRAP union. Native consume is
   written first, `CONSUMED` is selected second, and post-selection receipt is
   third; restart reuses the non-expiring selection. Revoke/removal follows the
   symmetric ordered protocol.
5. N0 active release, gate/fence/cleanup, scheduler/shim, broker client, and
   archive/tombstone evidence are selected through ISS-004. No candidate, shim,
   file presence, PID, timestamp, or receipt alone grants authority.
6. Crashes at every owner/anchor/use/E0/consumption/install/cleanup boundary
   resume the exact transaction. A pre-expiry use intent may finish after expiry;
   expired unused authority retires only with destination absence. Dot-before-
   successor-receipt and E0-before-owner-consumed are explicit recoveries.
7. Exact reinstall validates selected owner/anchor CONSUMED, consumption receipt,
   archive/tombstone/custody, and original E0. RETIRED, moved physical identity,
   changed bytes, stale intent/owner, pending/unknown, or rollback refuses.
8. Teardown selects anchor then owner RETIRED with FULL_REQUIRED archive. A new
   installation requires a different ID, exact prior RETIRED triple/archive,
   acyclic review core, fresh anchor, selected owner ACTIVE, and downstream
   review receipt.
9. N0 proves one no-work cycle before successor use and emits receipts without
   secrets, raw capabilities, absolute private paths, or adapter vocabulary.
10. The E0 `GENESIS` evidence proves exact `Dop`, `Dsc`, `Dgb`, branch-`Dh`,
    and downstream `Dgse` formulas; canonical decimal zero and
    genesis predecessor; selected owner/anchor ACTIVE and CONSUMED; use intent;
    bootstrap core/post/readbacks/consumption; no retiring epoch; and exclusion
    of successor value/proposal/tip/head from upstream digests. First `ROTATION` appends record `1` binding the genesis
    digest and cannot fabricate prior records, a forked chain, or a truncated
    walk.
    Tests mutate every bootstrap-operation/core/input/record/selection member,
    branch-only absence, type, canonical name, persistence disposition, and
    domain-versus-schema literal; each mutation refuses before E0 context
    issuance.
11. The reviewed N0 `release-manifest/v1` contains the closed, unique 1–16
    worker-host renderer mapping keyed by opaque host identity digest. The
    installer recomputes every mapped artifact digest from exact installed
    bytes, applies the total mapping parser, recomputes each identity from the
    artifact digest plus closed sorted capability array, reads the mapping back,
    and binds it to the selected N0 active release. Missing/extra/future fields,
    malformed/duplicate/case-substituted capabilities, duplicate identities,
    wrong package, stale, candidate/self-reported, moved registration/template,
    coordinated identity/artifact, manifest substitution, and read-back
    substitution refuse before active selection.
12. External schema-census tests remove, add, rename, null, reorder, cross-type,
    and cross-branch every physical/owner/successor/anchor/E0 ledger member;
    mutate every closed enum and nested schema; and substitute every framed
    identity, selected triple, readback, archive, observation, review, expiry,
    closed absence, exact reviewed candidate, one-way retirement archive, and
    downstream receipt independently and coordinately. The accepted graph
    proves use-intent-before-`Dgb` acyclicity and distinct `Dgp`/readback
    binding. Exact reinstall
    reuses the complete selected graph and any attempted new genesis artifact
    refuses.
