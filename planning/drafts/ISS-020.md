## Context and evidence

N0 is the only installation genesis. It must be built, certified, independently
reviewed, granted to one target, and installed by externally reviewed bootstrap
bytes; no candidate record or unsigned receipt grants authority.

## Scope fence

In: reproducible N0 build/aggregate/review/grant verification, target-bound
installer, exact installation/state roots, broker-first installation, recovery
authorization bootstrap mode, genesis active-release and state-mutation
authority selections, exact reinstall, native scheduler/shim, terminal cleanup,
and bootstrap receipts.

Out: defining contracts, general CAS/lock mechanics, probe conclusions, broker
core, provider policy, successor promotion, or candidate self-certification.

## Decisions already made

The attested grant and verifier authority in bootstrap architecture remain
mandatory. Bootstrap uses the shared ISS-004 pointer protocol. Genesis has
reviewed-bootstrap producer identity and selected state-mutation authority
before ordinary mutations. No bare absence is reused after genesis. Reinstall
requires the same reviewed external authority and exact selected state; it is
not an epoch rollback.

## Acceptance criteria and evidence

1. N0 build/certification/review/grant artifacts bind exact source, workflow,
   test bundle, all required OS receipts, reviewer separation, target identity,
   nonce, expiry, verifier anchor, and installer bytes; all substitution/replay/
   self-review variants refuse before mutation.
2. The installer establishes canonical custody, fixed non-symlink lock, broker
   custody, and externally reviewed `STATE_MUTATION_AUTHORITY_ROTATION` genesis
   binding helper/profile/ABI/custody. Ordinary state begins only after selected
   readback and private capability issuance.
3. Bootstrap recovery core includes the exact BOOTSTRAP union. Native consume is
   written first, `CONSUMED` is selected second, and post-selection receipt is
   third; restart reuses the non-expiring selection. Revoke/removal follows the
   symmetric ordered protocol.
4. N0 active release, gate/fence/cleanup, scheduler/shim, broker client, and
   archive/tombstone evidence are selected through ISS-004. No candidate, shim,
   file presence, PID, timestamp, or receipt alone grants authority.
5. Crashes at every genesis/proposal/consume/install/active/cleanup/rotation
   boundary resume exactly under the old or new selected epoch. Malformed or
   unknown authority refuses; abort is allowed only before the irreversible
   boundary and follows the exact clientless cleanup path.
6. Exact reinstall validates selected archive/tombstone/custody and external
   reviewed bootstrap authority. Moved state, different helper, changed bytes,
   pending/unknown proposals, or rollback request refuses.
7. N0 proves one no-work cycle before successor use and emits receipts without
   secrets, raw capabilities, absolute private paths, or adapter vocabulary.
