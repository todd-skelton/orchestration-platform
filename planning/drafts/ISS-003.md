## Context and evidence

ISS-041 needs one portable loader for its disposable state root, and ISS-013
needs the existing static `project` slot plus a closed command result boundary.
Rounds 241/242 showed that the former whole-CLI packet was both underclosed and
too broad. This slice now closes only those two consumers.

## Scope fence

In: the `config validate` and `config paths` rows; a pure
configuration loader; exact project/config/state-root selection and admission;
one canonical result envelope; the existing static handler ABI needed for
ISS-013 to replace only `project`; and three-OS Node evidence.

Out: every other command implementation, shell invocation/quoting parity, text
projection, path reveal, installation, state creation, journaling, credentials,
background services, native helpers, Git discovery, UNC roots, and
project-adapter behavior.

## Decisions already made

The loader receives one closed invocation instead of ambient process state:

```text
operatingSystem = WINDOWS | MACOS | LINUX
cwd = absolute host path
flags = {configPath, projectRoot, stateRoot} where each value is null or one absolute host path
environment = {HOME,LOCALAPPDATA,ORCHESTRATION_CONFIG,ORCHESTRATION_PROJECT_ROOT,
               ORCHESTRATION_STATE_ROOT,XDG_STATE_HOME}
```

Each environment member is null or a non-empty string; empty, extra, accessor,
proxy, or other values refuse. `packages/config` cannot import
`node:process`, inspect raw argv, write output, or set an exit code. The CLI
bootstrap alone snapshots this invocation and serializes the result.

Before any filesystem call, a non-plain top-level invocation or `flags`
record, an invalid `operatingSystem`, or any missing, extra, accessor, proxy,
or wrong-scalar-type member in either record returns the `ARGV_REFUSED` row.
The same closed-shape defect in `environment`, including any member or value,
returns `CONFIG_REFUSED`; a trap or throw while checking either closed shape
returns that shape's row and never escapes the loader. A well-typed but
non-absolute `cwd`, flag path, or selected environment path continues to the
`PATH_REFUSED` row.

`.orchestration/project.json` is canonical UTF-8 JSON without BOM/newline and
has the exact `platform-configuration-source/v1` members
`adapterId, capabilityNames, leaseFreshnessMs, maximumSessionMs, projectId,
schemaVersion, stateRoot, wallClockSkewMs`. `stateRoot` is null or a canonical
local `file:///` URL; the other scalar/array rules equal the landed
`platform-configuration/v1` parser. Capability names are non-empty, unique and
UTF-8 sorted. Resolution produces the exact landed
`platform-configuration/v1`; the source record is loader input, not authority.

Precedence is literal and per row:

| Selected value                  | Highest to lowest                                                                   |
| ------------------------------- | ----------------------------------------------------------------------------------- |
| project root                    | `--project-root`; `ORCHESTRATION_PROJECT_ROOT`; cwd ancestor walk                   |
| config path                     | `--config`; `ORCHESTRATION_CONFIG`; `<projectRoot>/.orchestration/project.json`     |
| state root                      | `--state-root`; `ORCHESTRATION_STATE_ROOT`; non-null source `stateRoot`; OS default |
| all other configuration members | source record only                                                                  |

An explicit project root is the exact directory and is not walked. Otherwise
the loader walks the physical cwd ancestors to the filesystem root and requires
exactly one project file; zero, two, moved, or project-ID-conflicting candidates
refuse. An explicit config path must name that default file or an existing
regular canonical file beneath the selected project root. Relative paths and
alternate project files outside the root refuse.

The state-root default appends `orchestration-platform/<projectId>` to absolute
`LOCALAPPDATA` on Windows, `HOME/Library/Application Support` on macOS, and
absolute `XDG_STATE_HOME` or `HOME/.local/state` on Linux. Missing/relative base
variables required by the selected OS default return `PATH_REFUSED`. Existing
path components must be ordinary directories with
stable `lstat`/`realpath` identity and no symlink/junction/reparse traversal.
For an absent state root, the nearest existing ancestor is checked and every
tail segment is literal and non-dot. The canonical local file URL must round
trip to the admitted host path. Project/config roots must exist; state root may
be absent. Either-direction project/state overlap, alias, root movement,
replacement during read, or any filesystem write refuses before result
serialization.

The pure async entrypoint is exactly
`loadConfiguration(invocation): Promise<ConfigurationLoadResult>` and never
throws or rejects. Its closed union is:

```text
{ok:true,value:{configuration,configPath,fieldSources,projectRoot,
                stateRoot,stateRootDisposition}}
{ok:false,error:{code,exitCode,message,outcome}}
```

`configuration` is the parsed final `platform-configuration/v1` record;
`configPath`, `projectRoot`, and `stateRoot` are the exact canonical absolute
host strings; `fieldSources` is the exact seven-member record below; and
`stateRootDisposition` is `ABSENT|DIRECTORY`. All records/arrays are frozen,
plain, closed data. The error is exactly one row from the failure table below.
ISS-041 consumes only this entrypoint and may create its disposable root only
after `ok:true`; it cannot reinterpret an error or durable redacted result.

Exact paths exist only in that in-process value. Durable results contain only
`pathToken = "<redacted:path:" + SHA256(frame("configuration-path/v1",
fixed(canonicalFileUrlBytes))) + ">"`. `configuration-provenance/v1` has exactly
`adapterId, capabilityNames, fieldSources, leaseFreshnessMs, maximumSessionMs,
projectId, projectRoot, schemaVersion, stateRoot, wallClockSkewMs`; both root
members are path tokens. `fieldSources` has the seven non-schema configuration
field names with values `CLI|ENVIRONMENT|PROJECT|DEFAULT`.
`configuration-paths/v1` has exactly `configPath, projectRoot, schemaVersion,
stateRoot`, with three path tokens. The digest has one fixed framed part; raw,
text, canonical, unframed, alternate-domain, or host-path bytes refuse.

The closed command rows are:

| Command           | Success result                |
| ----------------- | ----------------------------- |
| `config validate` | `configuration-provenance/v1` |
| `config paths`    | `configuration-paths/v1`      |

The static registration is one closed in-memory union. A `PLACEHOLDER` has
exactly `commands,family,implementation,issue,owner,schemaVersion`; every command
has the existing exact `argv,optional,required` members and no result schema or
handler exists. An `IMPLEMENTED` registration adds exactly `handler`; every
command adds exact `resultSchema`, which must be one supported public v1 parser.
The existing `project` family remains the valid handler-free `ISS-013`
placeholder; other placeholders are unchanged and not executable.

The dispatcher calls an implemented handler exactly once with one frozen closed
`{command,configuration,options}` record. `configuration` is the successful
loader value and `options` is the command row's closed name/value record. The
handler must return a same-realm native
`Promise<{ok:true,result:ContractRecord}|{ok:false,error:CommandFailure}>`;
each branch has exactly its shown two members. Synchronous returns, thenables,
throws, and rejections become the fixed `INTERNAL_ERROR` row. A success result
must be frozen closed data and parse under that command's registered result
schema before serialization. `CommandFailure` is the exact four-member loader
error record and must equal one registered non-placeholder failure row. A
placeholder is never called: the dispatcher constructs its failure from the
same registration's `issue` member as
`{code:"CAPABILITY_NOT_IMPLEMENTED",owner:issue}`; no second registry or
handler participates. Missing/extra/duplicate families, commands, handlers or
schemas, a handler on a placeholder, no handler on an implementation,
result-schema mismatch, or result/error union drift refuses before output. This
is the complete ABI ISS-013 later uses to replace only `project`.

JSON output is exactly one canonical `orchestration-command-result/v1` record
with members `command, diagnostics, outcome, result, schemaVersion`, UTF-8,
no BOM and one LF on stdout; stderr is empty. Success is exit 0 with one typed
result and no diagnostics. Failure has `result:null` and exactly one diagnostic
from the closed union `{code,message}|{code:"CAPABILITY_NOT_IMPLEMENTED",owner}`.
The exhaustive rows for this slice are:

| Condition                                                                                                                  | Outcome / exit          | Code                          | Exact remaining diagnostic members      |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------- | ----------------------------- | --------------------------------------- |
| malformed closed invocation/flags; unknown/duplicate/missing/positional argv; any `--output text`                          | `invalid-input` / 2     | `ARGV_REFUSED`                | `message:"command line refused"`        |
| malformed closed environment; read bytes are invalid UTF-8/JSON, BOM/newline/noncanonical, or source scalar/member refuses | `invalid-input` / 2     | `CONFIG_REFUSED`              | `message:"configuration refused"`       |
| zero/multiple/conflicting project discovery                                                                                | `authority-refused` / 3 | `PROJECT_ROOT_REFUSED`        | `message:"project root refused"`        |
| missing/relative OS-default base; relative/UNC/alias/symlink/junction/overlap/movement/replacement path                    | `authority-refused` / 3 | `PATH_REFUSED`                | `message:"path refused"`                |
| filesystem call returns no readable bytes/facts outside the closed path-refusal cases                                      | `operation-failed` / 5  | `FILESYSTEM_OPERATION_FAILED` | `message:"filesystem operation failed"` |
| a valid placeholder command is invoked                                                                                     | `operation-failed` / 5  | `CAPABILITY_NOT_IMPLEMENTED`  | `owner:<registration.issue>`            |
| registry/ABI/result-schema drift, sync return, throw, rejection or unexpected failure outside closed-input inspection      | `internal-error` / 70   | `INTERNAL_ERROR`              | `message:"internal error"`              |

For pre-command argv refusal `command` is `""`; otherwise it is the exact
canonical command row. Conditions are classified in table order. No message
contains input. The serializer constructs and validates all bytes before one
stdout write. Other bootstrap outcomes/exits remain reserved.

Everything out of scope unparks only when a committed ISS-041 or ISS-013
consumer test cannot pass through the records above, or when another command
owner becomes runnable and names its missing invocation/result row. The failing
test and missing member/row are required evidence; preference, shell variety,
operator path reveal, or hypothetical consumers do not unpark it.

## Proportionality

| Mechanism                 | Threat and deletion test                                                      | Smallest alternative / disposition                                           |
| ------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Closed invocation         | ambient argv/environment/output bypasses redaction; remove the source ban     | passing `process` is larger; retain six named environment values             |

| Result-schema handler ABI | ISS-013 replaces a slot with incompatible bytes; remove the schema census     | hard-coded family branches are larger; retain the static row                 |
| Shell/full-command matrix | no current consumer; delete it from acceptance                                | defer until the falsifiable unpark condition                                 |

## Acceptance criteria and evidence

1. The two config rows produce their exact typed result and canonical envelope
   on Windows, macOS and Linux. Evidence: ISS-006 Node matrix and byte goldens.
2. Every precedence arm, unset/empty input, and OS default reports the exact
   field source. Evidence: table-driven loader tests.
3. Missing, ambiguous, aliased, moved, overlapping, relative, UNC and replaced
   roots refuse with zero filesystem delta. Evidence: path matrix plus mutants.
4. Path/home/canary bytes are absent from envelopes and diagnostics, and every
   failure row matches exact golden bytes. Evidence: serializer scans, message
   canaries, and one golden per table row.
5. ISS-041 consumes the pure loader without process globals, and an ISS-013
   fixture replaces only the existing `project` placeholder through the named
   result schema. Evidence: import/registry census, one exact owner-bearing
   placeholder golden per registration, and duplicate/missing mutants.

## Predicted footprint and dependencies

Modify only predeclared `packages/cli/`, `packages/config/`, their tests; the
four parser/registry entries and compatibility/golden tests for
`platform-configuration-source/v1`, `configuration-provenance/v1`,
`configuration-paths/v1`, and `orchestration-command-result/v1` in
`packages/contracts/`; and the ISS-000-owned
`scripts/lib/static-command-runner.mjs` declaration/runner census needed to
replace the `config` placeholder with the closed data-only ABI. The ISS-000
amendment updates every existing census restating that runner and one
owner-bearing placeholder golden per registration in the same reviewed change.
The four contracts add exact-v1 supported/unknown-future/malformed compatibility
rows and no authority interpretation. No workspace, roadmap, dependency,
glossary, conformance-registry, shell-wrapper or other command-family change.

Prediction: ISS-041 and ISS-013 can consume these surfaces without adding a
configuration member, ambient input, output channel or root-discovery rule.
Review by the earlier of their implementation reviews; any such addition is
replan evidence.
