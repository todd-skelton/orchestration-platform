## Context and evidence

The platform needs one executable surface across shells and operating systems.
See `docs/architecture/vision.md` and the configuration contracts from
`ISS-002`.

## Scope fence

In: `orchestrate` CLI bootstrap, config discovery, explicit project/state-root
selection, structured output, exit-code contract, and diagnostic redaction.

Out: orchestration behavior, background services, automatic global installation,
or shell-specific wrapper scripts.

## Decisions already made

Configuration names, precedence, project identity, per-OS roots, ambiguity,
command grammar, output envelope, and exit codes are settled in
`docs/architecture/contract-decisions.md` and
`docs/architecture/bootstrap-manifests.md`. The trusted OS harness from
`ISS-006` is the authority surface for the shell matrix.

## Acceptance criteria and evidence

1. The same commands and exit codes operate under PowerShell, cmd, bash, and
   zsh where available. Evidence: CLI contract tests in the OS matrix.
2. Config precedence is deterministic and reports field provenance. Evidence:
   table-driven precedence tests.
3. Invalid or ambiguous roots fail before creating state. Evidence: disposable
   fixture asserting zero filesystem delta.
4. Durable structured output contains no tokens, credentials, or home-directory
   prefixes; only explicit interactive `config paths --reveal` displays exact
   paths and never journals them. Evidence: canary tests covering both modes.
5. The CLI composes the predeclared typed handler registry and the `config`
   package replaces only its command-family placeholder. Evidence: registry
   census and duplicate/missing-handler negative tests.
6. Every canonical argv row in the bootstrap manifest has one executable
   positive parser/envelope fixture; missing, duplicate, positional, misspelled,
   and wrong-schema single-token mutants fail with exit 2 before handler entry.
   Evidence: generated command matrix shared with every handler owner.

## Verification plan

`pnpm --filter @orchestration-platform/cli test`

`pnpm run test:cli-shell-matrix`

## Predicted footprint and dependencies

Create implementation inside predeclared `packages/cli/` and `packages/config/`
skeletons plus CLI fixtures. Blocked by `ISS-002` and `ISS-006`; no shared-
manifest or glossary edit. This slice owns CLI composition and `config` handler registration; other
command families remain named placeholders for their owning slices.

## Operator actions

None.

## Glossary impact

None; project root, state root, and configuration provenance are registered.

## Independent review packet seed

Attack quoting, Unicode paths, spaces, symlinks, environment precedence,
stdout/stderr separation, and pre-validation writes. Use a shell/OS/fixture
state-delta matrix.
