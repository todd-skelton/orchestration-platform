## Why

Platform #367's 2026-09-18 host observation records original run
`m1-sibling-mirror-recovery-20260917T0848`, cycle 5, ISS-182/#560 stopping after
publication of PR #576. Its final refreshed head
`465f1beb2f16c6d77a8b3e79bfac247884976f08` had independent PASS and native
local gates PASS. Own Actions run `35326425131`, attempt 1, had three actual
bootstrap jobs in progress at the host's stop observation. The supervisor
reported `hosted-observation-unavailable` with diagnostic
`applicable workflow changed during observation; reobserve checks`.
Retained `cycle-5-stop-3.json` carries attempts 1 and 18 participants, not a
cycle completion. This intake changes no historical verdict, charge or stop.

At stable source `2fae5debf1a70f93985e4ab73dd198c86ff1a859`,
`delivery-adapter.ts:293-311` compares the before/after selected workflow
tuples including `status` alongside workflow ID, run ID, run number, attempt
and path. A mismatch throws. `checks()` at :1283-1317 retries only startup
absence; a present run's mismatch exits through the non-parking host stop.
Normal lifecycle progress can therefore stop the loop even when publication
and selected run/attempt identity did not change.

The production response pair was not retained. Which field changed in that
incident is UNKNOWN; do not claim status alone caused PR #576's stop.
A pure fake-API probe against the unchanged public adapter demonstrates the
narrow false-stop class independently: queued-to-running and running-to-complete
status-only changes throw that same diagnostic. Stable pending/green/failure
return their correct evidence; run/workflow/number/attempt/path changes and
wrong-head/source controls refuse. Every probe identity is explicitly synthetic.
No live-provider call, Git process, mutation or real identity with altered facts
was used. This is a planning reproduction, not implementation qualification.

## Decision

Quality profile: core-library.

Constraint: lifecycle progress within the same proven publication and selected
run/attempt must not be mistaken for changed attribution. Chosen smallest
shape: keep the existing before/after authoritative association and immutable
selection comparison, but separate lifecycle status from that identity. Derive
pending conservatively from both validated observations and reuse the existing
`workflowPending`/`observing-hosted-checks` path and next supervisor observation.
No extra polling loop, sleep, retry allowance, persisted snapshot or schema.

G0: Removing the status equality alone is smaller but insufficient: a completed
first snapshot followed by a non-completed second snapshot must not authorize
merge from old green. Removing all before/after validation permits changed
run/attempt evidence to be mixed. Retrying every observation error masks genuine
identity/acquisition failures. Restarting the stopped run is a separate bounded
operator decision, not a fix for this reproducible false-stop class.

Accepted cost: a conservative extra ordinary observation when a run completes
during acquisition. Existing genuine attributed failure/log semantics remain;
pending is not permission to hide terminal non-success. Revisit only if an
observed provider contract change cannot be represented by the current run/job
selection. There is no new UI, public contract, configuration or hot-path
optimization. Use existing terms: publication, run, attempt, pending, host stop.

## Done when

1. **AC1 Same-identity lifecycle progress.** Through public
   `githubDeliveryAdapter(...).checks`, a current queued-to-in-progress or
   in-progress-to-completed transition between the two workflow reads no longer
   throws solely because status changed. Both observations independently retain
   repository, exact PR, source/base, head and owning workflow association. Every
   selected workflow must retain the same workflow ID, run ID, run number, run
   attempt and path across acquisition. Workflow addition/removal or immutable
   selection change retains the existing host-observation stop, not this pending
   exception. No current-head/job validation is weakened.
2. **AC2 Conservative pending and eventual completion.** If either validated
   snapshot of that unchanged selection is non-completed, keep the existing
   pending disposition so sampled green alone cannot authorize merge. Include
   completed-to-in-progress as a synthetic stale-read/no-early-green control,
   without claiming it occurred in production. A pending initial snapshot with
   missing or pending jobs followed by completion stays in ordinary observation;
   a later stable complete snapshot with all required green completes ordinary
   delivery. Preserve missing/duplicate terminal required-job refusal and all
   configured required contexts. Stable genuine failure/cancellation/skipping
   and complete attributable diagnostics keep existing handling, not synthetic
   green or indefinite error suppression.
3. **AC3 Narrow failure boundary.** Keep before/after publication identity and
   conflict validation, selected effective-job/run-attempt checks, failed-only
   rerun semantics and the failure-log acquisition binding. Wrong PR/repository/
   head/source/base, changed attempt/run/workflow/path, contradictory jobs,
   malformed/duplicate data and failed API acquisition must not gain admission
   from a simultaneous status change. Existing all-run-absent startup remains
   ten-second/twelve-wait bounded; present status progress adds no wait, retry,
   timeout, counter or automatic hosted rerun. No broad catch-and-continue.
4. **AC4 Owning regressions and lifecycle proof.** Add focused fake-command
   tests in the existing adapter test file for stable pending, stable complete
   green, stable genuine failure, queued-to-running, running-to-complete with
   pending and green job snapshots, and the reverse-status no-early-green
   control. Vary immutable selection fields one at a time and keep wrong
   publication/job controls. Count injected API calls, pauses and mutation
   calls: no new inner retry or mutation. Use the existing delivery test seam
   for pending then stable complete observations of one publication, proving
   no republish, early merge or corrective author from status-only progress;
   preserve participant/implementation/retry charges and prior records in the
   directly owning lifecycle fixture. Reverting the status fix fails the
   progress regression; deleting immutable checks fails its refusal controls.
   Invented controls remain unmistakably synthetic, never modified real IDs.
5. **AC5 Qualification and delivery.** Run complete owning tests and all four
   ordinary local gates, independent exact-head review, final-head Ubuntu,
   Windows and macOS bootstrap, normal publication/merge and applicable
   deployment. Keep workers, timeouts, skips and assertions unchanged. Update
   only the short standing observation rule in `docs/loop.md`; no other process
   document. Future implementation is loop-owned, not a host patch. This issue
   grants no installation, restart or automatic recovery of the preserved run.
