## Question

Can GitHub artifact attestations plus a protected `bootstrap-n0` environment
produce independently verifiable, fresh, one-use evidence of the exact pinned
workflow run and Todd's exact-digest approval that candidate code cannot forge?

## Probe method and lifecycle timing

On an exact synthetic source digest, execute the probe-owned workflows
`.github/workflows/probe-bootstrap-build.yml`,
`.github/workflows/probe-bootstrap-review.yml`, and
`.github/workflows/probe-bootstrap-authorize.yml` from `refs/heads/main`. Build and
aggregate under GitHub OIDC, then use a distinct isolated review actor/role to
attest an accepted/rejected exact-candidate `bootstrap-review-receipt/v1` with no
build/install/grant capability. Attest the candidate/certification predicates, then
request deployment to environment `bootstrap-n0`, configured with required
reviewer Todd, self-review prevention, and admin bypass disabled. After approval,
attest `bootstrap-grant-attestation/v1` containing repository numeric ID,
workflow ref/SHA/run/attempt, environment, build/review/approver numeric actor
IDs, target host/user/state-root identities, candidate,
certification, review, installer/test digests, UUIDv7 nonce, issued/expiry times
(maximum 15 minutes), and one-use transaction ID.

Target host/user/state claims come only from a live signed receipt produced by
the independently reviewed `ISS-038` pre-N0 custody kit. The probe verifies the
kit's `host-custody-bootstrap-review-receipt/v1`: GitHub artifact attestation,
landed commit/tree, PR/review and distinct numeric reviewer, workflow/run,
source/client/reduced-service/profile/host-method/lifecycle/Node/WinSW digests,
plus host signature/reference generation and passed repository-protection
receipt. The attested workflow performs the complete API census with its run-
scoped token; clean targets use the receipt's pinned GitHub CLI against the
downloaded public bundle with no local project credential or API re-query. An
unreviewed, dismissed, self-reviewed, stale/source-tree, or full downstream
broker composition cannot supply this input.

Verify the downloaded Sigstore bundle on clean macOS, Windows, and Linux runners
against issuer `https://token.actions.githubusercontent.com`, repository
`todd-skelton/orchestration-platform`, exact workflow ref/SHA, predicate type,
subject digest, environment, actor IDs, target-host fingerprint, current-user
identity, and destination state-root digest using one pinned cross-platform
verifier artifact. Capture at the lifecycle point after environment approval and
immediately before bootstrap authorization. Consume the nonce with create-once
state before first install mutation.

The probe build workflow triggers the pinned probe review workflow; only an
accepted, attested review workflow whose upstream numeric run/artifact IDs match
that build may trigger the probe authorization workflow. Todd cannot dispatch either
transition; review/trigger actor and approving numeric actor must be distinct.
If GitHub cannot prove that distinction, the result follows the blocking
disposition rather than weakening self-review protection.

## Required durable evidence

Publish scrubbed attestation bundles and predicates, the exact reviewed pre-N0
custody-kit/host receipt, GitHub repository/workflow/
environment numeric identities, protection configuration receipt, exact verifier
artifact/version/digest and invocation, three-OS verification receipts, nonce
consumption/replay receipts, and raw API provenance/pagination. Bind the probe
source and fixture/test bundle digests.

## Disposition rule

- PASS only if all three OSes independently verify build, aggregate, reviewer,
  environment approval, exact subject, freshness, and one-use grant evidence;
  `ISS-020` implements that exact verifier/schema contract.
- If GitHub's attestation/predicate cannot prove the required reviewer actor or
  protected-environment approval, `BLOCK_REPLAN`: select a separately protected
  operator signing key or different authority service before bootstrap work.
- If a required verifier is not portable/pinnable, `BLOCK_REPLAN`; one OS cannot
  stand in for another. Unsigned JSON or workflow environment variables never
  satisfy authority.

## Negative controls

Candidate-fabricated byte-identical JSON, wrong repository/run/attempt, moved
workflow bytes, unprotected environment, self-approval, wrong reviewer, expired
grant, future clock, changed subject, altered installer, duplicate nonce, replay,
wrong target host/user/state root, and verifier substitution all refuse before
mutation.

## Verification plan

## Predicted footprint and dependencies

Owns only `probes/bootstrap-authority/`, the three exact
`.github/workflows/probe-bootstrap-*.yml` synthetic workflows, synthetic
environment fixtures, and scrubbed evidence. Each workflow is visibly probe-
only, accepts only the fixed synthetic subject/repository paths, and cannot call
production bootstrap install/bind/broker commands. Blocked by repository bootstrap and trusted OS harness;
host/target assertions use the passed `ISS-038` custody implementation. Blocks
bootstrap root implementation. No production `bootstrap-build.yml`,
`bootstrap-review.yml`, `bootstrap-authorize.yml`, installer, or
grant is created here.

## Operator actions

Create the bounded synthetic protected environment and approve only the named
synthetic digest during the probe. Remove the environment after evidence review
if it is not the production choice.

## Glossary impact

None; attestation, authority grant, freshness, and one-use capability are
registered.

## Independent review packet seed

Attack candidate-equivalent files, OIDC claim confusion, reusable approval,
workflow movement, environment bypass, actor-name reuse versus numeric ID,
attestation bundle substitution, clock skew, verifier compromise, and evidence
captured after the authorization moment. Use raw claim-to-normalized-field maps.
