## Decision

The constraint is that this row must retain the unchanged 30,000 ms limit and
must not turn host-load timeouts into a timeout increase, retry or skip. The
simplest alternative is to keep local full-suite and consecutive focused green
runs as gates, but that repeats the proven host-sensitive failure and can stop
sound candidate logic before hosted CI runs. The chosen option keeps exact
child-process counts, mutant kills, typecheck, format and planning checks local,
moves the full suite and every wall-clock-dependent acceptance to the existing
hosted CI checks on the candidate PR head, and records a local load-only timeout
as non-blocking evidence when those hosted checks are green. The accepted
downside is that local timing no longer qualifies the change; hosted CI is the
qualification authority and must run the unchanged tests and 30 s limits.
The choice would be wrong if the current executor did not gate the candidate PR
on its hosted required checks, or if the hosted workflow did not include the
full suite at the candidate head.

## Done when

1. **Local census.** For each of the four rows, two consecutive focused runs
   record identical per-row child counts and their per-source breakdown. A
   count mismatch is a candidate failure; a run that reaches the unchanged
   30,000 ms limit under host load is recorded as local load-only timeout
   evidence under the rule in the Verification plan. Do not add a tolerance.
2. **Local redundant-work proof.** After the change, each row validates the
   executor exactly once (8 children). Every other assertion, replay and
   byte-equality check in `:3120-3286` is unchanged. Each row's count drops by
   exactly the removed validations (64 for `review-fail then retained complete`
   on the census basis above).
3. **Local regression proof.** Each row asserts its post-change exact count. A
   mutant that restores per-call validation fails that assertion (red) at any
   host speed. The mutant kill and exact-count assertions are local,
   load-independent checks; local consecutive green timing is not an
   acceptance gate.
4. **Unchanged test surface.** `vitest.config.ts` and every other test's
   expectations are unchanged. The counter is pass-through: other tests in
   `queue.test.ts` pass with it present. Prove this with the required hosted
   full suite, not a local full-suite gate.
5. **Hosted qualification.** On the candidate PR head, the existing required
   hosted CI checks are all green, including the full suite on the required
   Ubuntu, Windows and macOS paths. The unchanged 30,000 ms Vitest test and
   hook limits remain in force. Hosted per-row durations are recorded beside
   run 40510837186, but durations are reported rather than asserted.

## Verification plan

```sh
pnpm exec vitest run test/dogfood/queue.test.ts -t "carries the verification charge past later cycles above 64"
pnpm typecheck
pnpm format:check
pnpm planning:check
```

Run the focused census and mutant checks locally, serially, with no other
Vitest process running. Keep the exact child counts, mutant kill, typecheck,
format and planning checks local. Do not run local `pnpm test` as a gate: the
full suite is a hosted-CI gate on the candidate PR head, and the hosted run
must be green. The hosted bootstrap workflow's required contexts are
`Node 24 / ubuntu-latest`, `Node 24 / windows-latest`, and
`Node 24 / macos-latest`; each runs the full suite under the existing
configuration.

If a local focused or full-suite command reaches the unchanged 30,000 ms limit
without a candidate assertion failure, the author records one
`local-load-timeout` evidence entry in the PR summary and terminal evidence
with the exact candidate head, command, row/test identity, exit code and
observed timing. This entry is explicitly **non-blocking evidence, not a
failure**, only when the required hosted CI checks on that candidate PR head
are green. It is never reported as a local PASS, never used to waive hosted
CI, and never retried until green. If hosted CI is not green, the timeout stays
unqualified and the candidate does not pass.
