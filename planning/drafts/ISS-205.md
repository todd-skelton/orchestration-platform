## Decision

Quality profile: `core-library`. Start only at `assertExecutor` in
`scripts/dogfood/setup-adapter.ts:419-495`. It resolves the executing,
controller and repository roots at :421-426; it then separately reads both
top-level paths and HEADs at :455-471 and both cleanliness results at :485-490.
Prove equivalence before removing any read. Reuse one observation only when
the two roots resolve to the **same canonical checkout**, not when separate
worktrees merely share a Git common directory. Keep both configured identity
comparisons against that observation, including the matched-replay
controller-versus-pilot rule at :473-483. Preserve `joinGitReads`'s first
rejection and owned-child drain at :162-169, all fail-closed refusal reasons,
and freshness at each actual boundary. No persistent, global, cross-state or
cross-invocation cache and no ownership protocol.

The first slice leaves **all** transition re-observation untouched:
`scripts/dogfood/setup.ts:476-478` creates a worktree before observing it,
`:513-515` installs dependencies before observing it, and
`setup-adapter.ts:519-533` checks registered metadata against independently
observed checkout HEAD, branch and dirt. These reads have different authority
or freshness. Sharing a common Git directory, or arguing only that our code
did not write, is not a proof across an asynchronous boundary. A proposed
extension requires a separate explicit same-authority-and-freshness proof and
scope decision; it is not presumed by this issue.

If no safe reduction in the first slice survives this equivalence proof,
stop without edits and report the bounded negative result. Do not broaden
to a speculative cache, transition bypass, fixture-only shortcut or test
relaxation. End-to-end throughput benefit is to be observed, not promised.
