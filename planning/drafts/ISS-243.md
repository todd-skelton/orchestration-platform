## Decision

A blocking finding must stay inside the implementation candidate, while a valid advisory note must not turn PASS into a work stop merely because it cites unchanged context.
The simplest alternative is to suppress such notes in prompts, but the demonstrated controller failure would remain reachable.
Make changed-file membership severity-sensitive in the existing validator and align the existing source, repair and refresh reviewer prompts.
Accept that notes may name unchanged committed files, while retaining the exact-head file and line checks and all write boundaries.
The choice is wrong if the refreshed PASS still stops, a blocking location escapes the changed set, or a note grants repair or landing authority.

## Done when

   review schema, run/head/role/G0/length checks and PASS/FAIL consistency.
   Every `blocking` finding must name a file in `candidate.changed`; absence
   refuses `source-finding-location-outside-candidate`, even if its line is
   valid in the reviewed tree. A `note` may name an unchanged committed file
   at `candidate.head`. Both severities still require a real file and valid
   one-based line at that exact head. Missing files, directory/tree paths and
   out-of-range lines still refuse; malformed paths or line values retain
