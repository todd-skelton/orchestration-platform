## Decision

A completed publication may omit execution logs only for jobs whose complete attributed Actions metadata proves they never executed, while every executed failure remains actionable.
The simplest alternative is to suppress every cancelled job's log error, but that loses executed cancellations and real missing evidence.
Choose a narrow metadata partition before log acquisition, mixed-run failure evidence, and at most the existing ISS-223 two whole-observation retries for the all-never-executed case, followed by a non-parking stop.
Accept that an unchanged completed cancelled run normally exhausts those reads and needs separately authorized host action rather than an automatic rerun.
This choice is wrong if the real API shape cannot prove the partition at consumption time, if recovery cannot preserve the stopped publication and accounting, or if a smaller existing path satisfies all these constraints.
