## Why

This is the M1 exit evidence. Source changes and fixtures prove nothing about
unattended operation; three real consecutive issues do.

## Done when

- One `supervise` invocation with one `loop.json` lands three consecutive
  `ready` issues on this repository as merged PRs with green three-OS CI.
- No per-item host script, hand-edited state file or manual `gh` call is used
  between the first launch and the third merge.
- At least one cycle exercised an automatic retry (ISS-103) and at least one
  restart of the supervisor resumed the current item without a duplicate
  worker, PR or merge.
- The run records (state directories, worker identities, PR numbers, spend as
  reported by the CLI) are retained outside the checkout and linked from this
  issue.

## Out of scope

Any new capability. If a cycle stops, the learning note becomes a new `ready`
issue and this one waits.
