## Context and evidence

Generic adapter contracts cannot make the platform repository self-hosting. N0
needs released, concrete policy for its own frontier, workspaces, GitHub/CI
observations and mutations, certification, and the bounded N1 change.
`ISS-049` through `ISS-052` supply the consumer-tested generic allocation,
mutation, recovery/reclaim, and release-observation hooks; this issue may not
recreate or bypass them inside the concrete adapter.

## Scope fence

In: fill the predeclared `@orchestration-platform/adapter-self` package; exact
project configuration; frontier and readiness policy; Git workspace lifecycle;
GitHub branch/commit/pull-request and Actions read/dispatch plans; certification
facts; role/capability references; the production host-custody boundary from
`ISS-038`; recovery; and sanitized self-host fixtures.

Out: generic engine policy, bootstrap N0 authorization/install, external
consumer policy, broad autonomous backlog selection, direct secret storage, or
making a candidate its own reviewer/promoter.

## Decisions already made

The first self-host frontier contains exactly one operator-created work record
with the closed GitHub issue/label/body representation in
`docs/architecture/self-host-github-contract.md`, bound to the frozen N0 source and the
declared `modules/health-summary/` N1 outcome. The adapter admits only installed
N0 bytes, the exact default branch/repository numeric identity, a clean
adapter-created workspace, and these credential capabilities:
`code-host.read`, `code-host.branch-pr-write`, `code-host.merge`, `ci.read`, `ci.dispatch`,
`artifact.read`, and `artifact.write`. Implementation and review use distinct
Codex-home references; only stable N0 receives release-promotion authority.

All GitHub/CI facts and exact lifecycle operations are limited to the passed
`ISS-036` matrix and freshly observed with complete pagination immediately
before planning, branch/PR mutation, certification dispatch, review reduction,
and promotion. Candidate code may supply test bytes but cannot choose the suite,
aggregate certification, review itself, or call promotion.

## Acceptance criteria and evidence

1. The exact configuration binds repository/project numeric IDs, default branch,
   installed N0 digest, adapter digest, state root, workspace parent, module and
   credential-reference identities. Missing, symbolic, moved, or source-tree
   values refuse. Evidence: configuration/provenance matrix.
2. From the one bounded work record, the adapter emits one complete dispatch
   brief and creates/reclaims one isolated workspace without policy entering the
   engine. Evidence: frontier-to-brief-to-resource transcript and crash matrix.
3. GitHub/CI read and mutation plans are dry-run/plan-digest guarded, reobserve
   authority immediately before apply, and use only the closed capabilities.
   Evidence: paginated raw/normalized fixtures plus stale/moved/extra-capability
   canaries for branch, PR, checks, certification dispatch, and artifacts.
4. `worker-result-subject/v1` and its accepted review authorize only publication
   and merge of the identical tree. After merge, the adapter freshly observes
   landed SHA/tree, assembles/certifies a distinct
   `release-candidate-subject/v1`, obtains a distinct candidate-kind review, and
   supplies only that unchanged accepted candidate to promotion. Wrong-kind or
   reused review, moved landed tree/head, candidate-authored aggregation, or
   one-byte candidate/artifact change refuses. Evidence: five-cycle subject-flow
   census and cross-kind/reuse mutation matrix.
5. `@orchestration-platform/adapter-self` fills only `adapters/self/` and its
   predeclared `.`/`./workspace`/`./code-host`/`./certification`/
   `./bootstrap-canaries`/`./broker-operations` exports; filter,
   export, vocabulary-boundary, and clean-install censuses pass without a root
   manifest edit.
6. `./bootstrap-canaries` exports exactly the three GitHub descriptors in the
   broker-client manifest, using only the passed `ISS-036` endpoints/permissions
   and emitting non-secret read proofs. Evidence: descriptor/implementation
   digest census plus runtime-registration, alternate-endpoint, write-attempt,
   extra/missing row, and token-output refusals.
7. `adapters/self/build/composition.ts` is the sole installed self-host runtime
   composition entrypoint. Through the predeclared build-only alias it emits one
   closed bundle wiring engine, release, host custody, Codex host, self adapter,
   broker, the frozen registry containing exactly the four baseline module
   entrypoints from `modules/manifest.json`, and only manifest-listed narrowed
   clients. The embedded registry and module digests must equal the installed
   release manifest before session start. Evidence: bundle/
   method/manifest census plus alternate entrypoint, dynamic registration,
   missing/moved/unlisted/dynamic/candidate module, runtime deep-import, cross-
   client, source-map, and tarball leakage mutants.
8. The root build invokes only the `ISS-011` registry generator before the
   self-host target and consumes its exact generated static-import file; adapter
   code contains no hand-written module list. Baseline output has four literal
   imports. Generator bypass, stale/edited output, alternate generator, or an
   esbuild module-resolver plugin refuses before bundle write.
9. `./broker-operations` exports exactly the seven GitHub operation descriptors
   and implementations in `broker-operation-manifest/v1`; each uses the passed
   `ISS-036` endpoint/pagination/timing contract and returns only its typed
   redacted fact or mutation receipt. Evidence: descriptor/implementation digest
   census plus arbitrary endpoint/callback, token echo, extra method, widened
   capability, stale observation, and cross-operation refusals.
