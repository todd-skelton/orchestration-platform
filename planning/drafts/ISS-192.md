## Why

Run `m2-catalog-identity-20260919`, executor `601f79d`, delivered cs-3779:1
(chase-sets#3779, milestone 165 Catalog identity) from base
`c71968a91eabf9d3e07d496e1ded97c7e1821d63`. The native author
(claude-fable-5-1/high) returned PASS and the independent native reviewer
(claude-opus-5/high) returned PASS at exact head
`37deac76b94f153e787e4d992656f06d30a3b4e2`, 49 files. The first local gate
`verify:static:scoped` then failed and the supervisor stopped the run blocked
`gate-attribution-unknown:verify:static:scoped`: no gate-correction author ran
and no base control ran. Two proven PASS verdicts and a one-line mechanical
defect ended the loop with no author given a chance to repair it.

The candidate failure is a generated-artifact staleness check. Retained
`candidate.log:1422-1436` shows `check:design-system-component-index` emitting
`Error: packages/design-system/COMPONENT_INDEX.md is stale`, and the retained
regeneration diff is one table row: `StatusReasonList`'s recorded consumer moved
to `create-items-stage.tsx`. The committed file named by the diagnostic is
exactly the file the candidate had to regenerate and did not.

At unchanged `601f79d`, `delivery-adapter.ts:52-84` recognizes only `typecheck`
TS diagnostics, `format:check` style output and completed `test` assertions;
every other gate name falls through to `return []`. A read-only probe over the
retained candidate log against that unchanged source returns `[]` for all four
gate names, and the unknown guard at :56 does not fire on it. Retained
`gate-1-failure.json` independently records `diagnostics: []` and
`cause: "unknown"`. So `delivery.ts:234-243` types the stop
`gate-attribution-unknown`, and `queue.ts:3382` refuses to call `attributeGate`
because `failure.cause !== "diagnostic"`. Nothing about the base control,
timeouts or resources was implicated: the sole missing piece is that the scoped
static gate has no recognizer. ISS-156 recorded this carve-out explicitly
(`gateDiagnostics('test', retainedFullLog)` returns `[]`; "diagnostic parser
repair" declared a non-goal). This intake fills that one recorded gap and
changes no historical verdict, charge or stop.

## Decision

Quality profile: core-library.

Constraint: a gate failure whose complete output names committed candidate files
must reach the existing base control, and only then may it reach the existing
single gate-correction author. Chosen smallest shape: add one recognizer branch
for the Chase Sets scoped static gate covering, at minimum, the
`<repo-relative path> is stale` and `<repo-relative path> is missing` shapes
thrown by the `generate-*.mjs --check` family, so the existing committed-file
tie-in (`git cat-file -e <head>:<path>`, `delivery-adapter.ts:890-909`) yields
`cause: "diagnostic"`, the existing `attributeGate` base control runs, and
base-pass with candidate-fail yields `candidate`, and the existing DELTA
correction path proceeds unchanged. No new stop reason, no new schema, no new
correction mechanism, no timeout, worker, skip or gate-subset change.

Two fail-closed constraints are part of the shape, not refinements deferred to
implementation. First, recognition must account for the entire nonzero exit, as
the existing complete-assertion rule does: one unparsed failing check, runner
section or unrecognized tail anywhere in the output keeps the failure unknown,
and each recognized diagnostic must begin with a repo-relative path that the
existing tie-in can resolve at the candidate head, so an `is missing` diagnostic
for a file that was never committed stays unknown through the mechanism already
present rather than through a new special case.

Second, `verify-static-scoped.mjs` derives its own scope from
`git merge-base refs/remotes/origin/main HEAD` (:121) and returns an empty
selection with `"empty derived diff"` when nothing changed (:200). A base
control in a detached worktree at the delivery base can therefore pass
vacuously, without ever running the failing check. Attribution to `candidate`
must require positive evidence that the same failing check actually executed and
passed at base; absent that evidence the attempt stays unknown. This is the
`aggregate-failure-dismissed-as-environmental-without-a-discriminating-control`
class inverted: a base control that discriminates nothing must not be read as a
discriminating control.

Recovery path for the stopped cs-3779:1, decided from the code rather than
assumed: the stop stays history and recovery is a fresh attempt on a fresh run.
ISS-157's `gateStopAuthorization` cannot be satisfied here. `queue.ts:3221`
resolves the grant's `repairSha` with `native.git(delivery.worktree, ...)`, the
product worktree, and `queue.ts:3232` demands `main !== base && repairPresent`,
so the repair must be landed in chase-sets main and absent from the stopped head
and base (`docs/loop.md:789`). An orchestration-platform executor repair can
never satisfy that; the refusal is `gate-stop-repair-not-applicable`, correctly.
`supervision.ts:976-996` additionally binds a grant to the same run and an
attempt in `phase === "delivery"`. A same-run restart is equally unavailable:
`queue.ts:916-922` advances to attempt N+1 only when the retained attempt record
is `phase === "failed"`, so a restart resumes attempt 1 and replays the inert
retained stop (`queue.ts:3011-3023`; `docs/loop.md:260`, "`gate-stop.json`
retains a terminal gate stop; replay cannot bypass it by moving main"). Because
host and unknown stops do not park the issue (`docs/loop.md:228-230`),
chase-sets#3779 remains selectable: after this executor lands and is installed
by its own host decision, a fresh run re-selects it and authors it as that run's
attempt 1. `queue.ts:726-741` does not refuse that lineage.

G0: widening `gateStopAuthorization` to admit executor-side repairs is larger,
weakens the one control that proves a stop's cause was actually fixed in the
repository the gate ran against, and buys only the replay of a single historical
attempt that a fresh attempt reproduces at lower risk. Recognizing arbitrary
`Error:` lines is larger and admits host and environment failures as candidate
diagnostics. Removing the `cause !== "diagnostic"` precondition at
`queue.ts:3382` would run base controls for timeouts and resource failures, the
exact class ISS-152 deliberately excluded. Accepted cost: generated-artifact
staleness in gates other than Chase Sets scoped static stays unknown until a
separate intake names them.

## Done when

- **Recognized staleness diagnostics.** Through public `gateDiagnostics`, a
  `verify:static:scoped` failure whose output is wholly accounted for by
  `<repo-relative path> is stale` and `<repo-relative path> is missing` lines
  from the `generate-*.mjs --check` family returns those lines as diagnostics,
  each beginning with the repo-relative path. The retained cs-3779:1 candidate
  log shape (`Error: packages/design-system/COMPONENT_INDEX.md is stale`) is
  recognized. ANSI stripping, the existing unknown guard for timeouts and fatal
  runner errors, and the existing `typecheck`, `format:check` and `test`
  branches keep their current behaviour unchanged.
- **Committed tie-in reaches the base control.** With that recognition, the
  existing per-diagnostic `git cat-file -e <head>:<path>` tie-in
  (`delivery-adapter.ts:880-925`) resolves the named committed file and yields
  `cause: "diagnostic"`, so `queue.ts:3382` no longer short-circuits and the
  existing `attributeGate` runs with its existing preconditions unchanged:
  `evidence.head === config.candidateHead`, and base and candidate
  `package.json` and `pnpm-lock.yaml` equality. A diagnostic naming a path
  absent from the candidate head keeps the failure unknown; no path guessing,
  fuzzy matching or working-tree read is added.
- **Non-vacuous base control.** Attribution returns `candidate` only with
  evidence that the same failing check executed at base and passed. A base
  control whose scoped run selected nothing (`verify-static-scoped.mjs:200`
  `"empty derived diff"`, or the failing link reported `[SKIPPED-BY-SCOPE]`) is
  not evidence of a passing base and keeps the attempt unknown. Base-fail keeps
  the existing `base` attribution and `gate-base-failed:<gate>` stop; a base
  control that cannot install or run keeps the existing non-parking
  `gate-host-failed:<gate>` stop. Guard against
  `aggregate-failure-dismissed-as-environmental-without-a-discriminating-control`
  and `missing-fail-closed-regression-evidence`: no attribution without a
  control that could have come out the other way.
- **Retained unknown cases unchanged.** Mixed causes, any unparsed failing check
  or unrecognized tail in the same output, timeouts, resource failures,
  unsupported gates and empty diagnostics continue to stop as
  `gate-attribution-unknown:<gate>` without parking the issue
  (`docs/loop.md:228-230`). No timeout is raised, no test is skipped, no gate is
  subsetted, no local gate list changes, and the single-correction and DELTA
  allowance and correction ceiling from ISS-152 are not widened.
- **Stopped cs-3779:1 recovery is a fresh attempt, not a replay.** No change to
  `gateStopAuthorization`, its `repairSha` resolution against the product
  worktree, its `gate-stop-head-mismatch`, `gate-stop-repair-not-applicable`,
  `gate-stop-not-delivery` and `gate-stop-authorization-mismatch` refusals, the
  single `gate-stop-continuation.json` reservation, or the retained
  `gate-stop.json` replay at `queue.ts:3011-3023`. The stopped attempt stays
  history; chase-sets#3779 is re-selected by a later ordinary run as that run's
  attempt 1 under a separately granted install. Retained refusal controls for a
  grant naming an executor-side repair must still refuse.
- **Owning regressions.** Add focused tests to the existing
  `test/dogfood/delivery-adapter.test.ts`: synthetic recognized-output fixtures
  for stale and missing generated artifacts across more than one
  `generate-*.mjs` producer; unrecognized-output fixtures (an additional failing
  check, an unparsed tail, a timeout, a resource failure, an uncommitted path)
  proving each stays unknown; a real base-control case through the existing
  parameterized `attributeGate` fixture proving base-pass with candidate-fail
  yields `candidate` while a vacuous base selection does not; and the existing
  `typecheck`, `format:check` and `test` cases unchanged. Extend the directly
  owning `test/dogfood/delivery.test.ts` lifecycle fixture to prove the
  recognized failure reaches exactly one gate-correction author with the DELTA
  review allowance, and that the retained unknown cases still stop without
  parking. Reverting the recognizer must fail the recognition regressions;
  deleting the non-vacuous base evidence must fail its control. Every fixture
  identity is unmistakably synthetic, never a modified real ID.
- **Qualification and delivery.** Run the complete owning tests and all four
  ordinary local gates, `pnpm typecheck`, `pnpm format:check`,
  `pnpm planning:check` and `pnpm test`, plus independent exact-head review and
  final-head Ubuntu, Windows and macOS `bootstrap`, then normal publication and
  merge. Workers, timeouts, skips and assertions stay unchanged. Update only the
  short attribution rule in `docs/loop.md:219-230` to name recognized
  generated-artifact staleness and the non-vacuous base-control requirement; no
  other process document. Implementation is loop-owned, not a host patch. This
  issue grants no installation, restart, or recovery of the stopped run.

## Don't rebuild

ISS-152 owns gate attribution and the single gate-correction author with its
DELTA allowance; this issue adds one recognizer inside that mechanism and widens
neither the correction ceiling nor the allowance. ISS-156 owns the attribution
fixture and explicitly carved out diagnostic parser repair; this issue fills
exactly that recorded carve-out for one gate and does not re-author the fixture.
ISS-157 owns saved gate-stop recovery and `gateStopAuthorization`; this issue
changes none of it and adds no grant path. ISS-185 owns hosted current-run, job
and failure-log attribution, a different boundary from local gate attribution.
ISS-188 owns hosted lifecycle-versus-identity comparison. ISS-108 owns the Chase
Sets adapter's local gate list and ISS-131 owns worker-prompt gate timing;
neither is reopened. Preserve their accepted bodies, candidates and history.

Overlapping defect classes this intake must not reintroduce:
`missing-fail-closed-regression-evidence`, meaning recognition without a control
that can refuse;
`aggregate-failure-dismissed-as-environmental-without-a-discriminating-control`,
meaning the vacuous base control; `stale-review-bound-to-wrong-head` and
`mutable-reference-breaks-candidate-identity`, meaning the existing
`evidence.head === config.candidateHead` and manifest-equality preconditions
stay; and `retained-artifact-schema-ratchet`, meaning no change to retained
`gate-*-failure.json`, `gate-stop.json` or attempt-record shapes.
