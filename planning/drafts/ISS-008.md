## Context and evidence

The controller must assign bounded work without two sessions claiming the same
worker or opaque workspace subject. Project repository and workspace facts come
only through `ISS-013`; see process identity from `ISS-005`, session authority
from `ISS-007`, and the worker states in
`docs/architecture/state-machines.md`.

## Scope fence

In: dispatch plan over opaque adapter identities and preflight results,
ownership publication, startup liveness, occupancy reduction, terminal release,
role-specific capability fences, and ownership-scoped resource reclamation.

Out: project work selection, AI-provider SDKs, review semantics, and remote
workers.

## Decisions already made

The adapter must return an eligible preflight immediately before ownership.
Ownership binds exact session, launch, opaque workspace/subject, role, and
process identity. The engine never interprets Git, branch, or cleanliness facts.
Unknown ownership blocks capacity. The dispatch plan digest-binds the
deterministically rendered `dispatch-brief/v1` bytes.

## Acceptance criteria and evidence

1. An ineligible, multiply-owned, moved-subject, or identity-inconsistent
   adapter preflight refuses before launch. Evidence: two distinct fixture
   adapters—including one without Git concepts—assert no process or record.
2. Only exact owner exit produces vacancy. Evidence: lifecycle tests covering
   dead launcher/live child, moved revision, duplicate launch identity, and
   `TERMINATION_FAILED_LIVE`; the latter retains ownership and blocks capacity
   until exact exit is observed.
3. Role capability fences prevent review workers from mutation credentials and
   implementation workers from promotion authority. Evidence: environment and
   filesystem canary tests.
4. Every terminal path produces one canonical terminal observation. Evidence:
   event-count and idempotency tests.
5. `@orchestration-platform/dispatch` replaces only the static `worker`
   command-family placeholder. Evidence: registry census and command-envelope
   tests for dispatch, inspect, and terminate.
6. Missing, malformed, or unknown role refuses before ownership/launch; only an
   explicit `implementation` role can receive mutation capabilities. Evidence:
   omission/enum/capability-canary tests for all roles.
7. Exit, launch failure, forced termination, and restart retain capacity until
   adapter and host resources reach `RECLAIMED`; live, reused, concurrent, or
   malformed identity refuses reclaim. Evidence: full resource transition and
   day-after eligibility matrix.
8. The dispatch plan and launch identity digest-bind the host-rendered
   `dispatch-brief/v1` bytes and the executing host-renderer artifact digest;
   step 7 first proves that artifact equals the installed active-release
   manifest value. A mutated rendered brief, stale or candidate host artifact,
   self-reported digest, or moved template refuses launch. Evidence: binding
   mutants against both fixture adapters.
