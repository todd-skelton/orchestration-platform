## Why

The Chase Sets product orchestrator is replacing milestone ownership of the platform pilot with per-issue handoff. It adds the Chase Sets label `dispatch:platform` to an individual low-priority issue for this loop. To take an issue back it adds `dispatch:platform-return` and removes `dispatch:platform`, then touches nothing until the holder posts a release marker and removes `dispatch:platform-return`. Today the Chase Sets adapter selects from one milestone pull window (`targetMilestone`, ISS-135), has no label selector, does not recheck eligibility for in-flight non-ops work, exits when nothing is runnable, and never dequeues, so a return request would have no effect and a queued PR could still merge.

## Decision

The constraint is that the product loop must be able to take an issue back at any time without either loop landing duplicate work or waiting without bound. The simplest viable alternative is a label filter at selection only, which leaves in-flight work publishing and enqueueing after a return request. This issue chooses a selection filter plus an eligibility re-read at every effect checkpoint, a release that removes this loop's PR from the merge queue and records durable completion, and an explicit acknowledgment posted only after a fresh read confirms no effect can follow. The downside accepted is that a worker already running finishes and its output is discarded, because the worker adapter has no cancellation. A platform PR merging after an acknowledgment, or a return request that is never acknowledged while the supervisor is live, would show the choice was wrong.

## Done when

- `LoopConfig` accepts `handoff: {"label": string, "returnLabel": string}` with exactly those non-empty keys in the exact-key validator; a config with `handoff` and `targetMilestone` or `opsAdmission` is refused. The same object reaches supervisor selection and the `status.mjs` preview. Without `handoff`, behavior is unchanged.
- With `handoff`, `authority()` reads open issues in every open committed milestone instead of one pull window, and the runnable set is issues carrying `label` and not `returnLabel` that pass the existing refinement, `status:needs-*`, open-blocker and routing-marker rules; `kind:ops` is always excluded. Selection and preview share this predicate.
- With `handoff`, an empty runnable set keeps the supervisor live with no worker and selects again every 300 seconds instead of exiting; without `handoff`, the existing idle exit is unchanged.
- The supervisor re-reads the selected issue's labels from a complete read before launching a worker, before publication, before enqueue, at every merge-queue observation and before resuming a saved cycle. An incomplete read stops the run as a host stop with no acknowledgment. If `label` is absent or `returnLabel` is present, it releases the issue: no publication or enqueue; a running worker exits and its result is discarded; this loop's PR, if queued, is removed with `dequeuePullRequest` and re-read until a fresh read shows it out of the queue (left open) or merged; cycle completion is recorded through the existing durable completion with disposition `released` and charged history kept, so a restart never resumes it. Only then, in order: remove `label` if present; post `<!-- platform-released: {"version":1,"by":"platform","outcome":"released"} -->` (`"merged"` if the PR merged) with the PR link and attempts used; remove `returnLabel`. Then continue with the next candidate.
- At each selection pass, an issue carrying `returnLabel` whose cycle in this run is already complete (parked, released or delivered) is acknowledged in the same order without further work.
- Integration tests through the supervisor and the status entry cover selection across milestones and with no key, preview agreement, the refused combinations, an empty pool that later admits an issue, delivers it, empties and admits another without restart, release at each checkpoint (including a return request while the author runs and while the PR is queued), the merged-first outcome, acknowledgment of a parked issue, an incomplete label read, and a restart after release.
