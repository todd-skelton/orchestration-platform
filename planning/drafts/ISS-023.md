## Question

Can a pinned supported OpenAI Codex CLI version provide the exact executable,
requested/reported model, launch, terminal, process-tree, and per-role credential
isolation evidence required for an authority-bearing worker-host adapter on
macOS, Windows, and Linux?

## Pinned probe subject

The initial probe subject is npm artifact `@openai/codex@0.144.4`, installed as
`npm install --global @openai/codex@0.144.4`. The registry artifact identity is:

- tarball: `https://registry.npmjs.org/@openai/codex/-/codex-0.144.4.tgz`;
- SRI: `sha512-DTHzYatlKq9dw55E0/HsbK4tRCEKabuJ10ybbqpsG8gVv/kvwEdg3Z4OI3cvLXKa21xkIa4lkGlZoO/HmqmFFw==`;
- SHA-1: `8df4fe6cd2be440eaa349cb85ab4da06d0b031b1`.

Each target also records the resolved launcher and platform-native executable
hash; package identity alone is insufficient. This exact version was observed
locally on Windows during planning, but that observation is discovery evidence,
not a target-OS pass.

The requested model selector is exactly `gpt-5.6-luna`, as documented in the
[official OpenAI model page](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
and observed on 2026-08-15. The selector is intentionally not treated as an
immutable snapshot. The provider identity schema from `ISS-012` is the authority contract
for distinguishing selector, alias movement, and provider-resolved version.

## Probe method and lifecycle timing

Fixture tree bytes, prompts, environment maps, and effective-input admission are
fixed in `docs/architecture/codex-probe-fixture.md`; the probe may not invent or
weaken them. The closed raw tool/schema/capability surface is fixed in
`docs/architecture/codex-tool-manifest.md`.

Using the trusted OS harness, launch native argv arrays without a shell. Each
run uses a fresh initialized synthetic Git repository with a recorded tree
digest, closed stdin, a 15-minute outer timeout, isolated role-specific
`CODEX_HOME`, no inherited secret except the role's bounded authentication
capability, and this exact common argv prefix:

```text
["<resolved-codex-executable>","--model","gpt-5.6-luna","--config","shell_environment_policy.inherit=\"none\"","--ask-for-approval","never","exec","--json","--ephemeral","--ignore-user-config","--ignore-rules","--strict-config","--cd","<absolute-synthetic-workspace>"]
```

The role matrix appends exactly:

| Role | Additional argv items, in order | Exact final prompt argv item |
|---|---|---|
| implementation | `["--sandbox","workspace-write"]` | exact implementation prompt from the fixture contract |
| review | `["--sandbox","read-only"]` | exact adversarial review prompt from the fixture contract |
| observer | `["--sandbox","read-only"]` | exact adversarial observer prompt from the fixture contract |

The launcher passes the prompt as one literal final argv item; angle-bracketed
workspace is replaced only with the fixture's recorded absolute path. No
profile, add-dir, web-search, bypass, OSS/local-provider, or implicit approval
option is permitted. Capture executable hash/version before launch, startup
events before accepting liveness, reported model identity before accepting work,
process-tree observations while live/terminating, and terminal events after
exit. Probe absence, minimum-version refusal, alias/mismatch, stalled startup,
forced termination, author/reviewer environment crossover, and moved subject.
Negative fixtures remove the prompt, each isolation flag, or the clean
role-specific home; mutate each effective-input source enumerated by the fixture
contract; alter sandbox/approval; and verify pre-launch or canary refusal as
applicable. Against the exact backend/custody/IPC artifact selected by `ISS-031`,
on every OS and role execute every denied-capability canary in the
fixture contract: network, parent/sibling access, privilege, approval, write,
filesystem credential crossover, direct native-store extraction, and
interpreter/profile escape. The direct native-store extraction canary reruns
the ISS-031-owned shared byte-hashed native-store attack suite against each
worker role rather than restating its per-OS API list. Enforcement—not
cooperative wording or incidental unavailability—must produce an explicit
refusal and unchanged external census.
For cross-principal custody, also execute the selected endpoint-discovery,
handle-duplication, process-impersonation, replay, copied-executable, and wrong-
principal controls; a different synthetic topology cannot satisfy this gate.

The launcher resolves and hashes the executable before constructing argv; it
does not use `PATH` lookup at child creation. The Codex process environment is
an allowlist: role-specific `CODEX_HOME`; a fixture-only `HOME`/`USERPROFILE`;
an empty fixture temp root through `TMPDIR` on macOS/Linux or `TEMP` and `TMP`
plus required `SystemRoot` on Windows; and locale/terminal values fixed by the
harness. Authentication is installed only inside that role's isolated
`CODEX_HOME`; no API token environment variable is inherited. The exact final
key/value-name census (values redacted and path-normalized) is part of each OS
receipt, and extra keys fail preflight.

The requested selector is proven by the argument manifest. The initial accepted
JSONL surface is a startup event, before the first work item, whose `$.model`
reports the selector and whose `$.model_snapshot` reports a provider-
authenticated immutable version. Missing/mismatched fields, selector equality
without `$.model_snapshot`, or a value supplied only by prompt/config is a
failed exact-identity capability—not something normalization may synthesize. A
separately trustworthy provider-authenticated surface may replace
`$.model_snapshot` only through the bounded decision path below.

## Required durable evidence

Publish scrubbed raw JSONL/event fixtures, exact command/argument manifests,
prompt/workspace digests, environment allowlists, process receipts,
credential-canary results,
and one normalized capability receipt per exact OS image and CLI version. Bind
all evidence to probe source and test-bundle digests.
Include exact raw tool names, canonical schema bytes/digests, enforcement
capabilities, and one refusal mutant for added, removed, renamed, schema-expanded,
or authority-expanded tools.
Include the exact internal command-interpreter invocation/digest, the
ISS-031-owned shared attack-suite fixture identity and argv, and one
successful absolute-verifier execution without `PATH`, plus a distinct refusal
receipt for every denied capability on every role and OS.

## Disposition rule

- If every required identity and isolation property is proven on all targets,
  `ISS-021` implements that exact contract and minimum CLI version.
- If the CLI provides identity only through a separately trustworthy local
  surface, file one bounded adapter-authority decision/probe before `ISS-021`.
- If exact reported identity, filesystem and native-store credential isolation,
  or process lifecycle cannot be proven on any required OS, return
  `BLOCK_REPLAN` and select a different first host, a separately confined
  broker/worker-principal topology, or narrow the self-hosting authority claim.
  Prompt text, private exports, or aliases cannot emulate missing authority.
