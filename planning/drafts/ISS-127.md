## Why

On 2026-09-12 the ISS-126 author had executed 66 commands when the model
provider returned a 503 mid-turn (the local pool's upstream TLS handshake
timed out). Codex exited non-zero, `observe` in
`scripts/dogfood/dispatch-adapter.ts` raised `launcher-failed`, and the loop
parked the issue after one attempt with the whole author turn lost. Earlier
the same day two ISS-122 launches died the same way on a revoked token.

Rule 5 gives transient failures one automatic retry inside the attempt, and
`scripts/dogfood/flow.ts` already has that path for an unparsable reviewer
verdict (`retries === 1`). A dead worker process is the same class of
failure and has no retry. A restart does not help either: `flow.ts` reads the
recorded `<role>-attempt` whose exit receipt is non-zero and raises
`launcher-failed` again without launching, so the only recovery is a person
deleting the attempt directory by hand, which happened twice today.

## Done when

- A launch whose exit receipt is non-zero, or whose trace ends in
  `turn.failed` with no terminal report, is a dead launch. The role's
  iteration in `flow.ts` relaunches once with the same prompt, the same
  worktree state, and `retries: 1`, exactly as the reviewer retry does. The
  relaunch counts one native launch against `nativeLaunchCeiling`.
- A second dead launch in the same role and attempt is the typed stop
  `launcher-failed`, carrying the last error message from the trace as
  diagnostics.
- On restart, a recorded attempt with a dead launch is treated as the first
  dead launch: the loop relaunches once instead of raising `launcher-failed`
  from the old receipt. No attempt directory needs deleting by hand.
- The author relaunch starts from the exact base with a clean worktree: any
  uncommitted edits the dead author left are discarded before relaunch and
  the discard is recorded in the attempt directory.
- `test/dogfood/flow.test.ts` proves with a fake adapter: one dead author
  launch then success lands normally with `retries: 1`; two dead launches
  stop with `launcher-failed` and the trace message; a restart over a
  recorded dead launch relaunches once.

## Out of scope

Retrying inside Codex. Provider fallback tables. Changing the attempt
ceiling.
