## Why

The ISS-108 dry run against the live repository on 2026-09-12 selected
milestone #148 and issue #7926, a `priority:p0` `kind:ops` "[controller]"
issue, which is the incumbent controller's own runtime. The same runnable set
holds #7924 and #7925 labeled `status:needs-operator` and #7907 labeled
`status:needs-replan`. The product readers in `scripts/backlog-classify.mjs`
only require open, classified, unblocked and an executable milestone; the
incumbent's work-selection rule adds that operator-blocked and replan issues
are never implementation candidates and that ops work is dispatched only when
a product issue is blocked on it or Todd names it.

The adapter verifies the staging deploy within ten minutes, but the last four
`platform-production.yml` runs on 2026-09-11 and 2026-09-12 took 17, 24, 26
and 20 minutes. Every landing would stop with `deploy-not-verified` after the
PR had already merged.

The worker rules for Chase Sets are the three-line product `AGENTS.md`. The
incumbent's lanes run the product delivery skill in lane mode: a green ready
PR plus a completion report, scoped checks, rebase before push, no landing.
That skill is tracked at `.agents/skills/delivery/SKILL.md` in the product
checkout. The author prompt in `scripts/dogfood/queue.ts` also says "Keep the
loop smaller", which is this repository's rule leaking into every adapter.

## Done when

- `selectCandidates` in `adapters/chase-sets.mjs` excludes an issue carrying
  any label that starts with `status:needs-` or equals `kind:ops`, after the
  product readers have accepted it. The dry run against the live repository
  no longer selects #7926.
- The deploy verification window in `adapters/chase-sets.mjs` is 45 minutes
  and the poll interval is 30 seconds. Both are pinned by a test that uses a
  fake clock and fake `gh` output, not real time.
- `issueContext` in `adapters/chase-sets.mjs` returns as `rules` the product
  `AGENTS.md`, then `.agents/skills/delivery/SKILL.md` read from the executor
  root, preceded by one paragraph stating: lane mode applies, the loop owns
  publishing, landing and deploy verification, and the worker finishes with
  the JSON report the prompt requires. A missing skill file is the typed
  error `missing-chase-sets-delivery-skill`.
- The author sentence in `scripts/dogfood/queue.ts` becomes "Implement the
  selected issue completely and stay within its scope." The self adapter
  appends "Keep the loop smaller: prefer deleting to adding." to its own
  `rules`. Searching `scripts/` for "loop smaller" finds nothing.
- `test/dogfood/chase-sets-adapter.test.ts` covers the label exclusion and
  the rules assembly with synthetic inputs.

## Out of scope

Changing the product readers or labels. Parking a stopped issue (ISS-123).
Repairing from a failed hosted check (ISS-124). Model routing per issue.
