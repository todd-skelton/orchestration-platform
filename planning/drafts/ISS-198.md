## Why

Run `m1-iss167-20260921T1457` (ISS-167, #524) discarded **two complete
reviewer runs as `malformed` even though both verdicts were fully
schema-valid**. The preserved evidence is under
`/root/orchestration-m1/runtime/m1-iss167-20260921T1457/`.

I validated all four reviewer outputs in that run against each run's own
`reviewer-*.output-schema.json`. **All four parse and satisfy every declared
constraint** - required keys, `additionalProperties`, the `head` pattern, the
`verdict` enum, and each finding's `line` minimum and `severity` enum. Zero
schema errors in all four. Two were nevertheless discarded:

| reviewer | transport | final message | payload | outcome |
| --- | --- | --- | --- | --- |
| `75f8e370` (attempt 1) | fenced ```json block | 1376 chars | valid, PASS, 1 note | **malformed** |
| `e8ae49ed` (attempt 1) | raw JSON | 1232 chars | valid, PASS, 2 notes | passed |
| `12ba7a5d` (attempt 2) | raw JSON | **2036 chars** | valid, PASS, 2 notes | **malformed** |
| `7910ff8b` (attempt 2) | raw JSON | 1577 chars | valid, PASS, 2 notes | passed |

Both processes exited `{"code":0,"signal":null}`. The discarded work was not
cheap: `75f8e370` alone consumed **4,179,552 input tokens** (4,011,430 cached)
and 36,908 output tokens before being thrown away, and the loop then relaunched
a fresh reviewer from zero.

Two distinct causes, both in the verdict transport and neither in the verdict:

1. **Fenced output is rejected.** `repair-policy.ts` `parseReview` calls
   `JSON.parse(summary)` directly with no fence handling, so a reviewer that
   wraps its schema-valid report in a ```json code block throws and becomes
   `malformed-source-review-report`. That is `75f8e370`.
2. **A 2000-character bound discards a valid verdict whole.**
   `flow.ts` computes `oversizedReviewSummary` when
   `role === "reviewer"` and `summary.length > MAX_TERMINAL_SUMMARY_LENGTH`
   (2000), forces `status = "malformed"` with
   `source-review-summary-out-of-bounds`, and `parseReview` independently
   re-applies the same bound. That is `12ba7a5d` at 2036 characters - **1.8%
   over**, discarding a PASS verdict with two substantive findings.

There is a third, compounding harm. `flow.ts` runs `delete terminal.summary`
and, on the oversized path, `summary` is `undefined`, so the summary is never
restored. The retry context is then built as
`${terminal.summary ? ` Diagnostics: ...` : ""}`, which is empty. **The
relaunched reviewer is told only that the previous report "could not be parsed"
and is given neither the reason nor the discarded content**, so it cannot avoid
repeating the shape that failed.

## Done when

- **AC1: A fenced schema-valid report is accepted.** A final reviewer message
  whose content is exactly one fenced code block containing a schema-valid
  report is parsed and produces the same `ValidatedReview` as the identical
  raw payload. Evidence: a focused `parseReview` test using the **verbatim**
  `75f8e370` message text from the preserved run, red before and green after.
- **AC2: Length alone no longer discards a valid verdict.** A schema-valid
  report of 2036 characters is accepted. The reviewer bound is either removed
  or raised to a value that admits the recorded report, and whatever bound
  remains is applied identically in `flow.ts` and `parseReview` so the two
  cannot disagree. Evidence: a focused test using the **verbatim** `12ba7a5d`
  2036-character message, red before and green after, plus an assertion that
  the two code paths share one constant.
- **AC3: A rejected verdict never loses its diagnostic.** When a reviewer
  report is refused, the recorded terminal keeps a bounded copy of the offending
  summary and the specific reason, and the retry context passed to the
  relaunched reviewer names both. Evidence: a test asserting the retry context
  for an oversized and for an unparseable report each contain the reason and a
  non-empty excerpt; the current oversized path produces neither.
- **AC4: Refusals still fail closed.** Genuinely malformed output still refuses
  with the existing reasons and no whole-body fallback: non-JSON prose, a
  truncated JSON object, a report with an unknown extra key, a bad `head`, a
  `verdict` outside the enum, a finding with `line: 0`, prose containing two
  fenced blocks, and a fenced block followed by trailing non-whitespace text.
  Evidence: table-driven negative tests, each asserting the exact reason string.
- **AC5: The loop boundary is unchanged.** Selection, routing, model ladders,
  readiness labels, attempt and retry ceilings, author-role summary semantics,
  and Chase Sets adapter behavior are untouched. No worker, issue mutation, or
  runtime migration occurs while parsing. Evidence: existing flow, queue,
  supervision and adapter suites plus a negative control that a valid selection
  with a genuinely invalid report still reaches `reviewer-malformed`.

## Out of scope

Non-goals: raising retry or attempt budgets; changing routing, models, or the
fallback ladder; accepting arbitrary prose or reconstructing a report from
free text; relaxing any schema constraint in `parseReview` beyond the transport
envelope; editing or restarting the preserved `m1-iss167-20260921T1457` runtime;
changing Chase Sets issue or review parsing; altering author-role truncation
semantics beyond retaining diagnostics.

## Decisions and operator actions

The smallest fix is at the transport envelope: strip a single well-formed fence
before parsing, and stop letting a length bound discard an otherwise valid
verdict. No unresolved decision. Operator action after reviewed, hosted-green
landing: install the reviewed executor through the canonical path and restart
M1 canonically; implementation workers do neither.

## External authority

None. The evidence is the preserved local runtime and the run's own output
schemas.

## Review packet

Full-path review should attack fence stripping (nested fences, two fenced
blocks, a fence with trailing text, a fence with no closing marker), the bound
change (that it cannot now admit an unbounded payload, and that `flow.ts` and
`parseReview` agree), diagnostic retention (that a bounded excerpt cannot
itself become an injection or unbounded-growth vector in the retry prompt), and
any accidental relaxation of a schema constraint. The omission-revealing
artifacts are the two verbatim preserved reviewer messages, which are
schema-valid today and discarded today.
