## Why

Run `m1-iss167-20260921T1457` (ISS-167, #524) discarded **two complete
reviewer runs as `malformed` even though both verdicts were fully
schema-valid**. The preserved evidence is under
`/root/orchestration-m1/runtime/m1-iss167-20260921T1457/`.

All four reviewer outputs in that run satisfy every constraint in each run's own
`reviewer-*.output-schema.json` - required keys, `additionalProperties`, the
`head` pattern, the `verdict` enum, and each finding's `line` minimum and
`severity` enum. Zero schema errors in all four. Two were still discarded:

| reviewer | transport | final message | payload | outcome |
| --- | --- | --- | --- | --- |
| `75f8e370` (attempt 1) | prose + fenced block | 1376 chars | valid, PASS, 1 note | **malformed** |
| `e8ae49ed` (attempt 1) | raw JSON | 1232 chars | valid, PASS, 2 notes | passed |
| `12ba7a5d` (attempt 2) | raw JSON | **2036 chars** | valid, PASS, 2 notes | **malformed** |
| `7910ff8b` (attempt 2) | raw JSON | 1577 chars | valid, PASS, 2 notes | passed |

Both discarded processes exited `{"code":0,"signal":null}`. `75f8e370` alone
consumed **4,179,552 input tokens** (4,011,430 cached) and 36,908 output tokens
before being thrown away, and the loop relaunched a fresh reviewer from zero.

**Both discards happen inside `scripts/dogfood/dispatch-adapter.ts`.** Running
the shipped `parseTrace` against the verbatim preserved traces reproduces both:

```
75f8e370: parseTrace THREW message="malformed-worker-verdict" diagnostics=null ctor=Error
e8ae49ed: parseTrace OK status=passed summaryLen=1232
12ba7a5d: parseTrace THREW message="malformed-worker-verdict"
          diagnostics="Reviewer verdict serialized length is 2036 characters; maximum is 2000.
                       Shorten findings and G0 to fit." ctor=QueueBlocked
```

The preserved records corroborate the site: the recorded `parseError` in both
retry contexts is `malformed-worker-verdict` (the `flow.ts` default), not
`malformed-source-review-report` and not `source-review-summary-out-of-bounds`.

The two causes:

1. **A trailing closing fence refuses an otherwise complete verdict.**
   `finalVerdict` (`dispatch-adapter.ts:330-361`) scans for the first balanced
   JSON object, then asserts
   `check(message.slice(end + 1).trim() === "", "malformed-worker-verdict")` at
   `dispatch-adapter.ts:357`. The `75f8e370` message ends with `}` then a
   closing fence, which is non-empty, so it refuses. A variant probe through the
   real `parseTrace` isolates the cause exactly:

   ```
   REJECTED  <- VERBATIM (prose + fenced block + closing fence)
   ACCEPTED  <- prose + opening fence, CLOSING FENCE REMOVED
   ACCEPTED  <- raw payload only
   ACCEPTED  <- prose + raw payload (no fence)
   REJECTED  <- fence only, no prose
   REJECTED  <- fence + trailing prose after the closing fence
   ```

   Leading prose and the **opening** fence line are already tolerated
   deliberately (`dispatch-adapter.ts:331-332`, ISS-150). The sole cause is the
   trailing closing fence.

2. **A 2000-character bound discards a valid verdict whole.**
   `dispatch-adapter.ts:465-471` applies the bound to `JSON.stringify(verdict)`
   and throws `QueueBlocked("malformed-worker-verdict", ...)`. `12ba7a5d` was
   **1.8% over** and lost a PASS verdict carrying two substantive findings.

**Five in-code literals govern this one limit and can silently drift.**
`terminal-summary.mjs:1` exports `MAX_TERMINAL_SUMMARY_LENGTH = 2000`, imported
by `dispatch-adapter.ts:10` (author bound `:461`, reviewer bound `:467`) and by
`flow.ts:5` (length branch `:584`, and the reviewer prompt text at `:261-262`).
Its hand-written declaration `terminal-summary.d.mts:1` restates the value as
the literal type `2000`, and because `tsconfig.json` includes only
`scripts/**/*.ts` and `test/**/*.ts` with no `checkJs`, nothing ever compares
the two, so the declaration can lie about the constant while typecheck, format
and the whole test suite stay green. Separately, `repair-policy.ts:1` keeps a
module-private `MAX_REVIEW_SUMMARY_LENGTH = 2_000` used at `:57`, `:74` and
`:84`, and `repair-adapter.ts:35` and `:48` each hardcode the sentence "Keep
the complete JSON report within 2000 characters". Raising one without the
others makes `parseReview` reject a payload the adapter just accepted, and
leaves the reviewer instructed to a stale number. `flow.ts:262` interpolates
the shared constant into the instruction the reviewer receives, so that half of
the prompt tracks the constant; the `sourceReviewerReportPrompt` suffix
appended at `queue.ts:2993` does not, and neither does the repair-lane prompt
at `repair-adapter.ts:39-49` reached via `reviewedRepairAdapter` at
`queue.ts:3422`. `docs/loop.md:52,62,63` restates the same 2000 figure in
contract prose.

**What is genuinely missing is an excerpt, not always a reason.** The oversized
path *does* deliver a specific reason naming the observed length and the limit
(`iss-167-attempt-2/source/reviewer-attempt.json`). The unparseable path
delivers neither reason nor excerpt, because a plain `Error` carries no
diagnostics (`iss-167-attempt-1/source/reviewer-attempt.json`). Neither path
ever shows the relaunched reviewer any of the discarded content.

**`repair-policy.ts::parseReview` and the `flow.ts` oversized branch are
currently unreachable and are not the fix.** `flow.ts:616` passes
`terminal.summary`, which the adapter always produces as either
`JSON.stringify(verdict)` (already capped at `dispatch-adapter.ts:466-471`) or
`terminalSummary(error.diagnostics)` (sliced at `terminal-summary.mjs:3-5`), so
`parseReview` never receives a raw agent message and `flow.ts:584`'s length
test is never true. `codexAdapter` is the single native adapter for the whole
queue. Those two sites are in scope only for the bound unification in AC2.

## Done when

- **AC1: A fenced schema-valid report is accepted.** A final reviewer message
  consisting of optional leading prose followed by exactly one well-formed
  fenced block whose content is a schema-valid report is accepted, and produces
  the same terminal and the same validated verdict as the identical unfenced
  payload. Evidence: a focused test driving the **verbatim** `75f8e370` message
  through the real `parseTrace` / `adapter.observe`, red before and green
  after. The test target is `parseTrace`, not `parseReview`.
- **AC2: Length alone no longer discards a valid verdict, and the bound is not
  deleted.** A single **exported** constant governs every consumer:
  `repair-policy.ts` adopts the constant exported by `terminal-summary.mjs`
  instead of its own private `MAX_REVIEW_SUMMARY_LENGTH`, and
  `repair-adapter.ts:35` and `:48` interpolate that same constant instead of
  their hardcoded `2000`, so exactly one value drives the adapter bound, the
  `flow.ts` branch, the reviewer prompt text at `flow.ts:261-262`, the
  `sourceReviewerReportPrompt` suffix appended at `queue.ts:2993`, and
  `parseReview`. Its value is raised to a stated finite number that
  admits the recorded 2036-character report with stated headroom. **Removing the
  bound is not an acceptable implementation.** A report one character above the
  new bound is still refused with the existing reason and the existing specific
  length diagnostic. Evidence: a focused test using the **verbatim** `12ba7a5d`
  2036-character message (red before, green after), a test that one character
  over the new bound still refuses, an assertion that every consumer reads the one
  exported constant, and an assertion that the length stated in the reviewer's
  own prompt moves with it, asserted over the **fully assembled** source-stage
  prompt (`flow.ts` report text plus the `queue.ts:2993` suffix) so that both
  halves move together and no stale literal survives. `terminal-summary.d.mts`
  declares the exported constant without restating its value, so the shipped
  declaration cannot drift from the implementation. Evidence also includes a
  mechanical assertion that no occurrence of the superseded literal value
  remains under `scripts/` or `docs/`, including `.d.mts` declarations, so the
  enumeration in Why cannot silently go stale again.
- **AC3: A rejected verdict carries a bounded excerpt of what was discarded.**
  Red-before, stated per case: the oversized path delivers a specific reason but
  **no excerpt**; the unparseable path delivers **neither**. After the change
  both paths deliver the reason plus a bounded excerpt of the offending message
  in the retry context. The existing specific length diagnostic is preserved
  verbatim and is not replaced by a generic excerpt. Any excerpt entering a
  retry prompt is itself capped at a stated finite length. Evidence: tests
  asserting the retry context for each case, citing both preserved
  `reviewer-attempt.json` files as the red-before.
- **AC4: Refusals still fail closed, and today's accepted shapes still pass.**
  Negative controls, each asserting the exact reason string: non-JSON prose, a
  truncated JSON object, an unknown extra key, a bad `head`, a `verdict`
  outside the enum, a finding with `line: 0`, two fenced blocks, and a fenced
  block followed by trailing non-whitespace text. Positive controls that must
  keep passing: raw payload only, and **leading prose followed by raw JSON with
  no fence** (accepted today, and exactly what a naive fence-stripping change
  would regress).
- **AC5: Verdict admission stays fail-closed in both directions.** A verdict
  failing any schema constraint still yields a refusal - no malformed verdict is
  ever admitted as PASS - and no valid verdict shape is now universally refused.
  Evidence: the AC4 tables executed through the real adapter, plus a negative
  control that a valid selection with a genuinely invalid report still reaches
  `reviewer-malformed`.
- **AC6: The loop boundary is unchanged.** Selection, routing, model ladders,
  readiness labels, attempt and retry ceilings, and author-role summary
  semantics are untouched. `adapters/chase-sets.mjs` is not modified;
  `codexAdapter` in `dispatch-adapter.ts` **is** in scope and its behaviour for
  the Chase Sets routing row must be preserved unchanged. No worker, issue
  mutation, or runtime migration occurs while parsing. Evidence: existing flow,
  queue, supervision and adapter suites.

## Review packet

This slice modifies the loop's own verdict-admission path, so the two failure
directions are admitting a malformed verdict as PASS (an unreviewed candidate
proceeds) and refusing every verdict (deadlock); AC5 exists for exactly that.
Full-path review should attack closing-fence handling (nested fences, two fenced
blocks, a fence with trailing text, a fence with no closing marker), the bound
change (that it cannot admit an unbounded payload, that findings count is
bounded, and that all three sites read one constant), excerpt retention (that a
bounded excerpt cannot become an injection or unbounded-growth vector in the
retry prompt), and any regression of the ISS-150 leading-prose tolerance. The
omission-revealing artifacts are the two verbatim preserved reviewer messages,
which are schema-valid today and discarded today.
