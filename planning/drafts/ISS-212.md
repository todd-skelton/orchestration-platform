## Decision

The first deliverable is a bounded discriminator, not a repair. Reconcile the
retained logs and available per-test JSON first, then add test-only,
deterministic phase/process/Git timing capture for the two named cases so an
authorized host diagnostic can answer where time is spent without changing
their behavior. The current evidence cannot distinguish runner variation,
common real-Git cost, file order/reporting, or a sharding-specific effect.
Do not edit production behavior or the tests to make them faster on a guess.

The written conclusion must choose a supported narrow remedy for a **new,
separately reviewed** scope, or a no-edit negative result with the missing
discriminator and one explicit follow-up decision. Inconclusive evidence is a
legitimate terminal result for this intake, not permission for repeated runs.
A confirmed coverage, aggregate, security or required-diagnostic defect goes
straight to prompt M1 containment and repair-versus-revert planning; a latency
miss alone does not automatically revert the landed ISS-210 change. No
timeout increase, skip, retry policy, fixture split, runner increase, gate
waiver or speculative product/test optimization is authorized.
