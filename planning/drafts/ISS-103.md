## Why

A failed typecheck or format gate, an unparsable reviewer report, or a worker
whose exit receipt arrives late each stop the queue today and need an external
recovery authority file, a new state directory and one or two more native
launches. ISS-087 consumed twelve launches this way. These are transient and
deserve one retry inside the same attempt.

## Done when

- Gate failure: when `typecheck` or `format:check` fails in
  `scripts/dogfood/delivery.ts`, the loop dispatches one corrective author on
  the same branch with the gate output, re-runs the gates once, and only then
  stops. The `gate-N-intent` record carries an attempt counter instead of being
  write-once.
- Unparsable verdict: when `flow.ts` observes a `malformed` reviewer terminal,
  it reprompts the same reviewer configuration once with the parse error.
  `review-recovery-adapter.ts`, `review-policy.ts`, the
  `dogfood-review-recovery-authority/v1` input and the
  `dogfood-source-review-binding/v1` record are deleted.
- Delayed exit: a worker whose process is gone but whose exit receipt is
  missing stays in a bounded observing state (existing `observe-process.mjs`
  receipt path) for a configured window before the loop treats it as failed;
  no per-attempt host script is needed.
- Every retry is recorded in the run state with the reason; a second failure
  stops with a typed reason and a learning note.
- Tests cover each of the three paths with fake attempts.

## Out of scope

Retrying a genuine FAIL review beyond the existing four-attempt ceiling.
Hosted CI failure repair; that stays a new attempt on the same PR.
