## Why

ISS-101 tells the author to run typecheck, format and tests before handoff,
but two learning notes on #358 show the author sandbox cannot. With
`writable_roots=[]` and the temp directory excluded, `mkdtemp` under the user
temp folder fails with EPERM, so every real-Git fixture in `test/dogfood/`
fails. And `pnpm typecheck` never starts because corepack tries to fetch the
pinned pnpm from the network and times out. Until both are fixed, the author
cannot follow its own instructions and ISS-106 will stop at the first cycle.

## Done when

- The Codex launch in `scripts/dogfood/dispatch-adapter.ts` gives the author
  one writable temp root inside its own state directory and points `TEMP`,
  `TMP` and `TMPDIR` at it. The checkout, shared Git metadata and the
  controller remain outside the writable set.
- The worker environment carries what corepack needs to use the already
  installed pnpm offline (for example `COREPACK_ENABLE_STRICT=0` and
  `COREPACK_ENABLE_NETWORK=0`, or invoking the launcher resolved by
  `scripts/pnpm-launcher.mjs` directly), so `pnpm typecheck`,
  `pnpm format:check` and `pnpm test` run to completion inside the sandbox.
- A preflight in the dispatch adapter proves both on the host before the
  first author launch and reports a typed reason when either is impossible.
- One learning note on this issue records a real author run in which all
  three gates completed inside the sandbox.

## Out of scope

Retrying gate failures (ISS-103). Widening the sandbox beyond the worktree
and its temp root.
