## Why

In that run, the author trace contains `turn.completed` at
`2026-09-30T12:25:26.535Z`; the launcher wrote `exit.json` with `{"code":0}`
at `12:25:26.727Z`; and cycle 1 wrote `exit-receipt-timeout` at
`12:25:26.743Z`. The receipt existed 16 ms before the stop. The attempt had
launched more than 30 seconds earlier, so
`scripts/dogfood/dispatch-adapter.ts:671-690` treated the ESRCH result as past
the grace window even though this was the first poll that observed death.
The saved author trace had a terminal turn, so ISS-141's
dead-author-without-terminal-turn branch did not apply. After the host
restart, the same author verdict was consumed natively as cycle 2
`author-failed`, not converted into a new attempt.

The launcher ordering is confirmed in
`scripts/dogfood/observe-process.mjs:21-29`: the child `spawn` event writes
`process.json`, and the child `exit` event writes `exit.json` through a
temporary file and atomic rename. `dispatch-adapter.ts:635-638` reads the
receipt before the liveness probe. The reviewer path is not a separate
implementation: `supervise.mjs:511` composes `codexAdapter`, and
`queue.ts:3913-3925` delegates both author and reviewer observations to that
same adapter method.

## Decision

The smallest safe shape is one immutable, attempt-local first-observed-death
sidecar written when the real observe path gets `ESRCH` with no receipt. The
30-second `EXIT_RECEIPT_WINDOW_MS` is measured from that persisted instant,
not from `attempt.launchedAt`. Every later poll still reads `exit.json` first,
so a receipt written between poll N and N+1 is parsed as the terminal verdict.
The sidecar binds the attempt ID and PID, is written atomically without
overwriting, and survives a supervisor restart. If the sidecar is malformed,
belongs to another attempt/PID, the clock moves backwards, or a PID that was
already observed dead appears live again, observation stops unknown rather
than granting a new window or accepting a reused process. Unknown `kill`
errors remain fail-closed.

### Options

| Option | Assessment | Choice |
| --- | --- | --- |
| Persist first observed death and measure the existing window from it | Covers a long-running worker, the poll-N/poll-N+1 receipt race and supervisor restart with one bounded record; no new poller or retry mechanism. | **Select.** |
| Re-read `exit.json` immediately after `ESRCH` | Narrows the same-poll race but cannot preserve the first-death instant across restart, so a missing receipt can receive a fresh unbounded window. | Reject. |
| Persist the death instant and add an immediate re-read | Safe but adds a second read and branch that the next ordinary poll already performs; no acceptance criterion requires same-poll recognition. | Reject as unnecessary. |

The choice is wrong if a receipt appearing before the next poll still times
out, a restart resets the grace, a missing receipt survives past the bounded
window, or a reused PID/unknown liveness state is treated as terminal.

## Done when

1. **Bounded first-death state.** In
   `scripts/dogfood/dispatch-adapter.ts`, add an atomic sidecar beside each
   attempt trace (planned name `*.first-death.json`) containing a version,
   exact attempt ID, PID and the first observed-death timestamp. On the first
   `ESRCH` with no receipt, write it once and return `running`. On later polls,
   read and validate the same record and measure the existing 30-second grace
   from it. Never rewrite it from a later poll, never use `launchedAt` for this
   branch, and never reset it after a supervisor restart. A receipt read before
   the liveness probe continues through the existing parser and terminal
   identity checks.
2. **Fail closed.** A malformed or mismatched sidecar, a non-finite or
   backwards clock value, a PID that is live after the same PID was recorded
   dead (possible PID reuse), `EPERM`/`EACCES`/unknown `kill` errors, malformed
   `exit.json`, and an absent receipt after the sidecar's full grace all stop
   without a terminal verdict. Keep the existing ISS-141 author path exactly
   as-is for an author with no terminal turn. Do not infer success, failure,
   usage, retry permission or a new launch from process absence.
3. **Red-before through the real observe path.** In
   `test/dogfood/adapter.test.ts`, use the real `codexAdapter().observe()` with
   a fake clock and a controllable fake process table. Before the change,
   capture the deterministic failure: an attempt launched more than 30 seconds
   ago is first observed dead with no receipt at poll N, the receipt appears
   before poll N+1, and the current code throws `exit-receipt-timeout`. After
   the change, poll N records first death and poll N+1 returns the parsed
   terminal verdict. Exercise both `author` and `reviewer` roles through this
   same adapter path, and retain the queue delegation assertion showing there
   is no reviewer-specific observer.
4. **Negative controls and restart.** With every other input fixed, prove that

5. **Author-local handoff.** Planned files are

## Verification and boundaries

The implementation must exercise the real `codexAdapter().observe()` path,
not a copied classifier. The fake process table may be an injected liveness
function or a `process.kill` double, but it must control `ESRCH`, live, PID-reuse
and unknown-errno states independently while all files and trace events stay
fixed. A fake receipt is only the fixture input; the parser, role identity,
head checks and terminal status are production code. The restart case must
instantiate a fresh adapter with the same attempt directory, proving the
sidecar rather than an in-memory clock is authoritative.

No external authority supplies an acceptance value here: the lifecycle
authority is the child `exit` event plus the atomically renamed local receipt.
The exact lifecycle probe is captured above at `12:25:26.535Z`,
`12:25:26.727Z` and `12:25:26.743Z`; implementation evidence must record the
same ordering at poll N and N+1. Hosted CI, provider credentials, live runs,
executor installation and the real `/root` runtime are out of scope.
