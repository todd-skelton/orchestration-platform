## Why

In that run, the author trace contains `turn.completed` at
`2026-09-30T12:25:26.535Z`; the launcher wrote `exit.json` with `{"code":0}`
at `12:25:26.727Z`; and cycle 1 wrote `exit-receipt-timeout` at
`12:25:26.743Z`. The receipt existed 16 ms before the stop. The attempt had
launched more than 30 seconds earlier, so
`scripts/dogfood/dispatch-adapter.ts:671-690` treated the ESRCH result as past
the grace window even though this was the first poll that observed death.
The saved author trace had a terminal turn, so ISS-141's
dead-author-without-terminal-turn branch did not apply. After the host
restart, the same author verdict was consumed natively as cycle 2
`author-failed`, not converted into a new attempt.

The launcher ordering is confirmed in
`scripts/dogfood/observe-process.mjs:21-29`: the child `spawn` event writes
`process.json`, and the child `exit` event writes `exit.json` through a
temporary file and atomic rename. `dispatch-adapter.ts:635-638` reads the
receipt before the liveness probe. The reviewer path is not a separate
implementation: `supervise.mjs:511` composes `codexAdapter`, and
`queue.ts:3913-3925` delegates both author and reviewer observations to that
same adapter method.

## Decision

The smallest safe shape is one attempt-local first-observed-death sidecar,
written once when the real observe path gets `ESRCH` with no receipt. The
30-second `EXIT_RECEIPT_WINDOW_MS` is measured from that persisted instant,
not from `attempt.launchedAt`, for every receiptless dead worker, including
ISS-141's author without a terminal turn. Every later poll still reads
`exit.json` first, so a receipt written between poll N and N+1 is parsed as
the terminal verdict. The sidecar holds only that instant: its attempt-local
path already names the attempt and the loop has one writer (`docs/loop.md`
rule 9), so it carries no version, attempt, PID or schema checks. It survives
a supervisor restart; `supervise.mjs:511` also builds a fresh `codexAdapter`
on every loop iteration, so no in-memory clock survives even between polls.
Once the sidecar exists the PID is not probed again: the worker was observed
dead, so a reused PID cannot hold the attempt running past the grace. A
missing receipt past the grace, malformed `exit.json` and unknown `kill`
errors on the first probe still stop as they do today.

### Options

| Option | Assessment | Choice |
| --- | --- | --- |
| Persist first observed death and measure the existing window from it | Covers a long-running worker, the poll-N/poll-N+1 receipt race and supervisor restart with one bounded record; no new poller or retry mechanism. | **Select.** |
| Re-read `exit.json` immediately after `ESRCH` | Narrows but does not close the race: the observer's rename can still land after the re-read, and the window stays anchored at launch. | Reject. |
| Keep the first-death instant in memory | Adapter closure state is lost every poll because `supervise.mjs:511` rebuilds the adapter each iteration; module state is lost on restart and re-grants the window. | Reject. |
| Persist the death instant and add an immediate re-read | Safe but adds a second read and branch that the next ordinary poll already performs; no acceptance criterion requires same-poll recognition. | Reject as unnecessary. |

The choice is wrong if a receipt appearing before the next poll still times
out, a restart resets the grace, a missing receipt survives past the bounded
window, a reused PID holds the attempt running past it, or an unknown
liveness state is treated as terminal.

## Verification and boundaries

The implementation must exercise the real `codexAdapter().observe()` path,
not a copied classifier. The fake process table may be an injected liveness
function or a `process.kill` double, but it must control `ESRCH`, live, PID-reuse
and unknown-errno states independently while all files and trace events stay
fixed. A fake receipt is only the fixture input; the parser, role identity,
head checks and terminal status are production code. Every poll uses a fresh
adapter, and the restart case starts from a sidecar written before its adapter
exists, proving the file rather than any in-memory clock is authoritative.

No external authority supplies an acceptance value here: the lifecycle
authority is the child `exit` event plus the atomically renamed local receipt.
The exact lifecycle probe is captured above at `12:25:26.535Z`,
`12:25:26.727Z` and `12:25:26.743Z`; implementation evidence must record the
same ordering at poll N and N+1. Hosted CI, provider credentials, live runs,
executor installation and the real `/root` runtime are out of scope.
